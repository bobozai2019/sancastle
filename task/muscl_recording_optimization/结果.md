# MUSCL CPU 录制优化

状态：已实现并验证。范围是减少 CPU 每 tick 录制命令时的重复参数构造、字典查询和脚本函数调用。MUSCL 的数值公式、GPU 阶段数量、顺序和同步边界保持原样。

## 实现与边界

`scripts/simulation/unified_edit/water_muscl.gd` 缓存类型化命令描述：pipeline、uniform set、push constant 字节、间接缓冲和偏移、直接调度组数。缓存键包括请求 dt、cell size、边界启用状态、保波程度；键改变时重建。每 tick 仍调用 RenderingDevice 重新录制命令，不缓存引擎计算列表 ID。

边界参数仍在实际录制时读取；耦合、sim_finish 和尾部消费者仍在原位置调用。64 次候选尝试、GPU CFL 决策、接受/拒绝、材料处理及最终检查均保留。描述表属于当前 Water 资源实例，随释放清空，不写入检查点、不跨 generation 复用 RID。

本次只修改以上运行脚本。工作区其他场景、水边界、植被等并行改动均保留。基线取自开始优化时的实际工作区文件，包含当时已经存在的边界参数接口，不能用较旧的 HEAD 替代。

## 数值一致性

[测试脚本](../../tests/integration/muscl_recording_cache_probe.gd) 为新旧录制器分别创建真实 GPU 资源。五组初态覆盖静水、侵蚀/材料耦合、保波程度、开放边界和高流速；各组依次请求 `1/30, 1/30, 0.004, 0.004, 1/30` 秒，覆盖缓存复用、步长变化重建、重建后复用。

25 个逐 tick 对照全部逐字节相同：权威纹理及双槽、decision、control，以及 MUSCL trial、safety、audit、trial_indirect 缓冲。接受和拒绝候选的路径均实际发生；高流速用例出现 19 次接受、17 次拒绝。无效 dt 拒绝、释放也通过，共 231 项检查。没有专门构造耗尽 64 次尝试的输入；不能将本次覆盖宣称为所有输入的穷举证明。

结果和每个字段的 SHA256 见 [exact.json](evidence/exact/exact.json)，运行日志见 [exact.log](evidence/exact/exact.log)。

## 可见主场景成本

环境：Intel i5-9300H、NVIDIA GTX 1050、Godot 4.7.2 stable steam `ed1daf0bf`、D3D12 Forward+、1280×720、VSync 开启。加载完整主场景，参数窗口隐藏、无工具操作。脚本 profiler 关闭；启用有界 CPU 诊断和 GPU 时间戳。

同一运行实例、同一资源交替使用旧/新录制器，顺序 A–B–B–A；预热 5 秒，每段切换后稳定 2 秒，再采样 12 秒。场景状态连续演进。CPU 指标为 `submit_begin` 至 `submit_end` 的整个批次区间，并非单独 MUSCL 函数时间；各区间不叠加。分位数从原始样本合并计算。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| CPU 提交样本数 | 528 | 609 |
| CPU 提交平均耗时 | 6.050 ms | 4.650 ms |
| CPU 提交 P95 | 9.533 ms | 7.655 ms |
| 窗口帧间隔均值 | 68.037 ms | 59.423 ms |
| 窗口帧间隔 P99 | 127.076 ms | 131.667 ms |

本次 CPU 提交均值降低约 **23.1%**。两段优化后区间均低于两段优化前区间。诊断没有丢弃事件，场景未报告运行错误。

窗口均值改善，但长帧 P99 没有改善，卡顿没有解决。GPU tick 标记均值从 22.887 ms 变为 19.246 ms；本次没有修改 GPU 算法，状态连续演进、桌面负载和调度均会影响测量，不能据此宣称 GPU 计算量下降。主视口 GPU 时间仍约 14 ms。窗口焦点比例未单独记录，结果不构成固定帧率保证，也不能直接与其他场景版本的历史 FPS 比较。

当前稳定 dt 可重复利用缓存；持续改变缓存键会增加重建次数，这种调参压力场景的收益未单独测量。

原始数据：[capture.json](evidence/cost/capture.json)、[summary.json](evidence/cost/summary.json)、[日志](evidence/cost/run.log)。采集器：[muscl_recording_cost.gd](../../tools/parameter_windows/muscl_recording_cost.gd)；分析器：[analyze_muscl_cost.py](../../tools/parameter_windows/analyze_muscl_cost.py)。

## 复验入口

以下从工程根目录执行，`$godotExe` 指向上述 Godot 引擎。输出目录应使用新的空路径，冷启动探针拒绝覆盖已有结果。

```powershell
$godotExe = 'D:/game/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe'
& $godotExe --path . --script res://tests/integration/muscl_recording_cache_probe.gd -- --output=res://test_output/muscl_recheck/exact
& $godotExe --path . --script res://tools/parameter_windows/muscl_recording_cost.gd -- --output=res://test_output/muscl_recheck/cost
python tools/parameter_windows/analyze_muscl_cost.py test_output/muscl_recheck/cost
python tools/parameter_windows/run_muscl_restart.py --output test_output/muscl_recheck/restart
```

每条 Godot 采集命令结束并输出结果后再执行下一条；不要并行运行成本采集。冷启动辅助工具从已保存结果读取资源路径，在新目录复制当前代码后冻结两次运行的源码；旧数值结果仍以归档及记录的 hash 为准。
