# 水动量实验实现约定

日期：2026-10-19。角色：contract。状态：draft；G0/G1 后冻结对应部分。数值候选是拟定设计，实际结果仅进入验收目录。

## C01：场景与正式流水线隔离

1. 实验入口拟为 `res://scenes/experiments/water_momentum_lab.tscn`，显式启动；不加入正式切换菜单，不改项目默认入口，不继承正式可玩入口，不调用 `BeachScenes.attach`。
2. 实验只拥有新建的域、纹理、buffer、pipeline、材料实例、时钟、命令队列和输出目录。不能引用正在运行的正式 runtime/state，也不修改外部 Resource 实例的参数。可变材质使用本地资源或显式复制。
3. 固定节点、布局、光照、相机、网格和信号保存到 `.tscn`；运行时只分配 GPU 状态、动态指示和随输入变化的数据。
4. 正式浅水数学核可以只读复用，需记录源码 hash 和依赖闭包；需要改接口时将必要核复制到实验 reference 目录并记录来源／改动，禁止修改源文件。所有对照共用同一份数值核。旧 trial 脚本／核仅作参考，不直接挂到正式服务。
5. 允许新增实验目录、任务文档与独立证据；新证实的竞品知识更新 `docs/competitor/` 对应主题和统一入口。禁止修改主场景、正式公共编辑／调度／碰撞／存档、全局输入／autoload、现有 catalog 和封存白名单。
6. 审计正式入口的静态／动态资源引用和全局类注册；实验无全局副作用，不注册同名 class_name。若当前工程无法满足隔离，用独立小工程承载同一实验场景并保留来源清单，不能通过修改正式服务绕过边界。
7. 隔离证明比较本任务开始时的实际文件 hash，不用干净 Git HEAD 覆盖工作区其他改动；外部改动单独标注并重新取实验基线，不回滚他人工作。

## C02：实验输入与状态

本接口仅限实验，不使用或扩展正式512B命令。G1补齐二进制布局、打包／解码及合法范围；字段不经浮点存储整数身份。

| generation / command_id / stroke_id / sample_id | int64 | 非负有序、代次匹配；重复样本不重复注入 |
| target_tick / phase | int64 / BEGIN、SAMPLE、END | 编辑在对应实验水步之前，控制包本身不注入 |
| start_xz_m / end_xz_m / radius_m | Vector2 / Vector2 / float | 有限值、正半径、范围由profile约束 |
| bed_operation | dig / fill / shovel_transfer | 实验夹具；不冒称生产工具业务、库存或碰撞行为 |
| brush_transform / template_id、hash | 变换／字符串 | 记录坐标朝向、正负模板和mask；模板不可隐式更换 |
| response_mode | A0 / A1 / B | A0无额外冲量；A1现有响应公式对照；B新候选 |
| impulse_gain_m_s / max_speed_m_s | float，m/s | 无效数拒绝；增益范围及上限在G1冻结，先以现有4m/s保护作候选 |

## C03：参考、候选算法与对照

### 事实边界

- 竞品历史 mode6：`v_new = v_old − M × G × 5 × n`；M含范围／alpha／衰减，G来自有符号模板。n的归一化涉及竖直分量。实际绑定模板556不能用另一事件的578代替。
- 原作使用边速度参与量输运；项目保存格心动量。坐标、场位置及物理单位都要映射，不能只把原作速度5填进项目参数。
- mode2会改amount；原作全部挖沙工具与mode6的对应关系、持续调用频率和画面快速散水的因果尚未确认。
- 本实验选择“编辑水深不变＋局部动量源”的项目设计；不声称它就是竞品每种操作的实现。原作事实统一引用 `docs/competitor/`，本文件不创建新的原作结论。

### 首轮候选（G0决定最终形式）

```text
已接受床面变化／笔画新覆盖
  → 局部模板权重M、正负增益G、方向d
  → 有限的速度增量 Δv = gain × M × G × d × activity
  → q_candidate = q_old + h × Δv
  → 干湿保护、限速／数值检查
  → 与本次床面作为完整实验状态发布
  → 后续水步搬运水量，形成波动／回流
```

`activity` 是本次实际新发生编辑的无量纲权重，具体由新覆盖或实际床变归一化给出；G0选择一种并定义不变量。首轮按编辑事件注入有限冲量，不按渲染帧持续加速；停止输入后无新增源。若未来需要持续搅水，应独立定义 m/s² 源及真实dt，不能混用。

方向和符号先通过竞品有效分支与模板解释，再用明确标注的 Godot 模板落地；径向、两侧和移动方向不能同时凭观感随意叠加。沟底挖低和肩部抬高分别观察，不预设必须都向外推。

每个 pass 读不变输入、写独立候选，逐格并行，重叠命令按明确顺序执行；不建湿区连通域，不做全域水量搬移。必要的检查归约可以并行分块，统计单独计时；不能为“零同步”删除状态校验和资源完成证明。

### 三个对照

| 模式 | 水编辑 | 作用 |
|---|---|---|
| A0 | 保持h、悬沙、q，只改同一床面 | 测自然水模拟自身的响应 |
| A1 | 复现当前局部速度公式，形状工具只对抬床处响应 | 识别现有响应与新模板差异；抽样与源公式对照 |
| B | 候选有符号局部速度场，转换到q | 验证推水效果及成本 |

三组共用沙床轨迹、水核、dt规则、边界、初态、渲染和采样口径。A1仅是公式对照，不宣称复刻完整策略2、审计与正式调度开销。首轮不包含旧连通排水对照实现。

### 数值边界

- 编辑瞬间h与悬沙逐字节不变；笔刷支持域以外q不变，无编辑／零增益不注入。
- NaN/Inf、负深度、错误代次、非法模板和乱序输入明确拒绝，拒绝包不能产生部分可见修改。
- `h≤0.001m` 首轮不注入；干格q归零由明确的规范化阶段负责，不把规范化造成的改变混为冲量。
- 限速事件、实际Δq、动能变化分别统计。工具注入可以增加动量／能量，不要求全局动量守恒；水量守恒和沙量账本仍须验证。
- CFL根据更新后的速度决定推进dt；记录实际完成dt，不依靠clamp掩盖失稳。

## C04：时序、暂停与资源生命周期

- CPU提交本帧已知的命令序列；GPU按编辑→水步→发布顺序执行。未来输入不能预先提交，批次不能跨越未解决的真实依赖。
- 帧头只消费已完成的诊断／完成通知，不等待未完成GPU工作；回执可能晚于下一帧，不能把“下一帧”当完成证明。实验的槽数和容量在G1冻结并记录背压。
- 不在逐笔编辑路径调用同步全场读回或等待碰撞。统计读回异步且有界，缓冲耗尽明确丢统计／记缺口或背压，不能静默丢物理命令。
- 暂停冻结水步与表现时钟；允许编辑时仅应用编辑冲量。单步按实际完成dt推进一次；复位／对照切换只在旧工作退役后发布新代次。
- 退出等待真实完成并释放自有RID，不释放共享资源；旧回调不能写新状态。实验进程不加载正式会话存档。

| 类别 | 必需字段 |
|---|---|
| 身份 | run_id、profile/source/fixture/trace hashes、generation、command_id、sim_tick、state_seq |
| 时间 | CPU输入／入队／录制／完成通知时刻、GPU时间戳区间、实际sim_time_s、请求／实际dt、子步数 |
| 数值 | 水／沙存量与源汇、闭合误差、min_h、非有限值、max_speed、限速数、总Δq、动能变化 |

| 成本 | CPU输入/录制/消费ms、GPU沙夹具/冲量/水步/校验/发布ms、frame P50/P95/P99、队列深度／年龄／背压 |
| 环境 | GPU、驱动、Godot、后端、分辨率、VSync、窗口可见性、其他负载、采样模式 |

错误：`invalid_input`、`stale_generation`、`duplicate_sample`、`out_of_order`、`queue_full`、`nonfinite_state`、`mass_budget_mismatch`、`gpu_timing_unavailable`。时间戳不可用时标记GPU成本未知，禁止用CPU等待时间代替。

输出到独立英文 `run_id` 目录：manifest、有效配置、轨迹、原始指标、少量同完成态场快照、视频／截图与分析报告；保留失败。截图不能独立证明水量变化；异步统计不可把不同完成态的h和q拼在一起。
