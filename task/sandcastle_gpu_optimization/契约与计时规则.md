# GPU 优化契约与计时规则

日期：2026-10-17。角色：contract_draft。用户的半小时上限自计划起固定；技术字段和比较夹具在 P00 核对，现有运行契约立即适用。

## C01 每项一次累计窗口

1. 从开始该项针对性分析/编码/试验时记录 `started_at` 和单调计时，截止为开始后 30 分钟。准备该项专用测试、编译、等待 GPU/工具、比较、诊断、记录、回退均计入；提前进行该项工作也必须提前启动它的时钟。
2. 同项可在窗口内小步迭代，但多次候选、工具重试、上下文恢复、失败修复、聊天中断不能重新计时。没有“再给半小时”。不以改名、拆子任务、换 agent 或 P08 补调参绕过上限。
3. 每次长操作前检查剩余时间；不得启动预计无法在截止前停止并完成清理的操作。第 25 分钟开始收尾；测试需有期限和正常退出途径。
4. 到期立即停止性能探索。验证充分且收益可解释则保留；其余保存必要证据后撤下候选，状态写明超时/无收益/证据不足，转入下一独立项。已知错误不能带入后项。
5. 未使用时间不滚存。P00、P08 同样各有最多 30 分钟窗口；不能作为其他优化项的额外实现时间。
6. 用户显式暂停则保存已用预算；恢复时只使用剩余预算。普通等待不暂停计时。外部环境故障应尽早收束，不持续消耗时间做无限重试。
7. 预留清理时间，资源必须按最后消费者规则释放。若发生不可预见的所有权故障，截止后仅可停止自有探针和保全状态，不再改算法或补测；额外安全收尾时间单列报告，不能伪称在预算内完成。环境仍不安全时不得启动下一 GPU 探针。
8. 本轮结束后不自动重开跳过项；重新研究属于后续独立授权范围。

## C02 工作区、状态和历史

- 单主执行者串行；共享 shader、场景、profile、契约只允许一个修改者。本轮不复制整个工程。
- 起步记录 Git 状态和已有未提交文件身份。仅撤回本任务自身差异，禁止整树 reset/checkout 覆盖用户或其他工作的修改。
- 每项保存 parent baseline 与 candidate 身份；成功后更新保留集合，失败回到本项 parent。原始失败结果和旧性能判定保持原样。
- `[已完成]` 只用于本项交付与相应验证完成。`[已跳过]` 表示超时、无收益、证据不足或前提缺失后的排程关闭，不计优化成功。
- 全轮已处理率、技术小目标完成率、保留优化数分别统计；本轮关闭不等于所有优化成功。

## C03 技术边界

沿用[新流水线接口与状态契约](../sandcastle_gpu_pipeline/接口与状态契约.md)和[可复用技术契约](../../docs/knowledge/README.md)，本轮不修订物理语义。

- 保留普通命令顺序、逐笔独立拒绝、候选先验证后完整提交；GPU 完成发布不恢复为 CPU 逐笔授权。
- `generation/batch_seq/slot_id/lease_id/state_seq/sim_tick/revision` 的唯一推进者、整数身份和槽位所有权不变；不将提交成功当作 GPU 完成。
- CFL 安全约束、最大子步保护、实际积分时间、奇偶槽归一及关联表现时钟不变。不能直接缩小上限、少执行物理阶段或丢掉时间债务制造加速。
- 水沙/动量/悬沙/材料数据继续满足各自有效性和拒绝契约。自由编辑近似源汇不等于允许跳过这些校验。
- 并行归约改变浮点加法顺序时，先核对现有适用容差、拒绝边界和确定性要求；不能静默放宽容差或以近似账本豁免。现有要求无法满足就撤回候选。
- 无排水需求快路只省对应连通/容量求解；仍须正确初始化候选、速度响应、审计/错误标志和完整提交。不能只按“remove_sand”名称跳过水处理。
- 碰撞保留真实 rock+sand 高度、共享边、微小变化、版本单调与旧代次拒绝；新脏区不能被旧快照消费清空。
- 保存/恢复和切换保持既有完整快照、签名与失败隔离；新增工作缓冲应可重建且遵守生命周期，不随意新增持久格式。
- 可见绘制保持现有效果与消费资源。不可减少分辨率、关闭侵蚀/白沫/亮纹或降低模拟频率；不修改竞品资料。

## C04 内部接口与观测字段

无新 HTTP API、数据库或页面。原命令、完成通知、CFL 和高度快照的 ABI 沿用现契约；本轮优先不改生产接口。新增诊断使用独立、可关闭、有界记录，不阻塞提交。

执行记录建议 JSON 字段（尚未实现采集器）：

| 字段 | 类型 | 约束 |
|---|---|---|
| schema_version / task_id / run_id | int / string / string | 格式版本、任务和唯一运行身份 |
| started_at / deadline_at / finished_at | string | 带时区时间；用户展示 Asia/Shanghai |
| elapsed_seconds / safety_cleanup_seconds | number | 单调时间累计；无采样写 null，不能填假零 |
| parent_manifest / candidate_manifest | string | 指向本轮父基线与候选身份 |
| source_hashes / resource_hashes / effective_profile_hash | object / object / string | 实际消费身份，无法确认则证据不足 |
| hardware / engine / backend / viewport / vsync | object | 实际机器、引擎文件身份、窗口与并发负载 |
| case_id / seed / completion_state / input_trace_hash | string / int / object / string | 固定输入与完成态，跨版本不能伪称可恢复 |
| generation / batch_seq / state_seq / sim_tick | integer | 大整数无损记录，不经 float32 或不安全 JSON number 转换 |
| phase / frame_id / clock_domain / unit | string / integer / string / string | 区分 CPU 墙钟、GPU 时间戳、采样帧、单位 |
| metrics | object | 实测指标及样本/窗口描述；无具体目标阈值 |
| correctness / performance_evidence | string | pass/fail/incomplete；improved/neutral/regressed/inconclusive |
| decision / reason / evidence_paths | string / string / array | keep/revert/skip，理由与证据路径 |

GPU 分段至少区分水 tick、编辑水核、发布、碰撞打包与视口绘制；父子跨度不得重复相加。CPU 录制、提交至回调、实际 GPU 执行分开。采样默认粗粒度，局部详细时间戳只覆盖当前待测热点，避免每个空派发都计时造成额外负载。

## C05 保留判定

正确性通过、比较条件一致、受影响指标呈可解释改善且其他关键体验无明显退化，才进入保留集合。噪声大、样本不足、加载身份不明、测试超时均判证据不足。指标方向冲突时明确记录取舍；没有充分依据则回退。

占用百分比不作为放行门。计划不填任何 FPS、阶段耗时、吞吐、延迟、改善百分比目标；实际证据必须如实保留测量值和适用边界。
