# GPU 优化验证计划

角色：validation_plan。本文件保留执行前验证方法，命令示例本身不代表通过；本轮已经收束，实际命令、结果与局限见[验收索引](验收/README.md)。

## 1. 观察什么

| 指标 | 关注方向 | 计时/采样边界 |
|---|---|---|
| 整帧耗时分布和长尾 | 减少反复长帧与尖峰 | 可见窗口墙钟，记录完整负载 |
| GPU 编辑与水模拟阶段耗时 | 相同工作更快完成 | 同捕获帧成对时间戳；跨帧记录不能直接相减 |
| CPU 命令录制时间 | 减少参数构造与提交开销 | 函数录制墙钟，不冒称 CPU 实际指令时间 |
| 输入到发布与停手拖尾 | 减少等待与积压 | 入队/提交/完整发布分别记录；不冒称显示器扫出 |
| 实际模拟时间推进 | 保持推进、公平性与语义 | 同时记录完成 tick 和 actual time，不以少算冒充更快 |
| 队列、在途槽和回收等待 | 查出供给不足或背压 | 记录槽满原因；不盲目增大容量 |
| 碰撞传输、准备与版本年龄 | 减少无效更新，保证最终收敛 | GPU 完成态到物理应用；等待不当作独占物理成本 |
| 水核回退/快路命中 | 解释常见路径和长尾 | 有界计数，关闭观测不改变行为 |
| 资源与数值/视觉正确性 | 不增加泄漏或行为退化 | 实际字段、原始字节、射线和配对画面 |

本计划不设置上述指标的具体数值目标。原始测量保留实际数值；正确性继续引用现有契约，不另设更宽松容差。

## 2. 配对方法

1. P00 固定当前新路径、相机、seed、输入轨迹、初始完成态、profile、窗口与后端。检查点签名不同则使用同源初态重建，不能关闭签名校验硬加载。
2. 空闲运行、连续挖、连续填、暂停模拟下编辑分别使用独立且固定的输入。实时吞吐窗与同 tick 数值比较分开，不能因为候选推进更多 tick 就直接比较终态。
3. 每项只改变一个可归因因素；编译及初始化不混入稳定窗。冷启动现象单独记录，不删掉不利结果。
4. 先编译、短运行及受影响负例，再执行父基线/候选比较。时间允许时交错次序排查漂移；不足则判证据不足，不追加预算。
5. 同一时刻只运行一个自有 GPU 探针，保留用户已有进程并记录其负载；不擅自关闭用户游戏/编辑器。环境无法比较时跳过，不把 headless 成本当 GPU 结论。
6. 记录引擎可执行文件、源码/资源/profile hash、真实输出尺寸、VSync、硬件、后台负载、窗口和退出码。
7. 每项测试必须在其预算内结束并预留资源收尾。若既有大探针无法放入剩余窗口，选对应聚焦检查；不能削减必要的正确性覆盖后宣称通过。

## 3. 任务到验证映射

| 任务 | 重点正确性 | 性能比较 |
|---|---|---|
| P00 | 采样开关不改变字段/时钟；时间戳分类正确；无假零 | 采样开销与新路径完整性 |
| P01 | 动量/能量/最大信号、NaN/非法值、拒绝临界及材料开启/关闭 | 速度归约分项、整笔编辑、整帧 |
| P02 | 同实际步长/子步的水/沙/材料，奇偶及上限、非法 CFL、完整发布 | CPU 录制、GPU 水 tick、整帧 |
| P03 | 纯降床、混合抬降、干湿交界、障碍、速度响应、候选无旁写 | 快路命中、编辑阶段与拖尾 |
| P04 | 不连通湿区、狭窄连接、复杂行段、容量不足、残差、原回退 | 选定阶段、回退成本、整笔 |
| P05 | 跨块共享边、微小变化、后续新脏、乱序/旧代次、侵蚀后收敛、射线 | 回读量、打包/解码/物理应用和版本年龄 |
| P06 | 持续输入水 tick 仍推进、顺序/公平性、槽满、暂停与旧工具边界 | 队列等待、发布延迟、长帧、停手拖尾 |
| P07 | 固定完成态三入口画面对照、干湿接触、时间一致、有效绑定 | 选定渲染热点与视口耗时 |
| P08 | 保留集合的组合运行、必要保存恢复/切场景/退出、资源归属 | 只确认已保留收益未被组合抵消，不继续调参 |

## 4. 已有入口与新增入口

复用以下已存在的功能探针，执行时按受影响范围选择，不每项重跑全套：

- `tests/integration/async_pipeline_edit_probe.gd`：逐笔拒绝、实际编辑字段；支持 `--no-mold`。
- `tests/integration/async_pipeline_water_probe.gd`：CFL/归一/水场；支持 `--coupled --mold --boundary --visuals`。
- `tests/integration/async_pipeline_collision_probe.gd`：真实高度、物理查询及版本负例。
- `tests/integration/async_pipeline_main_probe.gd`：主场景与工具/UI；支持 `--scene=...`、`--tools --ui`。
- `tests/integration/async_pipeline_checkpoint_probe.gd`、`async_pipeline_lifecycle_probe.gd` 及相应 fault 探针：仅在保留改动影响其边界时选择。

P00 拟新增 `tools/gpu_optimization/profile.gd` 和小型结果分析入口，优先复用已有探针初始化，不维护第二套运行配置。这些文件目前不存在，不提供伪造的可运行命令。

已有功能探针的拟执行示例（每次使用新的 run 目录，先核对引擎与预算；不使用 headless 测 GPU）：

```powershell
$gpuOptEngine = 'D:/game/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe'
$gpuOptProject = 'D:/godot/project/sandcastle'
$gpuOptRun = 'run_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
$gpuOptOut = Join-Path $gpuOptProject ('test_output/gpu_optimization/' + $gpuOptRun)
New-Item -ItemType Directory -Path $gpuOptOut -Force | Out-Null
& $gpuOptEngine --path $gpuOptProject --log-file (Join-Path $gpuOptOut 'edit.log') --script res://tests/integration/async_pipeline_edit_probe.gd -- ('--output=res://test_output/gpu_optimization/' + $gpuOptRun + '/edit.json')
```

上例不是半小时超时监督器。实际执行须由主执行者在启动前记录截止、管理自有 PID 和正常关闭；不启动预计无法按时收尾的测试。机器输出使用完整英文目录，生成源码快照使用 `.source` 后缀并隔离 Godot 扫描。

## 5. 证据和最终核验

机器记录放 `test_output/gpu_optimization/<unique_run>/`；结论放本计划的 `验收/`。保留命令、运行日志、计时、身份、原始指标、负例及退出结果，不覆盖旧输出。

P08 只验证已经有单项证据的集合。新组合失败优先撤回可归因改动，必要时撤回本轮全部运行改动回到起点；不能占用 P08 做新性能方案。联合证据不充分的候选退出默认路径，结论明确写“部分保留”或“无性能项保留”。扩大验证或再次优化留待后续，不默认续跑。
