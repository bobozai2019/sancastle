# [完成] Sandcastle近似GPU编辑测试场景执行计划

日期：2026-10-12。角色：execution_plan。场景、验证与成本比较已交付；性能分项目标判定见验收报告。实际进度见[执行状态](执行状态.md)，实际结果另存[验收](验收/README.md)。本文件任务表保留计划起点，不用于累计实际完成度。

## 1. 项目目标

新增可独立启动的测试场景，验证固定方向玩法的性能取舍：鼠标射线与固定参考高度平面求交，GPU读取对应XZ的真实沙高并堆挖；不创建物理形状、不回传碰撞高度、不等待物理反馈；库存按请求设定量记账；每笔编辑不读取CPU结果回执；水响应采用高度/量及速度模板的近似思路。比较当前准确路径与独立候选的GPU成本、画面反馈、连续拖动和视觉表现，给出可采用范围与问题。

来源：[性能取舍分析](../../docs/sandcastle性能取舍分析.md)、[当前堆挖诊断](../../docs/search/edit_stutter_diagnosis.md)、[竞品compute对照](../../docs/competitor/GPU编辑计算_项目对照.md)。竞品只提供已确认的参考结构；本项目单位、近似公式和调度属Godot适配，不冒称完整原作复刻。

默认单主执行者串行推进，不启动subagent。计划、运行状态和实测证据分开保存，旧性能FAIL与旧Gate不计入新任务完成。

| 契约 | 内容 | 冻结任务 |
|---|---|---|
| C01 | 文件隔离、资源身份、原场景与checkpoint签名 | T00 |
| C02 | 屏幕/平面/XZ/沙高、相机及尺度 | T00 |
| C03 | 命令字段、固定库存、队列与错误 | T00 |

| C06 | CPU/GPU时钟、输入/发布/完成口径、测量开销 | T00 |

| 模式 | 入口/依赖 | 用途 |
|---|---|---|
| original_baseline | 只读加载scenes/main.tscn，固定相机与当前消费profile | 当前准确实现基线；不消费候选开关 |
| isolated_exact_water | 新测试场景；去物理与CPU回执门控，暂留准确GPU水候选计算 | 分离事务/碰撞收益；GPU内部receipt/control可保留，CPU不读取 |

| diagnostic | 在上述模式开启GPU时间戳/诊断快照 | 定位计算与发布；不得与无诊断性能混算 |

isolation与算法切换只能消费新场景自己的配置。原场景禁止新增候选flags。若准确水中间模式无法通过独立适配接入，在T00记录原因并以独立单因素探针补证，不能用受混杂整窗比较宣称各项独占收益。

## 5. DAG与门禁

```mermaid
flowchart LR
    T00[隔离基线与契约] --> T01[静态场景与固定相机]
    T01 --> T02[固定平面笔刷与GPU提交]
    T02 --> T03[近似水响应]
    T03 --> T04[功能/视觉/短成本对照]
    T04 --> T05[结论与复验交付]
```

安全并发窗口：无默认并行执行者。只读代码检查与文档整理可独立安排；scene、shader、profile、状态机和契约由主执行者唯一修改，GPU测量串行进行。

- Gate0：隔离路径、初始化同态、命令及近似语义冻结，旧签名影响已核对。
- Gate1：新场景直接启动，静态相机/UI/资源保存到tscn，无碰撞shape，无原场景改动。
- Gate2：GPU堆挖、固定库存、拖动及暂停闭环；无逐笔CPU回执、无物理等待；发布顺序可验证。
- Gate3：近似水响应可连续观察，无NaN/负沙/负水，无明显爆速或数值崩溃；视觉取舍有对照。
- Gate4：新功能负例、同态短测、完整负载和原入口保护均有证据，给出采用/继续调整/不采用建议。

性能期望：GPU编辑1–3ms与60Hz下1–2帧反馈为探索目标，不是已达成或承诺。必须单列帧p99/max、输入至画面提交、GPU执行及积压；目标未达到就如实记未达到，不以主观顺滑代替数据。

## 7. 验证与证据计划

先编译检查与数秒启动，再单笔挖填/拖动/暂停负例，之后单变量视觉与连续观察，配置稳定后集中做短成本。

- 功能：平面射线平行/背向/越界、干沙/湿沙/深坑/高丘、无沙可挖、无库存可填、UI阻挡、鼠标释放、快速交替堆挖、队列达到上限、暂停中编辑、复位、退出时在途工作。
- 语义：固定库存按请求量变化，GPU实际沙量可以不同；不写入原守恒账本。水量/动量偏差允许但须报告代表性净变化，不宣称守恒；大幅值与边界不得导致NaN、负高度量或持续爆速。
- 顺序：固定seed、初态、tick、相机、笔刷轨迹与参数；GPU只消费完成态，命令与tick不并发写同一资源；公开序列用于区分submitted、dispatched、published与诊断确认完成。
- 性能：D3D12真实可见窗口，当前默认1280×720与实际消费材质/80浪/侵蚀；默认VSync开启，关闭VSync另列。GPU时间戳诊断与无诊断短成本分开。稳定后各关键用例做至少3对交错30秒短窗；固定轨迹与执行tick同时记录，不以不同运行tick的状态冒充同态算法A/B。
- 视觉：同相机/完成态捕图；单笔及连续5分钟观察，关注指向偏差、空洞、堆沙水面突跳、速度爆发、岸线和白沫变化。禁止通过降低渲染负载把变化归因于编辑算法。
- 负载：启动前核对Godot/RenderDoc及其他GPU工作，保留用户PID21316和其他任务。若有并行GPU负载，先标记诊断受污染，不用于因果收益选型。

初始化优先从同一冻结的原生字段/visual完成态建立两个backend，生成新夹具身份与读取过程索引。原场景原生checkpoint规则不修改；候选用隔离夹具/新进程复位，不使用旧生产checkpoint标签保存近似状态。

机器输出统一`test_output/approx_gpu_edit_trial/<英文run_id>/`；Gate报告放本任务`验收/`，只链接原始数据。保留工具命令、引擎/硬件/驱动、窗口/VSync、源和profile hash、实际参数、原始计时、失败和退出状态。所有性能结论限当前新配置，不累计历史G5通过。
