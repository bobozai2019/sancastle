# Gate4 成本与交付结论

日期：2026-10-12。独立场景、功能、诊断、对照和交付工作完成；探索性能目标分别判定。建议继续使用独立实验分支验证固定方向玩法，暂不替换主场景。

环境：Godot4.7.2 ed1daf0bf、D3D12 Forward+、GTX1050、驱动581.83（Windows32.0.15.8183）、1280×720、VSync开启。原相机(-6,6,10)看向原点；完整水/沙材质、反射、白沫/亮纹、80浪调度与侵蚀保留。每个run保存实际有效profile、初态hash、源码/resource hash、命令、退出与原始计时。成本窗口禁止外部UI/相机输入；原性能面板的默认时间戳采样关闭。各正式短窗启动前未发现其他Godot/RenderDoc/Blender进程，不据此排除所有系统GPU活动。

准确policy3中的pass7（water_packed_cached）GPU中位数13.260ms、pass6（water_velocity_prefetch）13.444ms；其余水pass中位数约0.009–0.054ms。这是当前有效绑定核的实测，不按名字把pass1误判为主耗时，也不冒称竞品实现。policy0/3是同准确沙算法的单因素对照；近似候选沙算法也改变，因此两后端总差不能全部归因水核。

默认笔刷在本次诊断中低于3ms探索预算，GPU编辑成本目标在该限定样本内通过。真实逐像素变化和scanout未测，不能因此宣称1–2帧反馈通过。

## 适用边界与未解问题

适用于固定相机/平面指向、无需角色刚体碰撞、接受名义库存和局部水模板误差的独立玩法实验。半径0.125–1m、每笔量不超过0.06m³、厚度/水量/速度限幅与队列预算继续有效。正式守恒库存、物理接触和checkpoint仍使用原入口契约；主场景未接入候选。

- U01 整帧峰值来源C0：候选有154–232ms短窗峰值，可能是冷渲染/管线、RD排队或系统调度。区分方法是固定完整初态、同轨迹、逐帧渲染/GPU队列与首笔/热笔联合捕获；本次不凭局部核耗时排除排队或渲染成本，不反复改噪声/增益。
- U02 真正像素反馈C0：CPU发布请求与post_draw已有数据，但缺像素变化、Present/scanout时间。下一步以固定单笔和同步画面序列关联GPU事件测量；当前只报告已有口径。
- U03 模板误差已观察C3：挖沙增水、填沙删水、空沙也增加名义库存、限高/截边有偏差。固定平面在高丘与深坑存在透视偏差；不能用于要求真实体积/命中点的场景。
- U04 性能端点条件C0：部分窗口帧率/峰值差异未完全归因，早期短窗未逐帧记录聚焦与GPU时钟。最终受控长观察记录全程聚焦/未最小化及SMI遥测；不能反向补足早期证据。

保护核验：[438个生产文件及配置扫描](../../../test_output/approx_gpu_edit_trial/baseline/protection_check.json)，全部原hash保持且无新增扫描文件。原入口3对30s实际准确编辑通过；独立入口直接启动见direct_20261012_022522。没有修改原main、project.godot、ReleaseConfig、正式shader/profile和保存恢复校验；历史失败未改判。

源码中的最后两项收尾仅增强复位epoch、关闭优先级和拖动进入UI的终止保护；首次启动仍generation1，性能/模拟/shader不变。受影响的生命周期与输入探针单独复验，未机械重跑长稳。全部原始证据与失败入口见[验收索引](README.md)。
