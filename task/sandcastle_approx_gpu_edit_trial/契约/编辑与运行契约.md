# 编辑与运行契约

日期：2026-10-12。角色：contract。状态：C01–C06 冻结为独立实验契约。冻结数值与适配边界见[隔离与冻结](../验收/T00_隔离与冻结.md)。C05是近似Godot适配，不是生产守恒契约。只约束新测试场景，不修改原生产契约，不存放实测PASS。

## C01 隔离

原main、project.godot、运行资源和准确算法只读。新候选不注册默认入口，不修改生产ReleaseConfig，不借用原checkpoint标签。新增文件路径必须核对原source_signature扫描；原有签名变化不能靠放宽校验处理。

## C02 坐标与拾取

鼠标屏幕位置经固定Camera3D投影射线，与`reference_height_m`水平面解析求交；射线平行、交点在射线背后或XZ越界时拒绝。初始建议reference_height_m=0，按当前真实profile核对后冻结；相机位置沿用(-6,6,10)，朝向原点。定义米制cell_size、domain原点、闭开边界及XZ到cell-center规则；GPU读取真实床高，不从CPU碰撞命中取高度。

笔刷预览与实际消费XZ一致；预览贴地高度若来自GPU可见状态，不引入逐笔CPU读回。固定平面与可见沙丘偏差作为玩法规则展示和验收。

## C03 提交API、固定库存与队列

`submit_brush(request) -> admission`仅表示CPU准入，不表示GPU已经执行或实际挖取量已确认。

| 请求字段 | 类型/约束 |
|---|---|
| generation / command_id | 非负epoch、单epoch严格递增ID；拒绝过期与重复 |
| kind | dig / fill |
| shape | circle / swept_segment |
| start_xz_m / end_xz_m | 有限Vector2，坐标受有效域约束 |
| radius_m | 有限正值，默认0.3；上限在T00按域/dispatch预算冻结 |
| nominal_amount_m3 | 有限正值；UI默认0.015，拖动按当前距离/0.75m比例折算 |
| strength / seed | 有限有效强度，复现固定seed101 |
| input_us / requested_tick | 单调时钟输入记录、请求的模拟tick；不是实际执行完成时间 |

| 准入结果字段 | 含义 |
|---|---|
| accepted: bool | 是否进入有序提交队列 |
| command_id / generation | 对应请求身份 |
| error | 空或invalid_request / stale_generation / duplicate_id / out_of_domain / insufficient_nominal_stock / queue_full / closing |
| nominal_stock_m3 | CPU玩法库存估算值，不是实际物理沙量 |

库存：准入的dig加nominal_amount，fill减nominal_amount；库存不足拒绝整笔，拒绝不改库存。该量来自设定值，不做真实体积读回。实际无沙可挖/限高/截边时可有偏差，界面显示“估算库存”；运输或设备失败须标记实验失败/复位，不伪装已执行成功。

单个scene内队列有上限；建议每render batch最多消费8笔、CPU pending最多64笔，数值在T00按负载冻结。不能无限追赶，不能静默丢失或重复已准入笔。合并如采用，须保留累计名义量、有效路径和原command序列映射；优先先实现不合并的有序队列，再依据实测决定。

## C04 顺序与生命周期

在同一RenderingDevice/有序提交路径消费，笔刷与正常模拟tick不并发写同一sand/water/momentum。候选GPU更新双缓冲或显式候选态，发布sand/water/flow来自同generation的完整状态；保留必要的GPU屏障，不使用CPU回执作为每笔发布前提。

CPU状态区分queued/dispatched/publication_requested；诊断的GPU完成由时间戳或窗口末尾受控同步确认。CPU call_deferred、调用返回和frame_post_draw不能命名为真实GPU完成或屏幕scanout。GPU内部control/receipt缓冲可作校验与顺序控制，不等于CPU读取回执。

暂停停止正常模拟时钟，但允许测试场景编辑并发布；不等待physics_frame。复位停止准入、排空已有提交后切epoch与固定初态，旧回调拒绝消费。关闭允许一次边界排空/必要同步释放资源；“无每笔CPU回执”不禁止安全关闭或诊断收尾同步。

## C05 近似沙水算法与预算

沙：按笔刷权重执行正/负高度增量或目标高度混合。nominal_amount_m3转幅值采用可预计算模板归一化/固定标定，不对GPU真实可移体积作逐笔全域归约；干边、截边与限高不再精确补偿。保留rock底限、有限值与有效域检查，不伪称精确体积。

水：初步独立配置`none`、`amount_template`、`amount_velocity_template`。amount模板按权重趋向目标量；速度模板由带符号增益、权重、强度与方向生成局部扰动。目标量、方向、限幅、湿干规则和挖/填对应选择在T03单变量核对后冻结；不直接照搬竞品场景单位0.045或速度5。

候选允许水量/动量偏差，记录代表性总量净变化和视觉副作用；不保留每笔全域容量分配、速度账本归约和CPU库存核验。正常模拟的CFL/子步稳定性仍须成立：在不新增全域每笔归约的情况下，对允许编辑幅度、扰动速度和所需稳定性预算制定保守上界/固定上限，不能任意取消旧检查后宣称稳定。

## C06 观测

统一Time.get_ticks_usec记录input、admission、dispatch、publication请求、post_draw与queue长度。GPU capture_timestamp按generation/command/batch/pass配对，CPU/GPU时钟分别展示；GPU累计总和不包含未观测render成本。可见反馈使用发布后的post_draw，实际像素变化和scanout若未测明确未知。

诊断快照仅在固定验证边界读取；正常输入路径不得进行每笔buffer_get_data、texture_get_data、全沙高度CPU校验或碰撞高度回传。正常模拟CFL/审计的现存读回依赖单独列出，不将“没有编辑回执”写成“全程序零读回”。
