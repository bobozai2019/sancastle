# 水退后湿沙不明显：诊断

## 结论

两个正式入口都在更新湿度，沙材质绑定的发布纹理与权威湿度字节一致。主要问题是上岸薄水的湿润目标偏低、露出后的湿度回落，以及材质颜色响应弱；没有发现湿度数据漏绑或停止发布。提高显示网格精度不能解决这些问题。本次只诊断，未修改正式运行源码、场景或参数。

## 已验证事实

1. `material_step.glsl` 在每个接受的水子步中更新湿度：水深超过 0.001 m 时，目标为 `clamp(depth/0.06,0,1)`，按 `1.5×dt×target` 增加；低于阈值时按 `0.07×dt` 减少到 0.05，另有四邻域扩散。因此 3 mm / 6 mm 水深只提供 0.05 / 0.10 的局部目标，不能按“碰到水就充分湿润”理解。扩散和此前淹水可让实际湿度高于该目标。该字段也参与沙体材料行为，不能当纯渲染滑块随意改动。
2. 两个正式场景 `use_wet_finish=true`，`wetness_state` 实际绑定发布纹理。在 0、3、6、10、16、24 秒附近的完成态及视觉测试恢复后，发布纹理和权威湿度原始字节全部一致。湿度场随水步改变，水下可以达到 1。
3. 从初始露出的厚沙中选取曾在 3/6/10 秒样本被水覆盖、在 16 秒和 24 秒样本均露出的固定格子：main 349 格的湿度中位数由 0.2361 降至 0.0500；test1_geometry 292 格由 0.4180 降至 0.0509。两个端点之间是否短暂再湿未连续采样，此统计不证明全程干燥。
4. 沙 shader 干湿颜色只按 `wetness×0.65` 混合；默认干色 `(0.76,0.59,0.35)`、湿色 `(0.52,0.41,0.28)`。残余湿度 0.05 只产生 3.25% 的颜色混合权重。湿度只作颜色与粗糙度/高光参数插值，没有独立的长期表面湿痕字段；额外诊断湿痕增益为 0。
5. 沙 shader 使用 `specular_disabled`。因此当前湿沙高光参数不能产生镜面反射变化。不能凭 roughness/specular 数值在变，就认为画面有湿亮效果。
6. 在完全相同的 24 秒完成态，仅将 shader 读取的湿度强制为 0 或 1：两场景均产生画面变化，但整体干湿色差较弱。main 前景沙面示例像素 `(700,620)` 从 RGB8 `(244,208,148)` 变为 `(220,188,139)`；真实湿度画面为 `(242,207,148)`。这是当前曝光、光照和机位下的画面结果，不是通用材质测量。恢复 shader 后，两场景截图均与各自基线字节完全一致。

## 建议修正方向

优先调整纯表现层：让低到中等湿度的沙面有更清晰的变暗响应，保持未湿区域原色，并在固定完成态核对水下沙底。若要让退水留下更持久的湿痕，可设计独立的表面湿润记忆，明确其完成态、暂停、恢复和水沙接触规则；不能把这一新字段当作当前已有能力。

湿润速率、饱和水深、干燥速率属于材料模拟参数，会影响现有沙体行为。调整它们需要单独确认物理目标和重验影响范围。是否启用湿沙镜面反射属于另一个视觉选择，不是修复湿度绑定的必要条件。

## 证据与复验

`probe.gd` 从两个正式入口启动：D3D12、GTX 1050、1280×720、generation=1001、默认 profile、固定默认相机。正常边界叠加通过现有入口触发的 0.1 m、3 秒手动波；按实际完成时钟采样。`--ignore-parameter-config` 排除用户保存的参数覆盖。当前检查时没有发现默认路径的 startup.json。

原始结果、数据、截图与日志在 `evidence/main_v2/` 和 `evidence/geometry/`；命令、来源哈希、检查结果、固定格子统计及产物索引见 `result.json`。`analyze.py` 可从原始 `.bin` 复算；`seal.py` 保存证据，`inspected_sources.zip` 保存相关源码。初次诊断脚本的类型推断错误日志保存在 `evidence/main/`，该次未启动场景，不计成功。

视觉强制湿度测试仅替换内存 shader；前后 rock、sand、water、wetness、compaction 原始字节及完成 tick/time 相同。没有做性能测量、长期稳定性、所有机位或用户正在运行实例的验证；本结论不涉及新增竞品逆向。
