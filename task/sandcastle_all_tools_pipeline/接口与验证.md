# 全工具流水线接口与验证

日期：2026-10-17。用户要求将全部旧工具迁入新流水线。本次扩展覆盖沙墙、城堡、守恒铲子、投流沙、投碎石和平滑/压实；原任务的计划、证据和判定保持原样。

## 接口和状态

- 复用原64笔命令队列、3个持久工作槽、2个高度槽，GPU工作在同一RD顺序执行；正常工具不设置legacy/transitioning、不修改playing、不同步CPU影子、不等待碰撞才录制下一笔。
- 床面/悬沙命令保持128B编码；逐笔选择对应sand/sediment纹理，所有普通水/材料候选逻辑保留。干地投流沙拒绝后继续处理下一命令，源汇仍按准入量估算。
- 工具信封为独立扩展：64B头在字节40写扩展版本1、字节44写stride256，command_count=1；payload为256B。普通头及80B完成布局不变。工具读回长度336B，末尾256B为GPU在共享scratch复用之前复制的回执；每槽固定分配，不为每笔建销临时资源。
- GPU选取时填写真实revision/tick，不用CPU预测前一笔成功。CPU验证租约/代次、工具身份、状态与revision关系及与同次80B完成通知的一致性；坏结果不伪造成功，不重放，不以回调补写已提交权威。
- 形状begin/段/end按队列顺序执行，独立32B GPU暂态保存笔画身份、基准token、sample高水位及active位。保存、切换和退出前结束笔画并排空，因此不将活动笔画的暂态装成可恢复存档。形状算法及铲子供体/接收分配直接复用，去掉旧CPU回执授权/回滚阶段。
- 平滑/压实在GPU中先准备和验证，再写权威；平滑采用原加权目标与均匀校正公式的float32补偿求和适配，检查有限、非负、材料reference及体积误差；压实写R16F。保留apply_legacy_command名称作为兼容API，不再调用CPU编辑器。
- 碎石投放在CPU有界预留容量，GPU顺序执行原分布/贴床算法并以受control错误保护的compute归一双槽；正常模拟持续读取固定完整槽。拒收不占容量，已知未提交的取消可退预留；结果未知时停机并保留消费者所有权。
- 形状/平滑/压实当前保守全域标脏，新高度双槽异步追赶；公开API的gpu_complete不代表碰撞已追平。活动配置新增all_tools_pipeline_version=1，源签名不匹配的旧存档继续拒绝，不放宽原匹配规则。

## 验证入口与判据

| 入口 | 核对内容 |
|---|---|
| async_pipeline_all_tools_probe.gd | 暂停七工具、墙重复不叠高、铲子守恒、形状超预算全场不变、平滑CPU独立对照及材料reference、压实存储误差、悬沙/床面混合及干地拒绝继续、实时开笔水tick推进、完整保存恢复及恢复后工具 |
| async_pipeline_tools_boundary_probe.gd | 三形状工作在CPU消费前提交/完整发布、三碎石投放无覆盖、负例准入、UI笔画在途保存/切工具、三个场景往返和旧工具资源释放、在途关闭 |
| async_pipeline_tools_fault_probe.gd | 工具上传失败、回读注册失败、无法证明最后消费者、损坏回执身份/tick；不假成功、不重放、证明前不free |
| 原main/UI/public/checkpoint/bootstrap/candidate探针 | 受影响的普通输入、完整状态/候选、旧资源初始化与异常清理回归；旧工具结果等待按自身GPU完成更新 |
