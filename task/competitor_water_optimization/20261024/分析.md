# 水波传播的竞品对照与优化候选

范围：2026-10-24，分析当前场景2 `res://scenes/playable/test1_geometry.tscn` 的共享 MUSCL 路径。保留 MUSCL、现有波浪效果及数值契约。本轮只增加取证／诊断脚本和资料，没有实施运行求解器优化。

## 结论

有可保留算法的优化空间，优先处理无效候选步的速度归约。竞品所选水更新段调度较短，但离散方法、状态、时间及耦合职责不同，不能直接照搬三轮更新或据 dispatch 数推断性能倍数。

| 优先级 | 候选 | 已确认依据 | 收益与风险 |
|---|---|---|---|
| 1 | 跳过无效槽的 CFL 速度归约 | 每 tick 固定 129 次速度归约；场景2样本平均 85.62 次发生在无效槽 | 最小改动；保留有效计算。收益未测，须验证工作组统一分支及错误／审计路径 |
| 2 | 复用面状态和邻格读取 | `rk_edge` 的两个正向面在边通量与床源项中重复计算 | 不改公式；编译器已有优化和寄存器压力可能使收益很小 |
| 3 | 降低 CPU 录制开销 | 每 tick MUSCL 901 次、耦合 640 次 dispatch API 调用，描述缓存命中仍需调用 | 原生录制器候选；工程量较大，不能以合并调用破坏 GPU 同步 |
| 后续 | 减少接受步的整场 normalize 复制 | 8 个场逐格读写，按现有格式约 5 MiB／接受步的名义流量 | 需调整槽位、发布及恢复消费者，风险较高，暂不优先 |

这里的“优先级”是调查后的实施顺序建议，尚无优化版本或优化后的 FPS 结果。

代码每槽执行 mode 2、mode 3 两次速度归约，并有一次初始 mode 7：`64×2+1=129`。每次扫描 32×32 个速度块。样本对应无效归约均值 `42.81081×2=85.62162`，占归约调用数 66.37%，约 87677 次无效速度块读取／tick。**这是该部分工作量，不是 66% 的总耗时，也不承诺 FPS 提升 66%。** 即使提前退出，dispatch 本身和其同步开销仍存在。

此前场景2低干扰基准约 21 FPS，暂停模拟后约 60 FPS，见[原报告](../../scene2_performance/20261024/分析.md)。本次采样前，场景显示 profile、岸壁 manifest 与沙材质已有外部修改，配置 hash 与旧测试不同；数值核心身份一致。本次计数不能直接和旧 FPS 做 A/B。

## 保留效果的实施边界

第一项只针对 `rk_decide.glsl` 的 mode 2/3：目前整组先扫描／归约，lane 0 才检查 `tr[6]==0 || control[1]!=0`。候选改法将这项一致条件移到归约前，整个工作组同时返回，避免部分线程绕过 barrier。mode 7 仍校验初态；mode 1 的初始化／审计、mode 4 的错误传播、64 次容量、拒绝重试和完成态保持现有语义。不能把 `tr[14]` 等其他错误条件不加区分地并入跳过条件。

第二项在全湿内部源码路径中，共有 8 次 `face` 求值，其中中心格 X／Z 正向面各重复一次；先复用这两个结果和中心原始量，再评估更大范围的共享内存缓存。数学表达式相同不自动代表浮点逐位相同；需要核对实际编译产物和输出，不能仅凭源码计数宣称减少相同比例的 GPU 时间。

第三项沿用此前 CPU 描述缓存优化的边界。901 来自 64×（6 个决策 dispatch＋8 个间接场 dispatch）＋5 个固定 dispatch；耦合 640 来自 64×10。这些是 CPU 录制调用数，无效槽的全域间接组数可为零。原生实现应保持计算／同步顺序，不直接删除看似重复的屏障。

不以减少 64 槽容量、放宽 CFL、改重力／速度上限、降精度、降低网格、替换 MUSCL 或照搬原作同 UAV 更新来声称“无效果变化”。现有“波形保持”是 MC／Superbee 限制器混合，会改变传播结果，属于效果参数而非免费性能优化。

## 后续最小验证

先只修改无效归约跳过一项。固定同一初态、profile、源码和输入序列，对照权威水沙、动量、源汇／沙账本、决策与逐步审计；覆盖正常湿床、干床、拒绝重试、64 槽耗尽、非有限输入、错误传播、暂停和恢复。保留之前逐位一致的验证标准；任何非预期差异先定位再继续。

通过数值对照后，再以同一真实窗口、输出尺寸、VSync、后端和完整场景2负载比较主线程录制、GPU 区间与帧时分位。GPU 时间戳探针可能改变负载，正常帧时与探针分解分别记录。只有这一对照才能回答实际改善多少。
