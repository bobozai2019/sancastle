实测使用 `Mesh.get_vertices()` 与全部 submesh 的 `GetIndices(Int32 submesh, Int32 meshLod, Boolean applyBaseVertex)`（lod0/false）。返回 int32 API复制与源 indexFormat 分开。被裁剪的配置 getter 可使用已经验证的 engine icall，不改 readable 或原数组。临时数组用指针宽度 GC handle 验证 get_target 同一性后持有、释放；旧32位释放失败另存。

多 chunk 可能共享输入 mesh；快照必须贴着目标完成发布返回，同线程窗口内记录实际 setter 观测序号及 getter 前后对象。进场后数组重建须重新定位。snapshot 使用 run/attempt 命名空间；attach 时间不当进程启动时间。

## C01 请求和快照身份

原始请求JSON设计（保留作契约字段说明）；实际CLI见文末，原草案接口不属于已实现入口：

```json
{
  "run_id": "20261012_000000_runtime_collider",
  "mode": "owned_runtime",
  "target_pid": 0,
  "owner_record": "owner.json",
  "expected_gameassembly_sha256": "REQUIRED",
  "expected_metadata_sha256": "REQUIRED",
  "capture_limit_chunks": 1,
  "capture_limit_vertices": 1000000,
  "capture_limit_indices": 6000000,
  "max_snapshot_bytes": 67108864,
  "trigger": "after_successful_shared_mesh_binding"

```

真实PID必须为本任务拥有的进程，非0；run_id独一、目录不可覆盖。数量/字节上限是探针保护上限，不是原作参数；超限报错，不静默截断。目标模块实际路径/hash校验失败则不得使用旧RVA。地址/对象ID/byte offset均用十六进制或十进制字符串，避免JS精度损失。

快照必需字段：`run_id, snapshot_id, pid, process_start_identity, exe_path/hash, module_path/hash/base, metadata_path/hash, chunk_identity, collider_identity, meshC_identity, bound_mesh_identity, binding_seq, update_seq, capture_begin/end_monotonic_ns, frame_count(if available), capture_thread, consistency_status, unit_status, tool/version/command`。同frame不替代consistent边界；序号为探针观测序号，不冒称原作tick。

## C02 几何与配置

| 字段 | 类型 | 完整快照要求 |
|---|---|---|
| vertex_count / vertex_streams | int / list | 原始数据、dtype、endianness、stride、位置属性offset和空间local |
| index_format / index_count | enum / int | 明确UInt16或UInt32，原始缓冲覆盖全部submesh需求 |
| submeshes | list | 每项topology、index_start/count、base_vertex；局部索引与有效索引区分 |
| local_to_world | 16 floats | 明确矩阵布局/乘法约定；含父变换，不能只有position |
| bounds_local/world | min/max | 来源与计算方式分别记录 |
| collider_enabled / active / layer | bool/bool/int | 实际值 |
| convex / is_trigger / cooking_options | bool/bool/int | 实际值或null+unavailable原因；缺项保持partial |
| collider_resolution / chunks | int2 | 可得时保存实际配置，未知留null |
| verticesOS / readbackIndices / ReadbackCells | payload引用 | 辅助raw单独保存，字段布局/数量/快照版本明确 |
| retrieval_method / completeness | string / enum | complete / partial / failed，输入mesh不冒称cooked PhysX shape |

所有顶点有限，submesh范围有效；索引加baseVertex后落在vertex_count内。位置、法线以实际变换复验；非均匀缩放的法线需逆转置处理。OBJ/图片都标derived，规则三角化猜测不能充当原始index buffer。

## C03 绑定和物理对应

绑定记录包含PlaneChunk→collider→当前sharedMesh→meshC的对象身份、设置前后序号和getter读取来源；设null阶段不得提交。记录能证明getter读取的是实际sharedMesh，而非仅抓setter参数。先确认对象enabled/active与碰撞配置，再以真实Physics.Raycast补证。

射线记录：`snapshot_id, origin_ws, direction_ws, max_distance, layer_mask, query_trigger_interaction, query_timestamp, hit_bool, hit_collider_identity, point_ws, normal_ws, distance, triangle_index(if available), geometry_comparison`。只接收真实物理hit；平面回退单独标记，不算碰撞命中。

G1冻结默认候选容差：位置/距离 `max(1e-5, 1e-5 × max(1, world_bounds_diagonal))` 场景单位；边缘/退化三角形另记录，不反复放宽容差追求PASS。法线角差候选1度；先核对物理配置和法线含义，不把Readback平滑法线当物理三角面法线。比较基于同稳定快照的原生物理ray hit，不调用PlayerControls的平面回退或法线替换结果作为标准。

运行时mesh修改/发布跨越采集窗口则`consistency_status=changed_during_capture`，丢弃完整提交并记失败，保留partial原字节；不把两次不同状态拼为一个快照。不同chunk碰撞需记录实际命中，不伪装成目标chunk。

## C04 原始数据与溯源

`raw_index.jsonl`每条含source身份、snapshot_id、对象身份、来源地址范围或完整runtime API selector、raw_path、字节数、sha256、format、工具版本/命令、读数线程、completeness、error。API取数注明是运行时API复制的数据，不能写成原容器字节。

动态指针只在PID/进程启动身份/快照范围内有效。保留网格API返回数据、CPU NativeArray快照、派生导出三个类别；没有取到PhysX native payload必须明确写unavailable，不允许因为有OBJ就声称内部物理形状完整。
