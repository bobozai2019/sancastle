## 受力模型

每物理步，在浮力点世界位置y_i上，将竖直区间[y_i-r_i,y_i+r_i]与实际水柱[bed_i,eta_i]求交：

```text
wet_length_i = max(0, min(y_i+r_i, eta_i) - max(y_i-r_i, bed_i))
f_i = clamp(wet_length_i / (2*r_i), 0, 1)
F_buoy_i = rho * |g| * volume_i * f_i * UP
v_point = body linear velocity + angular contribution at point
F_drag_i = mass_share_i * f_i * (water_velocity - v_point) / tau_axis
```

这是有效体积的线性浸水近似；没有声称原作用球冠。水速度来自浅水模型的水平u，初版竖直水速度取0，竖直阻力仅抑制相对升沉。按点分配mass_share，合计为body.mass；旋转阻力按总浸水比例作用。所有力单位N，施力后由引擎积分，不额外再乘dt；默认重力保留，仅算一次。

在_integrate_forces安全阶段读取刚体状态并apply_force；position参数为世界坐标方向的“施力点减body origin”偏移，局部点须先转换。点速度使用同样偏移求取，不把世界绝对位置传入。参见[Godot物理状态接口](https://docs.godotengine.org/en/stable/classes/class_physicsdirectbodystate3d.html)。正常移动交由[RigidBody3D](https://docs.godotengine.org/en/stable/classes/class_rigidbody3d.html)积分和碰撞；水位变化不直接写body.global_position.y。

## 接触/搁浅/唤醒

FLOATING、GROUNDED、DRY、WAITING只是观测/控制状态，不替代连续受力。退水后浮力自然衰减，Jolt接触与摩擦承托；干燥不代表强制永久freeze。睡眠道具仍进入低成本采样/版本跟踪，当再浸水、流速变化或支撑床变化时唤醒；不依赖睡眠刚体自身回调发现水来。

同一RigidBody3D下用Box/Capsule/少量凸形shape；trigger/Area不能作为实体接触证据。道具之间碰撞启用；与表现碎石无实体碰撞。CCD对细长/快速对象做开关负例，不能认为开启就保证动态地形插入不穿透。现有HeightMapShape3D作为沙地；按实际床重建和碰撞形状检查足迹，不只用中心/浮力点代替整个接触外形。

## 编辑后的接触修正

1. 当前编辑产生受影响床面chunk后，标记其上/附近道具进入等待；覆盖跨块足迹，保留速度和姿态身份。
2. 编辑事务及required chunk碰撞发布完成，并达到实际物理同步边界后，检查整个简化碰撞体的嵌入与支撑。
3. 床上升造成瞬时深交叠时，允许一次有记录的向上解重叠修正，位移受实际床增量和shape尺寸约束；逐体/成组检查相互接触，不把物体抬进另一物体。以实际碰撞查询验证可行姿态后恢复积分；去除指向床内的速度分量，保留合理切向速度。
4. 床下降只唤醒、允许重力落下；不得每帧贴床。水再次支撑时按受力起浮。
5. 若无法消除重叠或接口失败，记录失败并停止放行该验收；不能仅隐藏网格、取消碰撞或每帧强行钳高度宣布通过。

候选验收容差：稳定后的最大床内穿入≤max(0.005m,最小shape半径×0.05)，且可见沙面不明显吞没道具；编辑修正后2个有效物理步内满足。T00先量测可见/碰撞床差异；若超差，定位几何重建/采样坐标再决定修复，不能单纯放大容差掩盖。任意增益/限速/抬升规则修改需留下单因素证据。
