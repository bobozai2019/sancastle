# 道具采样与时间同步

状态：draft。冻结前置：T00真实Jolt小样本。以下是计划接口。

## 批量接口

PropSystem在CPU收集点，GpuPropSampler在render线程从主RenderingDevice已完成的水沙状态采样；回调只交还不可变结果。主线程管理registry、节点及采样交接；受力仅在_integrate_forces使用本次PhysicsDirectBodyState3D，空间查询在合法_physics_process阶段进行。两类回调的实际线程/相位由T00记录，不据独立线程设置猜测；数据worker不访问SceneTree、RD或Jolt state，回调结束后不保留direct state供异步使用。

| request字段 | 类型 | 规则 |
|---|---|---|
| schema_version/request_id | int/int | version=1；request_id单调，属于sampler实例 |
| domain_id/generation | String/int | 同一活动世界；切换/恢复生成新token |
| completed_tick/revision | int/int | 指定本批GPU水沙完成态，不能读未结算编辑态 |
| pose_seq/physics_time_s | int/float | 所有道具已经完成的姿态版本及模拟时间 |
| points | Array | {body_id:int, point_id:int, kind:int, position_world:Vector3} |
| required_chunks | Dictionary | 接触足迹覆盖的chunk→最低所需床面revision，不只中心点 |

| result字段 | 类型 | 规则 |
|---|---|---|
| identity | Dictionary | request身份原样，另记实际captured_tick/revision |
| rows | Array | 每点返回ID、采样位置、bed、eta、h、u_xz、床法线、valid/in_domain |
| completed_us/error | int/StringName | 回调墙钟用于诊断；不得替代模拟时间 |

输入缓冲候选stride32：uvec4(body_id,point_id,kind,pad)+vec4(world_position,0)。输出stride64：uvec4(ID,point,flags,pad)+vec4(sample_xyz,bed)+vec4(eta,h,ux,uz)+vec4(bed_normal,0)。CPU侧不可变请求映射保存64位generation/tick/revision，不把它们截断塞进浮点ID。T00核对std430布局、变换及字节序，T01用哨兵值验证。

初版最多24个body；每体最多4个浮力点和6个支撑观测点，总点数≤256，单次输出≤16KiB。默认9件约27个浮力点，支撑观测按需要加入。最多1批在途，待发请求只保留最新可用的姿态版本；不能丢正在被物理阶段等待的批次。无道具时零dispatch/读回；常规运行不读全张水/动量纹理。

## 采样/有效性

- h=water，q=(momentum_x,momentum_z)，u=q/max(h,epsilon)，干区u=0；bed=当前可见rock+sand重建，eta=bed+h，米/秒单位。显示额外波纹不加进物理水深。
- 捕获实际绑定时重新核对版本，编辑receipt/publication_pending时不提交。请求版本与捕获版本不一致则明确重试，不将更新结果伪标旧revision。
- 水样与碰撞床允许不同存储/重建方法，必须测量差异。涉及道具的chunk需满足required_revision且已被物理世界消费；未变化chunk复用shape但推进revision的现有语义保留。不能仅因全局revision增加而重建全部沙地。
- worker的prepared不等于shape提交，更不等于物理可查询。applied_revision只由现有主线程提交/未变确认推进；保留编辑原有两次physics_frame完成契约。复用已有完成通知，禁止道具成为第二个worker回收者或通过提前确认碰撞放行。编辑等待的两帧与道具有效积分预算分别记录，不能互相充数。
- 水样与当前点的水平偏移候选上限0.5 cell（当前0.0625m）；超过时先重采样，不把旧位置水深用到新位置。两个物理子步中的位置/角度变化都需检查；可批采邻近点，不能无界外推。
- 离域点valid=false、该点水作用为0；道具越出有限沙滩域的策略为安全冻结并显示诊断，默认布局/验证不把离域当回海。不得在边界自动删除或瞬移重生。
- 错误码：invalid_probe_request、stale_generation、capture_revision_mismatch、stale_pose、probe_out_of_domain、probe_readback_failed、collision_not_ready、physics_clock_mismatch；旧回调只结算所属请求，不碰当前pending。

## 时钟与同步前置

S1仅为隔离候选：water完成→采样/必要碰撞更新→Jolt道具物理预算→允许下一water tick。当前water dt=1/30s；若实际physics step=1/60s，预算为2步。每步只积分一次，所有道具共享预算，不能每body回调各扣一次全局预算。无道具时保持原调度；隔离比较用空预算对照保证相同时间输入，同时保留原无道具调度作成本基线，不能把新增等待同时加进两侧而隐藏退化。

物理线程任务当前未选用worker/独立Jolt线程，不以其成功为前置。S1须测GPU读回、碰撞发布、回收唤醒顺序及物理预算带来的关键路径等待；T00冻结新增开销判据，正式接线前用完整负载复验。时钟功能通过不代表S1可上线；成本或接触失败则修订有界流水线/时间方案及本契约后重验。禁止通过减少既有两物理帧等待、改变准入或默认启用被拒绝的线程候选来补偿。

等待采样/碰撞、暂停、保存、切换期间阻止道具物理时间前进，并保存原速度/睡眠状态。默认候选使用局部freeze门闩，不暂停UI/相机/全树，不改变全局物理频率。只停止apply_force不能实现暂停；把力乘比例也不能缩放Jolt接触积分。门闩是否重置接触缓存、何时冻结/解冻安全、一次/两次physics_frame后何时可提交，均必须在T00用实际引擎和时间戳验证，失败则修订方案后再冻结契约。

保存/恢复边界要求water_tick=k且prop物理预算清零，physics_time_s≈k×SIM_DELTA，误差不超过冻结的浮点容限；请求pending为0。没有足够完成态时延后整个相关阶段，不能静默多走或少走刚体时间。
