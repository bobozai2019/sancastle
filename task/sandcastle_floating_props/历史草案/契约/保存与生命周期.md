# 道具保存、恢复与释放

状态：draft，T00/G0冻结。必须与当前edit v4/native v2、gravel_v1共存。

## 对外操作

| 操作 | 输入 | 返回/错误与约束 |
|---|---|---|
| prepare_epoch | 水沙generation/tick/revision、道具pose_seq | 创建批量probe与碰撞所需版本，返回accepted/明确error |
| physics_step | 已验证sample_bundle、step_budget、实际state.step | 单步结果/新pose_seq；只在批准物理阶段消耗一次预算 |
| quiesce | save/restore/switch/shutdown原因 | 等预算/请求清零并冻结；不丢最后一个在途物理步 |
| capture | 共同完成边界、registry | physics_extensions字典；所有body稳定ID唯一 |
| validate/build_candidate | checkpoint与当前profile/资产白名单 | StringName空=成功；候选body冻结且不进入活动碰撞空间 |
| commit/discard | candidate identity | 主线程安全物理边界提交/销毁；GPU采样资源在render线程处理 |
| release | owner identity | 解绑回调，drain pending，释放buffer/uniform/shader与body节点 |

错误至少区分props_state_invalid、props_profile_mismatch、unsupported_props_version、props_clock_mismatch、props_candidate_failed、props_capture_failed、props_generation_mismatch。保存恢复失败不能悄悄重置道具位置。

## 检查点字段

新增checkpoint.physics_extensions.floating_props_v1（独立于visual_extensions）。

| 字段 | 类型 | 校验 |
|---|---|---|
| version/enabled/domain_id | int/bool/String | version1，域匹配；关闭时最小明确schema |
| profile_hash/asset_manifest | String/Dictionary | 白名单资源身份，不允许任意对象反序列化/路径注入 |
| tick/revision/source_generation | int | 对应共同完成态；新世界generation重映射 |
| physics_time_s/pose_seq/remaining_steps | float/int/int | time与水沙模拟时间一致；保存时remaining_steps=0 |
| bodies | Array[Dictionary] | ID唯一，数目≤24，预置registry类型/资源匹配 |
| bodies[].id/archetype_id | int/String | 跨保存/切换稳定 |
| bodies[].transform | Transform3D或明确定义数值数组 | 位置/旋转有限，旋转归一，刚体scale=1 |
| bodies[].linear_velocity/angular_velocity | Vector3 | 有限，profile限幅范围内 |
| bodies[].sleeping/mode/wet_state | bool/enum/受控值 | 保存实际状态；暂停的临时freeze不能冒充永久搁浅 |

仅保存显式物理状态与profile，不保存过期GPU采样结果；恢复后先重新采样/确认碰撞，再恢复动力。可按契约保证姿态/速度瞬时恢复，但Jolt内部接触缓存、求解器warm-start等未保存，普通续跑使用误差判据，不宣称刚体逐字节确定性。水沙自身既有严格继续限制单列，不随物理容差放宽。

## 与现有链的必要修改

- 当前gravel_playable_entry保存回调会直接赋值整个visual_extensions。新物理扩展使用独立命名空间，并把扩展组装改为保留已有键的合并方式；不得丢gravel_v1或未来扩展。保持现有严格codec校验。
- 当前配置签名索引运行源码。缺道具扩展的旧检查点不一定能绕过源码签名变化：只对记录的“碎石完成版本”签名建立明确迁移映射；完全匹配且缺扩展时按预置布局初始化道具并标legacy_initialized。其他签名差异仍拒绝，不全局替换configuration。
- 保存：关闭新操作准入，完成在途编辑/water/prop物理预算及probe，固定body状态，然后捕获GPU水沙/碎石；相同边界才交Store。源汇/命令前缀语义保持。
- 恢复：先完整schema/身份检查；GPU候选仍走既有bundle；CPU候选道具在主线程创建且冻结/不进活动碰撞。预提交失败销毁候选，活动世界保持；所有可预验步骤在commit前完成。
- 提交：在安全边界切换world/bundle、道具registry和显示/碰撞资源，重设generation，先确认新床碰撞与水样，再放行物理。若现有commit后碰撞/显示步骤可能失败，必须有原状态快照回滚或明确的可恢复错误状态；不得提前销毁唯一可回退的旧道具状态。
- 场景切换：每个布局保存独立body状态；目标失败回退也恢复原道具。shutdown等待probe/physics阶段退出，回调按所属request结算，即使旧generation也不能漏计。

## 与物理线程任务共存

保留现有collision_proxy.has_prepare_in_flight()保存/恢复等待，以及shutdown的stop_prepare_and_drain()。道具quiesce补充自己的probe/刚体阶段，不替换既有编辑、worker、碎石和RD drain；先关闭新准入，确保完成/回收仍能推进，最后才释放所依赖资源。失效generation只取消发布，不取消已运行CPU任务的回收责任。

主目录与物理worktree的恢复代码已分叉；不得整文件覆盖。保留edit v4/native v2、gravel扩展、engine_executable_sha256及严格签名。若移植线程侧separate_physics_thread/physics_input_query_bridge字段，应明确默认值和已知版本迁移，再与道具扩展共同验证；不能拿另一个源码基线的origin冒充新配置起点。实际prepare_policy、独立线程、桥接、physics频率及道具时钟策略均进入运行manifest，T00明确各项是否参与恢复签名。

候选普通恢复标准在G0冻结：瞬时pose/速度与序列化数据一致到引擎浮点精度；固定平水用例续跑5模拟秒，位置差≤1cm、姿态差≤1°为起始目标。含碰撞长时轨迹需另报误差，不直接套无接触容差；禁止用“看起来一样”替代数值/接触证据。
