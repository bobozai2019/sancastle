# 漂浮道具决策记录

日期：2026-10-15。方案决策；契约尚未冻结。

- ADR01：CPU刚体承担运动/接触，GPU只批量采样水沙。竞品组件配置与既有动态沙地链支持这种架构；具体力公式属于Godot适配。
- ADR02：以当前水沙完成时间驱动物理步预算。S1局部门闩与water串行等待仅作隔离候选；不默认水沙真实30Hz，也不只靠停浮力来暂停。门闩接触稳定和新增等待/成本都需验证，G0冻结判据、T05确认完整负载后才可正式接线；失败先修订调度方案。
- ADR03：木棍3点、瓶子2点、船4点为初始方案。船左右分布帮助采到横向水高差；原作船2点证据保留，不宣称四点复刻。体积/质量采用米制profile重新校准。
- ADR04：正常搁浅由重力/接触/摩擦/睡眠完成；管理器持续采样睡眠物体以支持再起浮。编辑瞬时改变床面另设一次性解重叠，避免持续高度钳制掩盖碰撞错误。
- ADR05：道具使用独立physics_extensions.floating_props_v1；保留gravel_v1和edit v4/native v2。新代码读旧存档要按已记录签名迁移，不把任意签名不符存档放行。
- ADR06：普通恢复保存显式姿态/速度/睡眠和共同时间边界；Jolt内部接触缓存未保存，不承诺逐字节刚体轨迹继续。物理误差判据与水沙权威字段判据分开，旧严格继续FAIL保留。
- ADR07：先3件闭环，再9件默认/24件短测，正式三入口共享资源。暂不做拾取、深埋、排水/阻水与尾流。

- ADR08：以实际物理worktree而非主目录过期状态判断依赖。当前B/C未采用，道具基于baseline/off推进，不等待外部优化成功；将来获选补丁按最小职责接入，保留当前碎石/形状刷子/v4恢复链。见[衔接审查](物理线程衔接审查.md)。
- ADR09：collision准备、shape发布、物理消费分别记账，复用唯一回收/发布和既有两physics_frame语义。道具增量drain覆盖probe与物理阶段，不能删worker等待；两任务运行窗口串行，720p短测与1080p正式成本分别判定。
