# 第一阶段实现约定

角色：contract。状态：draft；T01通过后冻结。适用范围为main中固定3件道具。现有[水沙、碰撞与恢复契约](../../docs/knowledge/README.md)继续生效。

## 分层与场景层接口

第一阶段采用FloatingPropsPhysics专用服务。场景/道具层决定类型、预存布局和生命周期意图；服务负责受力、碰撞、时间协调及释放；BeachPhysicsAdapter集中连接现有水沙宿主和碰撞代理。场景层不持有solver、RD、worker任务或碰撞applied_revisions，也不直接施力或查询物理空间。

| 调用 | 输入 | 完成语义 |
|---|---|---|
| attach(registry, layout) | 固定3件预存节点的唯一ID/profile绑定，布局资源 | 当前世界水样/碰撞就绪、初始化完成后可运行 |
| set_paused(paused) | bool，来自现有暂停/保存流程 | true在共同边界保持姿态；false在条件就绪后恢复有效物理步 |
| reset(layout) | 固定布局资源，成功恢复/重新进入时调用 | 服务取得新世界身份，重置3件道具后完成 |
| shutdown() | 无 | 停止准入，结算回调及物理阶段，释放自身资源后完成 |

四个接口在主线程调用，异步完成后返回StringName错误码，空值表示成功。上层用await取得完成结果，等待期间让出执行权，主循环继续处理。内部请求ID、回调去重及generation由服务持有；上层无需管理GPU ticket。错误至少区分invalid_registry、busy、closing、backend_failed。

当前最多一个生命周期操作在途，重复暂停按相同目标合并，其余冲突请求明确返回busy；关闭先禁止新准入，按原回收责任完成/取消在途操作后退出，每次调用恰有一次返回。上层在shutdown完成后释放服务实例。上层负责传达意图和接收结果，底层负责版本、等待、物理相位与所有权。

适配器内部提供已完成水场采样、足迹碰撞就绪、模拟时钟接点和宿主生命周期对接。它将碰撞“数据准备/shape提交/物理可用”统一封装为可消费的结果，保留既有完成语义和唯一回收者。水沙下一tick准入所需的协调属于此接点，不散落到木棍、瓶子或船的场景逻辑中。

默认适配使用当前baseline/Jolt，无外部物理优化Gate依赖。后端只要维持这些语义，内部worker或调度变更不要求重写上层；改变语义时重新冻结协议并验证。第一阶段只实现当前后端，接口用例可注入延迟/失败结果，但真实GPU与Jolt仍是功能验收依据。

## 采样与时间

以下字段为物理服务与适配器内部协议，不暴露给场景/道具层。

| 接口 | 必需数据 | 约束 |
|---|---|---|
| 请求 | request_id、owner_token、generation、completed_tick、revision、pose_seq、points、required_chunks | points含body_id/point_id/世界位置；required_chunks为足迹chunk→最低床面revision |
| 返回 | 请求身份、实际captured_tick/revision、每点sample_position/bed/eta/h/u_xz/bed_normal/valid、error | 完整长度、有限值、身份及位置有效性全部通过后消费 |
| 物理预算 | epoch_tick、physics_time_s、remaining_steps、实际state.step | 所有道具共享同一预算；一次有效物理步只扣一次 |

固定3件，木棍/瓶子/船分别3/2/4个浮力点，连支撑观测总点数最多32。最多1批在途；后继请求只保留最新一份。输入候选stride32、输出stride64，T01用哨兵ID核对布局。旧回调只结算所属请求，不能覆盖新owner/generation结果。

从同一已发布完成态读取bed=rock+sand、h=water、eta=bed+h、u=q/max(h,epsilon)，干区u=0，单位为米、秒。实际捕获版本与请求不符则重试；水平姿态偏移超过0.5 cell则重采样。离域/读回失败时冻结相关物体并记录错误。错误至少区分invalid_sample、stale_generation、stale_pose、revision_mismatch、out_of_domain、readback_failed。

GPU采样在render线程进行，回调交还不可变数据；主线程管理节点与交接。刚体受力在_integrate_forces使用本次state，空间查询在合法_physics_process阶段执行。节点、Jolt state和RD资源保持各自线程所有权。

候选时序为water完成→水样及必要碰撞就绪→道具物理预算。water步长1/30秒；若实测physics步长1/60秒则每轮2步。以初始化/恢复后的epoch_tick作为道具时间起点，共同边界满足physics_time_s≈(completed_tick-epoch_tick)×SIM_DELTA。等待期间局部冻结并保留速度/睡眠，下一water tick的准入由协调器处理；T01实测冻结/解冻和回调相位，T04复核完整负载成本后才正式启用。

暂停同时停止道具有效物理时间。T01覆盖慢GPU、等待碰撞、接触上暂停/继续，记录额外等待；时钟或接触失败先调整协调方案再冻结约定。数据准备完成、shape发布和物理可用分别确认，保留原编辑两次physics_frame等待；它们与道具有效积分步数分别记账。

## 受力与接触

预制体根scale=1，Collider、网格和浮力点预存。profile包含质量、重心、点位置/半高/有效体积、水密度、水平/竖直阻力时间、摩擦、阻尼及限速。每点体积和质量份额之和对应整个物体。

浮力点的竖直区间与[bed,eta]水柱求交，得到浸水比例f；浮力为rho×g×点体积×f，流阻为质量份额×f×(水速−点速度)/阻力时间。点速度含旋转贡献，竖直水速初版取0。重力保留引擎默认一次，力单位N，由引擎积分。施力偏移使用世界方向的“施力点−body原点”。

正常运动、岸上支撑及道具互碰由Jolt接触处理。睡眠物体继续接受水/床变化观测，再浸水或失去支撑时唤醒。接触足迹覆盖全部相关chunk，并等待实际发布/物理完成边界。堆沙瞬时嵌入时允许一次有记录的有界解重叠，验证没有抬入其他物体；挖沙后唤醒下落。正常运动由力与碰撞推进。

T01测量可见沙面与碰撞面的差异并冻结容差；候选稳定穿入容差为max(0.005m,最小shape半径×0.05)。数值与连续画面共同验证。

## 运行、重置与释放

- 初次进入main：3件预存道具保持冻结，水沙与碰撞就绪后，在固定平面布局上根据当前床/水面初始化高度，再开始运动。
- 暂停与保存期间：等相关在途工作到共同边界并保持道具姿态；保存完成后继续当前运动。检查点沿用现有水沙/碎石数据及校验。
- 成功恢复场景：丢弃旧道具样本，递增owner_token；按恢复后的床/水面重置3件道具位置、速度和睡眠状态，建立新epoch_tick。恢复失败则保留原道具状态并恢复运行。
- 离开main或退出：停止道具准入，结算/回收在途采样与物理阶段，再释放资源。保留现有has_prepare_in_flight及stop_prepare_and_drain生命周期顺序。再次进入main重新初始化这3件道具。

实现采用组件和最小owner接点；保持当前gravel/shape继承链、edit v4/native v2及严格来源校验。修改共享文件前核对其他任务改动，GPU运行窗口串行。
