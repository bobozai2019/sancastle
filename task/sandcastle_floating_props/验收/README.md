# 第一阶段验收

角色：verification_plan。2026-10-15。范围：main中3件道具。所有实现Gate[未开始]。

| 用例 | 通过条件 | Gate |
|---|---|---|
| V01 水场采样 | 常量/线性床高、水深和流速与手算一致；干区速度为0；布局/坐标/长度正确 | G1 |
| V02 异步与时钟 | 旧身份/姿态、版本不符、失败/离域均处理；延迟GPU/碰撞及暂停后无时间偷步，接触不爆冲 | G1 |
| V03 漂浮随流 | 三类各1件静水稳定；波面差能引起倾斜；正反向流响应正确，无水时浮力为0 | G2 |
| V04 搁浅再起浮 | 同一物体连续经历水中→岸上支撑→再覆盖起浮，睡眠后能被唤醒 | G3 |
| V05 实体接触 | 沙地/跨chunk/道具互碰没有持续明显穿插；下方堆挖后支撑正确 | G3 |
| V06 main与生命周期 | 直接启动3件可见；暂停保持；保存后当前运动继续，成功恢复/重进重置，失败恢复保留；退出无旧回调污染或资源遗留 | G4 |
| V07 既有功能 | 当前编辑、碎石、水沙与账本无新增反作用；相关碰撞/恢复负例通过 | G4 |
| V08 短成本 | 同源同态0/3件真实可见1280×720对照，记录帧时间、完成tick吞吐和新增等待；队列/资源有界，明显退化先定位再交付 | G4 |
| V09 接口边界 | 场景层只用attach/set_paused/reset/shutdown；延迟、失败、reset/关闭交错时调用均恰好结束一次，无悬挂；后端身份变化不泄漏旧结果 | G1/G4 |

先编译检查，再运行真实RD/Jolt小样本；通过后接当前main。连续观察覆盖至少一轮搁浅与再起浮，以及堆挖、暂停和恢复。成本候选预热10墙钟秒、测30墙钟秒，功能稳定后集中执行，避开另一任务GPU测量窗口。

接口边界检查可用可控延迟/失败适配进行；浮力、接触、同步及成本仍用当前真实后端验证。物理优化任务的完成与否不作为本阶段放行条件。

保留原无道具调度作为成本基线，另用相同模拟边界对照权威水沙数据，避免用人为等待掩盖成本或拿不同tick比较数据。GPU耗时无timestamp则记unknown；旧底层失败按匹配对照保留，不以道具通过改判。

## 入口与证据

拟建tests/floating_props/下的sample_clock_probe.gd、buoyancy_probe.gd、contact_probe.gd和main_probe.gd。执行前核对真实引擎路径、SHA和有效物理设置；先check-only，再可见窗口运行，记录实际命令。

每个新运行写test_output/floating_props/<fresh_run_id>/，保留源码/profile/引擎身份、seed/tick/相机、样本原始字节、道具ID/姿态/速度/接触、generation/revision/pose_seq/模拟时间，以及退出和成本结果。G1–G4报告分别保存到本目录。

来源核对JSON、旧计划文档检查和原物理线程衔接审查是范围调整前的历史证据。第一阶段文档检查另存phase1_plan_check_20261015.json；它只证明计划结构/链接有效，不能算功能验收。
