# 水传播执行优化

三项已依次实现：无效候选步跳过速度归约、线程内复用面状态、CPU 固定耦合命令并入缓存。保留 MUSCL、SSP-RK2、64 次试算容量、供水／湿干／速度限制、源汇与沙量账本及同步顺序。未降低分辨率或精度，未修改波浪参数，也没有引入原生扩展或更换 Godot。

## 实现

1. `rk_decide.glsl` 的 mode 2/3 在 trial 无效或 control 失败时整组提前返回，避免读 1024 个速度块及共享内存归约。条件在 barrier 前对整组一致；mode 7 的初态校验、其他模式的审计和 fatal 传播保留。该改变省去无用扫描，仍需录制和派发这个小核。
2. `muscl_spatial.glslinc` 增加 `face_slope` 和 `cell_faces`。每个 `rk_edge` 线程复用中心原始量、可重构判断和 X／Z 坡度，四面值用于边通量及床源项。全湿内部源码路径从 8 次 face 求值改为一次中心四面重构和两次邻格 face；未改变算术公式或跨工作组读写关系。
3. `coupled.gd` 提供固定阶段描述，标准未包装 `record` 回调由 `water_muscl.gd` 在建表时展开；直接／间接派发标记也预先缓存。每个 tick 的 GPU 阶段及 compute-list 边界不变。新增缓存键覆盖耦合 Callable 和 prescribed_tide_boundary，原 dt、格距、边界开关及保波键保留。自定义／包装回调、无耦合、回调恢复仍按原语义工作。

此处第三项降低的是现有 GDScript 录制开销，没有减少 RenderingDevice 的实际 dispatch API 数量。原生录制器仍可作为以后更大范围的选项，本轮已有收益无需增加编译或运行依赖。

## 场景2结果

正式入口 `res://scenes/playable/test1_geometry.tscn`，完整负载、无操作、参数窗隐藏。Intel i5-9300H、GTX 1050、Godot 4.7.2 stable steam ed1daf0bf、D3D12 Forward+、实际窗口 1280×720、VSync 开启。每次初始化后预热 5 秒、阶段稳定 2 秒，正常段采样 20 秒，暂停绘制段采样 10 秒。正常帧率采样关闭详细 CPU 诊断和模拟 GPU 时间戳，保留轻量帧记录及视口计时；进程串行运行。未锁定时钟／功耗或排除所有桌面负载。

| 正式入口逐项版本 | 平均 FPS | 帧间隔均值 | P95 | P99 |
|---|---:|---:|---:|---:|
| 优化前 | 21.59 | 46.308 ms | 84.354 ms | 89.706 ms |
| 仅无效归约跳过 | 21.70 | 46.089 ms | 84.223 ms | 89.389 ms |
| 再加面状态复用 | 32.48 | 30.787 ms | 60.544 ms | 71.810 ms |
| 再加 CPU 录制优化 | 32.78 | 30.508 ms | 61.478 ms | 68.901 ms |

这组直接启动数据中 FPS 约提高 52%，平均帧间隔约下降 34%。主要收益来自第二项；第一项单独的差异很小，不能宣称已测得显著帧率提升。第三项普通帧率差异同样较小，其收益由独立 CPU 对照衡量。主视口 GPU 均值各次约 11.85–11.86 ms；暂停后约 60 FPS，暂停采样段没有推进模拟。正常采样各帧都具有焦点；最终版本暂停段部分时间失焦，不能将该段当作严格焦点控制实验。

各正式采样内来源无漂移；版本之间的完整 configuration.sources 逐项比较，第一项仅 rk_decide 变化，第二项仅 rk_edge／muscl_spatial 变化，第三项仅 water_muscl／coupled 变化。无显示／场景资源差异混入这四行比较。实际配置及指纹在各 capture.json 中。

额外的反向装载对照先排空工作，再装载保存的原版／最终版 shader 和 CPU 录制器，之后重新预热，保持当前场景和其他消费者。该口径原版为 16.09 FPS、最终版为 32.80 FPS，支持提升方向；原版低于直接启动基线的原因未单独定位。它保留额外 pipeline，初始化与装载过程也不同，**不与直接启动数据合并，也不据此宣称帧率翻倍**。实际覆盖的源码 hash 单独列在 metadata.runtime_override，不能仅看 configuration 的源码指纹判断覆盖后的求解器。

原始采样、汇总、来源差异见 [evidence/summary.json](evidence/summary.json) 以及其中各采样目录。场景2仍存在 60–70 ms 级长帧，尚未稳定 60 FPS；这些结果只覆盖本机、固定机位和这段完整负载，不是所有工具／机位／长时间运行的帧率保证。

## 第三项 CPU 对照

单独在同一个可见场景、同一组 GPU 资源内，按旧→新→新→旧顺序切换录制器。每段稳定 2 秒、记录 12 秒；状态持续演进。开启有界 CPU 时间线及 GPU 时间戳，不把该运行的帧率当作上表的正常运行结果。

| CPU 批次提交 | 旧录制器 | 新录制器 |
|---|---:|---:|
| 样本数 | 722 | 717 |
| 平均 | 5.273 ms | 4.347 ms |
| P95 | 10.061 ms | 7.244 ms |
| P99 | 15.534 ms | 11.213 ms |

平均减少约 17.6%。这是 submit_begin→submit_end 的整个 CPU 提交区间，不是 MUSCL self 时间。两段新录制器均值均低于两段旧录制器均值。计时运行里新录制器合并后的平均帧间隔反而略高（34.37 对 33.76 ms），GPU 标记区间也更高；状态演进、调度及计时扰动未被全部分离，不能将 CPU 改善外推成同等 FPS 或 GPU 提升。时间线未丢事件，运行无来源漂移或模拟错误。原始结果见 [CPU 对照汇总](evidence/step3_cpu_abba/summary.json)。

## 数值、行为与恢复

三个阶段分别以前一阶段为参考，各完成 36 个逐 tick 状态对照；最终再与初始基线比较，并增加缓存失效／包装回调场景。对照权威纹理及双槽、decision、control、trial、safety、audit 和间接参数，全部逐字节一致。测试覆盖普通湿床、侵蚀／材料、保波、开放边界、高初速、干床、障碍和容量耗尽；不是所有输入的穷举证明。

最终用例还在同一资源实例内切换包装回调、关闭／恢复耦合、关闭／恢复边界和改变保波值。包装回调在原版和新版均收到完整 64 次调用；容量用例实际接受 64 步，status=1，推进约 0.0080771 秒，未伪造完整 1/30 秒。

每个 GPU 改动阶段各自复验非有限水量和实质负水量拒绝，保持无接受步、无公开时间推进及原公开视图。最终强铲水冲量用例及一阶路径侵蚀用例通过。跨两个独立引擎进程保存／恢复，并继续模拟后进行 47 项比较，通过；generation 等字段按原恢复契约变化。保存源和恢复源固定，未据此宣称不同源码版本的旧检查点自动兼容。

核心证据：[最终精确对照](evidence/final_exact/exact.json)、[异常输入](evidence/step2_nonfinite/result.json)、[挖铲](evidence/final_strong_shovel/result.json)、[一阶侵蚀](evidence/final_erosion/result.json)、[恢复比较](evidence/final_restart/comparison.json)。

实际 RD 编译的基线／候选 SPIR-V 和展开 GLSL 已保存于 [shader_compile](evidence/shader_compile/result.json)，编译无错误。字节码体积有所增加，不能用文件大小推断指令成本；它也不等于最终 D3D12 驱动原生 ISA。性能判断以上面的可见场景对照为依据。

首轮容量测试错误地请求 10 秒，被现有入口的最大时间步校验拒绝；该轮整体标记失败并保留于 `evidence/step1_exact`，不计作通过。修正为合法 1/30 秒请求及 1000 深度的测试初态后，实际覆盖 64 次容量耗尽；后续所有逐项及最终对照均使用修正后的用例。

## 交付与复验

`baseline/`、`step1/`、`step2/`、`final/` 各保存 13 个相关源码及 identity.json。最终运行只修改 5 个既有源码文件，其他工作区改动保留。数值冷启动所需的完整固定源码／资源及检查点压缩保存于 `evidence/final_restart/source-and-results.zip`；这不是完整可玩工程。测试、成本及编译脚本在 `tools/` 保存交付副本，正式入口仍在项目 tests／tools 中。

```powershell
$godotExe = 'D:/game/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe'
& $godotExe --path . --rendering-driver d3d12 --script res://tests/integration/water_execution_exact_probe.gd -- --output=res://test_output/water_execution_recheck/exact
& $godotExe --path . --rendering-driver d3d12 --script res://tools/parameter_windows/scene_profile.gd -- --timing-off --output=res://test_output/water_execution_recheck/cost
& $godotExe --path . --rendering-driver d3d12 --script res://tools/parameter_windows/water_recording_cost.gd -- --output=res://test_output/water_execution_recheck/cpu
python tools/parameter_windows/analyze_muscl_cost.py test_output/water_execution_recheck/cpu
python tools/parameter_windows/run_muscl_restart.py --output test_output/water_execution_recheck/restart
```

使用新输出目录，等待各引擎进程退出后再运行下一条。Windows GUI 版引擎的 PowerShell 调用可能提前返回，自动采集应使用 subprocess.run／显式等待；本轮除第一份直接启动基线以外均保存退出码和 stdout，第一份以完整 capture、无 fault／来源漂移及进程已结束为依据，不补造退出码。

长期证据位于本目录，清空 test_output 不影响运行功能或本次证据。当前技术方案、规格及生成文档同步描述实际实现；竞品知识只更新 Godot 适配状态，没有将本项目成本或等价性结果当成原作结论。
