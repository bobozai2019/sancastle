# 本轮架构边界与基线审查

文档角色：verification_evidence。核对对象为 `baseline/identity.json` 中的当前工作区文件；历史优化不计为本轮结果。本表是源码审查，运行验证由独立运行目录证明。

## 数据流与所有权

`playable scene → runtime.current(Pipeline) → request_tick / pump → Transport.submit → Water.record_tick → Muscl.record_tick → Coupled → sim_finish / tail → Pipeline._finish_work → GPU readback → Pipeline._poll → Views.observe_complete`。

| 边界 | 责任与权威 | 同步、异常与生命周期 |
|---|---|---|
| 场景、参数与 configuration | 参数服务读取指定 startup；配置冻结来源指纹，场景通过统一 runtime 请求 tick / 编辑 | `parameter_service._ready/prepare_boot` 支持 `--parameter-config`，布局路径由配置目录派生；探针核验实际路径，进程外核对真实用户文件 |
| Pipeline | 请求准入、队列、租约、完成序列、账本与恢复；`_poll` 才更新 completed tick / state_seq / advanced_time_s | 记录顺序消费 GPU_COMPLETE；检查序列回退；提交失败区分 recorded / unrecorded，不发布半成品；释放前要求队列、租约、读回、预览和高度消费者空闲 |
| Transport | 有身份的输入/控制/回执资源及提交；回调携带原租约身份 | `_submit_render` 调用 submit，`_receive` 校验租约；retire 确认后才复用；cleanup_fault 请求终态而不提前回收 |
| State | 公共水深、动量、沙、材料、悬沙及双槽资源持有者；数值核受控写入 | 初始化源自 domain 或严格恢复数据；`publish_sand` 与 Views/Visuals 发布属于 `_finish_work`；不由录制器接管 |
| Water / Muscl | Water 持有 decision、indirect、kernel 与工作 RID；Muscl 组织固定 64 槽的 RK/耦合描述，借用资源，不提交或逐子步读回 | `Water._own` 汇总 Muscl 工作纹理/缓冲/绑定/编译资源；Muscl.release 先清描述及引用，再由 Water.release 逆序释放 owned RID；每阶段独立 compute list |
| Coupled | 自己的材料/坡度/支撑资源；MUSCL exchange_sediment 借用 Water 的私有暂存 | 标准 record 展开 `_passes`，包装/自定义 Callable 保留逐槽调用；耦合提交后 normalize 复原公共槽 0；不向水核搬入材料业务 |
| 完成态消费者 | Heights、Views、Visuals 在原发布链路消费同一代完整状态 | 不引入额外完成态或诊断写入者；关闭等待消费者释放；候选不能绕过 `_finish_work` |
| 恢复 | configure_restore 验证配置、generation、来源、边界、材料/视觉扩展后初始化和校验 | 源码不同的版本分别构造实例；不取消来源指纹；每个最终版本内必须另进程恢复 |

初始化中途失败通过 `_initialization_failed_render → _request_initialization_cleanup_render` 保留所有权直到清理；正常关闭通过 close_admission 和 drain 后 release_render。上述路径尚需本轮受影响的运行探针，源码审查不等于故障注入通过。

## 缓存与诊断边界

当前 `_prepare_recording` 键为 dt、cell_size、boundary_enabled、wave_retention、coupled_recorder、prescribed_tide_boundary。只有标准 provider 的原始 record Callable 才内联耦合描述；缓存不跨实例。旧 `scene_profile --detail-gpu` 包装 Callable，不能作为展开路径的成本依据。

本轮 T01 必须在现有描述录制处标记，并保持标准 Callable；只读诊断暂存由单一所有者持有、上限丢弃、完成后读取，不能同步等待或修改权威状态。采样失败、队列满、关闭时必须显式记录丢弃，不影响调度。

| 候选 | 涉及边界、写入与资源 | 同步与异常/恢复约束 | 撤回方式、待确认 |
|---|---|---|---|
| T03 邻格共享 | rk_edge 工作组内部 shared 原始数据；不新增持久 RID，不改变公共布局 | 所有线程到达 barrier；halo 掩码不新增错误；两个阶段输入不同 | 还原单个 shader；需核实 shared 容量、精确算术与成本后才能准入 |
| T04 拒绝复用 | Muscl 私有第一阶段派生缓存，仍由 Water 持有 RID；不成为权威状态 | correction/bed_source/speed_tiles 当前被阶段 1 覆盖，必须独立存活；失效集中在求解器内；不得让场景维护 | 还原 shader/私有绑定；额外内存、故障/接受/新 tick 的失效方案未完成，不进入实现 |
| T05 复制融合 | finalize、Coupled.commit / sediment_copy、normalize；水与材料职责保持分离 | 先证明最后读与首次写；公共槽 0 和备用槽均保持，故障不发布 | 还原局部核与描述；跨模块融合或全局轮槽直接转 vNext，读写依赖表待 T02 |
| T06 列表整理 | Muscl 的统一缓存描述录制；无新增长期数值路径或跨 tick list ID | 必须验证纹理/storage/indirect 写后读 barrier；回调前结束列表 | 还原录制循环；先做实际 D3D12 最小验证，不能假定 API 的隐式依赖完整 |

当前没有已通过的候选。T00 基线及 T01 有身份的测量完成后再决定投入，不以预估收益豁免架构条件。

## 测试入口

| 入口 | 用途与限制 |
|---|---|
| `tools/muscl_performance/baseline.py freeze` | 将当前运行源码、资源、配置与必要原型存入 runtime.zip 和 SHA256 索引；reference 是本轮当前 recorder / coupled / shaders，无历史 HEAD 覆盖 |
| `baseline.py scene --run-id <new>` | 独立真实窗口、D3D12 Forward+、1280×720；复制同一份用户参数，诊断关闭；预热 5s、稳定 2s、live 20s、paused 10s；记录模拟完成窗口 |
| `baseline.py exact --run-id <new>` | 显式 reference 本轮快照；复用精确探针比较公共双槽、control、decision、audit 等；固定合成输入，不用于成本结论 |
| 旧 water_recording_cost | 硬编码历史 reference，不能直接作本轮 CPU A/B；T06 前需替换为本轮独立进程入口 |
| 旧 run_muscl_restart | 默认读取历史 seed-result；最终版本必须生成自己的保存输入并重跑，不能照搬旧 PASS |

冻结归档不包含 `.godot` 派生导入缓存、竞品数据和历史任务大文件；运行必需的源资源及实际配置包含在归档。工具后续修订与运行源码差异在 manifest 明列；任何正式运行源码漂移都使对应比较无效。
