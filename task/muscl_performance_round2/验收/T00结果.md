## 来源与隔离

`baseline/runtime.zip` 冻结当前工作区 3112 份源码、配置与资源，身份见 `identity.json`；没有用旧 Git HEAD 覆盖工作区。`reference/` 为本轮原始 MUSCL 与耦合实现及 shaders。场景与精确运行的 manifest 都记录完整来源集合、引擎 SHA256、实际命令、退出码、运行前后来源与用户配置指纹。运行过程中无来源漂移；相对冻结点只有开发采集器的两份工具修订，不涉及运行模拟。

参数隔离复用正式参数服务已有 `--parameter-config`。每个进程从冻结的 startup/windows 副本启动，场景探针在创建场景前核验实际读取路径，并导出 `isolation.json`。两个场景进程及精确探针结束后，真实用户 startup.json 与 windows.cfg 的 SHA256 均保持不变。没有依赖未经验证的 user-dir 命令行参数。

冻结时的工具版本保留在 runtime.zip，修正后的工具保留在 `harness/`；原模拟源码与资源完全一致。最初 `baseline_a1` 在快照生成完成前尝试复制配置，FileNotFoundError 后退出，未启动 Godot；该失败不计入性能比较。

## 数值自对照

`baseline_exact` 显式指定 `res://task/muscl_performance_round2/reference/`；退出码 0，`exact.json` 的 pass=true。still、coupled、retention、boundary、high_velocity、dry、obstacle、capacity 八种固定输入共 36 个完成 tick 对照未发现任何比较字段差异；比较包括公共双槽、GPU control、decision 与原 MUSCL buffers/audit。实际出现最多 18 次拒绝并覆盖 64 槽容量耗尽。包装回调、参数键改变与释放使用原探针检查；所有来源在探针运行期间保持不变。

这里证明当前 reference 与当前实现的基线自对照可信；没有证明尚未实现的候选等价。该探针未比较独立的完整持久化账本、未做跨进程恢复或全部故障输入，这些仍属于后续 G2/G4 的补充范围，不能由现有 PASS 推断。
