# 水材质视觉与参数契约

日期：2026-10-11。角色：contract。状态：frozen v1.35；T00 G03 / G0已通过。本文只有接口与判据，实际验收另存。

## 1. 权威与显示边界

继承[状态与数据契约](../../../docs/knowledge/water_sand/状态与数据契约.md)。

- 只读 rock、sand、water、momentum_x/z、已有泡沫/浪前历史；不向水沙、源汇、库存、碰撞或保存数据偷偷写入视觉结果。
- 沙底、水面、细沫、接触共用实际可见床面/表面重构。细法线不能改变权威高度、浪形或碰撞。
- 同 generation、revision、completed_tick 的完整完成态才可绑定；表现时间沿用完成tick/30，暂停/冻结停止，恢复后继续同一时间。
- Shader 世界/视图/切线空间要显式说明；双面法线朝向修正不能反转细纹理坐标。法线混合需保留几何坡度。
- 新细沫若引入视觉历史，必须列入候选保存/恢复契约；优先用现有泡沫场和确定性seed表达，避免新增不必要历史状态。
- 显示层光照不得再次整体照明已受光 scene_color；折射/透射、反射、散射、太阳高光和白沫分别定义贡献。

## 3. 取证与结论

原包/RDC只读；先hash再复用对象/事件。源文件完整路径、字节数、SHA256；对象身份包含容器hash与PathID，RDC身份包含capture hash、event与ResourceId/subresource。

每份复取产物索引包含：源身份、字节范围或重放选择器、工具版本与命令、输出hash、失败/缺失项。对象raw、外部payload、RDC快照、PNG/JSON/反汇编分开；字节码不是原始HLSL。包内默认值与帧内有效值分别记。

重要结论记录：
statement_id、statement、kind（observed / inference / godot_adaptation）、confidence（C0–C3）、evidence_locator、reproduction、counterevidence、scope、unknowns。

## 5. 视觉与状态验收

1. 法线：开关实际生效；三路消融能区分细节贡献；无细法线时几何/权威场不变；记录周期条带是否由物理波形或合成保留。
2. 光照：转动候选光源时高光方向正确；高光关闭/阴影关闭/移除遮挡对象各自能区分；不用全画面压暗冒充阴影。
3. 光学：T00冻结浅水/中水/深水ROI及遮挡区域，按状态水深分组；优先检查0.02–0.08m和≥0.20m实际存在区域，若场景无该区间须补独立固定fixture；浅水可读底脊，深水逐渐衰减，湿干和屏幕边缘无拉伸/漏色。
4. 白沫：近景能区分细点与小团；浪前/面内/岸脚贡献分开；干沙、静水、无额外波及高沙遮挡负例不出现永久白环、穿透或悬空。
5. 反射/亮纹：反射随细法线产生可解释变化，边缘回退稳定；底部亮纹位于湿域可见床面，不与水面太阳高光共用一层。
6. 连续：固定沙床和耦合模式共用表现钟，暂停无持续漂移，恢复时间与绑定一致；60秒观察无明显闪烁、规则亮点跳变或无依据反向漂移。
7. 状态：同一冻结权威状态在视觉消融前后raw hash一致；动态对照比较同输入、同完成tick的权威状态，不把运行前后自然演化误当视觉污染。
8. 主观评价：每项附同条件A/B和改进/退化/无差异评语，选择依据明确；已有主因假设若被反证则回填问题，不靠随机换噪声反复试错。

ROI坐标、有效曝光、选用tick、成本增量预算及必要像素容差在G0冻结后写入附件；不得见到结果后放宽阈值。

## 7. G0 接口冻结附件 v1.1

本次 `/goal` 已授权执行。候选 schema1 初期仅实现 base_profile、normal_detail、cost_budget 与 deferred_interfaces；上表 lighting/optics/foam/reflection/caustics 在相应任务升级接口前为 deferred，不把未消费字段计 implemented。接口样本与五类拒绝用例见 `test_output/water_material_natural/t00_interface/`，校验器 `tests/water_material_natural/validate_candidate.py`。字段集合严格校验；base 文件及贴图 SHA256 必须一致。

- 初始三路：off / legacy_sine / texture_layers。贴图 raw RG 从 [0,1] 映射到 [-1,1]，作为局部 XZ 细坡度；属于 Godot 适配，原作解码/动画未知。采样无 source_color，无 normal_map 重新编码，linear_mipmap / repeat，mip 开启。原始 RGBA PNG 与 RDC mip0 raw 相同。
- 每层 scale_per_m 范围 [0.001,4]，direction_xz 长度2、模长1（平方误差≤1e-4），speed_m_s [-2,2]，gain [0,0.5]。取样坐标使用局部米制 XZ、单位方向旋转和 speed×完成态时间；纹理模式只改法线，不改位移。
- 候选预算在首次候选前冻结：相同 1080p 完整负载、各60秒，median 帧时间≤基线1.10倍、p95≤1.15倍。冷启动/编译单列；越界需归因返工。旧性能 FAIL 保留。
- 基线 target tick360 / visual_time12秒 / single_packet_v1，三机位由正式场景 CameraAnchors 提供；1280×720，D3D12 Forward+，VSync disabled，render scale1，MSAA/屏幕AA/TAA按实际 manifest。太阳、环境、曝光、床高、浪输入均保持正式值。
- ROI 以1280×720像素 `[x,y,w,h]` 冻结，后续1080p按1.5缩放：oblique 浅水 [450,420,155,80]、深水 [285,500,160,110]、接触 [755,495,110,120]、浪前 [655,315,120,95]；close 浅水 [30,580,215,110]、深水 [250,495,190,80]、接触 [845,545,135,110]、浪前 [510,337,155,60]；grazing 浅水 [850,625,240,85]、深水 [330,550,270,70]、接触 [900,405,260,95]、浪前 [665,380,235,80]。这些是视觉区域标签，不能仅凭区域名声称每个像素的物理深度；分组统计使用同态water raw，T03需深度调试图投影交叉核对。
- 视觉判据：三模式实际生效；原几何坡度保留；近景新增细节可见，远景无网格/明显重复单元或闪烁；旧正弦/关闭/贴图分别保存，不以纹理差异单独宣称整体改善。初期像素差异只作开关贡献，主观选择附评语。

### v1.2 / T01 支持范围

schema1当前实现严格支持两层（上表1–3为初始拟用范围，第三层尚未实现）；Python与运行入口统一拒绝其他层数。有效消费模式、层参数、方向、resource hash单列effective_candidate；候选v8派生base与源release除water_shader路径外须完全相同，禁止藏入浪/权威输入差异。当前default保持低gain0.06/0.025，测试用整体gain×3作为单变量归因负例，不回写选定profile。完整输出图的细节开关off必须与mode off相同。

### v1.3 / T02 受光接口

已验证normal schema1保留；新受光采用独立composition profile `lighting_schema_version=1`，由`lighting_entry.gd`消费，不能在normal profile写未消费lighting标签冒充实现。输出effective_lighting单列实际字段和资源hash，后续正式整合再统一版本化。

| 字段 | 类型/单位/范围 | 默认与消费 |
|---|---|---|
| normal_profile / normal_profile_sha256 | res path / SHA256 | 选定texture_layers配置，必须匹配 |
| route | enum | manual_glint / engine_light；manual路线拒绝shadow/直接散射/直接细沫 |
| base_profile / water_shader | res paths | 独立v8派生base，除water shader路径外等于源release |
| sun_glint_enabled | bool | true，实际太阳方向沿DirectionLight3D +Z（指向光源）；不另用固定光向 |
| sun_glint_gain | float / linear additive scale [0,2] | 0.32；gain0必须等于关闭 |
| sun_glint_exponent | float / Blinn幂指数 [4,256] | 42；非roughness或原作公式 |
| shadow_enabled | bool | manual false；engine路线待真实遮挡验证 |

manual太阳高光采用实际view-space半角向量与最终细法线，深度0.008–0.05m平滑门限，保留权威/几何/其他光学参数。它不证明引擎阴影；engine_light路线须真实遮挡存在/移除/禁用阴影负例。debug1只显示太阳项，off与gain0应为零水层；opaque沙体不是debug太阳项。旋转光源的场景色改变不能单独证明高光方向正确，须debug太阳项交叉复验。

### v1.4 / T02 引擎受光方案与 schema2

lighting schema1 manual接口保留。schema2 engine_light 在同字段基础增加必需`foam_shader`（res shader path），有效manifest记录水/细沫实际shader、参数及hash；schema编号须逐字段数值校验，不能以Godot数组成员的int/JSON float类型差异拒绝合法版本。

- 方案是Godot适配：去除候选unshaded，采用ambient_light_disabled和custom light；场景色透射/反射保存在EMISSION，不整体乘太阳或shadow。ALBEDO=1配合自定义colored DIFFUSE_LIGHT，SPECULAR=0关闭额外材质环境反射；高光只由custom light中的SPECULAR_LIGHT加入。
- 散射候选精确分离已存在项 `scatter*(1-transmission)*(1-shallow_preserve)*(1-reflection_weight)`，按已有主白沫覆盖减小其贡献；主白沫单列 `foam_tint*white_fraction`。候选只把指定fraction从EMISSION转移至custom direct layer。当前frozen试值scatter0.45、foam0.50；单变量开关与shadow负例通过前不标验收。
- 细沫geometry/coverage/alpha不改，颜色拆分ambient与direct，表面方向来自实际quad的view-space位置导数；太阳colored irradiance=LIGHT_COLOR/PI×ATTENUATION，角度max(dot(NORMAL,LIGHT),0)。DirectionalLight的实际shadow参与ATTENUATION，绝不贴黑图冒充阴影。
- debug1太阳高光、2实际ATTENUATION、3仅直接散射、4仅主面白沫；细沫可单独隐藏/显示。无受光fraction且关闭高光的engine候选应保留基线color；直接受光比例0是负例，不能用整幅压暗通过。
- 阴影验证fixture使用保存到独立tscn的两个不参与物理的静态opaque box。对照shadow_enabled开/关、caster存在/隐藏；量化在共同可见水像素上，不把caster本身遮住画面当阴影。实际接触/床深来自同完成态，无新权威写入。
- 静态LightFacing机位只用于太阳反射方向验证，position(-10,22,-14)、rotation(-52,-144.46,0)deg、FOV55；正式三机位/曝光保持。

### v1.5 / T02 影子网格成本候选

720p冻结短窗观察到完整engine+shadow相对normal-only明显增量，先登记返工，再允许单变量投影网格候选。schema3 engine_light在schema2基础加`shadow_proxy_mesh`资源path与`shadow_proxy_enabled`bool；profile/静态场景/实际mesh一致才生效。输出proxy绑定、启用、cast mode、visible terrain cast mode。

proxy网格预生成并保存`.res`，257²节点，UV/坐标是原512²可见网格精确子集（源索引0,2,...,510,511）；共享实际terrain ShaderMaterial、床面字段和当前完成态，不写几何/权威/碰撞。原可见mesh密度、shader、颜色不改；只是禁止其重复投影，用SHADOWS_ONLY proxy接替，仍由实际DirectionalLight阴影图生成。不存在低分辨率阴影通过前默认采用的授权；只有投影误差与成本对照通过才选择。

投影误差判据在采样前冻结：同态、相同太阳/视图，native/proxy二值阴影在共同可见水区域的显著差异（ATTENUATION调试8bit差>20）必须仅位于任一路阴影边缘2px内；内部不得出现新阴影块/漏光。生产色变化须局限同一区域。caster存在/移除负例保留；四机位验证，最终三机位长序列另验。预算仍为G0原1080p60秒median+10%/p95+15%，不能以短窗替代或放宽。

原细沫grazing诊断仅4个受影像素，低于该探针预设>5，保留FAIL；单独扩大验证caster覆盖复测，不改变细沫材质/几何/coverage或验收阈值。投影网格和caster覆盖是两个独立探针，不混作单变量结果。

### v1.6 / T03 光程对照接口

新增独立`optics_schema_version=1` composition profile，引用`lighting_profile`与其SHA256，不改变normal/lighting schema。字段集合严格校验；光学字段只写候选水材质。有效manifest列出实际shader参数、profile hash与路径/回退语义。

- `path_mode`只接受`legacy_vertical`与`depth_reconstructed`。前者保持既有`depth/max(abs(dot(VIEW,n)),0.25)`；后者用Forward+实际深度与INV_PROJECTION重建取色位置的view坐标，计算到实际水片元VERTEX的欧氏距离。该路线是Godot适配；原作指令支持距离衰减，但其有效单位/常量映射仍未知。
- 非法/天空深度、齐次w过小、取样点位于水面前方或距离超过50m时回退旧光程，不能把无限远天空当水深。折射屏幕外/前景回退仍使用原SCREEN_UV；边缘判据0.001–0.999与深度裕量0.005m保持。先只切换光程，再分别选择其余参数。
- `extinction_shallow_m`/`extinction_deep_m`为[0.001,20]m的指数衰减长度；`scatter_gain`为[0,2]显示色乘数；`shallow_preserve`为bool，仍用0.03–0.18m垂向水深区间；`refraction_scale`为[0,0.03]屏幕UV偏移系数，不能当世界米。首轮全部复制实际基线消费值。
- `optics_debug`只由探针设置：0生产、1垂向水深分组（浅红/中绿/深蓝）、2光程灰度（1m白）、3折射回退（前景红/越界绿/非法路径蓝）、4透射率灰度、5散射色、6无衰减床色。诊断层必须隔离太阳/白沫直接照明，避免把其贡献当光程变化。
- 本接口不增加RGB吸收系数。竞品反汇编的通道系数和本项目固定scatter tint先分别登记，不能未经单变量验证混入首轮光程对照。
- 本轮前景/越界负例须实际激发回退像素；仅代码含条件或捕图成功不算通过。深度分组必须与同态权威water raw及可见床面投影交叉核对；G2仍需浅水底脊、深水衰减与干湿/遮挡/边缘检查。
