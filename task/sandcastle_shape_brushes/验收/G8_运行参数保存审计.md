# G8 运行参数保存审计

日期：2026-10-15（Asia/Shanghai）。范围：侵蚀运行系数与实际保存配置的一致性；不是性能验证，也不替代严格继续验收。

## 已观察事实

`SandcastleGpuSedimentCoupler` 的三个可变探针参数实际进入 erosion push constant：容量系数、侵蚀率、沉积率。正式配置使用源码常量，但既有存档没有保存探针覆盖值，恢复构建使用默认值。

实际负例 `test_output/shape_brushes/20261014_235436_runtime_profile_fba921b3`：每次只将一个系数乘1.25，分别调用 `save_gpu_checkpoint` 和 `request_checkpoint_save`。六种组合全部成功写盘，实际恢复后分别从0.1→0.08、0.4375→0.35、0.5625→0.45。六个拒绝断言均FAIL，原始文件、日志、配置身份与索引保留。此证据直接证实未支持配置被静默接受，不说明默认配置长时分歧的原因。

## 实现

- 共享 native 捕获入口在提交前核对三个实际系数是否等于受支持的正式常量；不支持的值返回 `unsupported_checkpoint_erosion_profile`，不写文件。
- 异步读回完成后的最终写盘审计再次核对，防止捕获期间配置改变。v4 扩展验证必须先执行父级审计，再验证混合前缀。
- 维持既有存档版本和正式模拟公式。任意探针参数持久化不在当前支持范围；若以后支持，需同时定义序列化、配置身份和恢复契约。

## 验证

初次修补 `20261014_235719_runtime_profile_27fa7672` 六组合拒绝及默认恢复通过。扩展后的正式证据 `20261014_235854_runtime_profile_a85a31cf`：GPU 32项、独立文件/raw审计277项全部通过。

1. 三参数×两入口均返回明确错误、无文件；每次拒绝后的27项权威字段及账本元数据保持。
2. 通过实际 `beach_capture_submitted` 信号在GPU捕获提交后修改容量系数，确认回调执行、最终写盘拒绝、无文件及状态保持。此项覆盖最终审计，不能仅靠入口检查通过。
3. 还原正式参数后，实际磁盘保存/恢复成功，27项字段及元数据一致，资源关闭完成。
4. 独立Python读取全部9份快照的27个实际二进制文件，复核字节数/SHA256并逐字节对比锚点；检查六负例和捕获期间负例文件均不存在、正式文件存在。

命令：`tests/shape_brushes/run_shape_brushes.ps1 -Group runtime_profile`。环境：默认Godot 4.7.beta.custom_build.dff2b9bb6、D3D12/Forward+、GTX1050、可见1280×720；暂停态实际v4/native2实验场景。未测量成本。
