# C04–C05 几何、沙量与保形契约

状态：draft v1。C04于G1A冻结，C05于G4定案。所有拟定公式都是本项目适配。

## 1. 坐标和共同边界

当前域256×256，cell_size=0.125 m，A=cell_size²。索引=z×N+x，单元中心=((x+0.5−N/2)Δx,(z+0.5−N/2)Δx)。Y向上，bed=rock+sand，sand为参考密度等效沙厚，单位m。

工具不改rock，不把compaction当几何密度。绘制、碰撞、水响应均以同一完成态bed定义；只写渲染网格不能完成本任务。

新刷子完整工作范围必须在域内，castle整形超出域拒绝；wall/shovel按分段核对完整截面，越界段拒绝并中断子路径，不裁剪出半座城堡或单侧铲子。不跨有效obstacle移动沙/水。

所有读取、写入和归约使用明确矩形与掩码。掩码代表作用域，不能直接以高度值是否为0代替；转移donor/receiver区域互不重叠，同一格最终只写一次候选。

## 2. 沙墙目标覆盖

中心路径为P，横向距离为d。定义连续截面F(d)：中心为平顶，向底部边缘线性或平滑下降，底宽wb、顶宽wt、高h满足0<wt≤wb、h>0；G1A固定一个MVP截面，后续不反复改噪声。

基准B(x,z)来自该stroke开始的bed。拟定target=B+h×F(d)，候选bed=max(current_bed,target)，只增加不足部分。同一笔所有已覆盖路径以max合成目标，重叠角点不相加。

端帽按同截面封闭、相邻段联合，避免断缝。下一笔重新采集基准，允许再加高。形状刷子的静止按住不注入按秒沙量。

ΔS_i=max(0,target_i−current_bed_i)，实际Vadd=Σ(Snew_i−Sold_i)A。基底起伏是否跟随由B明确决定，MVP沿原床面筑墙；不得读已建墙顶作为同笔基准。

## 3. 城堡模板与放置

H(u,v)为float32非负局部高度；另存foundation_mask、shape_mask。塔楼、墙、底座和城垛都要在256²物理网格重采样后可读，预览使用相同模板和插值规则。

局部XZ由世界位置、yaw和scale逆变换获得。模板外不写；极小尺寸不能靠提高显示网格细分宣称物理细节存在。

MVP选水平基底。拟定基底B取foundation内编辑前bed最高值，且该区域max−min不超过预设落差上限，计划起点0.25 m；超限拒绝invalid_placement。基础mask内目标为B加模板高度，低处填实，较高existing_bed保留：

Snew_i=Sold_i+max(0,B+Hscaled_i−(rock_i+Sold_i))。

基础填充体积也必须计入Vadd。遇已有高结构不自动削平；若高处破坏关键模板轮廓，预览标不适合并拒绝，不静默切掉旧城堡。允许阈值和关键区域规则在G1A固定。

点击执行时从实际input_revision重算基底/体积；预览过期要刷新或等待，不能把旧CPU影子当最终计算依据。预算不足拒绝完整stamp，不把H按体积缩小变形。按住只提交一次。

## 4. 铲子守恒搬运

每段有效方向t=normalize(end−start)，横向法线n=(-t.z,t.x)。零长度不编辑。沟中央为donor mask，沿±n的肩部为左右receiver mask。端帽、反向与角点按固定规则生成，donor/receiver无重叠；同格别名必须在候选阶段解决。

目标床高为stroke基准B减depth×trench_profile，不能低于rock。每格最大可挖体积：

C_i=max(0,current_bed_i−max(rock_i,target_bed_i))A。

请求量还受每段transfer_budget限制。每侧可接纳量由非障碍receiver格、baseline上允许的ridge高度和当前sand计算。默认左右等量，Vcut≤2×min(Cleft,Cright)；若一侧无接纳量则no_change/明确拒绝，不全倒到另一侧。

执行顺序：

1. 从同一完成态构造可挖候选，基底截断，按确定权重/固定序归约实际Vcut。
2. 核对左右容量，必要时回缩Vcut后重新分配donor，绝不先提交挖坑。
3. 左右各接收Vcut/2，按各自权重分配、容量限幅并确定性再分配余量。
4. 量化到float32后再算actual_removed、left_received、right_received与净变化。
5. 如残差超过预先预算，使用有限确定性残差修复或拒绝完整事务，不把残差记入外部源汇。
6. 沙、水、材料全部候选核对通过后原子提交。

本地验收：abs(Vremoved−Vleft−Vright)≤eps_transfer，abs(ΣΔS×A)≤eps_transfer。左右量差仅允许量化预算；肩部峰高可因地形和可用面积不同而不同。薄沙只搬实际量；挖到底、越界、障碍和容量不足都不能制造沙。

同笔交叉/回头不重复超过已定义目标深度；后续模拟回填后是否再移出按同一目标规则处理，必须区分无模拟幂等与真实时间演化。

## 5. 账户和有限权限

| 操作 | sand_source变化 | sand_sink变化 | inventory变化 |
|---|---:|---:|---:|
| wall/castle成功增沙 | 实际Vadd | 0 | 0 |
| shovel成功搬运 | 0 | 0 | 0 |
| 新命令拒绝/no_change | 0 | 0 | 0 |
| 旧place/remove | 继续沿用external_v1或旧库存模式原规则 | 原规则 | 原规则 |

总体沙闭合仍为Σ(sand+sediment)A−initial−source+sink。刷子搬运不作为外部源汇，大域总量百分比不能掩盖逐笔局部误差。

新命令add/transfer配额均来自被冻结资源合法范围，必须有限、非负，接收端重新计算并校验。恢复前缀保存预算及实际结果，拒绝虚增权限。具体预算算法不同于旧amount×strength，不能全局删掉旧available_m3校验来兼容。

## 6. 数值容差

G1A以现有edit_protocol的ulp32/cell_budget/reduction_budget/volume_budget为起点，固定新donor/receiver联合受影响格、absolute_sum和归约次序的预算。CPU用更高精度做独立参考分配，但比较GPU最终float32场。

记录每笔eps_cell、eps_sand、eps_transfer、eps_water具体数值和计算输入，保持float32量化与归约分项。不能在看到FAIL后扩大容差，也不能用未冻结的1%总场比例代替局部搬运校验。

硬性要求：非有限值、未解释负沙/负水/悬沙、越基底、旧generation回调生效、重复结算、失败留下半次变化均为0次。raw字段用实际字节，hash和字段字节数进入manifest。

## 7. 局部保形（C05）

G4先做固定preset的单变量测试：普通sand baseline → 只改变新形状区域compaction → 在明确范围启用有限cohesion。已知现有compaction只改变休止角，不能预先断言能保住直壁。

拟定门槛：干态无波浪30模拟秒，代表性wall和四塔楼模板的主要峰高保留≥80%，轮廓占据区域IoU≥0.8；细城垛按物理尺度独立查看。阈值和测试ROI在G1A预先固定，不能靠提高render细分、冻结全域模拟或换机位过门。

如全域cohesion使普通沙负例改变，则不能采用该全域改法。局部mold_support是本次范围内的备选实现，字段与规则在G4冻结：

- support仅影响被新刷子塑形的沙，不改变沙量或rock；值和支持落差有有限上限。
- support=0的共享边计算与旧staged_slope一致；保守坡面转移的供受体配对保持。
- 挖削、侵蚀与搬运后support/compaction如何削弱或按实际沙量混合必须有明确公式；不留“沙已挖掉但支撑永久存在”的标签。
- 饱和、水冲与失去支撑后仍能演化；禁止每帧重写模板来恢复形状。
- 需要新增状态时，格式、双槽commit、初始化、候选rollback、raw审计、checkpoint字段和释放全部纳入C07；不只增加shader采样而漏掉恢复。
- 第一版不新增几何密度模型，不改悬沙质量定义。新增材料标记的输运若为近似须明确范围及负例，不能称为新的严格物质守恒字段。

对照必须记录实际param/profile/SPIR-V hash、seed、tick、相机、完成态和是否运行水沙耦合。最终策略无论复用还是新增，需写项目ADR和当前契约入口；竞品算法没有参与此结论。
