# C06–C07 完成态、水响应与恢复契约

状态：draft v1。G1A冻结生命周期和版本架构，G4冻结材料字段，G8验证真实整合。

## 1. 原子编辑边界

继承同域64 pending/1在途与现有revision/generation所有权。新刷子不能绕开_writes_locked、旧tick/保存/恢复锁或独立在render线程写同一状态。

事务顺序：admitted → execute on complete revision → sand candidate → material candidate → water candidate → all validation → conditional commit → one receipt settlement → publish → dirty collision replacement → collision_ready。

实现可在内部提前写受保护的私有/备用槽，但公开完成态及失败回滚必须满足：

- 回执结算前不发布候选，不让视觉提前出现未结算沙。
- sand、水/悬沙/动量及被修改材料以同generation的一份完整结果发布。
- 失败、旧generation、身份不匹配、预算不足、GPU候选无效时恢复完整输入态及材料，账本不变。
- no_change不推进实际编辑revision或账户；其命令身份终结规则在G1A固定，重复结果不再执行。
- 当前执行revision是GPU实际输入态，入队的路径基准是另一明确token，两者不能混用。

## 2. Mixed-delta水响应

wall/castle主要抬高床面；shovel同时降中央床面和升高两侧。水候选必须从同次sand_before/sand_after构造完整bed delta，不能用净沙量0推断“无需水响应”。

继续采用当前水策略及其明确范围：对床面升高区域处理保守位移，降床不凭空增加水；后续通量自然填沟。水/携水悬沙/动量搬运只在合法连通区域。接纳不足保留并报告retained，不能删除水或将其伪记为外流。

普通旧笔刷四策略行为保持；新刷子需要分别测试dry、shallow、underwater、岸边、隔离水池、障碍、全湿与容量不足。尤其验证带正负床差的候选是否被当前cells.x/dirty窗口/连通缓存正确消费；必要改法只限本次候选接口与有证据的水语义。

速度响应是显式配置而非默认套用旧圆形radial方向：新profile先以speed=0做量和几何测试，再单变量对照非零speed。新墙/模板/沟槽各自方向与增益在G1A记录，G8验证限速/CFL/冲量；保留旧速度规则，不把铲子左右沙搬运方向直接当作水速度真值。

闭域瞬时Σwater×A不变，开放边界只按真实边界源汇变化；sand+sediment闭合考虑现有侵蚀输运。超载/非有限/CFL超过既有上限明确处理，不能降目标Hz掩盖。

## 3. 显示、碰撞与拾取

发布只读取完整完成态；水、沙、白沫、接触与焦散沿用一致bed/eta基准和完成tick表现时钟。预览是只读层，不写权威沙水字段，不因暂停而推进表现时钟。

dirty范围包含全部中央/左右/端帽变化。碰撞仍按32²分块及既有两次物理帧等待，record applied_revision，不使用新brush的请求ID冒充碰撞revision。

ghost_preview、sand_published、collision_ready分开观测。若拾取块落后所需revision，显示等待并重核hit，不接受旧碰撞点；不通过取消碰撞等待宣称事务完成。新城堡与墙不能仅有视觉高度而没有可拾取床面。

## 4. 检查点和配置身份

当前gpu_beach_edit v2是库存模式，v3是external_v1；gpu_beach_native v1固定10字段、8 spare与foam历史。新操作/账户回执/可能的新材料字段不能塞入旧白名单而不升版。

拟定新检查点策略：

1. gpu_beach_edit新增显式版本（计划v4，T01核对占用后冻结），记录brush_schema、原外部账户类型、新命令prefix与各命令operation；账户不能由kind的else分支猜测。
2. 如C05无需新字段，native字段格式保持；如新增support，gpu_beach_native另升版并列出字段格式/尺寸/双槽。内部sidecar/transport与native的版本独立处理。
3. 权威状态与既有foam/bed/flux/spare历史一起保存，保形字段不能仅保存在UI或runtime dictionary。
4. 配置身份涵盖brushDefinition、实际模板原始数据、生成参数、material profile、schema、有效shader与新代码/资产目录。现有扫描不包含的新目录/扩展需显式hash；不能只hash模板ID或声明资源名。
5. prefix记录实际执行tick、请求/结果、预算、definition/template hash、材料profile、水策略与speed。新预算验证单独实现，旧available_m3≤stock_before等校验继续保留。
6. 保存先结束stroke/drain，等待当前在途结算、发布和必要一致边界，pending_count=0；baseline/path cache不持久化，恢复后idle，新的stroke重新采集基准。
7. selection保存当前刷子与合法参数，恢复时重新白名单校验；旧普通挖填量保留，不把三种刷子参数混入旧amount字段。
8. 不兼容源码签名/资源、未知字段格式、模板hash不符、虚增预算、搬运伪装外部填沙、缺少support或双槽数据明确拒绝。加载失败保持原场景完整状态。

### 恢复和切换验收口径

- 同一候选构建内保存→恢复：全部权威raw字段、双槽、foam历史及账本逐位/精确配对，selection等价，配置身份匹配。
- 恢复后再执行相同新刷子命令，与未恢复对照分支比较实际场、回执、账户与碰撞。
- 相同tick之后继续模拟的严格配对继续按现有门槛检查，不用CPU/GPU近似容差替代。若旧恢复差异在无刷子基线重复，单独归因并保持未通过，不冒称解决。
- 三可编辑场景共享UI参数，沙/材料/源汇按场景独立保存；切换在途、失败回退、新generation迟到回调都有负例。
- 不做任意旧签名存档迁移；旧格式回归在可重建的同构建fixture中运行，保留明确拒绝语义和用户原文件。

## 5. 资源、诊断和关闭所有权

| 对象 | 创建/释放边界 | 上限与观测 |
|---|---|---|
| 刷子资源/模板纹理 | 加载场景配置，render线程创建RD，shutdown释放 | 按实际模板尺寸/格式记录bytes与RID |
| stroke baseline/coverage | begin创建或复用，draining完成/取消后释放 | 同域至多一个活动stroke；可能一次GPU域复制，不逐笔CPU全图回读 |
| candidate/control/receipt | editor初始化复用，关闭等待回调后释放 | 每域固定scratch容量，不能每笔累积 |
| 路径点缓存 | 输入层有界 | 计划≤256点，入队命令≤64；停止接收需明确 |
| 命令历史/诊断 | 按既有有界运行诊断政策 | 新统计有界；持久prefix增长按现有真实保存需求单独报告，不称RID泄漏 |
| 新support双槽（若采用） | 与模拟态同生命周期 | checkpoint/restore候选和失败释放一起验证 |

关闭/重置/恢复禁止旧回调写入新域。wait循环必须有可定位状态、错误终结和所有者，不出现永远等一个已取消callback的状态。保存、切换与关闭时记录pending/readbacks/resources以区分合法历史增长与泄漏。

观测字段至少：input/sample/admission、GPU提交/完成、receipt callback、settle、publish、collision_ready、first_visible、buffer depth、queue depth、completed_ticks、generation/revision、资源数量/bytes。缺失标missing，不填0；GPU计时与CPU排队分别记录。
