## 字段及有限语义

每个cell存储 `(tagged_depth_m, reference_sand_depth_m)`。tag不是额外沙量、源或结构目标，而是当前沙柱中具有有限局部黏聚性质的层厚。约束：有限，`0 <= tag <= sand`；有tag时reference等于同generation完整完成态sand；无tag时两个通道均为0。权威沙量及账本仍来自sand。

参数候选使用 `assets/brushes/molded_material_candidate.json`：局部黏聚高度0.9m、tag饱和厚度0.125m、成型新增沙的compaction目标0.95。未接受profile，不能默认把所有现有高堆标记成型。shader只按当前字段使用有限黏聚，禁止保存/重放几何模板作为每tick恢复目标。

2. prepare读取同完成态sand/support/compaction。若 `d = next_sand-old_sand`，先按上层tag优先损失规则 `surviving_tag = max(old_tag-max(-d,0),0)`；仅molded新增沙 `max(d,0)` 进入tag。最终tag裁剪到next_sand。plain新增不造tag；plain挖削仍削弱已有tag。
3. 成型新增量为正才把compaction提升到至少0.95；未改变沙量的路径覆盖不能替原有普通高堆贴材料。plain路径保持原compaction位模式。成型影响范围以实际新增量/有效cell为准，不以整个包围盒为准。
4. 所有新字段必须先写候选，在receipt成功分支与sand原子提交到双槽。拒绝、额度不足、湿候选未支持、非法值及身份不符不得留下tag或compaction更改。既有candidate失败、transport失败和wrong receipt负例扩展到support/compaction双槽及coverage。
5. 每个可能修改的槽独立保存preimage；不能用live槽代替spare槽的原始字节。回执身份失败的rollback继续经main deferred/render线程重入，并等待GPU完成读回后解锁。
6. 既有legacy挖填也要纳入同一候选/commit/rollback事务，不能等到下一physics tick才消除 `tag > sand`。暂停中完成的挖削也立即满足不变量；零支持分支不增加原算法的有效算术。
