# 底层统一调度契约

日期2026-10-17；角色contract_draft。尚未冻结游戏接线，不把草案当实现通过。

## 层次

业务/UI：只提交领域意图、参数、笔划采样，消费业务结果；不能选择“legacy/普通新后端”、自行决定GPU写锁或等待碰撞来授权下一段。
系统调度：队列/ticket/代次、执行器、资源读写依赖、barrier、背压、公平性、完成与取消、各owner终结。
provider：将领域意图展开成CPU、RD、GPU、worker、physics、IO作业；复用现有数值/工具核，但不得再运行隐藏的第二套全局调度循环。
执行器：只执行已准入作业并上报对应阶段，不能假造完成或偷偷修改其他provider资源。

## Job字段

- ticket={generation:int64>0,job_id:int64>0}，代次内单调；耗尽明确拒绝，不wrap。
- kind:StringName：已注册provider类型；内核不包含wall/shovel等业务名称。
- lane:StringName：注册时绑定的执行域与有界容量；payload不能更改执行域。
- stream:StringName：有序执行流标识；空表示不能用录制顺序证明数据可见。
- payload:Dictionary：接纳时深拷贝。实际RID不进诊断序列化；租约另由provider持有。
- claims:Array[{resource:StringName,access:read|write,release:recorded|complete}]：资源是代次域内逻辑身份；数量有界，冲突串行，不按工具名称判定。
- dependencies:Array[{ticket,phase:recorded|complete}]：只能依赖已知同代次旧ticket；拒绝未来/未知依赖，防DAG环。
- state=queued/dispatching/recorded/complete/cancelled/unknown/failed；完成结果与仅记录阶段分开。

## 顺序与资源

读读可共存。存在write时建立对先前冲突作业的依赖；只有同一非空有序stream且前序资源允许release=recorded才以recorded满足，否则必须complete。后端私有输入/输出、回调和RID生命周期仍保持到最后消费者complete；“资源可接受有序后继”不等于“可以释放资源”。CPU读完整GPU状态/原生存档等真实读依赖不能被改成录制完成。

barrier应由具体资源与消费者范围生成，禁止业务层全局legacy开关。保存需要一致快照、恢复需要候选发布/旧owner释放、退出需要所有消费者终结，这些是系统作业依赖，不是取消安全保护。

## 错误

普通业务拒绝是完成的领域结果，后继继续。明确未记录失败可回收。已记录结果未知保持租约/资源并停止关联准入；终结证明只能确认生命周期，不能修复成功回执/重放。重复、过期或错代次回调不能释放新作业。关闭只取消尚未记录工作，已接纳/已记录遵守各provider取消点。

## 保持约束

沿用现有256²/0.125m、GPU实际dt、材料/水候选原子提交、铲子守恒、城堡固定标高、来源身份与严格有限值检查。普通自由编辑近似账本不推广到库存工具。新调度改变源签名后旧存档兼容必须有显式版本化策略，不能伪造旧签名通过。
