# 泡沫表现与性能契约

角色：contract。接口、观察方法与原有预算已冻结；有效数值对应已选定的正式材质。成本验收与数值重放的未决结果独立记在验收目录，冻结契约不代表Gate通过。按用户要求，A/A性能核验在效果实现之后进行。

## C01 只读完成态与单位

| 输入 | 当前接口/格式 | 语义 | 约束 |
|---|---|---|---|
| foam_state | sampler2D，发布RG32F | R∈[0,1]为历史强度；G为前次水深 | 本轮只读R；不改布局、ping-pong或恢复字段 |
| water_state | sampler2D，R32F | 水深h，米 | 近干区先遮罩；不可直接除以0 |
| momentum_x_state / momentum_z_state | 两个R32F | 深度积分通量qx/qz，m²/s | 速度q/max(h,epsilon)，薄水正则化对齐现有0.02m并单独核验 |
| rock_state / sand_state | 当前发布床面输入 | 米 | 只读，使用当前可见床面/水面的同一基准 |
| async_clock | 已有完成态时钟纹理 | 已完成模拟时间，秒 | 新流动不得直接依赖TIME或墙钟 |
| generation / completed_state_seq | 已有发布身份 | 读者看到的完整完成态 | 不从进行中的work/candidate纹理取数 |
| UV与米制坐标 | 当前场景网格、域和模型变换 | 图案尺寸与实际距离一致 | T00核对UV×32与两个场景变换；不能按场景名称缩放 |

保持visual_foam_step.glsl与visuals.gd的生成、平流、衰减、发布节奏。当前默认lifetime=1.8s、source_gain=25仅是基线值，实际启动参数需要记录。本轮不引入15Hz跳步，不修改水沙权威分辨率、源项、动量或账本。

暂停编辑可能更新床面而不推进历史时钟：水深/床面遮罩必须防止旧泡沫露到干沙上，不能为此偷偷推进模拟或新增墙钟衰减。

## C02 材质参数、资源与退回路径

沿用现有参数服务，不新增HTTP API、数据库或业务请求。以下是正式shader接口及静态场景选定值。

| 字段 | 类型 | 正式有效值/范围 | 作用与消费 |
|---|---|---|---|
| foam_detail_mode | int | 0：现有；1：新方案 | 候选切换；最终正式默认1，0用于诊断退回 |
| foam_detail_texture | sampler2D | mode1必填，自建512² RGBA8纹理 | 线性数据，正式shader仅读R覆盖纹样；G保存生成变化但不参与当前相位；9额外mip、repeat |
| foam_detail_scale_per_m | float | G1选定1，范围0.5–12 | 图案空间尺度，cycles/m |
| foam_hole_strength | float | G1选定1，范围0–1 | 纹样对覆盖阈值的影响 |
| foam_flow_cycle_s | float | 4，范围0.5–8 | 双相位重置周期，秒 |
| foam_flow_gain | float | 1，范围0–2 | 视觉输运比例，0冻结空间位移用于对照 |
| foam_flow_speed_cap_m_s | float | 2，范围0–4 | 视觉位移上限；只截断表现速度 |
| foam_flow_debug | bool | false | 任务夹具灰度诊断；正式关闭，不暴露产品参数 |
| natural_main_foam_gain | 既有float | 沿用场景有效值及catalog范围 | 兼容已有“水面白沫强度”，不要重复新增强度项 |
| foam_tint / natural_foam_direct_fraction | 既有材质字段 | 记录现有值后校准 | 颜色及受光分配，统一覆盖输入 |

产品参数窗口新增“泡沫纹样密度、泡沫破碎程度、泡沫流动周期”三项；模式与速度限幅作为材质诊断配置。值校验沿用现有有限数/范围/类型规则；非法输入返回已有参数校验错误，不修改状态。新模式关闭时相关参数标记不可用，不能恢复PrototypeFrontFoamDense。

素材使用本项目自建、可复现的离线生成图或许可明确的自有资源。建议从512² RG8+完整mip起步；核对Godot实际导入格式，不能以PNG磁盘大小当显存。正式图和生成说明进入assets/water_foam，绝不依赖test_output或未知许可外部图片。

资源未绑定或导入不可用时，在正式初始化校验中给出明确错误/诊断并保留现有路径；不得采样空白默认纹理导致全水面发白，也不得静默宣称新方案生效。如何复用已有错误通道在T00冻结，不新建无消费者错误API。

T00接入决策（接口待G0整体冻结）：新模式资源校验放在已有`Presentation.material_plan()`的材质检查路径，使用其`error: StringName`返回值，由正式入口现有`_fail()`呈现诊断并停止错误初始化。候选资源缺失不能静默当作成功；模式0仍保留现有材质算法和无新纹理依赖的诊断回退。模式1仅接受实际绑定的Texture2D及有效尺寸。纹理使用项目离线程序生成的512²线性数据；不调用外部竞品素材。固定流速夹具只在任务探针中覆盖只读材质输入，正式发布链保持原样。

场景变更同步对应manifest的真实shader/scene/资源身份，保留严格校验。模式0只回退表现，不保证绕过旧检查点的来源校验。

## C03 形态、流动、合成与岸脚

1. 历史场决定泡沫存在和覆盖，纹理阈值决定孔洞与碎边；强度0必须没有历史泡沫。已有独立前缘/接触贡献明确归因，不借噪声在清水里凭空造泡沫。
2. 同一像素的最终水面覆盖计算一次，混色、alpha、泡沫直射分量与glint抑制共享结果。检查prototype_whitewater与prototype_apply_whitewater调用链，不预设编译器是否已经消除重复。
3. 双相位a=fract(t/P)，b=fract(t/P+0.5)；每相位只做有界的局部流动，重置时该相位权重为0，两权重和为1。速度单位、周期与纹理尺度显式换算；不持续使用velocity×累计时间造成长时拉伸。
4. 两相位接缝用纹理自身的固定扰动打散时，必须验证其导数、边缘和重复周期。使用mip与导数抗锯齿；远景淡化细碎结构而非加锐化维持白噪点。
5. 接入已有EMISSION/ALBEDO分配和light()。泡沫应降低清水镜面尖峰并保留环境/直射响应，不仅设置可能无效的ROUGHNESS；不重写整个反射、折射或沙底亮纹系统。
6. 岸脚以同代水深和可见表面为界，静水不因浅就持续发白；上岸/退浪有不连续、带宽变化的接触，不出现永久等宽白圈。
7. 接触遮罩与主水面叠加不足时，仅做必要的材质协调。原5×5邻域成本先测，本轮不新增接触RT、compute、调度或恢复字段。

## C04 正式入口、状态与兼容性

- 两个正式表现场景静态绑定新纹理和有效参数；直接启动、捕图、性能探针均消费这套配置。探针不得私自绑定正式入口没有的纹理来制造效果。
- 候选对照阶段保留可关闭分支；最终默认开启通过验收的配置，小白点节点继续visible=false。
- 实时、冻结、暂停、恢复、场景重进使用完成态时间。暂停期间相机固定且无编辑时泡沫图案稳定；恢复同版本检查点时相位来自恢复时钟，不出现墙钟跳变。
- 不改当前检查点格式/历史布局；同版本保存与恢复必须通过。修改来源身份可能让旧版本存档按现有规则拒绝；保留错误语义，不承诺跨版本可读，不绕过身份验证。
- 同初态、同输入、同完成tick的权威水沙/动量/账本输出应与基线一致；同硬件同后端优先比较字节。若存在既有非确定性，先量化A/A差异并按已有数值契约处理，不通过新增宽容阈值掩盖物理变化。
- 正式PCK在项目外验证新纹理、导入资源与原始来源字节，退出/切换无新增RID或节点泄漏。

## C05 性能预算与判定

### 优化时间硬上限

用户确定：本轮性能优化累计最多30分钟（1800秒），不属于待G0调整的预算。

- 起点：首次专门为改善性能进行瓶颈诊断、调参或代码优化。即使提前在T01–T04发生，也计入同一个总预算。
- 计入：诊断、代码/参数修改、编译、工具与GPU等待、优化候选复测、失败重试及相关视觉复验，按实际墙钟耗时累计。切换方案、场景、分辨率或执行轮次不清零；中断前保存已用时，恢复后只使用剩余时间。
- 不计入：首次建立基线与初始成本验收、停止优化后的只读最终验收/长稳、必要的回退与报告整理。上述阶段不能继续优化或以重复采样选择更好结果；一旦继续诊断调优就必须计入剩余预算。
- 运行优化探针前检查剩余时间并设置相应超时；到期不再发起优化动作，安全终止尚未完成的优化探针并保留已有输出，不为凑齐样本延长。
- 达标可提前停止；到期仍未达标，停止调优并报告最佳候选、基线/候选实测、已用时间、剩余瓶颈。仅保留已验证可用的候选，未完成验证的修改回退；没有可用候选则恢复基线。
- 时间耗尽不等于性能通过。未达指标记[需返工]，缺有效数据记未测；G5不得标为通过，也不得借后续返工自动重开30分钟。继续完成不涉及调优的必要验收和交付说明。

执行状态记录budget_s=1800、used_s、remaining_s、首次开始时间、每段起止时间与停止原因（达标/时限/无需优化）。当前尚未执行，used_s=0。

### 耗时与资源指标

以下为冻结的验收上限，不是实测；不得在候选失败后放宽。计时能力与A/A稳定性仍须有实际有效样本。

| 指标 | 1280×720 | 1920×1080 |
|---|---:|---:|
| 完整场景GPU渲染P50增量 | ≤0.5ms | ≤0.8ms |
| 完整场景GPU渲染P95增量 | ≤1.0ms | ≤1.5ms |
| 完整帧P95增量 | ≤max(1ms，基线P95×5%) | 同左 |
| 完成模拟时间/墙钟时间 | 不低于基线97% | 同左 |

增量是候选统计量减基线统计量，不将不同帧样本强行配对，也不相加各分段P95。帧时间/GPU渲染/模拟吞吐分别报告；现有完整负载若未达到60FPS，报告基线与候选，不能用低增量冒称达标60FPS。

结构预算：新增大面积透明draw=0；新增历史RT/compute dispatch=0；每个有效水片元新增细节采样≤4次、默认目标2次；新纹理含mip裸显存≤2MiB。额外水深/动量/遮罩采样也要列入总成本，不能只报细节图读取。

测量：GTX 1050、当前正式引擎/渲染后端、真实可见窗口与完整负载；固定分辨率、相机、质量、VSync、频率与有效配置。每个配置预热10s、记录30s，按A-B-B-A顺序做两对对照。两个场景、两个分辨率分别测。固定完成态用于渲染隔离，真实运行用于总帧与吞吐；性能运行期间不录像/截图/同步回读。

先做A/A稳定性检查。无有效GPU计时、后台负载导致波动超过预算、样本不足或温度/频率漂移，均为成本证据无效。记录原因再修复测量，不反复抽样挑最好结果。正式VSync开关状态需保留；为解除帧上限做的VSync关闭诊断单独标注。
