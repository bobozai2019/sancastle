# Water foam detail

`foam_detail.png` is statically bound by both formal water scenes. It is an
original procedural periodic 512×512 RGBA data texture, generated by
`python tools/water_foam/build_organic_texture.py`, using no third-party image.
R contains warped, irregular cellular edges with broken connections; G stores
periodic variation. The active shader reads R as linear data, with repeat and
explicit base-UV derivatives for mip selection. PNG colors represent data,
not the rendered foam color.

The imported format is RGBA8 with nine additional mip levels, totaling
1,398,100 raw bytes. The source PNG SHA256 is
`05c18a800db479f3e2a2568867051d29a3438d2cd7225830e000e8598935e50b`.
The PNG and its `.import` configuration are runtime resources.

The formal water shader combines detail with existing foam history R. It derives
bounded visual velocity from completed-state water depth and momentum, blends
two offset flow phases, and shares coverage between color, alpha, direct foam
lighting and glint attenuation. Its phase clock is completed simulation time.
Defaults: mode 1, density 1 cycle/m, hole strength 1, cycle 4 s, flow gain 1,
speed cap 2 m/s. Mode 0 retains the legacy material path. No history writer,
physical input or checkpoint format is changed by these resources.

`foam_cells.png`, `foam_cells_organic.png`, `static_candidate.gdshader` and
`flow_candidate.gdshader` preserve reproducible comparison resources. The
regular-cell texture is not the formal binding. Generation metadata records
candidate derivation; final resource identity and selected values are stored
separately in the task evidence.
