# 实施与验证细则

本文件为计划；实际进度统一写入[执行状态](../执行状态.md)，原始结果写入[验收目录](../验收/README.md)。执行者均为单主执行者，无并行修改窗口。

## T01 基线与契约冻结

依赖：无。交付：两个正式入口的源/配置索引、确定性对照输入、冻结契约。

允许修改：本任务目录、针对性探针。禁止修改：正式运行行为、既有竞品证据和历史失败结果。

- G01：记录当前 dirty 工作树相关文件 hash、启动参数、硬件/后端、固定相机/seed/profile；核对已有诊断与当前源码的差异。
- G02：核实成功 tick 实际 dt、tail recorder 次数、编辑/发布先后及拒绝分支；核定无额外床面纹理能否安全完成比较。
- G03：确认 v6 严格 schema 和已知来源迁移边界，冻结 profile/API/存档契约；准备基线 checkpoint 和对照命令。

验收：G0。无法确认的时序须通过小探针区分候选解释，不能靠沿用旧 PASS 放行。

## T02 历史与完成态

依赖：T01。交付：三个 R32F 资源、湿润/干燥 kernel、提交/发布和编辑刷新。

允许修改：契约所列 visual 模块、共享 finish/publish、必要 views/配置入口与探针。禁止修改：权威物理公式、native3 字段布局、数值/账本语义。

- G01：实现 profile 验证、初始化、资源归属及退场清理；关闭泡沫/碎石/植被后湿痕单独可用。
- G02：实现单次成功 tick 更新、成功提交、完成态发布与失败丢弃；处理裸底和域边界。
- G03：实现编辑床面变化重置，检查暂停/冻结不计墙钟时间；执行 V1、V4 的低层部分。

验收：公式边界、时间步一致性、负例、拒绝任务后 committed/published 不变；正式视觉效果仍需 T03。

## T03 材质与正式入口

依赖：T02。交付：两个入口的材质绑定和默认配置、参数页、单变量图像/连续片段。

允许修改：沙 shader、两个正式 presentation 场景与 manifest、参数 catalog/schema/service 与生成器、显示绑定。禁止修改：无关材质/水波算法、重建静态 UI、无依据提高网格分辨率。

- G01：替换原湿色权重为新状态完整混合；保留色端点、几何与其他颜色链，校验开关和无裸岩染色。
- G02：固化两个场景与配置，加入必要参数并生成窗口；真实直接启动与测试入口读同一配置。
- G03：完成 V2、V3、V7 的短运行；固定状态对照颜色强度，再连续观察退水过程，必要时每次只调一个参数。

验收：G1。更新 shader hash 后执行既有 presentation hash 校验；水侧几何 manifest 通过其正式生成器更新和检查，不绕过 guard。

## T04 存档与生命周期

依赖：T03。交付：v7 容器、新扩展精确捕获/恢复、受控 v6 迁移与负例报告。

允许修改：checkpoint codec/router/capture、restore verifier、来源注册、有关配置 hash 与针对性测试。禁止修改：历史旧文件、未获证来源的白名单泛化、原权威数据数值。

- G01：增加严格扩展 schema、显式读回大小、发布态一致性验证；保存 committed，恢复三态一致。
- G02：保留旧格式校验并实现已知来源迁移；记录丢失旧湿痕历史的真实限制，不放宽来源签名。
- G03：执行 V4、V5、V6；在同一完成态保存/恢复、换场景、取消/失败和重复初始化后验证生命周期。

验收：G2。物理字段、material、控制物理部分和账本相同；仅新扩展及明确迁移元数据可不同。

## T05 成本与交付

依赖：T04。交付：完整负载成本对照、稳定性记录、当前技术文档和有效生成产物。

允许修改：验证工具、本任务证据、涉及本功能的当前文档/生成器；性能修复限本扩展，需重验受影响项。禁止修改：用不同负载/分辨率包装成本、将方案或进度流水混入当前技术文档。

- G01：在可见窗口完成 V8，记录开关状态、实际尺寸、VSync、驱动/后端、实际模拟推进和真实消费 profile；归因新增开销。
- G02：完成 V9 和必要负例；封存代码/资源/profile hash、日志、图像及有时间依据的连续观测。
- G03：同步当前方案/规格/参数页及生成器，确认文档入口与资源 hash 一致；汇总限制，不宣称未执行的验收。

验收：G3。若成本超标，先优化纹理/dispatch/发布；若要切换 R16F，必须验证低速干燥不会停滞并修订契约及预算。
