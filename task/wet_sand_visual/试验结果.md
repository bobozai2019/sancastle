# 合并发布湿痕：效果试验

类型：正式接入前的历史试验记录。当前场景2实现见[正式接入记录](正式接入记录.md)，下文保留原试验范围和结论。

本轮交付为可复跑的效果原型，未修改正式运行源码或默认场景；存档接入、参数页、完整生命周期与正式成本验收尚未完成。试验使用两个正式场景的现有初始化，随后仅在试验进程内替换发布 kernel 和沙面 shader。

## 已观察结果

- 一张 256² R32F 历史，原始数据 262144 bytes。湿痕读写合并进原有 sand/water 发布 dispatch，没有增加独立更新 dispatch。
- 两场景均运行到约 36 模拟秒，按 0/3/6/10/16/24/36 秒目标记录完整场状态与图片；未出现脚本/shader 错误，结束时无孤儿节点。
- 每次冻结完成态后分别捕捉试验材质和原材质。图中水沙几何、相机和模拟状态相同；试验材质替换干湿混合权重，保留现有颜色端点与颗粒。
- 先干、曾在采样时被水覆盖、当前露出的沙格：主场景约24秒时1386格，物理湿度中位约0.0501，新历史中位约0.7922；几何场景3095格，分别约0.0671和0.8244。说明物理湿度降低后仍有独立湿色记忆。各时刻格群不同且可能再次覆水，不能用这些中位数反推固定干燥时长。
- 全部采样历史值有限且位于[0,1]；冻结等待2秒，历史原始字节完全一致。所有捕获的物理湿度与已发布湿度保持一致。

## 初步成本

GTX 1050、D3D12、1280×720、VSync关闭、窗口始终有焦点，编辑器仍开着。主场景进行 ABBA 开关，各段预热2秒、采样6秒，冻结和实时分别采样。该短测不替代方案要求的正式成本验证。

| 模式/顺序 | 帧间隔中位 ms | viewport GPU中位 ms | 完成tick/s |
|---|---:|---:|---:|
| 冻结 A1 原材质 | 16.96 | 14.49 | 0 |
| 冻结 B1 湿痕 | 16.85 | 14.39 | 0 |
| 冻结 B2 湿痕 | 16.76 | 14.34 | 0 |

| 实时 B1 湿痕发布/材质 | 35.07 | 14.52 | 29.89 |
| 实时 B2 湿痕发布/材质 | 30.77 | 13.92 | 30.13 |

冻结图像没有测出明确的新增着色成本，不宣称湿痕使渲染变快。实时 A 自身前后差异很大，B 位于其波动范围内，水面状态和CFL负载在变化；viewport GPU计时不包含所有独立计算，不能由该列推断完整模拟成本。这轮实时结果不确定，不能确认≤0.3ms或≤3%的预算。

## 可复验与边界

原始结果与命令见[index.json](evidence/trial/index.json)，包含执行脚本、试验kernel的hash、实际配置、捕获字段与图片hash。正式配置中的源码索引没有包含试验替换，因此额外单独记录了实际试验源码及材质源码hash。索引核查的正式源码没有漂移。

运行 `trial_probe.gd` 可复现两场景效果；`cost_probe.gd` 为短期成本观察。`seal_trial.py` 把必要证据从临时输出封存到本任务目录。原始捕获、失败/检查状态均保留，不把 probe PASS 当成全功能验收。

未覆盖：独立无再覆水的完整30秒干燥曲线、编辑重置负例、所有失败/恢复路径、独立基线完整物理字节对照、存档新格式与迁移、两个场景代表性总成本。当前算法存在可见格点轮廓，后续应在同一固定状态评估，不以增加噪声掩盖输入精度。
