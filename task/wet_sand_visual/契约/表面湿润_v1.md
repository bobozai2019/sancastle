# 表面湿润 v1 契约

状态：draft。本文规定拟实现行为，不描述当前已经生效的实现。实现前在 G0 核对接口和提交时序后冻结。

## 数据与权限

`surface_wetness` 记作 M，为 [0,1] 的表面外观记忆，无量纲，不是水体积、物理湿度或可搬运沙层含水量。采用 256×256、单通道 R32_SFLOAT，小端 float32；对应当前域 0.125 m 格点及现有场景坐标映射。

| 字段/资源 | 读者 | 写者 | 约束 |
|---|---|---|---|
| `water`、`sand`、`rock` | 湿痕计算 | 既有权威流程 | 本扩展只读，不加入水量/沙量账本 |
| `wetness`、`compaction`、动量、material、源汇 | 既有消费者 | 既有物理流程 | 不因湿痕改变算法、数值或 ABI |
| `wet_committed` | 湿痕更新、捕获 | 成功提交分支 | 有限且位于 [0,1] |
| `wet_candidate` | 成功提交分支 | 更新 kernel | 临时态，失败不得发布或写回 committed |
| `surface_wetness` 发布纹理 | 沙面 shader、只读探针 | 统一发布阶段 | 与可见 sand/water/clock 共用完成态身份 |

所有 RID 由已有 Water 生命周期 owner 管理。扩展不开第二个 frame pump、不增加独立工作队列、不在渲染帧回调里推进历史。

## Profile 与公式

启动时冻结 `effects.surface_wetness_enabled`（默认 true）与 `environment.surface_wetness_profile`；规范序列化后参与 configuration/source hash。未知字段、非有限数、越界与反向阈值均报错。

| Profile 字段 | 类型/单位 | 初值 | 允许值 |
|---|---|---:|---|
| `version` | int | 1 | 必须等于 1 |
| `contact_on_m` | float / m | 0.001 | 0…0.01，严格小于 contact_full_m |
| `contact_full_m` | float / m | 0.003 | (contact_on_m, 0.05] |
| `fill_time_s` | float / 模拟秒 | 0.75 | 0.1…10 |
| `dry_time_s` | float / 模拟秒 | 30 | 1…300 |
| `full_wet_at` | float / 无量纲 | 0.4 | 0.1…1 |
| `surface_reset_m` | float / m | 0.005 | 0.001…0.05 |
| `sand_min_m` | float / m | 0.02 | v1 固定，与裸底阈值核对后冻结 |

使用实际完成态水深 h，不增加水深偏置。接触强度 q 与历史更新：

```text
q = smoothstep(contact_on_m, contact_full_m, max(h, 0))
若 sand <= sand_min_m：M_next = 0
否则若 q > 0：       M_next = min(1, M_base + dt * q / fill_time_s)
否则：              M_next = max(0, M_base - dt / dry_time_s)
wet_weight = smoothstep(0, full_wet_at, M_next)
```

dt 只取成功 tick 的实际累计推进时长，沿用 `async_d[3]`；不得取请求 dt、墙钟或渲染帧间隔。一次 accepted tick 更新一次，不能在子步和 tick 末尾重复计时。G0 必须验证本项目当前 tail recorder 的实际调用位置和成功判据。

充分接触时，从 M=0 到全湿颜色为 `fill_time_s × full_wet_at = 0.3 s`，到 M=1 为 0.75 s。充分浸润后完全无接触，18 s 后开始褪色，30 s 后 M=0；从 M=0.4 开始则 12 s 后归零。这是该线性历史与颜色阈值的设计结果，均不是竞品实测时间。

不做横向扩散、噪声抖动或时间随机化。渲染时对发布态做线性过滤，避免格点边界；边界寻址 clamp，域外不扩散湿痕。算法按 tick 末接触采样，不保证捕获完全发生在同一 tick 内的瞬时覆水，V1 必须覆盖最薄、最短的正常上岸水流；若发生漏记，先测明再决定是否读取现有子步接触峰值。

## 初始化、表面编辑与时间

新场景用 `M_seed = full_wet_at × q` 初始化已有水覆盖的沙面，其余为 0；裸底为 0。所有三张纹理一致，发布后才允许表现消费者读取。

床面 B 使用同一 rock+sand 定义与域映射。每次成功工作中，比较旧发布沙厚与本次完成沙厚得到床面变化；无变化时 `M_base=M`，变化绝对值超过 `surface_reset_m` 时 `M_base=M_seed`。该规则同时覆盖编辑与模拟导致的床面明显改变，不依赖泡沫历史。

对编辑工作只重置受影响格，**不推进湿润/干燥时间**；未改动格保留原历史。比较发生在旧 published_sand 被替换前，结果只在本次成功时提交。G0 若发现该读取时点不能安全提供旧完整态，必须先修订契约和内存预算，不偷读未完成态。阈值按每次完成工作判断，不声称检测多个小改动累计或同高表层材料替换。

湿痕附着于表面位置，不随被搬运沙粒迁移。新暴露干面可变干；新面已有水则立即获得接触种子。这是首版表现规则，不是分层含水模拟。

| 模式 | 历史行为 | 发布/恢复 |
|---|---|---|
| 正常模拟 | 按成功 dt 推进 | 与同一完成态 sand/water 发布 |
| 暂停、冻结、零推进 | 不推进；仅成功编辑可重置变动格 | 保留历史；墙钟等待不改变颜色 |
| 拒绝/失败工作 | candidate 作废 | committed 和 published 不变 |
| 新场景/换域 | 按新域初始化 | 不沿用旧域湿痕 |
| 新格式恢复 | 恢复已存 M | 验证通过前不接收新工作 |
| 旧格式迁移 | 仅按已知水深重新播种 | 不伪造已丢失的退水历史 |
| 开关关闭 | 不分配、不调度历史资源 | shader 使用干色分支；其他物理输入照常工作 |
| 泡沫/碎石/植被均关闭，仅湿痕开启 | 正常分配、推进 | 不得被 visuals.enabled 的旧条件提前返回 |

## 本地接口与错误

接口名称为拟定名称；G0 可以按现有命名约定调整，但字段及行为需保持明确。

| 调用/输出 | 输入 | 结果与失败行为 |
|---|---|---|
| `validate_profile(profile)` | 上表严格字段对象 | 空错误表示合法；非法返回 `invalid_surface_wetness_profile`，不创建资源 |
| `initialize(water, config, domain, restored)` | owner、冻结配置、域、可选已校验状态 | bool + last_error；分配失败 `surface_wetness_allocation`，编译失败 `surface_wetness_compile`；沿用初始化失败清理 |
| `record_tick()` / `record_edit()` | 已绑定的水/床面、控制、候选与提交态 | 只向同一 RD 流记录；tick 用成功实际 dt，edit 无时间推进 |
| `publish()` | committed + 成功控制 | 绑定名 `surface_wetness`；使用已有 generation/state_seq/tick/revision 标识，不另设外观时钟 |
| `checkpoint_record(raw, identity)` | 捕获完成态字节与身份 | 严格 wet_sand_v1 字段；字节数或发布态不匹配则拒绝保存 |
| `restore_verify(...)` | 校验后的扩展记录 | committed/published 与预期逐字节一致；失败沿用统一恢复屏障 |

扩展初始失败不能静默降级并报告成功。capture 目前依据名称猜纹理字节数的逻辑必须改成显式格式/尺寸描述；不可将新增 R32F 湿痕按 RG32F 读取。

## 沙面材质与调节

新增 `surface_wetness_state`，线性过滤并 clamp，保留已有 `sand_state` 线性过滤和精确几何取样。`use_wet_finish` 为 false 或功能关闭时权重为 0；切换着色开关不清空正在运行的历史。

```text
w = use_wet_finish ? wet_weight * wet_color_strength : 0
base_color = mix(sand_dry_color, sand_wet_color, clamp(w, 0, 1))
```

`wet_color_strength` 初值 1、范围 [0,1]。保持已有压实色、裸底混合、颗粒和受光链的顺序；替换原湿色因子而非叠加第二次压暗。首版不调整 roughness/specular/法线链，不把禁用镜面时的参数变化当成已实现高光。

参数窗口复用已有沙参数页，实时开放“湿色强度”与已有干/湿颜色；“湿润速度”“干燥时间”映射到冻结 profile，提示重启生效。技术阈值留在 profile，不增设面向用户的底层资源控件。启动、普通游玩、捕图、性能探针均消费同一实际配置。

## 存档与兼容

新容器建议使用 `SANDUE07` / version 7，保留 native version 3 的原权威物理字节布局与既有扩展。**不向严格 v6 白名单直接塞字段。** 保存 v6 严格解码/校验能力，经来源签名核对和明确迁移再构造 v7；既有数值配置迁移路径仍须保留。

`visual_extensions.wet_sand_v1` 关闭时严格为 `{version:1, enabled:false}`；开启时严格字段如下：

| 字段 | 类型与校验 |
|---|---|
| `version`, `enabled` | 1、true |
| `domain_id` | 必须匹配所恢复域 |
| `width`, `height`, `format` | 256、256、`R32_SFLOAT_LE` |
| `profile_id`, `profile_sha256`, `profile_values` | 稳定标识、规范化 hash、上表 profile；必须与恢复配置一致 |
| `tick`, `revision`, `source_generation` | 与保存时完成态一致；恢复 generation 按既有规则重新分配 |
| `state` | 262144 bytes；全部 float 有限且 [0,1] |

仅保存 committed，candidate 恢复时复制它；published 同值恢复。复用容器完整性校验、尺寸上限和严格字段白名单，不放宽未知来源或错误 profile 的接受范围。

v6 及既有支持的更早来源迁移：先通过原格式/来源校验，保留物理 raw 与账本，使用目标 profile 和实际保存水深生成 M_seed，并写入明确的“旧文件无湿痕历史”迁移来源信息。旧档可恢复已知状态，但旧退水湿痕无法精确恢复；不伪称无损。未注册来源仍拒绝。新格式不要求旧版本程序反向读取。
