# 低开销湿沙候选

类型：draft / 方案比较；没有修改正式运行代码，没有实测新增帧耗时。本结论来自当前项目源码，不新增竞品实现结论。

## 推荐：保持公式，合并到成功发布阶段

原方案为独立更新 + committed/candidate/published 三张 256² R32F。湿痕公式逐格计算，无邻格扩散，可以考虑在整项工作成功之后直接更新一张历史纹理，供沙面读取。

| 方案 | 可达到的表现 | 新增原始纹理数据 | 主要代价/限制 |
|---|---|---:|---|
| A 仅重映射现有物理湿度 | 上水更暗，沿现有物理湿度留下短暂痕迹 | 0 | 几次着色算术；无法独立控制长时间退水湿痕，物理湿度归底后历史信息已丢失 |
| B 合并发布、单张历史（推荐候选） | 目标为保持原方案的快速变湿、30 s 干燥与编辑规则 | 0.25 MiB | 现有发布 pass 增加逐格读写和计算；沙面多一次纹理采样；需验证同队列资源同步与状态一致性 |
| C 独立更新、三态历史（原基线） | 同上 | 0.75 MiB | 独立更新 dispatch，候选写回、发布复制和更多资源 |

0.25 / 0.75 MiB 是纹理有效数据字节估算，不是实际驱动显存；纹理减少不等于整帧耗时同比下降。B 仍有实际计算与带宽成本，不能称为零开销。

## 当前源码支持的接入点

- `transport.gd::submit()`：先记录工作，再 `work_seal`，最后执行 `after_seal`。
- `pipeline.gd::_finish_work()`：统一发布 sand/water、views 与 visuals。
- `publish.glsl`：已遍历 65536 格，读取本次完成的 sand/water，并在 `control[1]!=0` 时返回。
- `work_begin.glsl`：每项工作清零 `control[9]`，编辑不推进时间；`work_seal.glsl` 把此字段作为 actual_dt 返回。
- `scripts/simulation/edit_validation/frame_pipeline/async_sim_finish.glsl`：把成功水 tick 的实际 dt 写入 control 字段。实施时沿实际编译替换结果复核偏移与来源。

因此，新增历史计算不必天然拥有一个独立的模拟前候选阶段。它可以在已有失败判定结束后作为表现发布的一部分执行；不修改权威水沙、账本或成功判据。

## 候选数据流

```text
原有水沙计算 / 编辑 → 既有校验与提交 → work_seal
    → 原有 publish：
        成功控制检查
        读取本格 old visible_sand、完成 sand/water、旧 M
        按床面变化决定是否重置 M
        使用本项 actual_dt 推进湿润/干燥（编辑为 0）
        写回本格 M；发布本格 sand/water
    → 既有消费者发布与渲染
```

M 为单张 256² R32F，由统一发布阶段唯一写入；材质只读。每个 invocation 只读写自己的 M，更新阶段不做线性过滤或邻格读取；材质采样仍可线性过滤。裸底、初始化、颜色公式、时间参数及新旧存档语义沿用原方案。

旧 visible_sand 必须在同一格覆盖前读取，因而无需另存床面历史。M 应归属既有 owner，发布函数借用它，禁止为节省 pass 引入新的资源归属或销毁时序。新存档保存单张 M，恢复它并验证；无需再复制候选与发布纹理。若异步消费者确实要求历史私有态和发布态分离，则退回两张纹理约 0.5 MiB，仍可保留计算合并。

## 实施前验证与对照要求

1. 确认每项工作只更新一次：成功水 tick 使用实际 dt；编辑、装饰命令与暂停 dt=0。失败不更新；读回失败后的未知结果不得重放造成重复干燥。
2. 检查所有正式数值后端均正确填写 actual_dt；不能用请求 dt 替代。新场景和恢复直接初始化历史，不假造一次模拟更新。
3. 复核 RenderingDevice 队列、存储写入到材质采样的同步和存档捕获屏障。单张纹理不能暴露半幅新历史，也不能和不同 generation 的床面一起读取。
4. 同一输入与 dt 序列，比较 C 参考公式和 B 的 M 原始结果；相同运算顺序争取逐字节一致，差异须定位，不直接称为表现等价。再执行两个正式场景的固定状态截图和连续退水观察。
5. 保留原方案生命周期、存档、物理不变和真实可见窗口成本验收。分别报告 dispatch 数、纹理数据量和实测帧耗时，不以结构简化代替性能测量。

以上通过后，把总纲、表面湿润契约、T02/T04 细则和成本预算统一改为 B，再冻结实施边界；当前仍为未开始的候选。

## 其他减负方式的取舍

直接用现有 wetness 的 `smoothstep` 替换 `wetness×0.65` 最便宜，但只能改善响应强度。它无法区分“刚退水后物理湿度已经降低”和“一直干燥”这两类状态，不能承诺与独立历史一样的持续湿带；调慢物理湿度干燥还会改变压实/塌落语义。

128² 历史或降频更新可作为后续成本档位，但会使窄水沟、短时掠水或岸线边缘更难保留；若用多次采样补偿，计算也不按格数简单缩减为四分之一。首选 B，在同精度、同公式下先消除独立调度和多余复制。
