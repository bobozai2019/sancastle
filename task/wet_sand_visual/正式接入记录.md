# 场景2正式接入记录

范围：用户指定仅场景2。正式实现与字段定义见[沙面湿痕](../../docs/沙面湿痕.md)；早期两场景原型和三态方案不代表本轮交付范围。

## 实现与架构审阅

- 两个test1_geometry playable入口固化启用开关，原presentation沙材质固化启用标志，manifest声明动态采样器。main未启用、未分配历史，保持原颜色响应和v6存档。
- State在初始化时创建单张R32F历史，所有权沿既有RD资源列表；Views只读绑定，在现有解绑与最后读者证明完成后释放。不建立独立调度器或frame pump。
- `publish_wet_sand.glsl`读取本格完成sand/water、旧visible_sand及M，仅写M、原visible_sand/visible_water与原stamp。权威sand/water声明readonly。成功guard、stamp映射与旧发布保持；每格一对一读写，没有跨格竞争或半成品邻域读取。
- control[9]由既有工作开始清零，由成功水tick结束填实际dt；编辑/显示不推进历史时间。surface重置只比较同一格可见沙厚，rock为不可变底层。
- v7扩展独立于native3，仅启用湿痕时需要。严格字段、字节数、单位范围、域、profile和完成身份验证；容器magic与payload version必须对应。原v6白名单未被直接放宽成任意扩展。
- 捕获在已有屏障内登记262144字节读回，恢复候选对历史逐字节验证后才切换。不会由source文件中的任意参数注入shader或执行器。
- 旧文件仍受完整来源登记约束；本轮没有增加任意旧v6到新配置的自动迁移。已存在的受控legacy投影按水深生成新种子并记录历史缺失。

上述语义审阅对应architecture_policy中本轮资源和敏感方法更新，不使用全量自动刷新方式抹掉其他工作的指纹差异。前后源码位于`evidence/scene2_integration/before/`，当前归档索引记录实际消费的源码hash。

## 验证范围

专项探针 `tests/integration/surface_wetness_scene2_probe.gd` 从普通正式场景启动，不注入或替换运行shader。场景2覆盖手动波与正常模拟到24秒、多个关键帧、暂停、编辑、保存、恢复、再保存、严格扩展负例和资源释放；main验证不开启湿痕、v6保存恢复和权威字段一致。

失败日志保留：geometry_v1的正式wrapper漏设开关导致unknown_view_field，已补齐；main_v1再次保存时未等恢复完成，main_v2的CPU读取未覆盖参数返回null被错误判成启用差异，main_v3测试代码错误调用bool(null)。后续探针等待恢复完成，使用`value==true`识别显式启用。上述失败属于接入或测试发现的问题，不改写原报告。

geometry_v3另有一次初始化等待90秒超时，未输出明确运行错误，关闭过程也未完成后终止了该测试进程。增加初始化状态日志后geometry_v4正常启动；该次超时原因仍未知，不标成已修复，也不据一次未复现宣称长期稳定性通过。

最终geometry_v4与main_v4专项结果均通过，消费源码与当前磁盘无漂移。最新专项结果、命令、源码身份和文件hash见[index.json](evidence/scene2_integration/index.json)。运行PASS只覆盖上述专项，不等于长期性能或全量故障注入通过。
