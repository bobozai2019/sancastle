# 碎石数据与更新契约

状态：frozen_v1（2026-10-15，G0）。负责人：主执行者；T00/G0冻结。以下均为Godot适配。

## 1. 状态与profile

| 字段 | 类型/布局 | 单位/约束 |
|---|---|---|
| particle_id | INSTANCE_ID / texel线性索引 | 0≤ID<count；整个生命周期不重排、不在搁浅时删除 |
| state[2] | RGBA32F、64×ceil(capacity/64)的ping-pong纹理 | texel=(domain-local x,y,z,wet_state)；wet_state严格为0或1；全部值有限 |
| current_index | int | 0/1；更新成功后切换，未完成纹理不得发布 |
| count/capacity | int | 候选默认512/1024；0≤count≤capacity；无效texel写确定零值 |
| seed | uint32 | 固定profile输入；响应/半径/色差/朝向由ID+seed确定，不用墙钟随机 |
| generation | int | 跟所属世界；异步回调必须匹配活动generation/请求身份 |
| completed_tick / revision | int | 对应输入完成态；分别区别时间推进与无tick的编辑发布 |
| transform | Transform3D | 统一domain-local↔world；不得另猜海滩中心/缩放 |

profile保存schema_version、count/capacity/seed、spawn_bounds_xz、radius_min/max_m、response_min/max、h_on/off_m、speed_on/off_m_s、h_epsilon_m、speed_cap_m_s、max_step_cell_fraction、max_microsteps及mesh/material身份。profile和实际消费参数必须进入运行manifest。

冻结v1工程起始值（不是原作常量，尚未声称完成观感调参）：h_on/off=0.012/0.006m；speed_on/off=0.08/0.04m/s；response=0.25–0.65；radius=0.02–0.05m；h_epsilon=0.006m；speed_cap=4m/s；max_step_cell_fraction=0.5，max_microsteps=8。要求on>off≥0，半径/epsilon正值。水深on为off两倍提供明确滞回区间；epsilon等于off使薄水除数有下界。最大正常tick位移0.086667m，0.125m网格最多两个microstep，低于8步上限。观感不足时按单变量证据修订profile及hash，不反写旧验证结果。

profile固定白名单：schema_version=1、count、capacity=1024、seed=57849、spawn_bounds_xz=[min_x,min_z,max_x,max_z]（main初值[-6,-8,6,8]，capture/backwash初值[-10,-6,6,6]）、radius_min_m、radius_max_m、response_min、response_max、h_on_m、h_off_m、speed_on_m_s、speed_off_m_s、h_epsilon_m、speed_cap_m_s、max_step_cell_fraction、max_microsteps、bed_reconstruction（bool）、mesh_path、material_path。profile_id为gravel_v1/<scene_key>，profile_sha256为按上述固定字段顺序输出JSON的UTF-8 SHA256；保存消费值，恢复逐字段与当前profile核对。mesh/material身份另随runtime source signature记录源码hash。布局为初始范围，不声称已完成三场景观感验收。

domain-local水平范围为[-16,16]m，纹理cell坐标=(xz+16)/0.125-0.5，越界cell逐点clamp到[0,255]。GravelLayer与床面采用相同Node3D变换（当前为identity）。水深和q使用四点双线性；床高在bed_reconstruction=true时按当前沙shader的三角划分插值（fx+fz≤1用v00/v10/v01，否则v11/v01/v10）；false时使用与nearest材质相同的cell。此规定替代本草案原来泛称的床高双线性，以避免三角床面悬空。

数值容差提前冻结：单步位置绝对误差≤1e-5m，累计≤1e-4m；常量纹理回读采用float32舍入容差1e-6；干燥/零流/重贴床xz要求字节不变。高dt上限测试按实际受限速度比较，不放宽普通案例误差。RGBA32F 64×16主RD storage/sampling和vertex texelFetch已在G0实测。

初始分布由各布局profile的spawn_bounds确定，覆盖浅水和岸脚；初始化贴当前床，依据当前h设wet_state。保持固定数量，初始落在干区也保留，之后可被浪覆盖；不每帧随机重新发射。

## 2. 输入采样与公式

同一solver完成态的rock、sand、water=h、momentum_x/z=q；网格256×256、cell_size=0.125m为当前基线，初始化从solver读取并校验。纹理坐标、cell中心与双线性边界规则必须与当前可见床高rock+sand一致。

```text
h = max(0, bilinear(water, old_xz))
u = bilinear(q, old_xz) / max(h, h_epsilon)
u = clamp_speed(u, speed_cap)
dry -> wet: h >= h_on
wet -> dry: h <= h_off
speed below speed_off: water displacement = 0
speed above speed_on: water displacement = response(id, seed) * u
between speed_off/on: smooth ramp (stateless; water-depth state supplies hysteresis)
new_xz = domain_clamp(old_xz + displacement_velocity * dt)
new_y = visible_bed(new_xz)  # rock+sand，与显示采样契约一致
```

干状态水平水流项严格为0。仅水面波纹/相位动画不触发搬运；再覆盖但速度为0也不触发搬运。初版没有物理惯性、粒间碰撞、沙床水平速度或坡面滑动项。

允许一个tick内对碎石做小步重采样，以最大位移≤0.5 cell限制跨浅水区跳跃；使用独立microsteps，不改变权威solver子步。根据speed_cap、response_max和dt计算次数；若超过max_microsteps，明确限速并记诊断，禁止丢失时间步却不记录。闭合边界clamp保持ID/数量，不离域消失或自动换粒。

## 3. 时钟/发布

- advance：水沙tick所有子步成功后、显示发布前，输入(target_tick,revision,generation,dt)。每个target_tick至多一次，当前dt=SIM_DELTA；禁止render帧、重复publish或CPU回调再次推进。
- reproject：编辑发布成功后dt=0，仅更新y与wet_state，保留xz/ID；包括暂停挖填。编辑前的中间状态不消费。
- pause/freeze：无tick则无水平移动，不读TIME作为输运时钟。恢复/切场景重置去重元数据到恢复后的tick和新generation。
- publish：碎石、水沙及床基准来自相同generation/完成态；GPU计算/采样的屏障与RD命令顺序在T00验证。不得把CPU命令提交完成称为GPU已执行完成。
- 所有输入水沙纹理只读；开启/关闭碎石，同seed/tick/命令下权威水沙字段和源汇账本逐字节一致。
