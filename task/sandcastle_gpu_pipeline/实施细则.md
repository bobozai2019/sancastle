# 流水线功能实施细则

角色：task_details。所有任务负责人：主执行者 `/root`；单写者串行执行。每任务 4 个小目标；初始均为 [未开始]、0/4、0%，实时状态以[执行状态](执行状态.md)为准。最终32项均完成，逐项证据见[G7索引](验收/G7_功能交付.md)。

共同约束：复用当前工作目录；不创建工程副本；不改竞品数据、历史报告和无关用户修改。每任务只修改列出的职责范围，新增模块放在现有相邻代码目录，不把运行依赖放入 task。完成时报告改动、4 项小目标状态、验证命令/结果、契约变化和证据路径。

| 小目标 | 交付内容 | 初始状态 |
|---|---|---|
| P00.1 | 当前 checkout、差异、引擎身份、实际 profile、入口继承链和资源依赖记录 | [未开始] |
| P00.2 | 普通挖填/模拟/碰撞/存档等待点清单，以及保留/移除/迁移的决定 | [未开始] |
| P00.3 | C01–C07 物理布局、容量、状态机、新旧语义兼容表及 ADR 草案 | [未开始] |
| P00.4 | 最小可见窗口基线和现有探针适配表，G0 报告 | [未开始] |

输入：旧线程计划的合批预览、当前 `scenes/main.tscn`、项目技术契约及本计划总纲。重点核对 `scripts/beach/beach_gpu_entry.gd`、`beach_interaction_entry.gd`、`beach_recovery_entry.gd`、`tests/visual_water_alignment/prototypes/reference_preview.gd` 的真实继承路径；不要把相似的 demo 脚本当作 main。

允许修改：本阶段文档、最小测试探针/观测和拟定 ADR 草案；本任务不先改运行行为。禁止：建立 frozen 工程副本、启动旧正式性能 runner、删除旧数据、增加独立物理线程。

验收：每项旧锁能找到消费者，协议字段具有明确 byte layout 和所有者，三个入口路径可定位，基线错误/未知项如实记录；旧 96 项结果只作参考。证据：`验收/G0_基线与接口.md`。

主要位置：`scripts/simulation/edit_validation/frame_pipeline/{controller,editor,layout}.gd`、`gpu_edit_scheduler.gd`，必要时新增相邻资源池/协议模块。允许补充内部控制 shader 和测试；禁止提前改 main 默认模式或绕过旧工具事务。

验收：V02/V09/V15 中对应 P01 的部分通过；GPU 尚在使用的输入字节不变，重复通知不二次释放，完成后槽可再次使用。证据：`验收/G1_资源与完成状态.md`。

## P02 GPU 合批独立执行和完整发布

依赖：G1。目标：一次上传多笔；每笔独立成功/跳过；后续执行不依赖 CPU 回执和整批回滚。

| 小目标 | 交付内容 | 初始状态 |
|---|---|---|
| P02.1 | 修改 select/capture/control 逻辑，拒绝后继续，GPU 使用真实当前状态 | [未开始] |
| P02.2 | 覆盖沙、水、悬沙、动量、mold/压实全部写点的候选统一提交 | [未开始] |
| P02.3 | 移除普通路径整批 14 份临时备份/restore 和 CPU 结算发布门 | [未开始] |
| P02.4 | 混合成功/拒绝/连续拒绝、后续批次与完整显示状态回归 | [未开始] |

主要位置：`frame_pipeline/{editor,controller,layout}.gd`、`select.glsl`、`capture.glsl`、`gpu_sand_editor.gd`、`scripts/simulation/brushes/brush_material_solver.gd` 及其沙/水/材料候选和提交 shader。

实施：先锁定每个字段首次权威写入位置；若候选阶段存在旁路写入，先改到工作缓冲。每笔结果只影响本笔提交分支，控制流无条件抵达下一笔；不再预设 `revision + index`。保留单 GPU 有序计算，不把多笔体积相加替代笔段顺序。CPU completion 不再调用逐笔精确校验/授权才能开放显示。

验收：V03/V04；在测试 RAM 内比较正常拒绝前后全部相关字段，无副作用；A 成功/B 拒绝/C 成功与按同顺序只执行 A/C 的功能结果一致；B 失败时 C 确有执行证据。普通模式实际资源创建记录中没有每批 14 张全量备份；不能只从调用次数推断所有字段安全。证据：`验收/G2_GPU合批执行.md`。

## P03 GPU 自主 CFL 和水模拟

依赖：G2。目标：水模拟进入同一有序 GPU 工作流，CPU 不为 CFL 或潮汐账本往返等待。

| 小目标 | 交付内容 | 初始状态 |
|---|---|---|
| P03.1 | GPU 全局 CFL 归约、子步参数与有界间接派发 | [未开始] |
| P03.2 | 变动子步数的纹理槽位、状态版本、实际积分时钟完整一致 | [未开始] |
| P03.3 | 侵蚀/材料等关联步长及潮汐源汇处理脱离 CPU 准入门 | [未开始] |
| P03.4 | 奇偶/上限/非法 CFL、暂停和编辑交错模拟验证 | [未开始] |

主要位置：`scripts/simulation/gpu_shallow_solver.gd`、`shaders/simulation/shallow_cfl_tiles.glsl` 及新增归约/参数 shader，实际 main 基类 `reference_preview.gd` 的 `_render_begin_tick/_cfl_ready/_maybe_finish_tick/_render_finish_tick`，关联 erosion/material/foam 调度。

实施：CPU 提前录制有限数量阶段，GPU 通过写入参数和间接组数选取执行；阶段之间使用正确的全局可见性边界。采用 GPU 结束归一的槽位策略，避免 CPU 读取动态 N。潮汐曲线和表现采样使用同一实际完成时钟；必要时预先上传曲线参数/采样表。不得通过固定子步、关水模拟或只把 CPU `await` 删掉来宣称 GPU 自主完成。

验收：V05/V06/V10；覆盖 N=1/2/3/64 和要求超过上限的有限输入；GPU 决策与测试用 CPU 公式比较，但运行主路径不读回求 N。超过上限时实际 dt 缩短且关联时钟一致。持续提交编辑时水模拟完成计数确实增加。证据：`验收/G3_GPU模拟调度.md`。

## P04 异步高度快照和碰撞消费

依赖：G2；执行顺序置于 P03 之后，减少共享状态定义反复修改。目标：碰撞使用真实完成高度，等待快照不阻止 GPU 继续写入。

| 小目标 | 交付内容 | 初始状态 |
|---|---|---|
| P04.1 | 输入保守脏区和模拟地形变化脏区统一管理，pending 与 in-flight 分离 | [未开始] |
| P04.2 | 固定容量不可变高度快照，内容与 GPU state_seq 同步提取 | [未开始] |
| P04.3 | 主线程物理阶段应用、每块版本过滤、相同高度跳过、快照槽满持续记脏 | [未开始] |
| P04.4 | 失败后刷新、跨块/共享边、乱序/旧场景/损坏快照及停手收尾验证 | [未开始] |

主要位置：`scripts/collision/gpu_collision_proxy.gd`、`scripts/simulation/edit_validation/collision_proxy.gd`、`collision_chunk_selection.gd`、`frame_pipeline/controller.gd` 及高度 pack shader。复用已有数据准备 worker；不开展线程数量选型。

实施：先移除“碰撞还没拍下全部区域就禁止后续 GPU 写”的全局依赖，再通过 GPU 提取位置保证快照一致性。槽忙保留 pending；只能合并同块后继请求，不能丢失其他块。回调仅转交结果；实际 shape 更新遵守线程/物理查询规则，不强制每渲染帧跑一次物理。

验收：V07/V08；延迟碰撞消费期间 GPU 继续推进，停止输入/自动模拟后碰撞最终等于最新完成高度，实际射线和共享边通过。无迟到旧高度覆盖，损坏快照不会污染 shape。证据：`验收/G4_异步碰撞.md`。
