# 流水线接口与状态契约

角色：contract。版本：pipeline_v1，2026-10-17。P00 冻结下列物理布局与行为；后续功能证据分别归属 G1–G7，冻结不表示实现通过。本文件不保存测试结果。

## C01 输入与批次

普通自由挖填进入新路径；形状刷子、守恒铲子、投流沙和碎石走受控交接后的原有功能路径。使用现有世界 XZ/米、体积 m³、网格与边界定义。

| Batch 字段 | 逻辑类型 | 约束 |
|---|---|---|
| `protocol_version` | uint32 | 新模式独立版本，不能将不同语义伪装为旧协议 |
| `generation` | uint64 | 当前场景/恢复代次，必须与 GPU 控制块一致 |
| `batch_seq` | uint64 | 同 generation 单调递增，只标识提交顺序 |
| `slot_id` / `lease_id` | uint32 / uint64 | 绑定缓冲槽及本次租约；旧通知不能释放新租约 |
| `command_count` | uint32 | 1..batch_limit；空队列不发空编辑批 |
| `commands` | 固定 stride 数组 | 一次上传，同批顺序不变 |
| `predicted_dirty_chunks` | 有界块集合/bitset | CPU 从笔段扫掠范围、半径和算法邻域保守估计，仅用于请求高度 |

| Command 字段 | 逻辑类型/单位 | 约束 |
|---|---|---|
| `command_id` | uint64 | generation 内严格递增；拒收的编号允许留空 |
| `kind` | uint32 enum | 普通挖/填；其他类型不得混入此批 |
| `start_xz` / `end_xz` | float32×2，m | 有限值，沿用现有坐标映射 |
| `radius_m` / `strength` / `amount_m3` | float32 | 有限、现有允许范围内；无效输入在入队前拒绝 |
| `water_policy` / `shape` / `seed` | uint32 | 保留现有必要语义；同批兼容性由准入器检查 |

普通命令不再携带 CPU 预测的“上一笔必定成功后的 revision”。旧结构若保留该字节位置，GPU 必须在选取本笔时用实际控制块的版本覆盖，且有明确新协议标记；不得只改验证器让不匹配悄悄通过。

批量默认 2、可设 1–64；待处理队列上限先沿用 64；在途批次初始 3 槽。容量独立配置并记录实际值。取队列中到期且类型/策略兼容的连续前缀，保持旧工具边界。每渲染帧至多上传一批，不能在同帧回调里递归清空整个积压队列。容量范围内后续批次可在 CPU 尚未消费前批完成信息时继续提交。

输入入队接口返回 `accepted` / `queue_full` / `invalid_input` / `transition_busy` / `closing`；上传尝试返回 `submitted` / `no_slot` / `empty` / `submit_error`。`no_slot` 只保留队列到下一帧；`queue_full` 拒收新增笔段，不阻塞、不自动扩容。鼠标释放和工具切换属于控制事件，不能随普通笔段一起被丢弃；跨拒收空隙重置笔段起点，避免下一笔暗中补画被丢弃的轨迹。

## C02 版本、完成通知与所有权

| 字段/对象 | 唯一推进者 | 语义 |
|---|---|---|
| `command_id` / `batch_seq` | CPU 调度器 | 输入/提交身份，与实际成功笔数无关 |
| `state_seq` | GPU 控制序列 | 每个完整编辑批或模拟工作单元结束时推进；即使整批无修改也可推进，表示完成边界，不承诺内容改变 |
| `sim_tick` | GPU 模拟完成序列 | 仅实际完成模拟工作单元时推进，不因命令提交或碰撞应用增加 |
| `advanced_time_s` | GPU 模拟完成序列 | 累计实际积分时长；用于潮汐、关联模拟与表现时钟对齐 |
| `snapshot_seq` | 快照调度，绑定 GPU 标记 | 区分高度快照；CPU 不能预填未知的 GPU 内容版本 |
| `applied_state_seq[chunk]` | CPU 碰撞应用端 | 每区域最后实际应用的完成态版本，只增不减 |

uint64 的 GLSL 编码优先使用两个 uint32，避免引入 shaderInt64 硬件假设；P00 固定高低字顺序。字段布局测试覆盖边界，不允许通过 float 承载身份值。

批次槽状态：`FREE → CPU_FILLING → GPU_QUEUED → GPU_COMPLETE → CPU_RECLAIM → FREE`。完成确认来自该工作单元末尾有序的异步读回/等价已验证完成机制；“提交函数返回”不算 GPU 完成。CPU 暂不处理通知时可以使用其他空槽，但槽满后必须有界背压。

轻量完成信息：`protocol_version, generation, batch_seq, slot_id, lease_id, state_seq, sim_tick, advanced_time_s, error_flags`。逐笔 actual volume 与 receipt 数组不再是调度依赖；可选诊断应有界，关闭时不影响正常执行。CPU 只校验通知身份、长度和必要有效性后回收资源，不做逐笔质量结算授权。

上传缓冲、间接参数、候选数据、uniform set/RID、读回目标在最后 GPU/CPU 消费者退出前保持有效。共享 scratch 只允许单个有序 GPU 序列访问；若后端不能证明跨列表排序，增加明确 barrier/工作单元边界，不能用 CPU await 每批回执代替设计。

## C03 GPU 编辑与显示提交

每笔：选取输入和当前 GPU 版本 → 候选计算 → 统一有效性标志 → 沙/水/悬沙/动量/材料提交或全部跳过 → 下一笔。正常拒绝只影响本笔；下一笔读取实际未变/已变状态，不继承“前笔成功才运行”的条件。

候选检查保留有限值、范围、必要的可用资源等基本约束；CPU 精确质量闭合不属于提交前提。去掉普通编辑路径 `_make_backups()` 的每批 14 份全量临时副本和批次 restore，前提是已证明所有受影响权威字段在拒绝时均未写入。材料算法仍需要的持久工作缓冲不因名称含 backup 就删除。

显示发布由完整 GPU 工作单元和渲染顺序决定，不需要 CPU `authorize_publication`。水面、沙面、泡沫和材料读取同一完成态；不能显示候选写到一半的纹理。已有双槽和稳定发布纹理按实际需要复用，不默认复制更多全域场。

状态数据异常或设备错误不按普通拒绝掩盖：停止受影响提交、保留可用已完成显示/碰撞并报告。不能自动加载旧快照丢掉用户编辑而无任何说明。

## C04 GPU 水模拟与 CFL

固定参数（网格、cell size、重力、安全系数、最大子步数）通过只读参数上传；本次请求时长也由 CPU 提供。动态 `max_speed, substeps, substep_dt, actual_dt, active_slot, status` 写入 GPU storage buffer；使用 GPU 归约和有界间接派发选择要执行的步骤。

P03 先采用可审查的固定上限派发框架，沿用当前 MAX_SUBSTEPS=64；不依赖单个 shader 内跨工作组全局同步。无效步骤不得改状态、计数或双槽索引。奇偶子步结束时由 GPU 将最终状态归一到已知完成槽/发布布局，CPU 不猜 N 的奇偶；关联侵蚀、悬沙、材料、泡沫使用同一实际步长和完成时间。

超过子步上限时，缩短本次实际积分时长到安全范围，保留可观测的 `time_limited` 状态；禁止只把 N 截到 64 而继续用原时长。所有相关时钟按 actual_dt 推进；CPU 调度时间债务有界，不为追赶丢失时间无限追加工作。该方案会使模拟在极端情况下变慢，属于功能保护，不作为性能达标声明。非法 CFL 数值则停止该模拟工作单元并报告，不继续计算无效状态。

潮汐/源汇诊断与 CFL 读回都不得阻挡下一阶段派发；GPU 记录必要数据，CPU 在可用时异步消费。无输入时正常推进；连续输入时每个编辑批次后最多安排一个到期水工作单元，后续输入排在已安排的水工作之后。暂停不产生自动模拟，暂停时普通编辑沿用当前交互语义。

## C05 高度快照与碰撞

请求包含 `generation, snapshot_seq, chunk_ids`。结果包含 `generation, snapshot_seq, state_seq, sim_tick, chunk_ids, grid_size, cell_size_m, sample_layout, heights`。`state_seq/sim_tick` 由同一 GPU 提取边界写出，和高度同属一份完整状态；不得用请求时 CPU 最近知道的版本冒充内容版本。

高度保留当前每块 33×33、共享边采样和 rock+sand 的实际定义。保持当前块数容量，快照在途槽初始 2 个；P00 固定具体字节长度、元数据绑定及上限。GPU 写入快照后不能被后续地形编辑覆盖其内容；GPU 源场可以继续变化。

CPU 输入范围仅决定“可能需要取哪些块”。GPU 算法若影响范围超出笔刷，必须扩大请求到真实写入上界；水模拟/侵蚀引起的地形变化继续有脏区来源，无法提供局部范围时采用有界分批的全域脏标记。

脏块采用 pending/in-flight 分开管理或等价可证明的代次机制。快照请求移走当时 pending；请求后新变化进入新的 pending，完成时不能清掉这些新变化。失败恢复相应区域为 pending。快照槽满则保留脏区，不全局禁止 GPU 编辑；停手后分批取得最新快照并收尾。

CPU 异步回调只传递不可变结果，实际形状变更在主线程合法物理阶段执行，不在 GPU 读回回调里递归提交新读回。按区域拒绝更旧版本；一份更新快照不能使其他区域的有效待应用结果丢失。相同高度沿用现有跳过形状重建逻辑，但更新已应用版本。

不用逐笔 success 判定是否刷新；正常拒绝后的旧高度仍是合法结果。异常长度/非有限高度拒绝该结果，旧形状保留并重新请求；旧 generation 丢弃。shape 已提交与已跨过物理边界分别观测，均不成为普通输入下一批的门禁。

## C06 账本和旧工具边界

普通输入 CPU 估算只在真正提交后累计一次；队列拒收、提交前取消不累计，GPU 跳过允许留下估算误差。字段标记 `ledger_precision=approximate`，不得声称实际体积。严格闭合检查改成诊断；NaN、无效高度、持续负值等数值保护继续保留。

碎石可视范围等派生逻辑改为保守空间上界或来自有效完成态的范围，不依赖近似累计加沙量证明不会裁剪。守恒铲子等旧工具自身的库存/动作限制维持原语义；不得把普通自由挖填的近似外部账本当成它的真实库存。

进入旧工具时，按交互序列建立边界：先暂停新普通批次准入，异步收尾已接纳前缀并同步必要状态，再执行旧工具；完成后恢复普通调度。只在这些低频边界允许 drain，不把此锁保留在普通拖动路径。

## C07 快照保存、生命周期与错误

新存档头至少包含 `format_version, pipeline_protocol_version, grid/units, state_seq, sim_tick, advanced_time_s, active_slots/published_layout, authoritative_fields, material_state, ledger_precision, approximate_ledger, visual_extensions, checksum`。保存当前完整状态及实际运行必需的时钟/随机状态，不保存逐笔命令历史作为恢复依据。

P00/P06 分配明确新格式版本；旧 v4 等格式由专用旧解码器读取并显式迁移，旧原始回执不重新伪造。兼容受支持且身份/资源匹配的旧存档；不承诺读取未知格式或任意不兼容源码签名。新保存不再用逐笔 prefix 校验近似账本。

| 操作 | 边界行为 |
|---|---|
| 暂停模拟 | 不再安排新自动 tick；已在途任务完成。允许的暂停编辑保持可用 |
| 保存 | 暂停新准入，drain 已接纳命令和在途模拟，选择完成边界取一致快照；不必等待旧碰撞逐笔确认 |
| 恢复/场景切换 | 完成受控交接，验证候选快照后切换新 generation，重建碰撞；候选验证/构建失败保留旧可用状态，提交后的管线致命错误停止新所有者并明确报告，不伪装回滚 |
| 退出 | 停止准入、按已冻结策略取消未提交输入，等待资源最后消费者释放；设备失效时有界终止，不无限等待 |

错误分类：普通命令拒绝→继续；提交前资源/上传失败→标记未提交并回收，防重复提交；损坏快照→保留旧碰撞重取；旧结果→丢弃；权威数值损坏/设备失效→停止相关管线并明确报告。GPU 很慢不等于设备损坏，不因普通超时自动回滚或重放可能已经执行的批次。

## P00 冻结的实施布局

全部 little-endian，uint64 由 low/high 两个连续 uint32 表示；CPU 可用身份范围 1..INT64_MAX，float32 不承载身份。保留字写零。基础布局常量位于 `scripts/simulation/edit_validation/frame_pipeline/async_protocol.gd`。

| 结构 | 字节与 offset | 用途 |
|---|---|---|
| batch header，64B | protocol u32@0，count u32@4，generation u64@8，batch_seq u64@16，slot u32@24，reserved@28，lease u64@32，reserved@40..63 | 输入槽前缀；后接 count×128B 命令，固定分配 8256B |
| command，128B | 原 edit_protocol 编码：ticket u64@0，command_id u64@8，generation u64@16，tick u64@24，revision u64@32；kind@40、shape@44、start vec2@48、end vec2@56、radius@64、strength@68、amount@72、cell@76、grid@80、policy@84、epsilon@88、available@92、seed u64@96、dry_depth@104、speed@108、destination@112 | 旧 revision/tick 字节在 GPU select 时以 control 实值覆盖；只以独立 header protocol 标识新语义 |
| GPU control，128B | protocol u32@0，error flags u32@4，generation u64@8，state_seq u64@16，sim_tick u64@24，time f32@32，last actual_dt f32@36，revision u64@40；@48..127 为模拟决策/诊断保留 | GPU 唯一推进，初始化由 render thread 写入；后续水决策专用块，不与命令 scratch 混用 |
| completion，80B | protocol u32@0，errors u32@4，generation u64@8，batch_seq u64@16，slot u32@24，reserved@28，lease u64@32，state_seq u64@40，sim_tick u64@48，time f32@56，actual_dt f32@60，revision u64@64，累计成功/拒绝 u32@72/76 | GPU work unit 最末 seal；异步回调最后消费者。无逐笔质量数组；末两计数只作诊断，不授权发布 |
| CFL decision，64B | max_speed f32@0，N u32@4，substep_dt f32@8，actual_dt f32@12，status u32@16，active_slot u32@20，request_dt f32@24，reserved@28..63 | P03 GPU 归约写入；间接参数为 64×12B 各 xyz uint，inactive x=0 |
| height snapshot header，64B | protocol u32@0，flags u32@4，generation u64@8，snapshot_seq u64@16，state_seq u64@24，sim_tick u64@32，count u32@40，samples u32@44=33，grid u32@48=256，cell f32@52=.125，payload bytes u32@56，reserved@60 | 后接固定16个chunk u32 ID（未用写零），从byte128接count×33×33 float32高度，单槽上限69824B；同GPU pack写标签和高度 |

GPU binding：seal set0 0=input storage，1=control storage，2=completion storage，3=1×1 R32F完成时钟image。时钟在同一seal写control累计实际时间，实际水面/沙床材质只采样该纹理，普通路径不等待CPU回执更新表现时间。新编辑select/capture单独引用GPU control，不改旧validator。P04明确高度pack set0为rock image@0、sand image@1、合并header+高度的output storage@2、块IDstorage@3；set1 control storage@0。相对P00草案的header/control双buffer绑定，实施改为header与高度同一buffer，以一次异步读回获得不可变元数据和内容；逻辑字段/64B头/容量不变，旧pack ABI不改。CFL参数/间接缓冲放专用set。

容量：CPU 队列 64，batch 1..64 默认2，batch slots=3，height slots=2，每快照最多16块/总64块。禁自动扩容。输入为一次 header+commands buffer_update。input/completion/uniform/indirect 各槽持久拥有；命令 scratch、cells、候选和所有水沙材料场由唯一 render 序列共享。下一次记录按上一工作单元末尾之后顺序排队；RD compute list end 的资源 hazard/barrier 承担跨阶段可见性，G1 GPU 次序负例验证该假设。

所有权：CPU slots 模块只在主线程变更，回调通过 deferred 传不可变 bytes+closure identity。GPU transport 只在 render thread 分配/更新/退租/释放 RD。GPU_COMPLETE 也不允许覆盖，必须显式 CPU_RECLAIM；重复/旧通知不推进状态。提交前失败可取消 CPU_FILLING，提交后读回注册失败属于未知完成错误，保留租约并停止，不重发。共享 scratch 在最后工作完成前不得销毁；设备故障释放边界于 P06 冻结实现。

保存：为新模式保留 edit v5/native v3；material/visual 子记录沿用其自身版本，ledger_precision=approximate，显式带 pipeline_protocol_version/state_seq/sim_tick/actual time/权威双槽及 active slot。旧 v4/native v2 原 decoder 不改语义，支持范围为完整校验且资源签名可迁移者；不伪造 prefix。P06 决定具体 codec 容器字段时不得挤占旧格式。

P06已落实独立SANDGP05容器：48B头（magic 8B、容器版本u32=1、payload长度u32、SHA256 32B），payload edit version=5，native version=3，最大32MiB。native固定包含fields/spare/material/foam/histories/control/current_index=0；完整RG32F local-front输出位于histories.local_front，按实际simulation开关校验存在性；X中间场由下一次两段dispatch完整覆盖，不保存。另存实际模拟开关/运行态prescribed_tide_boundary、近似账本/库存、初始总量/供给上界、选择与高水位、波请求/实际起始时间、碎石子记录及源码/资源/引擎配置身份。selection包含policy/speed/brush，brush用既有校验器校验工具/形状参数/挖填量，只在成功提交后恢复。没有prefix或旧shadow投影；旧容器解码器未改。保存、同版GPU候选恢复及兼容旧v4迁移已验。

独立候选构建或验证失败后，在任何候选资源release前追加有序终结证明，并排空已注册的验证回调。候选自身transport尚未建立时可使用同一主RD的活跃control作为排序锚点，其数据不校验或修复候选。终结不可用返回candidate_ownership_unconfirmed，独立候选与旧活跃资源均保留，元数据不提交，相关管线停止；关闭不无限等待released。恢复终结能力仅丢弃已有候选，不重建、不重放、不恢复失败管线。候选正常验证完成后才允许原子提交，原验证数量不混入终结证明。

旧工具的rollback与延迟finalize不占用新controller.records，不能以新槽池为空授权释放。低频关闭使用独立16B控制缓冲做同一主RD的有序读回；它不依赖候选/活跃transport完整初始化，返回字节不作为状态或回执。旧工具故障先请求probe，仅证明当时已记录的工作；必须等CPU工具协程、原生receipt、主线程调度的finalize/rollback及preview消费者结束，再请求final证明，才解除释放限制。probe成功不等于final完成，重试只确认既有工作，不重放、不恢复失败管线。
