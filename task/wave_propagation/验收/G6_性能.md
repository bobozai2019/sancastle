# G6 实际窗口成本

性能测量完成，二阶未达放宽目标，按D06明确带性能限制交付。没有修改生产数值核或引入未验证优化；保留已通过功能、体验与长稳的候选。专项起止、累计耗时与1800秒上限见`test_output/wave_propagation/g6_cost_budget_01/budget.json`，首次定位即启动，编写/编译探针、等待与测量全部计时。

设备为i5-9300H、NVIDIA GeForce GTX1050，Windows报告驱动32.0.15.8183；Godot4.7.2、D3D12/Forward+。实际可见客户区和viewport均1280×720，VSync关闭，测量帧焦点比例100%。完整main默认相机、侵蚀/材料/白沫/亮纹、512颗碎石、原布局三道具与碰撞均保留，诊断timeline关闭。没有关闭root正常_process，没有手动加速tick，仍使用生产累积器、pending限制和三工作槽。

引擎完成全部boot后正常播放预热至少10墙钟秒，再取首个不少于60秒的完整帧窗口。每5墙钟秒通过真实PlayerInput提交1m铲沙，X按−0.75、−0.25、0.25、0.75m循环，共11笔；两种算法分别串行运行。source map、非数值配置、相机与输入节奏相同；预热和窗口内实际模拟时间不同，因此这是完整产品运行对照，不是相同演化态的纯内核计时。

目标为p99≤50ms且推进比例≥0.80。一阶两项达到，二阶两项未达；0.78703不四舍五入判成0.80。每完成tick平均推进相对1/30秒分别为0.9999876与0.9999890，接近完整请求时间；现有证据显示主要为单位墙钟完成吞吐不足，不能只以FPS推断CFL缩时。未采集每tick完整子步/拒绝trace，不能宣称每一tick都没有缩时。

两组各22个物理编辑终结均为APPLIED/NO_CHANGE且error_code为0，输入接纳通过；无水沙或浮物故障，碎石可见数量保持512，完整关闭通过。截图在窗口结束后取得，保存截图与关闭不计入稳态窗口。CPU观察到的完成时钟与帧边界来自同一单调时钟，仍受异步通知领取量化；一阶略大于1倍不能解释为物理超速。整帧分位数按样本排序的nearest-rank计算，不用产品面板120帧滚动P95冒充全窗口p99。

`g6_cost_mc_01`与`g6_cost_fo_01`保存每帧时钟/队列/焦点/消费者记录、实际配置、输入与终结、截图和生产消费来源zip；`paired_conditions.json`独立核对完整来源及非算法参数相等，并复核实际编辑终结。MC首次分析器原文按原SHA保存在`analyzer_v1.py`；补充终结核对独立保存，原分析不覆盖。

测量边界：两个既有Godot进程49500与51752在场，保留原用户会话，未关闭或伪称空闲；未测其GPU占用，数值只代表本次桌面条件。没有取得可靠分pass GPU时长、CPU/GPU校准时间线或驱动总显存占用；video memory为引擎监视值，不是完整驱动显存。没有将通知时间当GPU成本，没有把720p结果写成1080p达标。未追加其他不同入口成本、512²、替代算法或全项目优化。

二阶相对一阶的整帧成本增加明显，既有固定尝试录制与更完整阶段链是可调查方向，但本次没有独立profiling证实各自贡献，不将其写成已定位根因。交付采用已验证正确版本；性能目标未达作为明确限制保留，一阶仍可在新generation中显式选择并恢复受支持的完成态。
