# C02 时序、接口与兼容

状态：frozen v1.1（T01原版保留在G1归档；G4补充旧发布独立版本映射，实际验收另见Gate报告）。保持现有公共ABI；实现与实际通过范围以对应Gate报告为准，契约冻结本身不构成验收。

## 保留的调用接口

| 接口 | 请求 | 返回/消费 | 约束 |
|---|---|---|---|
| `pipeline.request_tick(dt)` | 有限正数，秒；主入口通常 1/30 | StringName，空为接纳；非空为既有准入错误 | 接纳不等于完成，不改变现有错误语义 |
| `water.record_tick(input,control,output,count,requested_dt)` | 已录制的统一流水线工作 | 录制 GPU 操作 | 中间 RK 阶段不是新用户命令或完成回执 |
| 完成元数据 | GPU 完成头 | generation、state_seq、sim_tick、revision、advanced_time_s | 只反映已接受工作；actual_dt 累计，不用 tick/30 代替 |
| 编辑 intent/result | 已有工具字段和 command_id | 既有 APPLIED/拒绝结果与 delta | 两阶段不得重放编辑、重复记账或领结果 |
| 公共采样 | 已有 Probe ABI3 点位与身份 | bed/h/eta/u_xz、完成时间和身份 | 同 generation 的完整最终状态；不暴露阶段态 |
| checkpoint/save/restore | 已有配置、原始 fields/control、provenance | 完整校验后的候选状态 | 不保存半个 RK 子步；失败不替换当前域 |

严格的错误码集合沿用实际源码，新增错误必须在 G1 逐项定义和映射，不用任意 StringName 规避既有 verifier。

## 私有阶段生命周期

`已发布状态 → 私有水子步初态 → RK1 → RK2 → 验证/合成 → 一次耦合 → 接受子步 → tick尾处理 → 发布完成态`。

试算回退不推进 revision 或 actual_dt。一个接受子步对应原语义的一次 revision 推进；两次阶段调用不翻倍。工作槽/借用生命周期仍由统一 transport 管理；新增 RID 必须纳入创建失败、在途取消、恢复替换、关闭及迟到回调终结证明。

## 数值配置身份

在现有hash覆盖的environment下添加严格消费的 `water_numerics` 对象，不向strict顶层schema加键；具体校验与历史缺失字段规则见后文。

| 设计字段 | 类型 | 设计值 | 验证 |
|---|---|---|---|
| schema | int | 1 | 未知值拒绝 |
| solver_id | string | `rusanov_first_order_v1` / `muscl_mc_ssprk2_v1` | 显式白名单；必须对应实际录制路径 |
| grid_size | 不新增重复字段 | 继承 configuration 的 256 | 不允许私有设置与权威网格不同 |
| cell_size_m | 不新增重复字段 | 继承 configuration 的 0.125 | 同上 |
| courant / 保护策略 | 算法版本常量 | 经证明的值 | 进入代码/profile hash，不开放无校验滑杆 |

合法请求成功产生含有效算法身份的冻结配置；非法对象/未知键/未知 solver_id 明确拒绝，并且不能创建半初始化域。选定算法后不在活动域原位切换；需要新 generation 和完整候选构建。

必须通过“改变 solver_id → 实际 GPU 路径改变、配置 hash 改变”的测试，不把只写 manifest 当实现。新 shader、coupled 与 scratch 相关源码加入 configuration.sources。

## 检查点兼容

- 首选保留 `SANDUE06`、native3 物理字段布局；RK scratch 不持久化。恢复时由完整最终字段重建工作资源。
- 同算法同配置保存/恢复按既有原字节规则；恢复后继续推进的数值比较使用同算法参考，不要求二阶结果等同一阶未来轨迹。
- 实施前封存现行合法 SANDUE06 一阶样本，以及当前已支持来源 fixture 的路径/hash/配置。不得直接把旧配置 hash 改成新配置来绕过完整性。
- 新算法对现行合法快照的迁移需显式来源白名单、原始字段保留、原 provenance、数值算法切换策略；旧结果不重算为新算法结果。
- 原生结构若确需改动，先版本化 codec、界限和迁移；不能用本计划“默认保持 native3”代替可行性核对。
- 数值回退使用受支持旧算法身份重新构建；不回滚已经发生的真实编辑或抹除源汇账本。

## 消费者

材质和几何仍读同一 bed+h；浮物读同一 h/eta/u。白沫、碎石、探针、碰撞只在已有正确阶段消费；新增水阶段不额外推进其时间。检查点/暂停排空到完整完成边界；同代新完成与旧代迟到回调必须区分。

不因更快的小波放宽浮物 0.15 秒采样年龄等既有保护。若测出相位延迟，优先改善有效采样供给与调度，变更保护预算需独立依据。

## 冻结的数值身份规则

`environment.water_numerics`的精确键集合为`schema/solver_id`。schema必须为int且为1，solver_id必须为String且仅允许`rusanov_first_order_v1`或`muscl_mc_ssprk2_v1`。courant、干格阈值、速度帽、64次容量和roundoff规则作为算法版本常量，不开放未校验字段。对象/类型/未知键返回`invalid_water_numerics`，未知整数schema返回`unsupported_water_numerics_schema`，未知字符串算法返回`unknown_water_solver_id`。

Config.freeze总是复制environment并补入有效数值对象，随后计算配置hash。T02–T05缺省为一阶；T06仅在G0–G5与稳定性/恢复通过后改缺省二阶。显式一阶始终可选。Config.validate对历史缺失对象的原快照解释为一阶，但不补字段、不改原hash；含对象的快照严格校验。Pipeline.configure保存实际solver_id到State/Water，Water.initialize分配相应私有资源、record_tick按身份进入不同路径。只改manifest而不改变录制路径为失败。

所有新增数值shader、include、录制器和迁移代码加入configuration.sources；新建域验证完整盘上来源后才初始化。数值scratch归water所有，由原初始化失败清理/在途终结/关闭路径释放，不增加另一个异步提交所有者。G2必须证明算法字段改变hash和实际dispatch路径；G4必须覆盖water资源创建失败及候选域保留旧域。

## 冻结的来源与迁移路径

保留SANDUE06/native3以及control保留字零约束。数值统计与audit不存档，恢复时重新创建并清零；原native字段、spare、时间、账本、波请求及现有provenance按原验证闭环。算法改变只对新generation生效。

1. 同配置：现有Codec.validate完整校验，通过后按原字节恢复。
2. 同发布源码、不同数值算法：仅允许完整sources相同、数值对象有效、其余声明参数相同的显式投影。先按来源自己的配置完整验证，目标按当前盘上源码验证；保持全部native字节，替换目标配置并在provenance.policies记录from/to solver、原配置和parent_provenance。该规则支持本发布的一阶/二阶相互回退，不依赖把自身配置写入自身catalog，避免hash循环。
3. 旧发布native6：必须命中离线bake的完整原始configuration白名单；不能从当前打开文件自动登记。G0一阶main及本机可读的既有合法样本已由`g1_recovery_inspect_01/source_configurations.variant`保存原Variant配置，T04将受支持旧consumer来源一并纳入。原字段/ledger/full container验证仍执行。历史混合String/StringName排序仅在已精确pin住完整原配置时，可在校验副本中规范化派生configuration_hash；原配置和原文件不改写。
4. 旧发布来源投影还要求当前发布的target_sources/target_parameters匹配离线审阅catalog。target_sources只排除catalog本身及其检查器自身，避免自引用；其余所有来源精确匹配。target_parameters仅去掉sources/hash/diagnostics和water_numerics，旧consumer已有的profile派生hash/model身份变换须独立保留其原审阅边界，不能把任何新参数差异一并忽略；确需跨越已存在的声明版本差异时，仅允许下述v1.1逐来源/逐目标的独立版本映射。未知原配置或未经审阅的目标拒绝。
5. edit5_native3/edit4_native2继续走现有可信legacy_source_catalog和完整legacy validator，再用现有投影函数保留物理字段及原时钟语义；只增加明确的数值目标身份和迁移说明，不伪造旧格式头。历史原始fixture目前缺失，G4须用原catalog配置构造合法测试容器并保留“重建fixture、不是原始文件”的身份，不能宣称找回旧证据。

新增错误码为`numerics_source_catalog_identity_mismatch`、`invalid_numerics_source_catalog`、`unknown_numerics_source_configuration`、`unreviewed_numerics_target_configuration`、`numerics_parameter_mismatch`。任何投影必须最后通过Codec.validate(result,target)，再经过原candidate/restore_verifier/物理切换流程，失败不替换旧域。catalog由独立bake工具显式生成，版本/fixture/hash/参数映射进入索引；它不是运行时学习机制。T06稳定源码后同步审阅target_sources；改变hash而不复验不构成迁移通过。

## flux读者清单

生产`coupled.gd`的sediment_step是唯一按四向flux搬运悬沙的求解读者，必须在二阶路径拆为阶段输运＋一次交换；一阶路径保留原合并核作比较。state/async_normalize、views/view_publish、checkpoint capture/restore只是复制或持久化flux，继续保留四向ABI；白沫/亮纹/浮物按现有水深与动量消费，不能引入额外阶段时间。公开flux是最后接受物理子步的阶段加权流率，继承原“最后子步”语义，不宣称为整tick累计通量。需要重建整tick水量时使用逐接受dt与对应通量证据，不能用最后flux乘整个tick时间。


## v1.1 旧发布独立版本映射

本补充不改变数值容差、原生字段布局、物理量或历史账本。它处理已固定旧来源与当前发布之间真实存在的声明版本差异；不是给所有配置忽略profile或ledger_policy字段。原v1全文及hash保留于G1冻结归档。

- 来源仍须逐字命中G1完整Variant配置白名单。catalog schema2的每条来源保存configuration、原fixture身份与有限mappings；不从打开文件补登记。
- 每条mapping保存完整source_parameters、完整target_parameters及逐叶path/from/to变化。运行时两端分别完全相等，且目标完整sources匹配审阅目标；否则拒绝。参数投影仍只去掉sources/configuration_hash/diagnostics和water_numerics，没有通用“忽略其他差异”路径。
- 离线bake只允许固定差异：profile派生hash、模型源码身份（含旧导出错误的空文件模型hash）、原声明water_policy=[3]扩为当前[0,1,2,3]、castle/wall material_policy=[1]扩为[0,1]、既有shovel_v1声明从version1/transfer1到version2/transfer2并绑定已审阅的两个资源SHA，以及既有transfer策略标签从conservative_source_sink_unchanged_v1到balanced_conservative_or_capped_exact_sink_v2。其余字段、参数范围、物理/效果/环境差异拒绝；实际每对来源/目标还由完整值pin限制，不仅靠字段名许可。
- 旧ledger_policy标签描述来源发布中未来操作的规则，不是历史库存数值。完整来源pin后，专用source validator以原标签校验原schema、profile、native、控制、时间、材料、表现及ledger；仅在私有副本中规范化历史混合键的派生configuration_hash。目标/运行校验始终要求当前ledger_policy。来源字段和历史ledger值不因校验重写。
- 输出provenance保留原完整configuration、真实输入文件SHA、原fixture信任定位及parent_provenance，增加逐项parameter_changes和“未来操作仅用审阅目标、过去账本不变”策略。旧代码/model身份不冒称当前源码；不重放旧命令或重算旧模拟。
- 缺失原文件的fixture按原精确配置、合法原生数据和真实格式构建，记录synthetic身份/时间以及原始缺失状态，分别经原完整validator通过。不得称为找回原始fixture。

该版本映射必须有离线反例、实际GPU候选恢复、原位重保存及继续推进证据；catalog/Config/Codec/factory变更后重新审阅目标来源。最终仍经当前Codec.validate和原候选/物理提交路径，任何失败保留旧域。
