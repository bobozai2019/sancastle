# 计划决策

角色：planning_decisions。以下决定路线和待冻结边界，不宣称生产实现已修改。

## D01：先做当前网格二阶守恒求解

- 状态：proposed_for_execution。
- 依据：当前短波耗散与一阶格式预测一致；一维候选提示二阶有改善，同时存在网格上限。
- 决策：先保持 256²、0.125 m、g=9.81、铲子与湿干参数，采用 MUSCL/MC＋SSP-RK2 候选；是否改限制器须单变量证据。
- 影响：T01/T02/C01；512² 与频散不并入首轮。

## D02：悬沙随 RK 阶段，床面交换每接受子步一次

- 状态：proposed_for_execution，G1 必须完成数学与字段冻结。
- 依据：现有 `sediment_step.glsl` 将输运与侵蚀沉积合在一起；直接调用两次会重复交换，调用末阶段一次会丢失阶段输运。
- 决策：拆分阶段输运与交换；公开 flux 为时间加权净边通量，阶段搬沙使用各阶段供水侧与浓度。
- 影响：T03/C01；不能只平均最终 h/q。

## D03：保持现有公共状态，版本化数值身份

- 状态：proposed_for_execution。
- 决策：RK scratch 为私有工作资源；数值模式与实际源码进入有效配置身份。新算法与一阶回退不可共用身份。默认不更改 native3 原字段布局；如设计证明必须改变，先修订版本与迁移，再实现。
- 影响：T01/T04/C02。现行已支持旧来源不能通过修改 hash、放宽校验或删兼容用例绕过。

## D04：单主执行与阶段门禁

- 状态：accepted_scope。
- 决策：按项目规范串行；历史调查仅为输入，新任务执行进度从 0 开始。G5 用户效果与正确性失败时不得宣布完成；G6性能按D06用户补充要求处理。
- 影响：全部任务；不自动启动 subagent，不自动实施扩展分支。

## D05：证据与当前文档分离

- 状态：accepted_scope。
- 决策：本包存计划/状态/验收，原作事实继续在 docs/competitor；技术实现生效后才更新当前文档与生成器入口。
- 影响：T06。缺失旧原始产物保留缺失说明，不伪造恢复。

## D06：性能放宽与半小时优化上限

- 日期：2026-10-20。状态：accepted_user_constraint。
- 来源：用户“性能部分可以降低标准，优化最多执行半小时”。
- 决策：本任务性能采用实际720p、预热后60秒测量；p99≤50ms和模拟推进≥0.80倍墙钟为尽力目标，替代原1080p/33.3ms/0.95硬门。目标未达可明确带性能限制交付，不能伪写达标。
- 时间预算：性能专项累计最多1800秒，包含定位、优化改码、编译、等待与复测，跨任务/回合不重置；末5分钟预留验证/恢复和收尾。计划编写不启动计时。
- 截止行为：到期停止性能工作，不因目标未达自动进入其他算法或全项目优化；交付最近已验证正确的版本及实测/未知项。
- 保留：水沙正确性、用户波动效果、生命周期和五分钟正确性长稳要求。功能缺陷不借性能豁免放行。
- 影响：总纲、C03、T00/T06、执行状态、需求映射和验收记录。本条优先于本包此前更严的性能表述，其他项目任务的标准不变。

## D07：逐阶段GPU接受与原生字段兼容

- 状态：accepted_design，G1冻结；生产接入尚待T02–T04验证。
- 数值：MUSCL/MC重构h/eta/u/v，配套静水压力修正及单元内床源项；二维重构速度界取0.2dx/(ax_max+az_max)。阶段1实际界不安全则GPU内减半重试，64为试算容量而非强制接受子步数。
- 状态：每接受步RK两阶段只生成一个revision增量；时间只累计接受dt。私有U1/U2、边、donor、统计与audit不发布、不进入native3。slot1完成接受及一次耦合后完整归一到slot0。
- 悬沙：跟随各阶段真实供水侧搬运；反向边用例已证明单个净flux不能代替阶段方向。公开四向flux保持最后接受子步的加权净流率ABI；侵蚀/材料每接受步仅执行一次。
- 保护：阶段和最终态均干格归零及限速；roundoff只有8epsilon局部界且≤2e-6m才允许归零，并记录次数及RK加权体积。实质负值或非有限不发布。
- 兼容：保留SANDUE06/native3；历史缺失数值对象解释为一阶，新的冻结配置显式包含严格water_numerics。迁移区分同发布显式算法切换、旧发布完整原配置白名单和现有legacy目录，目标来源需离线审阅，不自动信任打开文件。
- 证据：`g1_reference_final_01`、`g1_policy_02`、`g1_recovery_inspect_01`。早期斜向粗档失败与policy首次JSON序列化错误保留。性能专项尚未开始。


## D08：旧发布声明的独立、精确版本映射

- 状态：accepted_design；实现及验收归G4。来源为本任务保留既有旧来源兼容的要求，以及g4_migration_03的明确拒绝证据。
- 原因：旧consumer使用shovel/transfer-v1标签，当前项目早已使用v2；旧导出曾将模型文件身份写成空文件hash，并保存了较窄的允许特性声明。只切换solver_id不能让这些历史来源通过当前完整配置校验。
- 决策：C02增至v1.1。离线bake固定完整来源和目标参数，逐叶记录并仅允许列出的既有版本差异；运行时完整值匹配。来源以原策略标签验证全部原数据，目标仍按当前规则验证；原物理字段和历史账本数值保持。
- 约束：不泛化放宽校验，不把原文件中的签名登记为信任，不忽略任意profile/环境差异，不伪造旧格式或原始缺失文件。模型身份变换不证明旧算法与新代码等同；恢复的是明确保存的状态，未来执行当前已验证实现。
- 影响：NumSources catalog schema2、Config/Codec专用来源校验入口、C02兼容冻结索引与G4矩阵；数值/守恒/性能要求不变。G1原冻结产物保留原样。


## D09：按正式main效果交付，平床持续增量作为已接受限制

- 日期：2026-10-21。状态：accepted_user_constraint。
- 用户明确指示：“接受平床差距，按 main 效果推进 G6”；随后指示“自行判断，将差异最终汇报到结果里，我人不在，不要再问我问题。持续推进直至完成”。
- 证据：main起伏中位数3.613倍、持续+1.6s（并集+1.1s）、实际浮物和连续画面通过；平床起伏3.131倍、持续+0.7s。独立粗/细参考均复现持续差距，原1s门失败保持。
- 决策：C03更新v1.1，仅将正式main/用户入口作为持续效果交付判定；平床0.3s差距作为明确已知限制记录，不称原门通过。G5按用户接受范围通过，进入G6。
- 保留：全部数值/守恒/稳定性、同源同工具同点、浮物与生命周期、五分钟正确性长稳、性能专项1800s上限。默认仍在G6验证后接入，不提前宣称完成。
- 范围：不据此启动生产512²、替代求解器或其他物理扩展；不再向用户提问，后续自行实施并在最终结果报告全部差异、未达与未测。
- 原始数据：G5原门fail报告、所有旧索引、CPU归因及原C03v1保持原身份，新增生效范围文件及索引。
