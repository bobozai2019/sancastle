# 显示输入 v1：公共工作槽内的颗粒投放

范围：已有碎石显示状态的有界投放。物理ABI v1的布局、枚举、APPLIED/revision语义及量化预算保持原定义。新增显示数据使用显式魔数识别，复用现有512B输入、384B输出和96B工作槽完成头；不根据消息长度猜schema。

| 数据 | 标签 | 版本 | 语义 |
|---|---|---:|---|
| 显示批次 | `0x31424455` / UDB1 | 1 | work_kind=2，固定1个显示请求 |
| 显示请求 | `0x31434455` / UDC1 | 1 | primitive=1：既有gravel mode3投放 |
| 显示回执 | `0x31524455` / UDR1 | 1 | 已提交的显示数量及实际总数量 |
| 完成头 | 现有公共完成头 | 物理ABI v1 | 同一generation/batch/lease/slot、实际state_seq/tick/revision |

物理旧批次标签仅允许其原EDIT/WATER_TICK枚举；新显示批次必须使用自己的标签和work_kind。物理codec不接受显示回执。显示APPLIED保持权威revision稳定，所有沙量、源汇、动量、水量、权威changed_fields/dirty/rect均为0；state_seq在实际公共work seal后推进一次，tick和时钟不因投放推进。

## 准入、编码和结果

API `submit_display_intent`必填且仅允许：domain_id、generation、command_id、sim_tick、point_xz_m、count。ID及代次沿用公共signed int64约束和单调高水位；同一有界队列最多64项、共享3个工作槽及512份结果容量。count为整数1–128，point为有限Vector2且两个分量绝对值不大于15.55。半径固定0.45 m，seed及其余参数消费已冻结gravel profile，调用方不能提供shader、资源路径或执行函数。

请求512B中：0/4/8为魔数/版本/stride；12为primitive=1；16为count；32为command_id；40为generation；72为sim_tick；96/128/160为domain/effective/profile SHA256；192/196为point float32；320为原profile seed int64。其余必须0。effective hash绑定schema、profile、位置、数量和seed。批次字段和租约仍逐项核对。

回执384B保留公共身份和版本字段的相同offset，但使用UDR1标签；120/124分别表示实际emitted_count和actual_active_count。APPLIED的emitted_count等于请求数量；REJECTED的emitted_count为0，实际总数保留。拒绝码：1请求/身份无效，2容量不足，3候选非有限或越界。回执含真实GPU完成phase和整批seal写入的state_seq/tick；物理revision前后相同。所有浮点量、coverage、dirty/rect、stroke/sample和保留字节均为0。Python/API上提供display_count、active_count、authority_changed=false，不将它们计入沙量账本。

## 执行和所有权

显示请求进入公共Pipeline，沿Slots→Transport→work_begin→显示候选/校验/提交→work_seal→公共发布/回读/退休执行。旧gravel mode3生成候选；GPU元数据决定当前有效尾部，原前缀保留，候选全部检查有限、范围、湿态及零尾部后提交。水步和纯编辑重投影直接读取同一GPU数量，因此可在CPU回执前继续录制，工具不拥有额外pump或忙锁。

CPU准入容量包含已完成数量和所有未消费显示请求的预留；未录制取消释放预留。GPU实际分配连续尾部，取消不会制造空洞。数量、profile hash和显示ID高水位位于Water所有的80B显示元数据，不使用保留物理control字段；所有显示RIDs和固定3份槽绑定均由既有Water所有权统一释放。

录制未知、fatal、上传失败和重复/错代回调使用既有公共生命周期规则；没有GPU回执时不制造APPLIED/REJECTED，也不授权重放。native保存额外回读4B实际GPU数量并与公共完成回执的CPU数量匹配；不匹配拒绝写档。恢复由原gravel_v1扩展的已验证active_count重建元数据，并独立GPU回读确认；ID高水位取已验证的checkpoint highwater_id。物理native-v3布局及其保留0字段不变。

可见MultiMesh数量随经过验证的公共完成态更新；不根据准入预测增长，也不阻塞下一工作单元录制。恢复提交在材质换代回调中同步可见数量。实际实现见display_intent.gd/display_emit.glsl；组件验收见[G6碎石公共输入](../验收/G6_碎石公共输入.md)。
