# 沙水主流程与玩法扩展契约

日期：2026-10-18。角色：contract。状态：T01/G1数据契约已冻结，实施义务由T02–T08逐门验收；本文件不记录实际测试PASS。公共语义以当前已生效项目契约为准，旧文中的单在途/逐笔CPU授权已被后续异步方案取代，不借本轮恢复旧等待。精确字节布局见[ABI v1](ABI_v1.md)，配置与历史支持矩阵见[配置与存档 v1](配置与存档_v1.md)。

## C01：唯一执行权

正式域只绑定一个SandWaterPipeline实例（暂定名）。UI/道具调用submit_intent；公共调度器决定批次与顺序；唯一编辑执行器调用固定阶段骨架。时间步、预览/高度读取、快照边界和碎石等消费者登记在同一域的依赖与生命周期中，不建立第二个沙水frame pump。

只有公共提交阶段或获准的模拟tick执行器可以写权威沙/水/悬沙/动量/材料。原语只能写其已分配候选与scratch；任何失败校验都不能先改权威再以CPU回滚补救。工具ID不得决定调度器、提交器、发布器、碰撞或存档实现。一次命令可有多个数值阶段，但不是多个独立业务事务。

继续复用有界队列、3个工作槽、2个高度槽和同一有序RD流；容量变更需要证据。GPU同流顺序可授权后继录制，资源释放仍须最后消费者完成。工作槽用于在途所有权，不宣称GPU并行写同一权威场。

## C02：ToolProfile与配置边界

使用带类型的Godot Resource（建议.tres），固定资源由场景/注册表预绑定。注册表解析一次并校验；工具不能携带任意脚本路径、Callable、自选shader、阶段顺序数组或依赖图来绕过公共流程。

| 字段 | 类型/含义 | 约束 |
|---|---|---|
| profile_id / version | StringName / 正整数 | 注册表唯一身份；资源及依赖hash参与有效配置身份 |
| operation | 枚举 | volume_delta / target_height / transfer / redistribute / field_adjust |
| destination | 枚举 | bed_sand / suspended_sand / material；由operation组合白名单限制 |
| shape | 枚举 | disk / swept_capsule / height_stamp；复用权重/采样接口 |
| shape_resource | 已注册模板/曲线Resource | 有界尺寸、实际内容hash；禁止用路径偷渡执行器 |
| limits / defaults | 带单位数值字段 | 半径m、宽度m、深度m、高度m、体积m³、强度[0,1]等；范围来自已验证工具规格 |
| volume_sign | add/remove | 只对volume_delta生效，禁止未知枚举被当成填沙 |
| height_reference | fixed_world / stroke_baseline | 明确世界标高或单笔固定基准；不得随每段漂移 |
| target_rule | fill_to / carve_to | 本轮目标高度只启用已存在的行为；其他组合验证前拒绝 |
| transfer_policy | 通用搬运配置 | 供体/接收区域、比例/对称约束、容量与上限；铲子沿现有两侧规则 |
| material_policy | plain / molded / preserve等已注册策略 | 必须支持对应操作，参数来源于有效材料profile |
| water_policy | 已验证水响应策略 | 选择既有语义；禁用响应必须是明确合法配置，不自动绕过验证 |
| stroke_policy | none / fixed_baseline_coverage | 决定是否需要有界笔画状态，状态仍由pipeline持有 |
| sampling | 间距、段长上限、合并策略 | 参数组合须验证；不能任意合并铲子而改变逐段容量分配 |
| effects | 受限能力开关集合 | 例如保形/压实/动量模板；只启用已注册且验证过的组合 |
| display | 名称、图标、预览参数映射 | 不参与物理执行分流；静态UI继续保存在场景 |

配置可以决定“做什么”和数值，不能关闭身份/有限值/非负/守恒/原子提交/最后消费者检查。影响字段集合由公共注册表根据操作和能力推导，不信任调用方自报更小的write_mask。相斥组合明确拒绝，不做隐式默认猜测。诊断开关不改权威结果；玩法开关改变结果时进入命令快照和存档配置身份。

示例是配置设计目标，不是已创建的运行资源：

| 配置玩法 | operation + shape | 参数变化 | 可共用的后续阶段 |
|---|---|---|---|
| 小铲/大铲挖沙 | volume_delta(remove) + disk | radius、amount、strength | 完全相同 |
| 填沙笔/宽填沙带 | volume_delta(add) + disk或swept_capsule | radius、amount、权重 | 完全相同 |
| 矮沙墙/高沙墙 | target_height + swept_capsule | height、bottom_width、top_width | 完全相同 |
| 城堡/另一沙模 | target_height + height_stamp | 模板、缩放、旋转、高度 | 完全相同 |
| 窄沟铲/宽沟铲 | transfer + swept_capsule | trench_width、depth、shoulder_width | 完全相同 |
| 平滑刷/压实刷 | redistribute或field_adjust + disk | radius、strength、material策略 | 适用字段阶段复用，其余由公共规则跳过 |

遇到既有原语不能表达的算法：新增通用原语注册项与候选实现，写清输入/输出、边界、守恒和负例；必须由公共执行器调用，不能新增道具专属controller、water_transaction、commit或save类。不要为了强行配置化引入任意表达式语言或上百个无约束布尔组合。

## C03：命令、候选、结果字段

本地API：submit_intent(intent) → admission；结果通过同一完成通道以command_id查询/消费。兼容旧公开API的适配器可以保留，适配后不保留schema-v1/v2执行分支。无HTTP/OpenAPI。

| Intent字段 | 类型 | 规则 |
|---|---|---|
| domain_id, generation | StringName,int64 | 当前域与代次；旧代拒绝，ID不得转float |
| command_id, sim_tick | int64 | 保留单调ID与现有排序；溢出明确失败，不回绕 |
| profile_id, profile_version, profile_hash | 注册身份 | 准入时验证、冻结有效值，排队后修改资源不影响已接纳命令 |
| transform/path | Vector2/Vector3/角度/缩放 | 有限、有界，世界XZ/Y和米单位保持 |
| parameters | 白名单键值 | 只覆盖profile允许字段，未知键拒绝 |
| stroke_id, baseline_token, sample_index | 可选int64 | 需笔画状态时必填且有序；begin/end进入同一队列 |
| source_context | 来源诊断 | UI/API/测试等，只作诊断，不决定后端 |

admission返回{accepted:bool,command_id,error}，只表示准入；错误至少覆盖invalid_profile、invalid_parameters、unsupported_combination、queue_full、results_backpressure、stale_generation、invalid_stroke、closing、backend_failed，并在兼容API映射到原错误语义。未知能力必须拒绝，不能fallback。T05终端保留容量512：接纳时预留结果位置，result(id)只读，take_result(id)取走终端结果并归还容量；没有消费前不静默淘汰。取消结果也占预留位置。满载只背压新准入，不阻挡已接纳命令、控制或GPU后继执行；在途未知结果不制造业务回执来释放容量。

公共GPU Candidate表达：修改前/后的沙或悬沙、field_mask、影响tile/cell、形状权重/方向、材料候选、笔画coverage候选；Summary表达：实际增减/搬运量、touched量化界、分配统计、非法标志、实际脏块。附加搬运scratch由通用原语持有，不能要求所有工具读取未初始化字段。

候选局部存储必须有明确的本次有效范围/代次，未覆盖格从当前权威读取，不能残留上一命令候选。墙可能重新约束本笔累计coverage，范围不能只取最新线段；完整候选不等于强制全域做昂贵算法。

| Result字段 | 含义 |
|---|---|
| identity | domain、generation、command_id、batch/slot/lease |
| outcome, error_code | applied / no_change / rejected；内部fatal/unknown属于执行状态，不伪装业务拒绝 |
| input_revision, output_revision, applied_tick, state_seq | GPU实际执行与完成版本，不能CPU预测前一笔成功 |
| changed_fields, dirty_chunk_mask | 已提交实际变化，含碰撞共享边；水tick后续变化另行合并 |
| volume_summary | 实际增减量、source/sink、transfer/左右接收量、相应误差预算 |
| ledger_precision | 按既有公共语义区分估算/精确；不静默把近似账本推广到守恒搬运或库存 |
| completion_phase | gpu_complete；collision_applied另有版本，不能混为一个完成位 |

GPU ABI需在T01冻结字节布局、版本/stride、最大批次、每槽输入/结果容量、溢出和长度验证。当前128B普通命令与256B工具命令以及80/336B完成不能直接相互解释；扩展统一格式时同步调整槽分配、编码/解码、restore重建及故障注入。源签名与检查点版本策略一起验证。

## C04：公共数值阶段与提交

固定逻辑顺序：读取完整输入 → 生成操作候选（可含原语所需迭代）→ 材料/水响应候选 → 统一归约及业务不变量校验 → 条件提交 → 结果/版本 → 批末发布。阶段需要多个dispatch时由公共执行器安排；单核/多核是实现细节，不产生第二套业务事务。

- 普通挖沙保留当前最多4轮权重重分配；填沙保留体积/强度和准入预算。城堡固定世界标高、低填高留、重复不叠高；墙保留固定基准与覆盖历史。
- 铲子必须整笔供受体共同验证，removed=left+right及两侧分配在已冻结预算内，源汇不变。并行化允许改归约实现，但须先明确确定性/量化容差并回归，禁止无序浮点atomic决定分布。
- 公共材料阶段维护tag深度、reference高度及R16F压实语义。no_change可能仍需更新笔画coverage，但不得伪造沙量变化或错误推进权威revision。
- 水响应统一消费old_bed/new_bed、水深、悬沙、动量和障碍；保留已验证速度归约、参数复用和无排水需求快路。连通水域影响可超出编辑矩形；只在GPU证明无需求/不影响时跳过计算。
- 形状私有全场串行water_merge迁为公共分块校验；普通工具也要满足适用的公共校验要求，不能通过删除形状检查来实现“统一”。同一套归约基础设施支持各原语的不变量。
- 所有验证先于权威写入；沙、水、材料、coverage等关联候选按同一决定提交或拒绝。一个批次含多笔不等于全部命令合成一笔：每笔按顺序应用，业务拒绝不阻挡有效后继，fatal则禁止后继写入。
- 实际脏块来自已提交字段差异。保留touched格的数值预算，不能为了缩小碰撞量把数值预算改为changed-only。

## C05：批次、碰撞和消费者

工具共享有界批次、一次上传、每笔结果槽及批末完整发布。常规后继不等CPU逐笔ACK或物理追平；快照/外部CPU精确读取等边界等待真正依赖。批次大小/时间预算由公共配置决定，不能按道具名特判。

actual dirty mask与当前state_seq绑定，延迟到达仍需合并，不能清掉后续编辑/水模拟产生的脏块；范围覆盖共享边和边角。物理可消费较新的完整高度快照，记录真实来源版本。两个高度槽饱和时背压保留脏块，不丢请求，不占着主线程等读回。表现/预览/碎石消费同generation完整状态；不为每道具新增读回和发布循环。

T05候选实现使用每个完整工作单元的实际沙床前后差，不以水/动量/材料变化扩大碰撞范围；固定rock在该域内不变。GPU保留64块各自clean/dirty/borrowed状态和最后变脏state_seq，只有已借出快照的最后消费者确认后才释放borrowed；若期间又变脏，确认只恢复dirty，不能清掉新变化。两个高度槽各最多16块、固定69828B独立v2高度快照（与统一命令ABI v1分开），包含generation/snapshot_seq/state_seq/tick/revision、实际块ID和33×33高度；不足16块的尾部不消费。未知读回保留原槽并重读同一输出，不重放执行/捕获；坏包或worker非有限值经GPU确认将原块重列dirty。

批末公共发布在work_seal之后录制，GPU fatal guard同时保护published_sand/published_water及32B完成戳[gen,state_seq,revision,tick]（各int64两uint32）。批中途fatal可保留此前已提交的有效权威写入，但不得覆盖上一完整公开显示态或伪造完成结果。publication_count是CPU录制尝试数，实际公开版本以GPU完成戳为准；正式表现绑定和恢复仍须由G6/G8验证。

T05的views统一消费者在同一封口后读取完成场并发布材料、悬沙、动量、flux及baseline/stroke副本。bind_material只绑定同组已注册字段并持有读者所有权；解绑恢复调用方参数，经过render帧边界及真实有序设备证明后才解除资源持有。预览使用一个有界96B结果通道、冻结Intent和同一模板表，不进入编辑队列，也不改变权威版本或结果容量。返回actual GPU generation/state_seq/revision/tick/time，允许领先CPU完成消费；上层须使用实际版本及错误/flags，不将统计当准入保证。上下文/版本过期和关闭明确拒绝缓存，未知读回重读原输出，不重新捕获；已销毁接收者不再调用。正式UI实时就绪策略、表现能力及恢复换代在G6/G8验收。

## C06：生命周期、唯一正式路径与兼容

begin/end/cancel、保存、候选恢复、切场景、退出都依赖统一域的所有权记录。取消只撤销尚未提交工作，已提交未知结果不重放；没有最后消费者证明不能释放RID。恢复构建独立候选，完整验证后原子替换域与消费者绑定，失败保留原场景。

T06候选组件增加`domain_runtime.gd`与预制双槽场景：候选碰撞槽禁止碰撞，完整64块同代同版后，在同一主线程物理提交中同步恢复旧材质原参数、绑定新材质并切换碰撞。旧槽须完成旧高度/预览/材质GPU终结后才能复用；高度回调携带generation，复用时重置旧版本表。旧GPU释放不删除未领取终结结果；按generation/command_id转交CPU档案，全部代次合计最多512条，领取归还容量。仅有生命周期证明的已录制工作保持unknown，不伪造outcome。该组件不代表正式UI、开笔/关闭所有组合及启用能力已接线，见[证据边界](../验收/G6_消费者交接.md)。

正式路径移除async_pipeline_enabled/edit_frame_pipeline_enabled作为后端选择开关以及legacy桥接/旧CPU patch执行分支。保留必要诊断/效果开关。消除继承链可达的旧写点，不能只把开关固定true仍留下可调用旁路；旧测试参考单独隔离。启动失败明确报错，绝不静默创建旧editor。

旧存档格式支持由显式适配器转换数据并经过新候选校验；未知格式/源码身份拒绝，不伪造hash。当前已有旧存档兼容能力是否全部可保留须在T01列明；不能因移除旧执行器而悄然丢失已承诺的数据迁移。正式入口/恢复只初始化新路径所需资源，清理旧备份/rollback/bridge资源后重验部分初始化和退出。

## C07：成本与证据

阶段耗时、CPU录制、队列年龄、输入到GPU/首见/碰撞时间分别记录。先按T00测量冻结本轮成本目标；未经测量不承诺固定FPS。保留完整负载、输出尺寸、同初态/输入和采样开关对照；功能PASS不改写旧性能FAIL。改归约/局部化必须对应数值对照及实际阶段成本，只有短测不能宣称长稳。

## C08：防分叉规则

检查正式场景可达依赖图及权威写入点，而不只搜索legacy字符串。公共调度/提交/发布/恢复层不得引用工具ID或具体ToolProfile资源路径；按operation原语和field_mask选择算法可以。新增profile后这些核心文件hash必须不变。

至少用三种仅配置夹具证明复用：宽填沙笔、另一高度模板、另一沟宽/深度的搬运刷。验证默认/边界参数、功能开关有效值、非法组合拒绝，并比较标准化阶段轨迹：除必要能力阶段启停和原语内部迭代外，提交/发布/碰撞/生命周期节点相同。测试专用违规模块应能被架构检查抓住：按工具ID分流、私有RD写入、旧fallback、私有碰撞等待。夹具不接正式游戏菜单。


## T06启用显示历史的实现边界

公共Water末段可按冻结配置更新foam、local-front窄/宽和gravel；需要上一拍水深/床面的local-front显式保留foam历史依赖。历史与只读公开槽分离，公开复制受work_seal后的fatal guard约束，与沙水同完成态；纯编辑最终床面的gravel重投影不推进时间。所有RID纳入已有Water所有权，快照与恢复登记实际显示历史和公开槽回读，不能用CPU零数组替代启用历史。恢复保留视觉current_index及非当前槽原字节，gravel profile须匹配当前冻结配置。实际能力与负例证据见[启用表现报告](../验收/G6_启用表现.md)；边界/正式UI及碎石生成意图仍待接线。


## T06潮汐/波浪配置与生命周期

启用边界通过冻结environment.boundary绑定实际main/test1/geometry参数，geometry mode3核与现有初态/水循环资源一起建立身份。wave声明使用独立递增request_id和128容量，保留原名义tick到实际时钟的起点映射；每个排队水步及未来编辑隐式水步携带准入时的波包快照，后来的声明不得改变旧步。统一recorder在对应水步前有序上传，不增加第二个权威pump或CPU回执授权。保存排空后固化声明并回读实际2048B波浪缓冲，校验有效数据与零尾部；native恢复保留起点时钟/highwater并换代声明身份，再核对缓冲。边界本身沿用项目现有Godot适配，不冒称原作周期；当前证据和精度边界见[报告](../验收/G6_潮汐波浪边界.md)。
