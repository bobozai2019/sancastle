# 旧档路由与固定来源目录

此契约补充C06。迁移经过“容器读取与旧数据验证 → 投影 → 统一候选构建与比对 → 物理阶段交接”，不构建旧控制器、旧场景或旧求解器。正式入口是否切换由T06验收单独判断。

## 来源身份

`assets/unified_edit/legacy_source_catalog.variant`保存两份已验证真实旧档的完整来源配置和原始夹具路径/SHA256；对应JSON保存提取工具与产物身份。目录由离线`bake_legacy_catalog.gd`读取旧格式并验证后生成，已有文件不覆盖。Variant保存原有数据类型，不通过JSON重建配置。

`checkpoint_router.gd`固定目录路径与SHA256，并由候选场景配置冻结这两个文件。运行时不需要开发用`test_output`夹具；待打开的旧档必须与目录中的某一来源配置精确一致，再通过旧格式的完整数据验证。来源配置允许同一已知旧实现产生的不同存档，不要求每份存档等于原始夹具hash。未知来源、缺失或修改后的目录均明确拒绝，不能用待打开文件为自己建立信任。

## 格式与适用范围

| 文件头 | 路由 | 保留与限制 |
|---|---|---|
| SANDUE06 | 原生Codec.load | 当前完整配置和来源hash必须匹配，不自动接受此前源码版本 |
| SANDGP05 | 已知edit5/native3 → 数据投影 | 保留原始物理字节、实际时钟/seq/账本及来源；目标域与物理配置须兼容 |
| SANDCP01 | 已知edit4/native2 → 数据投影 | 只支持已验证的v4/v2，原始字段与prefix保留；新seq从0开始，时钟按f32(tick/30)明确映射 |
| 其他或截断头 | 明确错误 | 不按后缀、字节长度或猜测版本选择执行流程 |

投影不等于运行时恢复成功。统一后端继续检查边界状态、碎石profile、普通凝聚阈值、epoch及全部物理/显示数据；候选验证成功后才换入材质与碰撞槽。其他域的档不能跨域恢复。目录不是通用历史版本兼容承诺；新增来源须先取证验证，再更新固定目录和发布hash。

## 换代元数据

物理control中的generation、波请求generation及碎石source_generation按新epoch重绑。碎石v1在新保存中以v2写出，active_count取旧count；已有v2保留实际active_count。碎石state_0/state_1、profile、current_index、tick与revision保持原值。比较必须逐字段区分这些明确的元数据变更，不能要求整个扩展字典与旧档相等，也不能因此跳过原始数据检查。

恢复后仍经公共输入、记录、发布与保存路径工作，旧域按已有读者与解绑证明退休。失败不退回旧运行实现。未修改水沙算法、权威账本或物理ABI。
