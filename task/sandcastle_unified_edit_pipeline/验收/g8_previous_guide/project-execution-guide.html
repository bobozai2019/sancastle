02 / 初始化

启动到 ready：资源先就绪，输入再开放

场景、UI层级、固定资源和信号连接来自 .tscn/.tres。运行时创建的是 RD 纹理、缓冲、求解器与协调对象；没有在 _ready 中重建固定 UI。

03 / 普通帧

每帧调度：就绪消费、有限提交、独立物理应用

正常路径避免应用层等待上一批CPU验收。固定容量形成背压：槽忙时本次不提交，输入保留；已有GPU工作继续。GPU对共享scratch保持单一有序录制与执行。

pump 的实际提交优先级

poll：按 batch_seq 消费已经就绪的通知
pump：ready / 非 frozen / 无错误时才进入
  1. 显式水 tick（有界请求）
  2. 保存/恢复边界：只补足已接纳 future 命令到期所需 tick
  3. 实时模式中，上次因满槽欠下的 water_owed
  4. 本渲染帧尚未提交过编辑 → 普通前缀或队首工具工作
  5. 若本帧还没提交水且自动累计到期 → 尝试 water tick
  6. 尝试 pending 高度快照；满槽继续记脏

所有 edit/tool/water 工作共用3个槽；一帧最多一次编辑或工具提交，水工作优先级用于防饥饿。工具不进入legacy，实时笔画期间水模拟继续。根入口仍调用 super._process 处理继承功能，新模式禁止基类再启动第二套自动水tick。物理消费由独立 _physics_process 阶段调用。

04 / 命令接纳

从鼠标到GPU批次：身份、模式和拒收边界

所有操作进入同一有界队列。schema-v1的床面/悬沙挖填可取同策略批次；形状、平滑、压实和碎石作为独立工具工作，共享相同槽、GPU顺序与碰撞发布机制。

标识表示什么不能用来替代什么
domain_id场景域身份不能只凭同一场景名跨域恢复
generation场景/恢复代次旧回调不能回写新场景
command_id已接纳命令顺序，高水位单调不是成功笔数，拒绝也不重用身份
batch_seq + slot_id + lease_id工作单元与当前槽租约slot_id单独不能证明当前所有权
state_seqGPU seal后的完整工作序号不等于sim_tick或revision
sim_tick / revision水tick计数 / 求解器修订不能当作每块碰撞已追平的证明
snapshot_seq不可变高度请求身份不是全场统一物理版本
05 / GPU 编辑

候选先验证，成功才写权威场

一次批量上传保留笔段顺序，不把多笔体积融合成一次求解。A成功、B拒绝、C成功时，B不污染权威状态，C读取A完成后的真实GPU控制状态继续执行。

账本与公开接口

普通自由编辑按已记录提交的名义体积×strength更新近似源汇，只计一次；正常GPU拒绝也可能保留名义估算，不能以严格闭合误差阻止普通发布。提交前明确失败不记该名义量。。公开 是等待自身 command_id/generation 终端结果的便捷协程；普通UI只入队，不逐笔await。真实故障/关闭/换代返回明确错误，不等待实时管线全局idle，也不伪造成功。

06 / 水沙 Tick

GPU决定子步，全部关联阶段消费同一实际时间

CPU为一个名义1/30秒tick记录有界的64段间接工作。GPU决定有效N和actual_dt；未使用的子步组数为0。边界写入前先做安全CFL判断，边界后再次归约，整个过程不离开GPU序列。

GPU决策safe_dt = courant × cell_size / max_speed
N = clamp(ceil(requested_dt / safe_dt), 1, 64)
actual_dt = min(requested_dt, 64 × safe_dt)
substep_dt = actual_dt / N

超过64子步需求时缩短实际推进时间；不能把tick数/30当作真实表现时间。侵蚀/沉积的小步比例保持1−exp(−rate×dt)语义，使用小量稳定展开避免float32相消。local-front读取当前水沙及上一泡沫/床面，然后更新泡沫；碎石只读权威水沙，使用本tick实际dt并归一自己的历史。

资源/时钟写入位置使用者
GPU control / decisionCFL、sim_finish、seal后继GPU工作、异步CPU完成镜像
1×1 R32F completed_clocksealasync水/沙静态派生shader；暂停保持完成时间
稳定发布纹理 / Texture2DRD完整工作边界沙面、水面、相关显示层；不等CPU账本授权
CPU shadow保留旧模式和初始化/恢复容器；默认工具不请求同步不是编辑、形状或水tick的逐笔准入条件
07 / 异步碰撞

实际床面快照：GPU继续写，CPU之后装形状

pending表示尚需采集的脏块，in-flight表示已拍下的不可变快照。两者必须分开：同块新修改不能因旧请求在途而丢失；不同块也不能互相覆盖。

情形处理验证含义
槽满保留pending，之后重新拍最新高度不得封锁所有GPU写入
普通拒绝笔仍按保守范围请求高度不假设拒绝代表无需刷新
同块旧结果晚到按每块state_seq过滤不能用单一全场watermark覆盖所有块
坏长度/NaN/旧代次不污染shape；适用时重记脏保留上一份合法碰撞
停手收尾停止输入及自动地形改变，排空pending和in-flight最终逐点等于当前GPU rock+sand；不承诺固定落后帧数
08 / 全工具流水线

形状、平滑、压实和碎石共用有序GPU工作流

沙墙、城堡、守恒铲子、平滑/压实和投碎石以独立工具信封提交；投流沙已并入普通编辑批次。工具与水tick共享3个工作槽，不暂停整笔画墙期间的水模拟。

形状基准/coverage按笔画保留；铲子按原采样段分配实际挖出量，不按忙闲改成长段。平滑在GPU使用加权目标和校正，并协调材料tag/reference双槽；与旧CPU double实现按float32误差及守恒边界验证。压实写R16F；碎石只改表现状态，允许多个投放在通知前接纳。细节见 全工具迁移。

09 / 保存与恢复

完整状态快照和独立候选：不用逐笔重放

保存读取完整完成态；恢复先验证私有输入，再创建独立资源候选，确认原生数据后发布。提交前失败保留旧状态；发布后致命错误停止新所有者，不能声称已回滚。

子记录保存内容适用边界
edit v5 / native v3权威fields与spare、材料双槽、泡沫/床面、local-front、control当前槽规范为0；大小/有限值/身份严格校验
运行元数据state_seq/tick/revision/actual_time、近似账本、选择、高水位、波请求时钟不依赖旧prefix、撤销或逐笔重演
visual_extensions.gravel_v1独立碎石profile/状态双槽/active_count表现子记录，不混入沙量
受支持旧v4/nativev2原Store/BeachRecovery/BrushCodec验证后投影只迁移相容引擎/源码/资源；不伪造回执
local-front浮点边界保留原始RG32F字节，允许已推导的质心归约舍入上界NaN/Inf/负值和明显越界仍拒绝；不裁剪或量化
未覆盖开关structures、rise_front、contact_history明确unsupported，不能遗漏记录后假装恢复成功
10 / 切换与退出

场景销毁的条件是最后消费者完成

BeachScenes持有会话进度和当前场景身份。正常切换先保存、释放旧场景，再准备目标；新旧场景不并行写共享后端。文件扩展名可能仍是 .sandcp，格式识别依赖magic而不是扩展名。

异常分类处理策略禁止的替代做法
正常GPU命令拒绝只跳过本笔，后续继续不能当成设备错误整批回滚
明确提交前失败unrecorded_abort、回收未记录租约不记成功或名义源汇，不伪造完成
已记录但完成读回注册失败停止管线；独立有序终结证明后清理不因返回错误而重发可能已执行的命令
坏协议/身份/时间/错误标志不正常consume，不推进CPU成功状态不拿终结payload修复回执
工作/高度/捕获/候选/旧工具所有者每个通道分别确认最后消费者不能用新records为空证明所有资源可free
真实驱动失效保留明确未测试边界；本轮仅可控注入不能把注入PASS写成真实驱动重置恢复已验
