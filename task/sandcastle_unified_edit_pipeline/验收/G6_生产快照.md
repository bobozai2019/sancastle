# G6公共生产快照、账本与保存

日期：2026-10-18。角色：verification_report。本轮[生产快照组件](G6_生产快照组件.json)通过，实现公共生产API，不再由探针手工构造保存数据。**完整G6仍未通过，整体24/36、T06仍0/4。**正式三入口尚未切换，实际消费者原子切换及启用表现/边界能力仍缺。

## 已实施与验证的公共行为

`Pipeline.request_checkpoint(selection, callback)`和`save_checkpoint(path, selection, callback)`共用唯一pump。保存暂时阻止新的编辑/control/tick，排空已接纳工作并完成账本结算；活动笔画通过相同Intent、transport、执行器和GPU结果结束。内部END只使用公共工作/结果缓冲，不占公开终端保留容量，已完成但未领取的结果全部保留。保存结束后上层通过command_highwater分配新ID，不重用内部END的ID。

`checkpoint_capture.gd`仅借用26份现有GPU字段/完成戳/时钟/笔画读回；对齐CPU实际消费版本、published/current场及immutable输入，再完整校验并写真实SANDUE06容器。`checkpoint_accounting.gd`维护非权威历史元数据：普通volume在确认录制时按f64请求量记估算，包括业务拒绝；target按验证后的GPU实际结果记源汇；取消、transfer、smooth、compact不产生外部库存。水账本保留f64历史锚点，叠加原始GPU累计值的实际增量，缓存附water_state_seq。

## 保留的失败及修复

UEP-LEDGER-ROUND-001：合法amount=0.01、strength=0.7，GPU按各自已编码f32值相乘，原始回执source为0.00699999975040555；旧CPU验证先f64相乘再舍入，得到0.007000000216066837，错误报告result_approximate_ledger。证据：`g6_capture_quantized_fail03/checkpoint_quantized/failed_quantized_completion.bin`，96B完成头后的首条384B结果，source_m3相对结果偏移148。失败报告及原源码ZIP保留，02的探针缺少故障退出清理、03已修正该夹具并保留完整回执。

观察事实C3；单变量修复`protocol.gd::gpu_nominal`按实际编码参数量化顺序验证，未修改GPU公式、原数值预算或f64历史估算规则。最终quantized用例通过完整生产保存/恢复/继续/二次快照；212项协议数据回归通过。

`g6_capture_matrix05`的corrupt负例预期不匹配保留：异步buffer回调可先于texture回调，原“首回调翻转一字节”实际改到control，正确被invalid_pipeline_control拒绝；后续将该注入明确定位到immutable rock来验证CRC，未放宽生产校验。

`g6_capture_spine07/upload`仍要求known-unrecorded无任何终态，已按新的明确aborted语义更新：它不是GPU业务结果，可领取并归还保留容量；未知录制则仍不得伪造结果。旧失败保留，未修改运行结果来迁就旧断言。

独立审计07首版用JSON近似f64与原二进制严格比较产生误报；新夹具输出原Variant账本/结果，独立解码后严格比较，旧审计结果保持FAIL，不放宽物理量预算。
