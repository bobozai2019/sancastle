# MUSCL developer measurements

These tools attach optional diagnostics to the existing recorder. Normal game startup leaves the observer unset. The recorder retains its standard coupling Callable and descriptor cache.

`baseline.py`, `isolate.py`, `run_abba.py`, `compare_abba.py`, and `run_restart.py` accept `--task-root` and `--temp-root`. Pass both explicitly for a new round; omitted arguments retain round-two destinations. `freeze --parameter-source <directory>` reads an explicit startup/window pair without changing the user's files. Each task owns its own baseline archive, reference sources and retained evidence. The archived baseline remains immutable even when developer probes are subsequently extended.

Round three uses `prepare_round3.py` to retain each candidate's diff and source hashes, `validate_round3.py` for serial byte/fault/lifecycle gates before cost, and `restart_readers.py --case ordinary|molded` for one writer and three independent readers. The molded fixture verifies nonzero tags in the actual checkpoint. `first-order` tests the shared coupling path with support appearing and disappearing. Historical `prepare_t03`–`prepare_t06`, screening and final-audit scripts remain round-two reproduction entry points; use the round-three entry points for new work.

`baseline.py freeze` creates the immutable round baseline once. `isolate.py --name <new> --diagnostic` reconstructs that baseline in a new temporary project and overlays the current recorder and developer tools. It copies referenced imported resources, rather than linking live caches. Source archives and retained evidence belong to the task acceptance directory; temporary projects can be regenerated.

The current-numerics overlay keeps Water/Muscl/numerics/coupled scripts and MUSCL shaders together, including private layouts. To reproduce a retained historical candidate, prefer `--overlay-root <acceptance directory>/sources` with its immutable project-relative files; do not copy an old recorder onto incompatible new shader bindings.

Run `baseline.py <mode> --run-id <new> --source-root <isolated project>` with modes `scene`, `exact`, `diagnostic`, `diagnostic-exact`, `diagnostic-lifecycle`, or `dependency`. Each run uses its own copy of startup/window parameters and verifies the actual user files afterwards. Source changes during a run invalidate comparison even when numerical fields match.

`cost` measures the existing whole-tick profile intervals without wrapping standard coupling. `run_abba.py --a <project> --b <project> --prefix <new> --mode cost` runs four independent A→B→B→A processes. `analyze_cost.py` joins GPU batch labels to actual completion time deltas and CPU recording durations; generation and recording sequence are captured by the developer timeline. Its CPU submission bounds include more work than the recorder duration and must remain separate. Uncollected substep counts and recorder interval endpoints are null, not inferred from requested dt or submission timestamps. `compare_abba.py` reports identity checks, paired gains and baseline noise; it does not waive architecture/numerical gates or establish normal-window FPS from diagnostic runs.

Normal `scene` measures the formal visible scene with detailed diagnostics off. `diagnostic` samples one candidate slot every eight recording ticks, rotating through 64 slots for 40 seconds. `--duration 10 --cpu-only` records CPU intervals with no GPU marker/snapshot sampling. Diagnostic FPS is not a normal-path performance result.

`analyze_diagnostic.py <run directory>` joins immutable audit snapshots to actual completion events and same-frame timestamp pairs. Missing, duplicate, conflicting or cross-frame samples are excluded with counts. CPU intervals use monotonic microseconds; GPU intervals use nanoseconds. Never subtract or add across these clocks, and never add nested spans to their whole-tick parent.

The observer owns four 2240-byte staging buffers, up to 1024 samples and 4096 CPU intervals. Saturation drops diagnostics. Close blocks new sampling and frees an outstanding buffer only after its callback. Staging payload is 8960 bytes; driver physical allocation is not inferred from this payload size.

`exact` compares the original public double slots and control/audit fields against the explicit frozen reference. Its borrowed uniform-set mechanism requires compatible private layouts. A candidate that changes those layouts must use independent initialization of each version, never force old shaders onto incompatible sets or remove spare-slot comparisons.

`variant` independently constructs one version and archives every captured original field, both slots and CPU completion/ledger in `states.zip`; `compare_variant_states.py` decompresses and byte-compares the versions. Additional retry-cache members remain explicit. Synthetic inputs use GPU copy plus exact readback because production textures lack CAN_UPDATE. Unexpected engine error log lines invalidate a run even when its process returned zero.

`formal-states` holds the formal scene at tick zero and compares fixed public tick requests with complete scene configuration. `restart`/`run_restart.py` save and resume in separate processes with unchanged source identity; retry scratch must be zero after restoration. `flat` measures only no-retry overhead on a uniform domain; its GPU counter verifies zero rejected trials and zero retry-cache hits over the run. It is not a full-game FPS benchmark. Optional `--telemetry` records read-only NVIDIA clock/temperature samples, without changing driver settings.

`formal-inputs` adds a wave at completed tick 10 and public shovel strokes at ticks 40/70 to the formal byte-capture probe. Use `--scene res://scenes/main.tscn` for main; `--case` selects probe cases and does not select a scene. `input-cost --case wave|shovel` measures the two workloads separately with one outstanding manual water tick, a visible full scene, original coupling and whole-tick timing. It has no state readbacks during measurement; its FPS is not ordinary realtime scheduling FPS. `run_final_inputs.py` records serial ABBA sets against the frozen original and retained candidate. Byte comparisons and performance measurements remain separate.

`continuous` records one 120-second visible scene run, 24 RD memory samples, queue counts, pause/resume and final release. It does not prove unlimited stability or constant total driver memory. `main-live` uses normal main scheduling and records active props receiving same-generation completed Probe samples. `run_final_lifecycle.py --prefix <new>` runs current-workspace formal main inputs, continuous scene and cold restart in sequence; every evidence prefix must be fresh.
