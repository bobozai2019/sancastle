# 沙面湿痕

场景1 `main`（域 `main_beach`）与场景2 `test1_geometry` 默认启用独立表面湿痕。两场景各自的正式及 unified_edit playable 入口的 `surface_wetness_enabled=true` 进入冻结的 `environment.surface_wetness_profile`，presentation 的沙材质启用 `use_surface_wetness` 并绑定 `surface_wetness_state`。关闭该功能的配置保持原物理湿度颜色响应，不分配该纹理。

## 表现与物理分工

原有 R16F wetness 仍参与压实、侵蚀与坡面稳定等物理过程。表面湿痕 M 是独立的无量纲 [0,1] 外观记忆，不是水体积或沙层含水量；不回写水沙、动量、材料、源汇或账本。

| 参数 | 当前值 |
|---|---:|
| 接触起点/充分接触水深 | 0.001 / 0.003 m |
| 湿痕从0到1的充分接触时间 | 0.75 模拟秒 |
| 完整湿色保持时间 | 默认18模拟秒，可设0–300秒 |
| 湿色褪色时间 | 默认12模拟秒，可设0.1–300秒 |
| 完整湿色阈值 | M=0.4 |
| 新表面重置床高变化阈值 | 单次完成工作0.005 m |
| 不记录湿痕的沙厚上限 | 0.02 m |

q=`smoothstep(0.001,0.003,max(water,0))`。q>0 时 M=`min(1,M+actual_dt*q/0.75)`，无接触时先将 M>0.4 部分按 `0.6/hold_time_s` 衰减，再将 M≤0.4 部分按 `0.4/fade_time_s` 衰减；同一tick跨越阈值时把剩余dt用于褪色，保持时间为0则跳过保持段。着色权重为 `smoothstep(0,0.4,M)`，在既有干/湿色端点之间完整混合；`use_wet_finish=false` 时仍显示干色，但不清空历史。关闭表面湿痕时沿用 `wetness×0.65`。

默认配置下充分接触时约0.3秒达到全湿颜色，0.75秒饱和；从饱和状态退水，约18秒保持全湿色，再经12秒褪色。短时覆水历史较少，消失更快。所有时长按成功工作实际推进时间计算，具有一个tick的采样离散误差；暂停不按墙钟干燥。参数属于本项目适配，不能视为竞品实测时长。

## 资源与发布

[surface_wetness.gd](../scripts/simulation/unified_edit/surface_wetness.gd)定义严格profile、初始化与扩展数据验证；[publish_wet_sand.glsl](../scripts/simulation/unified_edit/publish_wet_sand.glsl)在既有发布阶段更新历史。State拥有单张256² R32F纹理，原始数据262144 bytes，Views只读绑定，释放沿既有域退休及最后消费者证明执行。

更新发生在work_seal之后，`control[1]` 非零时不写入。每格先读取旧visible_sand和完成sand、水深、旧M，写回本格M及可见沙水。无邻格读写，因此无需候选副本、独立dispatch或每帧CPU回读。实际dt来自control[9]，编辑/显示工作由work_begin清零；表面明显改变时可以重置历史，但不推进干燥时间。

新域按现有水深初始化 `M=0.4*q`。新旧沙厚差绝对值超过5mm时也重新播种；沙厚≤2cm时M归零。rock在本域不可修改，因此沙厚差即床高差。湿痕绑定表面位置，不随搬运沙粒迁移，也不追踪多次低于阈值的累计表层更换。

片元采用线性过滤、域边缘clamp。tick内部曾短暂覆水但末态已干的格可能漏记；当前没有子步接触峰值或横向扩散。高光、粗糙度和法线链保持既有实现，沙材质仍禁用镜面；不能把湿色压暗描述为新增镜面反射。

## 保存与恢复

启用湿痕的配置写入SANDUE07，edit version7、native3、container1；未启用湿痕的配置继续写SANDUE06/version6。头部和完整性验证保持48B/32MiB上限与禁止对象反序列化。

v7的 `visual_extensions.wet_sand_v1` 严格包含version=1、domain_id、profile、tick、revision、source_generation、state。state为262144 bytes float32，必须有限且在[0,1]；身份必须与检查点完成态一致。保存沿公共排空/读回屏障读取，恢复直接初始化单张纹理并逐字节验证后才切换generation。不会从物理湿度估计新存档的历史。

旧文件仍受完整来源配置与已有离线迁移登记限制。原固定30秒的profile版本1存档不会自动转换为可调时间的profile版本2；来源或配置不匹配时按既有校验拒绝。旧v6没有该字段，不能恢复过去的退水湿痕，且未登记的新目标来源不会自动放行；目前不提供任意旧v6到两场景新配置的通用迁移。已通过原有受控legacy数据迁移的来源若进入启用配置，只能按保存水深生成接触种子，并在迁移策略中注明历史缺失。

“沙子参数”窗口提供“湿色保持时间（模拟秒）”与“湿色褪色时间（模拟秒）”，分别对应 `surface_wetness_hold_time_s` 和 `surface_wetness_fade_time_s`。两个场景独立保存参数；修改后点击保存并重启生效，当前域保持旧值，窗口显示待重启。保持时间针对饱和历史，短暂覆水可能没有完整保持段。profile版本2在启动前冻结，并随检查点保存实际的两项时间；恢复验证扩展profile与配置一致。当前仍使用单张纹理，发布通过16字节push constant传入时间，不增加dispatch。修改shader、profile或资源后须同步表现manifest和来源身份。纹理字节数是资源估算，不是帧耗时或驱动实际显存；完整场景的计算、发布和采样成本需要实测。
