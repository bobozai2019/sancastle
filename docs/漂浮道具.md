# main漂浮道具

正式main在场景中固定放置水瓶、木板、木棍各一件；三个test1入口不放置。G1–G6已通过，300秒连续观察、十轮生命周期、30组回归与三对可见成本均已完成，见[执行状态](../task/sandcastle_floating_props/执行状态.md)。这是本项目Godot适配，不是对竞品道具算法的还原。

## 使用与生命周期

直接启动main即可看到三件道具随水流运动、受浮力倾斜，并与沙地、其他道具碰撞。没有新增投放、拖拽或道具编辑UI；沙刷只拾取Terrain，不被道具挡住。三件的固定节点与资源保存在[组件场景](../scenes/components/floating_props.tscn)，服务不会在_ready重建节点。

暂停停止新的道具积分并在共同完成边界保持线速度、角速度和睡眠状态。暂停时仍能编辑沙床；填沙造成嵌入时允许有记录的有界解重叠，挖空或水重新覆盖会唤醒。正常运动由Jolt解算，不每帧吸附床面。

保存期间保持道具，但SANDUE06/native3检查点只保存已有水沙、账本和显示扩展，不保存道具姿态。成功恢复或重新进入main时，根据恢复后的床水和预存XZ重置三件；失败恢复保留原姿态、速度、睡眠和owner。道具发生独立故障时局部保持，水沙继续运行，可保存沙场或恢复清除故障。关闭会等待公共读者终结和资源退休证明。

## 数据与受力

服务只使用DomainRuntime公共只读批量probe和已有Height碰撞消费者，不拥有RenderingDevice、私有GPU队列或水沙写入点。单批最多32点，当前瓶2点、板4点、棍3点。每点读取同一完成态的床、水深、表面与局部动量；水深≤float32(0.001m)时水力为零，流速为q/max(h,float32(0.005m))。

浮力按点的有效体积与竖直浸没比例计算；阻力使用当前采样点相对水速度。重力只由原生Jolt施加一次。质量、COM、体积、阻力、摩擦、阻尼与采样点均来自精确脚本绑定的[Profile](../scripts/props/floating_prop_profile.gd)资源；通用服务不按类型名分支。

道具累计时间来自实际Jolt state.step；原生休眠省略回调的世界步另列sleep_step并保留边界证明。完成水时钟提供积分余额；局部保持不伪造已消费时间，生产队列和编辑准入不等待道具。查询位置可以按已测读回延迟做有界预测，只改变采样请求，交付后仍检查0.15秒、0.15米、0.35弧度预算。共线采样云只观察轴方向；水瓶和细棍的轴向滚动另受实体半径导出的全角速度界约束，横向方向速度仍≤8rad/s，点速度≤4m/s。

## 碰撞与版本

复用64块HeightMap及原有两槽读取、worker准备和物理线程赋值。道具足迹最多12个优先块，每批保留至少4次普通轮询机会，快照仍最多16块。Probe ABI3和Height快照ABI3携带保守累计床变上界，原始容量分别保持3200B和69828B。

初始化、编辑恢复要求同代所需碰撞版本已安装。受力允许使用较早碰撞快照的唯一例外，是原始完整33×33共享顶点变化上界证明总床面差≤5mm；旧水样和旧碰撞面的差共享这一个预算。未知、非有限或较大变化一律保持道具。Height压缩字段按向上舍入的区间处理，不能把上端点当作精确旧值相减。

填沙纠正只从真实沙床触发：下扫排除其他道具，上扫检查实际阻挡并在注册的三件之间传播同一个地形位移，单次最多2m。悬空邻体不能成为抬升依据，防止两件相互抬升。接触容差5mm，Jolt penetration_slop为2mm。

## 扩展与复验

新增类型优先使用同一Profile模型和静态预制体，确保碰撞体与采样点被足迹半径完整包住；超出三件/32点/12优先块须先调整容量契约和相关回归。改变质量、体积或采样云须重验静水、正反流、倾斜与实际时钟；改变生命周期或碰撞只重验受影响用例。

真实可见运行入口是`tools/floating_props/run_probe.py`；每次指定新输出目录，保留源码zip、引擎hash、原始JSON、日志、图片和drift判断。`verify_bottle.py`独立重算受力、真实时间、采样位移和可观察姿态角；`verify_height_bounds.py`从原始沙字节独立核对完整共享顶点上界。历史失败不覆盖，机器契约与完整报告见[任务验收](../task/sandcastle_floating_props/验收/README.md)。
