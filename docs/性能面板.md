## 数值口径

| 显示 | 来源及口径 |
|---|---|
| FPS、帧、峰值 | 半秒窗口内的实际主循环帧间隔，以单调墙钟计时；FPS为帧数/窗口时间，峰值是该窗口内最大帧间隔，不是历史p99 |
| CPU峰值、物理峰值 | Godot `Performance.TIME_PROCESS` / `TIME_PHYSICS_PROCESS` 最近约一秒内的最大处理/物理帧耗时，秒换算毫秒直接显示；不是平均每帧成本。物理阶段包含延迟回调和碰撞数据处理，两者不直接相加 |
| 渲染CPU/GPU | 开启主视口`viewport_set_measure_render_time`后读取其测量结果，窗口均值，单位ms；不覆盖所有脚本、GPU独立计算或异步等待 |
| 模拟tick/s、倍率、子步 | 当前完成tick增长/窗口墙钟秒；倍率为tick/s除以30；子步取最近已完成tick。恢复改变generation时重置窗口 |
| GPU阶段 | 已完成RenderDoc式时间戳对的差值；同一捕获帧内相同阶段的重复pass累加，再对窗口内含该阶段的帧取平均。因此不是单pass、单tick或每个显示帧的总成本 |
| 碰撞回读 | 最近完成一批GPU回读请求到回调的等待时间，包含异步排队，不能冒称纯GPU执行时间 |
| 碰撞CPU | 最近有效GPU回读批次的完整主线程处理：解码、有限值校验、分块切片、高度比较、形状更新及完成记录；不含异步回读等待 |
| 替换阶段、替换/跳过块数 | 完整回调内从分块切片到形状更新的子段耗时，以及该批实际替换/高度未变跳过的块数；该耗时不能与完整碰撞CPU相加，旧修订号忽略的块不计入两类 |

GPU阶段分组：`tide/cfl`为边界与步长，`edge/drain/update`为水流，`sediment`为侵蚀/沉积，`material`为湿润/沙坡，`foam`为白沫，`gauge/audit/sand_audit`为统计/审计，`tool/edit_*`为挖填沙，`collision`为碰撞打包。只有白沫补加了受`solver.profile_passes`控制的起止标记，其余复用现有计时点。阶段没有覆盖整个渲染与模拟流水线，也不与视口渲染数字直接相加。

本项目Godot4.7.2 D3D12的`get_captured_timestamp_gpu_time()`底层单位为纳秒，除以1,000,000转成毫秒。该单位由[Godot4.7 D3D12驱动实现](https://github.com/godotengine/godot/blob/4.7-stable/drivers/d3d12/rendering_device_driver_d3d12.cpp#L5130)核对；[Vulkan驱动](https://github.com/godotengine/godot/blob/4.7-stable/drivers/vulkan/rendering_device_driver_vulkan.cpp#L6105)也返回纳秒。类参考的微秒描述与该版本实现存在差异。视口计时口径见[RenderingServer参考](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-viewport-get-measured-render-time-gpu)。

## 状态与成本边界

默认采样开启；关闭“分阶段采样”、F6隐藏、初始化/恢复和退出时停止面板所属的计时标记，并恢复原先的solver/collision profiling标志，不覆盖命令行原已开启的profiling。主视口测量随采样开关同步。

读取时间戳在渲染线程进行，只读已完成结果，不调用`sync`、强制flush或新增水沙纹理回读。累计内存为固定分组字典，没有逐帧无限日志。对返回结果按采样epoch、generation及捕获帧标签过滤；跨恢复的旧帧或混合generation帧不进入当前显示。暂停时FPS继续更新，模拟速度降为0，阶段保留最后有效值并标记“上次”；没有有效样本显示“—”，不伪填0。

开启标记和视口测量存在采样成本，因此界面数值是当前实际启用状态下的观察结果。该任务未执行正式成本验收或性能优化，旧性能FAIL、长稳及严格冷恢复未知保持原判定。测试中的关闭VSync仅为测试运行配置，UI不会修改用户的VSync设置。

## 编辑器启动修复（2026-10-12）

用户直接点击编辑器调试后遇到`Class "SandcastleGpuFoamField" hides a global script class`。错误停在正式脚本第1行，但`.godot/global_script_class_cache.cfg`中的该类实际指向`test_output/main_profile_20261012_delivery/delivery_source_snapshot/scripts/visual/gpu_foam_field.gd`。原因是交付源码快照保留了`.gd`扩展名，编辑器扫描后把快照注册成同名全局类。先前进程测试完成在生成该快照之前，因此44项PASS没有覆盖交付产物生成后的编辑器扫描。

修复为：给`test_output/`与该源码快照目录添加`.gdignore`；将快照中的5个`.gd/.tscn`文件改名为`.gd.source/.tscn.source`，保留字节hash；更新快照索引并保留原索引副本`delivery_audit_before_editor_fix.json`。在现有编辑器执行资源扫描后，通过`EditorFileSystem.update_file("res://scripts/visual/gpu_foam_field.gd")`重新登记正式类，修正已有内存缓存；没有修改`.godot`缓存文件内容，也无需重启编辑器。正式运行脚本和水沙算法没有改变。

生成产物必须与Godot资源扫描隔离；源码快照默认使用`.source`后缀，不能把运行扩展名的副本直接放到可扫描目录。后续交付应在快照/报告生成后再复验编辑器直接启动。修复证据见`test_output/editor_profile_fix_20261012/`；此前操作检查和错误结果保持原记录。
