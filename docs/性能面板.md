# 当前性能面板

当前正式场景从“参数窗口 → 性能与诊断”查看统计，由 [parameter_service.gd](../scripts/parameters/parameter_service.gd) 持有采样和只读状态。统计不创建第二个求解器或GPU回读；原场景内性能面板不再实例化。

## 当前显示口径

| 显示 | 实际含义 |
|---|---|
| FPS、帧均值、P95 | 最近最多120个 `_process(delta)` 样本；FPS=1000/均值；P95取排序数组 `min(n−1,int(n×0.95))` 项 |
| 刷新 | 每0.25秒刷新；采样开关关闭时清空帧样本，状态仍刷新 |
| 模拟秒 / 运行或暂停 | Pipeline累计完成时间与入口播放状态 |
| 排队工作 / GPU在途 | pending_count / active_count |
| 完成态版本 / 完成tick | completed_state_seq / completed_tick，不能当作碰撞版本 |
| 未消费结果 | Runtime.result_reservations()，包含尚未领取的结果预留 |
| 最近消息 | 当前场景操作状态 |

面板没有显示当前完整CPU/GPU分阶段成本。隐藏HUD或关闭参数窗与停止采样不是同一操作；采样归服务所有，按sampling开关收集样本，不能套用旧面板“F6必然停止GPU采样”的说明。

## 性能判定

多原生窗口共享同一进程的帧间隔统计，不代表任意单窗GPU成本。窗口delta统计不能当模拟tick吞吐、GPU执行时间、输入到显示延迟或正式长稳P99。帧P95也不能替代固定条件旧新交替成本对照。暂停仍可能有编辑，GPU完成仍可能有碰撞读者。

成本口径与实现边界见[技术规格](当前技术规格.md#性能统计口径与限制)。变更数值、资源或显示负载后需要重新解释受影响的成本，不能把单次FPS读数当作稳定性能结论。

逐批次CPU回执、槽位、碰撞worker及GPU水响应可通过 `tools/unified_edit_pipeline/diagnose_shovel_latency.gd` 采集，并由 `analyze_shovel_latency.py` 分析。分帧高度应用按slice_id配对，按真实时间区间求帧内交集。诊断默认关闭，不增加产品面板采样。
