## ADR-001：生产水流求解器

- 日期：2026-09-28
- 状态：accepted
- 背景：虚拟管道实现成本低，保守浅水方程更能表达动量、反射和破坝。
- 决策：生产 GPU 后端采用保守二维浅水方程（带床面静水平衡、正水深出流限制、二维动量）；虚拟管道只保留 CPU 对照。海侧潮汐边界采用给定水位/零动量水库单元作为首版参考，后续须以流量/反射曲线复核。若 256² GPU 性能不达标，应优化 pass/内存访问或以新 ADR 调整目标，不默默降格为缺乏冲击行为的虚拟管道。
- 证据：`验收/S2_solver_comparison.csv` 七场景；`验收/S2_wall_reflection_curve.csv` 墙前反弹与开口；`验收/S2_closed_water_300s_{virtual_pipe,shallow_water}.csv` 五分钟静水；10 周期潮汐记录见 `验收/S2_求解器初步对照_20260928.md`。两者守恒均通过，但虚拟管道在 5 秒弯沟/开口/破坝与墙前冲击试验中显著迟缓；浅水墙前最大深约 0.417 m，回流 118 步，开口后下游进水。
- 成本：64² GDScript 对照中，浅水 CPU 时间约为虚拟管道的 2–4 倍；这不代表 256² GPU 耗时。T03 从原估算 2–3 周暂重估为 3–5 周，待 GPU 基线实测调整。
- 影响：T02、T03、状态与数据契约；新增二维动量权威状态。

## ADR-005：扫掠笔刷的体积与端点语义

- 日期：2026-09-28
- 状态：accepted
- 背景：鼠标跨格拖动只按离散点击取样会漏格；一条命令的 `amount_m3` 也不能随采样密度重复扣除。
- 决策：`shape=swept_segment` 时，`transform.position_m` 为起点，`transform.end_position_m` 为终点；按单元中心到闭线段的最短距离计算覆盖权重。`amount_m3` 是整条扫掠命令的总量，只在覆盖单元间归一化分配一次。端点在同一点时退化为圆笔刷。
- 影响：T01、Gate 1B 命令契约、固定种子重放。

## ADR-006：跨 tick 撤销的 CPU 参考语义

- 日期：2026-09-28
- 状态：accepted（仅 CPU 参考层；生产增量优化未完成）
- 背景：当前工具队列的全域快照只在命令应用 tick 内可安全恢复。水流推进后直接恢复旧 `SandWaterDomain` 会把水、潮汐账本和地形倒回过去，但浅水求解器的二维动量与场景 `tide_time` 仍在当前时刻，产生不一致状态。
- 决策：同 tick 最后一条命令维持快照快速撤销；跨 tick 从固定种子初态离屏全量重演到当前 tick，事务验证命令结果后才替换活跃领域、二维动量、潮汐相位与账本。被拒绝的后续命令也纳入重演，并要求结果状态不变；否则事务失败并保持原场景。只有暂停时接受撤销/重做。现有 JSON 仍只记录工具命令，不是完整检查点。
- 证据：`tests/run_scene_tests.gd` 验证跨 tick 无编辑对照、重做状态/账本哈希与被拒绝命令；`tests/run_history_stress.ps1` 的 100 命令/100 tick 测试通过，原始耗时见 `验收/T01_history_100_tick_stress.csv`。此 CPU 路径每次重演约 7 秒，不能直接用于 256² GPU 产品交互；T03/T08 须引入有界检查点/差分、显存与延迟验证。跨运行环境/存档重载后重放仍未验证。
- 影响：T01 G05、T03 权威状态/代际编号、T08 存档。

## ADR-011：T05 压实不改几何，材料 pass 位置

- 日期：2026-09-29
- 状态：accepted
- 背景：状态与数据契约 v1 把 T01–T04 的绘制高度固定为 `bed = rock + sand`，并规定“T05 若启用密度曲线，必须先以 ADR 定义体积重映射”。T05 引入的两条新物理都需要明确它们对几何和账本的影响：湿度/压实演化（T05 G01/G02）与守恒坡面松弛（T05 G03）。同时，`wetness`/`compaction` 存在求解器的 ping-pong 数组里，但只有水流子步会翻转索引。
- 决策：
  1. **不启用密度曲线。** T05 v1 保持 `bed = rock + sand`，压实度不改变绘制高度。压实通过两条既有路径起作用：`sediment_step.glsl` 的强度因子（压实 0→1 使 strength 从 0.7 升到 1.8，抗侵蚀能力更强）和坡面休止角（压实每单位增加 0.3 的 tan）。启用密度曲线需要同时定义邻水回填与沙账户不变的重映射事务，留待需要“压实可见变矮”的独立 ADR；届时按契约改 `sand_height = sand × ρ_ref/ρ_bulk(compaction)`。
  2. **材料 pass 排在侵蚀之后**（契约第 3 条“随后侵蚀/沉积、湿度/坡面等 pass”）。坡面松弛作用在侵蚀刚写出的沙层上，因此侵蚀下切引发的失稳在同一步内就开始松弛。
  3. **写备用槽再回拷。** 由于只有水流子步翻转 `current_index`，材料 pass 读当前槽、写备用槽，再由 `material_commit.glsl` 把备用槽拷回当前槽，使两个槽始终与求解器索引一致。代价是每子步多一次 256² 拷贝。
  4. **坡面松弛共享边只评估一次。** 两个单元用同一份输入算出同一个转移量，供体减、受体加，因此沙总量按构造不变；单边转移量再上限到供体存量的 1/4，使一格四条边之和不超过其存量，无需 clamp。湿度/压实用共享边交换做横向扩散，按契约只要求“有界”，不声明守恒。
- 证据：`tests/material/gpu_material_step_probe.gd`（`tests/material/run_gpu_material_step.ps1`）三项 64² 用例：湿度曲线（吸满 1.000、排到残值 0.050、单调连续）、坡面松弛（沙闭合 10.9e−6 m³ = 5.1 ppm、末段 1500 子步爬升 1e−6 m）、强度曲线（松散 1.2125 m³ vs 压实 0.4600 m³ vs 湿润 0.9623 m³ 侵蚀量）。256² 集成回归见 `验收/T05_GPU材料与坡面_20260929.md`。
- 成本：每水子步新增 3 次 256² dispatch（湿度/压实、坡面、回拷）。256² 耦合预览 150 tick 回归仍通过。
- 已知偏差：共享边交换只能重分配、不能改变均匀坡度，因此松弛后的坡面停在名义休止角之上约 2.4%（实测 0.086287 m vs 0.084250 m），且收敛是扩散式的（约 23 格坡面需 4000 子步量级）。若画面需要精确休止角，需要改为非对称松弛，届时另立 ADR。
- 影响：T04 的侵蚀强度此后随湿度/压实变化，T04 的既有数值证据须以新物理重跑（`tests/erosion/run_gpu_num09_reroute.ps1`）。T06 的构件强度可直接复用同一 strength 曲线。检查点必须携带 wetness/compaction，因此完整影子同步字段由沙/悬沙扩为四项。

## ADR-012：存档格式版本策略

- 日期：2026-09-29
- 状态：accepted
- 背景：`checkpoint_store.gd` 写 `MAGIC + u32 format_version + u32 payload_size + sha256 + payload`，外层信封与内层影子各带一个 `format_version`，当前都只有 v1。T08 G01 要求「一致 tick 快照与版本迁移」，但现场只有一个版本，没有可迁移的旧版本。
- 决策：**采用硬门而非迁移框架。** 版本不匹配一律拒绝（`invalid_envelope` / `invalid_shadow_header`），拒绝时保留活跃场景不动。不预先实现迁移代码——没有真实旧版本可测的迁移逻辑就是未验证的代码，反而会掩盖格式变更。将来若真要换格式，必须同时交付 (a) 从旧版到新版的迁移函数，(b) 覆盖新旧两侧的回归，(c) 本文件的 ADR，然后才能提升 `FORMAT_VERSION`。
- 证据：`tests/integration/save_version_probe.gd`（`run_save_version.ps1`）五项：新存检查点回读成功（tick 60、preset 1、enable_erosion=true）；外层版本改 99 **并重算摘要**后仍被拒（证明是版本门而不是校验和拦下的）；内层影子版本改 99 并重新序列化+重算摘要后被拒；载荷翻一个字节而摘要不动被拒；原始文件仍可加载（载荷 3671092 字节）。
- 影响：T08 G01、T08 存档可靠性、未来任何格式变更的流程。

## ADR-013：单域性能达标，不启用分块模拟

- 日期：2026-09-29
- 状态：accepted
- 背景：范围口径表把「全局分块模拟」列为**条件式 MVP**——「单域不达标前不启用」，且「跨块通量须唯一计算」。T08 G04 要求「单域性能达标后评估分块」。性能回收后需要就该条件做一次有证据的判定。
- 决策：**不启用分块。** 冻结档位（GTX 1050、D3D12、全屏 1920×1080、VSync off、256² 耦合、预设 2）实测：
  - 30 分钟（54000 tick）帧分布 p50 2.636 / p95 6.296 / **p99 7.410** / max 167.110 ms，门槛为 p99 ≤ 33.3 ms，**余量 4.5 倍**；
  - 吞吐约 33 tick/s，达到冻结的 30 Hz；
  - 同期 GPU 渲染 p99 仅 0.978 ms（短采样），说明算力远未吃满。
  单域既然达标，按范围口径表就不启用分块；跨块共享边「唯一计算」的复杂度与守恒风险因此不必承担。
- 证据：`验收/T08_长稳与过载_20260929.md`；`验收/T08_stability_1080p_30min_20260929.csv`（30 个采样点：0 负值、0 非有限、最小水深 0.000000000 m、沙账本漂移 2.817e−4 相对）；`验收/T08_1080p_coupled_frame_baseline_after_20260929.csv`。
- 成本与前置：判定的前提是**窗口可见**。隐藏窗口下 Windows 会节流，长跑会退化到约 2.7 tick/s——这是测量条件而非产品性能，见验收报告。若将来地图放大到 512² 或增加更多 pass 导致单域失守，本 ADR 作废并重新评估分块。
- 影响：MVP 边界（分块保持不启用）、T08 G04、未来分辨率扩展的决策入口。

## ADR-010：效果先行，卡顿不阻断开发

- 日期：2026-09-28
- 状态：accepted（用户调整执行优先级；不修改已冻结的最终门槛）
- 背景：T04 耦合连续编辑在 GTX 1050 / 256² 下仍偶发超过碰撞最高 100 ms；继续围绕尾部性能打磨会推迟水沙、湿度、构件和画面的可玩效果。
- 决策：当前迭代优先实现和观察效果闭环：侵蚀/沉积与玩家改道 → 湿度/压实/塌坡 → 构件破坏 → 画面和工具手感。**不能仅因帧率低、碰撞延迟或测试卡顿而停止 T04–T07 的功能/效果开发**；性能尖峰如实登记，效果完成后再集中优化，不为暂时流畅删减目标功能，也不把失败项标记为通过。卡顿妨碍操作时，先用较小地图/局部场景或开发画质档继续迭代；现有数值测试已验证 64²，GPU 主预览若需缩图则先建立并验证开发入口。128² 等新尺寸需先验证格式、边界和数值行为。所有效果证据标注网格尺寸、物理范围、画质档和硬件，不得冒充 256² 主场景或 1080p 发布证据。
- 保留门槛：水沙守恒、非负/NaN、命令确定性与同源状态在开发尺寸上继续测试；正式 Gate 2/4 仍需回到冻结的 256²/30 Hz、目标硬件 1080p、碰撞最高延迟及长稳态指标，不降低阈值或悄悄缩小最终产品范围。T08 集中回收性能债；如最终确需变更发布规格，另立 ADR 并重新验收。
- 影响：T04–T08 的执行顺序、开发测试矩阵和 Gate 调度；状态与数据契约 v1 不变。
