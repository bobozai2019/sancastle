# 验收证据规范

状态：frozen v1（Gate 0 基线，2026-09-28）；Gate 1C 对场景/回归的引用以本规范为准。项目当前不是 Git 仓库，无提交号时记录绝对源文件路径、Godot 精确版本和必要的 SHA-256，不得杜撰 commit。

每个任务必须在 `验收/` 建立对应报告，并引用以下六类证据：

1. 代码与配置：提交号、Godot 精确版本、渲染器、物理引擎、GPU/驱动、网格、步长、格式。
2. 可重现输入：场景、种子、命令日志、运行秒数、CPU/GPU 配置。
3. 行为证据：固定镜头截图、连续录像、调试层录像；T03–T08 涉及可视运行时行为的阶段验收每阶段至少一段无遮挡、无剪辑的 30 秒录像。T00–T02 的纯数值/参考风险验证可由逐步 CSV、自动测试和短调试录像替代，但必须写明不能证明最终视觉质量。
4. 数值证据：CSV/JSON 水沙曲线、源汇、负值/NaN、关键测点。
5. 性能证据：CPU/GPU 分项、p50/p95/p99、显存、碰撞更新量和延迟。
6. 阶段结论：通过/未通过、复现步骤、依赖、范围取舍和新风险。

建议命名：`Txx_<case>_<YYYYMMDD>.<ext>`。未实测字段必须写“待测”，不得以估计冒充实测。

原作连续参考视频目前未取得。源计划允许在缺时序视频时改用文件内定义的固定行为测试作替代验收，但不得据 RDC 静态帧或本项目自录短片声称还原原作动态细节。`T00_阶段进展_20260928.md` 记录该证据边界。NUM-08..11、生产 GPU 性能、完整场景长稳与发布录像尚未实测，后续报告必须标“待测”而非把 CPU 原型数据外推。
