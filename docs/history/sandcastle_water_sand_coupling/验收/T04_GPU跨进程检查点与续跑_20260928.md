# T04 GPU 跨进程检查点与续跑（2026-09-28）

状态：水沙耦合主场景的版本化检查点持久化、独立进程载入及 60 秒续跑通过；T05/T06 未来结构状态和完整存档 UI 尚未覆盖。

## 实现与时序

- `SandcastleCheckpointStore` 将固定 tick 的水/动量 GPU 完成态、CPU 沙/悬沙/湿度/压实等影子快照、源汇/库存和命令前缀写入 create-only 二进制封装；含格式版本、长度与 SHA-256。写入先落临时文件，再重命名为目标。读取拒绝格式、尺寸、账本或校验不符的数据，不反序列化对象。
- 主场景 `save_active_checkpoint(path)` 只在 GPU、暂停、无待处理命令/读回时发起新检查点；保存期间拒绝新笔刷。`load_saved_checkpoint(path)` 先验证文件，再在隐藏候选场景恢复，并等待 64 个碰撞块就绪后替换可见权威场景。损坏文件不会改变原场景。
- 保存端和载入端由 `tests/erosion/run_gpu_process_checkpoint.ps1` 启动两个独立 Godot 进程。临时检查点约 3,671,504 字节；测试结束清理临时文件。

## 验证

进程 A 在 SCN-02 耦合模式 tick 70 运行中挖沙，tick 120 暂停并通过主场景 API 保存。进程 B 首先将存档末字节翻转，验证主场景拒绝损坏文件且旧权威场景不变；随后载入有效检查点。10 tick 续跑已重复三次。`-ContinuationTicks 1800` 从 tick 120 继续 60 秒至 tick 1920，保存端和重启载入端的 `water`、`momentum_x`、`momentum_z`、`sand`、`sediment`、`rock` 六张 GPU 纹理 SHA-256 逐项完全相同；水源/汇、沙源/汇、桶内沙量逐项一致，碰撞块 64/64 就绪。短测中源进程可能因暂停时序多完成 1 tick，比较器使用实际完成 tick 并在载入端精确重演到该 tick，不把时序差误报成状态差。

这证明当前水沙状态与命令历史可跨进程一致恢复和继续运行；不代表将来 T05 湿度模型、T06 构件拓扑/损伤、用户存档选择界面或跨硬件浮点容差已验收。
