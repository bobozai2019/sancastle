# T03 GPU 逐 pass 时间戳：2026-09-28

结论：256² 独立预览已能在诊断模式下输出主 RenderingDevice 的逐 pass GPU/CPU 时间戳。`profile_passes` 默认关闭，验收探针临时启用；这补齐 G04 的计时入口和局部样本，不代表完整数值调试层或发布性能门通过。

环境：Godot 4.7.2.stable.steam.ed1daf0bf、GTX 1050、D3D12 Forward+。`powershell -NoProfile -File tests/run_gpu_pass_timestamps.ps1` 采集 360 个渲染帧、约 185 个模拟 tick，并每 30 帧交替挖/放沙。最新 `tests/run_gpu.ps1` 整套通过；此次原始 1,190 对标记见 `T03_gpu_pass_timestamps.csv`。

重要单位核验：Godot [RenderingDevice 类文档](https://docs.godotengine.org/en/4.7/classes/class_renderingdevice.html)将 `get_captured_timestamp_gpu_time()` 描述为微秒，但 4.7.2 的 [D3D12 驱动实现](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/d3d12/rendering_device_driver_d3d12.cpp#L5130-L5132)以频率换算后乘 `1,000,000,000`，实际返回纳秒；[CPU 标记](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/rendering/rendering_device.cpp#L7857-L7867)来自 `get_ticks_usec()`。因此 CSV 明确写 `gpu_ns,cpu_us`，下表将 GPU 纳秒除以 1000 后列为微秒。直接按文档将 GPU 原值视为微秒，会得到与整帧耗时相矛盾的假数据。

| 标记区间 | 配对数 | GPU p50 / p95（µs） | CPU 派发 p50（µs） |
|---|---:|---:|---:|
| 潮汐边界 | 180 | 29.70 / 33.79 | 7 |
| CFL tile | 180 | 26.11 / 29.70 | 4 |
| 边通量 | 264 | 71.68 / 73.73 | 9 |
| 正水深限流 | 264 | 44.03 / 45.06 | 4 |
| 状态更新 | 264 | 102.40 / 105.47 | 4 |
| 工具补丁 | 12 | 12.29 / 16.64 | 8 |
| 碰撞脏块打包 | 14 | 15.36 / 21.50 | 7 |
| 水账户 tile 归约 | 6 | 27.65 / 31.74 | 3 |
| 沙账户 tile 归约 | 6 | 27.65 / 31.49 | 4 |

水/沙审计各仅 6 对，不能据此推断长时尾延迟；不同探针运行的 GPU 数值也不宜直接比较。标记包围的是一次 compute list，不是只测 shader ALU；GPU 队列同步/屏障可能包含在区间内。CPU 列是渲染线程记录/提交命令的耗时，不是主线程完整等待时间。独立短样本的整帧视口计时见 `T03_GPU调度与帧采样_20260928.md`，两种口径不可直接相加。

仍需湿度、悬沙、侵蚀等未来 pass 的标记，以及新增沙审计后的真 1080p 完整交互场景五分钟逐帧性能分布。
