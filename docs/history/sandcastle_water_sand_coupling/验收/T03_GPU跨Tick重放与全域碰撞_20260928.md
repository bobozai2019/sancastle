## GPU 跨 tick 撤销/重做

- 主入口暂停时，Z/Y 先尝试同 tick 快照；若编辑属于过去 tick，则在旧场景保持可见的同时，创建隐藏候选 GPU 场景，从同一固定种子初态按 `(sim_tick, command_id)` 重放保留的命令及全部水 tick。候选场景验证命令结果、目标 tick、初始 64 个碰撞块均就绪后才替换旧场景；失败路径保留旧场景。切换后清除候选场景的快进模式，允许继续正常模拟。
- `tests/run_gpu_cross_tick_replay.ps1` 覆盖单命令及跨两个 tick 的双命令历史，撤销后与独立从头重放场景、重做后与操作前状态比较。整域 65,536 格的水深、X/Z 动量、沙层、岩层及水源汇误差均为 0（同机本次运行）；编辑使水深最大变化 0.03620018 m，故不是只对沙层做了空洞比较。实际变更处碰撞射线亦通过。
- 另以 `tests/run_gpu_cross_tick_replay.ps1 -ReplaySteps 300` 验证到第 309 tick：单/双命令历史的整域水、动量、沙、岩及源汇对照仍为 0 误差；首次撤销/重做重放耗时分别为 10,444.471/10,493.621 ms。当前从 tick 0 全量重放虽正确但交互延迟过高；更长历史需 GPU 检查点或增量历史，内存峰值尚未验收。运行态状态切换与存档/加载未实现。
- 后续补充失败语义：同 tick 撤销后提交“库存不足”的放沙命令，验证沙床、桶、GPU 纹理和 GPU revision 不变，redo 分支仍可执行；跨 tick 候选场景注入故障后，原可见场景、命令历史、目标 tick 及五个全域 GPU 字段仍不变。短/完整 GPU 回归通过。尚缺真实设备异常与资源分配失败注入；这里的候选故障是确定性模拟，不能替代驱动失效试验。
- 重放瓶颈对照：同一 `-ReplaySteps 300` 回归加 `-DisableVsync` 后，首次撤销/重做降至 2,261.560/2,118.644 ms，整域数值误差仍为 0。默认约 10.5 秒的大头是显示帧节奏；关闭 VSync 仍需约 2 秒，不能把测速配置当作交互优化。下一步应保留相同命令顺序与状态校验，设计 GPU 状态检查点以缩短需重算的 tick 区间。

## 全域碰撞批次修复

- 新增 `tests/run_gpu_collision_full.ps1`，把 64 个 32×32 块的全部 33×33 共享边界样本与当前 GPU 岩层+沙层逐点对照。修复前首批 16 块正确，后续 48 块共 52,272 个样本错误，最大误差 0.447678 m。原碰撞探针只检查少量射线，未覆盖该缺陷。
- 原因是碰撞代理在 D3D12 异步纹理回读回调内部递归提交下一批计算/回读。现改为回到主线程后再安排下一次渲染线程提交。修复后 64 块所有样本通过，最大绝对误差约 10⁻⁸ m。
- 完整 `tests/run_gpu.ps1` 通过；工具编辑到射线可用延迟本次 79.757 ms，低于 100 ms 门槛。此为单次与短回归，不代表多块长期压力或 5 分钟性能验收。
