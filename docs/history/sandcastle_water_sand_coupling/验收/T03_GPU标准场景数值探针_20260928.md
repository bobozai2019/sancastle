# T03 GPU 标准场景数值探针（2026-09-28）

状态：局部通过；不是 Gate 2 完整验收。

## 方法

- 输入：`scripts/scenarios/standard_scenarios.gd` 的三个固定种子预设，`η(t)=0.10+0.11sin(0.35t)`，30 Hz、150 tick；Godot 4.7.2 D3D12、GTX 1050。
- 64²（8 m）每 tick 以同网格 CPU 浅水参考对照 CFL 子步数、潮汐源汇、水量和海岸内侧测点，并在结束后逐格对照水深与两个动量分量。
- 256²（32 m）只查 GPU 逐 tick 账本闭合、非有限/负水、CFL 子步数、测点曲线及最终全格有限性；不拿 64² 的到达 tick 或体积当 256² 数值误差。
- 测点 x≈0.12 域长；弯沟预设的 z 位于该 x 对应沟槽中心，其余 z≈0.5。此为探针测点，不改场景初态与已冻结契约。
- 账本阈值：`|现存−初值−累计源+累计汇| ≤ max(0.001 m³, max(初值,累计源,0.001)×0.5%)`；64² 逐 tick 测点误差 ≤0.0001 m、水量差 ≤0.001 m³，源/汇差各 ≤0.0001 m³；最终单格水深差 ≤0.0001 m、动量差 ≤0.001。全程负水/非有限格为 0。

## NUM-06 破坝专用复验

封闭域左半初始水深 0.45 m、右半干床，不施加潮汐；下游测点为 x=53/63 域长、z=中心，64² 对应冻结契约的 x=53。64² 运行 150 tick 并逐 tick 对照 CPU 浅水参考：最大测点差约 6×10⁻⁸ m、水量差 1.03×10⁻⁶ m³、终态全格水深差 1.5×10⁻⁷ m、动量差 2.6×10⁻⁷；目标点第 31 tick 超过 0.005 m，满足 150 tick 内到达。256² 运行 500 tick，目标点第 135 tick 到达。两尺寸累计负水/无效格均为 0，最大封闭水量相对误差分别约 8×10⁻⁸、1.8×10⁻⁷；源/汇均为 0。逐 tick 曲线见 `T03_gpu_standard_dam_break_64_150.csv` 与 `T03_gpu_standard_dam_break_256_500.csv`。

64² 的到达步数不能直接要求 256² 相同，因为后者以相同 0.125 m 格长覆盖四倍物理距离。常规回归纳入 64² 40 tick（仍覆盖第 31 tick 到达）和 256² 500 tick；150 tick 完整 CPU/GPU 对照另行归档。

## NUM-03 单侧注水专用复验

左侧 x=0 每格每 tick 注入 0.001 m 水深，其他边界封闭，初始无水。GPU 边界 pass 新增明确的注水模式：只累加水深、保留动量，并把每格增量写入同一 1 列源汇账本；潮汐模式仍按指定水位覆写并重置边界动量。64² 运行 150 tick，逐 tick 对照 CPU 参考：最大水量差 3×10⁻⁸ m³，终态水深/动量差在打印精度内为 0；累计源 0.150000013 m³、最终水量 0.150000011 m³，负水/无效格为 0。256² 运行 9000 tick（五分钟模拟时间），累计源 35.999992516 m³、最终水量 35.999706598 m³、汇 0；从逐 tick CSV 重算的最大闭合绝对差 0.00028592 m³，相对累计源约 7.942×10⁻⁶，低于 0.5%；负水/无效格累计 0。CSV：`T03_gpu_standard_one_side_inlet_64_150.csv`、`T03_gpu_standard_one_side_inlet_256_9000.csv`。探针还独立核对累计源应等于 `0.001×网格高×单格面积×tick 数`（允许浮点累计误差）。

首测曾仍表现为旧潮位覆写（第 2 tick 源仅约 0.000013 m³）；确认是修改后的 GLSL 尚未由 Godot 编辑器重新导入。等待 `--headless --editor --import` 进程退出后重测通过，原 64² 潮汐和三场景边界回归也通过。自动化环境必须先完成 Godot 资源导入，不能只修改 GLSL 后复用旧 SPIR-V 缓存。

## NUM-04 弯沟导流专用复验

封闭域弯沟中心 `z=0.5+0.12sin(1.5·2πx)`、沟外岩床 0.32 m，左端前 10 列初始蓄水 0.40 m；不施加潮汐。64² 使用契约测点 x=53 及该 x 的沟中心，150 tick GPU/CPU 同网格逐 tick 对照：最大测点差约 2×10⁻⁸ m、水量差 9×10⁻⁸ m³、终态全格水深/动量差约 1.5×10⁻⁷/1.2×10⁻⁷；目标在第 125 tick 超过 0.005 m，符合 150 tick 内到达。256² 以同一归一化位置测点、相同格长运行 1000 tick，在第 775 tick 到达；其物理距离是 64² 场景的约四倍，不应用 150 tick 阈值。两尺寸最大封闭水量相对误差约 5.9×10⁻⁸、3.39×10⁻⁷，负水/无效格均为 0。逐 tick CSV：`T03_gpu_standard_curved_channel_64_150.csv`、`T03_gpu_standard_curved_channel_256_1000.csv`。该结果验证导流到达与 CPU 趋势；NUM-05 运行时开口另行测试。

## NUM-07 256² 往复潮汐压力复验

复用 64² 冻结输入形式：岩床沿 x 从 0 到 0.30 m 线性升高，初始水面 0.15 m；左侧海面为 `0.12+0.16sin(2π·0.25t)` m。256²、30 Hz、1200 tick 为 40 秒模拟时间、10 个完整周期。256² 不预跑耗时巨大的 CPU 全域参考；同网格 CPU 对照由 64² 的 1200 tick 证据承担，此处独立审计 GPU 每 tick 的边界源汇、全域水量、CFL、测点及最终三份全域状态。`-DisableVsync` 仅缩短墙钟运行，不改变固定步长。

两次运行均通过，逐 tick CSV 的 SHA-256 相同：`EFB3746D75778AAA2C7CD960FE0C35A420BC0376B7BF0759744F39A4CB4D9988`。累计入水 36.981292 m³、出水 33.678360 m³；内部测点有 1 次湿干转换。独立按 256² 初始水量 38.550588235 m³ 重算，1200 行最大绝对闭合差 0.00000580 m³，最大相对差约 1.50×10⁻⁷，远低于 0.5%；源汇单调，负水、无效格、NaN、过载行均为 0。终态全域水深及双动量逐格检查有限，水深无负值。证据：`T03_gpu_tide_025hz_256_1200.csv`；执行器：`tests/run_gpu_tide_ticks.ps1 -GridSize 256 -Steps 1200 -DisableVsync`，已加入常规 GPU 回归。这不是 256² CPU/GPU 同网格曲线误差声明，也不是完整场景帧性能证据。

## 尚未覆盖
