# T07 画面可读性（2026-09-29，首增量）

状态：G01、G02、G03 完成；G04 的透明排序回归与工具反馈均已完成并出片。掠射角的网格面片阶梯如实记录为已知限制。

## 目的

`细则/T07_画面与工具手感.md` 的验收是「关闭调试色仍能读懂深浅、流向、湿沙和冲刷因果；无露沙蓝片、持续白环或低视角分离」。改前的地形与水面都是 `unshaded` 平涂：

- `gpu_water.gdshader` 只输出一个恒定色 `vec3(0.055, 0.42, 0.67)` 与恒定 `ALPHA = 0.72`，浅水和深水没有区别；
- `gpu_terrain.gdshader` 只按湿度和「沙厚」上色，没有光照也没有坡度线索，沙丘、水道和玩家构件都读不出形体。

## 允许修改

`shaders/visual/`。本轮只改了 `gpu_water.gdshader` 与 `gpu_terrain.gdshader`；另外在 `scripts/demo/gpu_water_preview.gd` 把 `momentum_x/z_state` 接到水面材质（接线，不属于表现层写物理）。表现层没有写入任何物理量，也没有参与侵蚀判定。

## 阈值来自实测而非估计

水面着色需要知道真实流速量级。`tests/visual/capture_readability.gd` 在抓帧前读回 GPU 状态并打印分布，tick 600（预设 2）：

| 指标 | 实测 |
|---|---:|
| 湿格数 | 17969 |
| 最大水深 | 0.2870 m |
| 深度平均流速 p50 / p90 / p99 / max | 0.3360 / 0.7148 / 1.0291 / 1.4713 m/s |

第一版按 `foam_speed_m_s = 0.20` 设阈值，结果中位流速 0.336 就超过了它，白沫铺满整个水道、水面变成一片白色（见「第一版失败」）。改为 **0.85 m/s（高于 p90）** 后白沫只出现在最快最浅的水股上。

## G01 深浅水 / 水下地形 / 流纹

`gpu_water.gdshader`：

- **深浅**：Beer–Lambert `optical = 1 - exp(-depth / 0.09)`，颜色在 `shallow_tint` 与 `deep_tint` 之间插值，`ALPHA` 从 0.55 升到 0.94。浅滩透出河床、深槽合拢——这也同时避免了「露沙蓝片」。
- **水下地形**：地形着色器按同一指数把淹没的河床乘向 `vec3(0.44, 0.63, 0.80)`，退潮后露出的滩面因此读作「刚被水淹过的浅滩」而不是「亮干燥沙」。
- **流纹**：`sin(dot(UV, normalize(flow)) * 150 - TIME * 2.6)`，条纹沿流向排布并随时间推移；`moving_fraction = clamp((speed - 0.15) * 2, 0, 1)` 让接近静止的积水保持平滑，只在流动处出现纹理。

## G02 白沫

白沫**不**按水深阈值单独触发——那会在每条水线上画一圈永久的白环，而验收明确禁止「持续白环」。规则要求**同时**有速度与浅水：

```
moving = smoothstep(0.85, 2.13, speed)
thin   = 1 - smoothstep(0.05, 0.15, depth)
foam   = clamp(moving * thin, 0, 1) * 0.55
```

因为速度随潮汐与编辑变化，白沫会自然出现和消失，而不是固定环。静帧中水线干净、无白环。

湿边见下文单独一节。

## G03 干湿压实沙可读性

`gpu_terrain.gdshader` 的 `else`（画面）分支现在分开表达四种状态：

| 状态 | 规则 |
|---|---|
| 干沙 | 暖色基准 `vec3(0.78, 0.62, 0.37)` |
| 湿沙 | 向 `vec3(0.38, 0.31, 0.23)` 混合，权重 `wetness × 0.65`（沿用改前公式） |
| 压实 | 在此基础上再向偏冷的自身 `vec3(0.86, 0.89, 0.95)` 混合 `compaction × 0.35` |
| 露基岩 | 沙厚 < 0.30 m 处向 `vec3(0.28, 0.27, 0.26)` 混合，沿用改前公式 |

**形体明暗**：`vertex()` 用中心差分（跨 2 格 = 0.25 m）算出真实坡度的法线，`fragment()` 以 `clamp(1.0 + (dot(normal, sun) - sun.y) * 0.6, 0.55, 1.30)` 调制颜色。以平地（`dot = sun.y`）为 1.0 基准，所以整体色调不变、只增加起伏——沙丘、水道、玩家建的墙与塔因此有了可读的形体。

调试视图（`debug_mode != 0`）保持各自的配色不受明暗影响，避免污染数值编码。

## 湿边（G02 补完）

在地形着色器加了一条沿湿度场的湿痕：退水后**刚露出**的沙比周围湿润沙再暗一档。

```
exposed = (1 - smoothstep(0.0, 0.02, depth)) * smoothstep(0.75, 1.0, wetness)
color   = mix(color, color * vec3(0.60, 0.60, 0.63), exposed * 0.55)
```

它跟着 T05 的湿度场走，所以随潮汐移动，而不是钉在一条固定等高线上；也不是水面上的白环。

## G04 透明排序回归（低视角）

`ALPHA` 改为随深度变化（0.55→0.94）后引入了新的透明排序变量。`tests/visual/transparency_probe.gd`（`run_transparency.ps1`）在**掠射视角**（相机高 0.95 m 沿海道看）渲染同一帧三次：水深调试视图给出「哪里有水」的逐像素掩码，然后画面视图分别在水面网格开/关时各渲染一次。掩码内两次画面完全相同 = 该像素水没盖住。

| 指标 | 实测 |
|---|---:|
| 掩码像素（PIXEL_STEP=2 采样） | 56492 |
| 完全没被水盖住 | 25（0.04425%） |
| 掩码内读作裸沙 | 1（0.00177%） |

因为水的颜色与水下河床的颜色差异远大于容差，这两项都远低于 2% 的门。**代价**：水面在掠射角下沿近岸有一道可见的阶梯状面片（网格 0.125 m 一格，浅水半透明，视线几乎平行时每个面片占很多像素）。这不是「分离」——水一直贴到岸边，探针也证实掩码内没有裸沙——而是粗糙网格 + 半透明浅水的固有观感。已把水面不透明度在最初 3.5 cm 水深内渐入以软化岸线，但没有消除阶梯；要真正消除需要更密的近景网格或屏幕空间的水深测试。

第一版探针报出 66.5% 未覆盖，原因是掩码把天空（0.73,0.86,0.93）也算成「蓝主导」了。修正掩码（排除高红通道）后才是上表数字。这条记录保留，说明掩码判据也需要按调色板实测。

## G04 工具反馈

`scripts/visual/brush_indicator.gd` 在光标处画一个半径等于真实笔刷（0.38 m）的环，落在阴影床面之上 0.025 m：挖沙橙、放沙蓝、空闲深灰。它是纯表现层——只读光标与影子床高，不写任何状态。

环的显隐用独立的 `show_brush_indicator` 开关，而不是复用 `hide_hud`：录制无遮挡画面时要关掉 HUD 文本，但工具反馈恰恰是要拍出来的东西。这个区分是实测踩出来的——第一版把两者绑在一起，录像里根本看不到环。

30 秒交互录像 `T07_tool_feedback_20260929.avi`：1280×720、30 FPS、1813 帧 = 60.4 秒、58,663,178 字节。一次连续运行内：空转（环为深灰）→ 沿滩面四下拖挖（环转橙、留下四道坑）→ 回程放沙（环转蓝）→ 从桶里筑一道墙。影片比 30 秒长，是因为渲染帧率（30）高于模拟步进率（约 15.8 tick/s），900 个模拟 tick 铺成 1813 帧。

关键帧：`T07_tool_feedback_hover_20260929.png`、`T07_tool_feedback_dig_20260929.png`（橙环 + 身后的坑链）、`T07_tool_feedback_wall_20260929.png`。

## 第一版失败（如实记录）

首版 `foam_speed_m_s = 0.20` 低于实测中位流速 0.336 m/s，白沫覆盖大部分水面，整条水道变成灰白色，同时 `ripple_frequency = 26` 只在全幅画出约 4 条粗条纹。两者都改为按实测分布取值后才得到当前结果。这条记录说明阈值不能凭感觉设，test 脚本因此保留了打印流速分布的部分。

## 新风险

- 水面 `ALPHA` 由 0.94 到 0.55 随深度变化，最深与最浅处的混合量差 0.39；若后续加入不透明物体（船、铲子）需要重新检查排序。
- 地形 `vertex()` 增加了 4 次纹理取样（法线中心差分），水面 `fragment()` 增加了 2 次动量取样。1280×720 下未见异常，但真 1080p 的 p99 未复测，按 ADR-010 记债 T08。
