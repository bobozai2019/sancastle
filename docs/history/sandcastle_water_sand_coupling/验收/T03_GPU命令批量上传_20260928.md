# T03 GPU 工具命令批量上传：2026-09-28

结论：G03 已有可重复的局部实现与数值证据，但尚未完成连续操作、跨 tick 撤销/重放与正式主场景验收，不能据此通过 G03 或 Gate 2。

`ToolCommandQueue` 仍在 CPU 参考域内完成契约校验、按 `(sim_tick, command_id)` 排序和五类工具的沙量/背包结算。每批只将最终受影响格的 `sand`、`compaction` 以唯一升序索引打包为 16 字节记录；主 RenderingDevice 的 `shallow_tool_patch.glsl` 每格单写，同时更新两组 ping-pong 纹理，不使用浮点原子加。预览在水流 tick 开始前上传该批，并在完成后发布同一 GPU 状态 RID；暂停状态也可单独派发编辑。

环境：Godot 4.7.2.stable.steam.ed1daf0bf，GTX 1050，D3D12 Forward+。命令：`powershell -NoProfile -File tests/run_gpu_tool_patch.ps1 -GridSize 64`、`-GridSize 256`、`powershell -NoProfile -File tests/run_gpu_preview_tool.ps1`、`powershell -NoProfile -File tests/run_gpu_preview_command_timing.ps1`。64² 命令探针及两项预览探针已接入 `tests/run_gpu.ps1`，整套通过。

本阶段的 CPU 影子域仅用于执行工具队列；GPU 沙/压实度尚无自主物理演化。T04 接入 GPU 侵蚀后，不能再无条件用 CPU 影子域最终格值覆盖 GPU 状态，须重新设计工具与侵蚀的权威状态同步。预览使用平面射线拾取，尚非地形精确拾取；截图差异很小，仅证明有变化，不是画质或同帧/下一帧时限证明。仍需连续挖沙 1 分钟、拒绝语义与跨 tick 回放、编辑到显示的帧延迟、主场景整合和碰撞代理验收。
