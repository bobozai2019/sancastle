# test1 原比例沙滩

2026-10-18。main.tscn 右上角场景菜单新增 **test1 原比例沙滩 · 30×15**，点击“切换”进入。[独立入口](../../../scenes/playable/test1_geometry.tscn)继承 main 的工具、GPU流水线、相机、暂停和检查点流程。

同日追加修复：改为平静低水位起步、20模拟秒的上岸/回落输入，并默认启用自由相机。用户报告的持续淹没来自先前持续保持强浪高水位；原先强制固定相机也使WASD失效。完整原因、当前验证及旧失败保留见[回落与相机修复](test1场景回落与相机修复_20261018.md)。

## 几何与交互

- 可见范围严格为 X=-15..15、Z=-7.5..7.5，长宽比2:1。地形、水面及悬沙共用保存到资源中的矩形网格，没有把沙滩拉伸到32×32。
- 初始地形使用本次直接取证的 E5006 完整 ground 数据，包含岸边坡面、沟脊和局部高堆沙。[竞品取证与边界](../../competitor/test1场景尺寸与沙深度.md)保持独立。
- 现有权威系统保持256²、0.125m/格，在其中容纳240×120个可见沙格。双线性重采样后的最高沙面约6.58833，原始数据最高约6.64325；原始1024×512高度另保存在资源目录，不能宣称所有细节逐点等价。
- 本项目将原作场景单位按1:1数值用于米制，保留原始绝对Y。不可挖底层设为Y=0，sand为其上的高度；**这是Godot适配，原作现实米制和所有编辑动作的可挖底界仍未确认**。
- 原坐标映射为 `(x,y,z)→(-x,y,z)`，海侧朝项目-X边界。当前水深为 `max(0.95-沙高,0)`，初始动量为0；约55.18%的可见域起步为干沙/极薄水。水面与沙面共用完成态，原始沙形未修改。先前将捕帧强浪水位约2.566持续作为海侧目标的方案已撤销。
- [water_cycle.json](../../../assets/test1_geometry/water_cycle.json)保存项目适配：低水位0.95、上岸抬升0.45、周期20模拟秒。每周期0–1秒低水位，1–4秒平滑抬升，4–5秒高位，5–9秒平滑回落，9–20秒低位；水通过现有求解器真实搬运和回流。岸边响应包含传播延迟，不能将海侧输入时刻直接当作上岸时刻。原作后续时间规律仍未知。
- Z方向域外为干燥障碍区；原有32m模拟域的X边缘各保留1m隐藏延续段，用于接入现有海侧边界。显示和鼠标编辑限制在30×15矩形内；这些边缘处理属于适配。
- 四周静态侧面网格从Y=-0.1连接到当前完成态沙高，可读出沙体厚度，并随挖填更新。其底板样式是本项目表现选择。
- 默认无草、鱼或石头；复用流水线的碎石状态仍分配，初始数量为0且不显示。用户以后主动使用“投碎石”工具仍可添加。
- 自由挖填、水响应、碰撞、沙源汇、暂停、保存恢复与切换继续使用main流程。新场景采用2m沙体内聚高度参数以保持捕帧中陡峭高堆沙，未更改main或旧场景的该参数。

## 视角与使用

默认自由相机从全景锚点起步，垂直FOV为30°以看清整片沙滩和边缘。进入后WASD移动、Q/E升降、右键转向可立即使用；F5在固定全景和自由视角之间切换，SPACE暂停/继续。数字框获得焦点时仍阻止相机移动。所有静态节点、相机、资源绑定和菜单条目保存在场景文件中。

场景菜单包含原有三个入口与新增入口。各场景独立保存沙、水、动量、进度和相机状态；切回时恢复自己的状态。首次进入尊重场景指定的默认相机，后续仍恢复已保存的相机选择。检查点允许新的明确domain_id，同时继续拒绝未知domain_id和跨场景/配置不匹配。
