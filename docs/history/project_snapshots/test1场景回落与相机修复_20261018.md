# test1 原比例场景：水位、相机与回落修复

日期：2026-10-18。范围：用户报告的切换后水过深、WASD及相机操作失效，以及加入回落。沙体取证结论、原始RDC、30×15可见范围和现有物理账本语义保持原范围；这里记录Godot适配与本次验证，不宣称恢复了原作周期秒数。

## 问题与修正

| ID | 直接原因 | 修正 |
|---|---|---|
| T1-WATER-LEVEL-01 | 原比例场景将捕帧中的强浪目标约2.566316持续作为海侧平均目标。按现有沙形静水平衡估计，仅约1.24%的可见域高于它，持续输入会淹没大部分沙滩。上一轮20tick约0.7模拟秒未覆盖传播后果 | 平静初态 `h=max(0.95-H,0)`，初始动量0。海侧目标限定0.95–1.40，并留出完整回落和低位间隔 |
| T1-CAMERA-01 | 场景入口 `_ready` 在基础交互启用自由相机后，又调用固定全景选择；free_camera.gd只在current=true时响应移动 | 默认自由相机从静态全景锚点起步，FOV30°；保留F5固定/自由切换，数字焦点和右键释放规则 |
| T1-RUNUP-01 | 先前矩形边界mode3只固定高位并叠加小正弦，没有完整回落时序 | GPU实际模拟时间驱动平滑抬升/回落周期，CPU保留路径使用同一周期定义。只在海侧改变水量，水由原求解器向岸推进、反转和退去 |

新旧初态逐字段比较表明沙高完全相同，改动只涉及初始水深和动量。当前初态露出比例约55.18%，最大水深约0.947；这些是本项目米制适配数据。原作世界米制、正常波周期及customWave未来输入仍未知。

## 当前周期

配置：[water_cycle.json](../../../assets/test1_geometry/water_cycle.json)。低水位0.95，上岸抬升0.45，周期20模拟秒。相位 `u=mod(实际GPU时间,20)/20`，包络：

```text
e = smoothstep(0.05,0.20,u) × (1-smoothstep(0.25,0.45,u))
海侧目标水位 = 0.95 + 0.45 × e + 手动波浪
```

无手动波浪时：0–1秒低位，1–4秒抬升，4–5秒高位，5–9秒回落，9–20秒低位。此时序是Godot适配；输入与岸边之间存在水波传播延迟。手动波浪仍使用已有独立请求、幅度限制和源汇记录。

边界继续只作用于原比例场景的有效Z范围；不向干燥封闭区注水。GPU/CPU路径共用profile定义的低位、抬升与周期；保存包含实际模拟时间，暂停和切回不会按墙钟重置相位。profile及新初态hash纳入现有配置身份，旧配置检查点仍按既有规则拒绝。
