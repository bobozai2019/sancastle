# P02 G02 沙体、沙材质和受光

日期：2026-10-10。捕帧：`test1.rdc`，SHA256 `761aa980c2426f75a1fa7364bf6d2655ff4dd20ea76566e630ee5b53ea0ec5b2`。本报告只分析沙滩视觉技术，未读取竞品业务方法或流程。

## 问题一：有体积的沙形从哪里来

**已观察事实（C3，限本帧）：**RDC中像素shader `ResourceId::3382` 对应的117次绘制均可重放。每次绘制返回4,225条88字节VSOut记录（65×65规则X/Z位置），24,576个索引、1实例。遍历结果的X/Z范围合计约`[-15,15]×[-7.5,7.5]`个场景单位；取VSOut第4–6个float为传给PS的`o1.xyz`后，Y覆盖`0.0024–6.6435`。最高两个patch为事件5018（Y最大6.6435）与5030（5.7459），不是只有平坦底板。[逐patch取数](../evidence/p02_sand_patches.json)；三个代表patch完整原始VSOut和stride见[几何索引](../evidence/g04_vsout.json)。

**指令依据（C3）：**5006的VS反汇编中，`o1.xz`由顶点位置经`cb1`变换取得；`t0`为16字节stride结构化缓冲，指令14–20读取并解码，指令26将结果写入`o1.y`；`o0`接受同一高度参与的投影计算。[VS反汇编](../data/readable/rdc/test1/event_5006_vertex_disassembly.txt)、[原字节](../data/raw/rdc/test1/event_5006_vertex_shader.bin)。因此本帧沙层使用规则网格patch和缓冲驱动高度，能够呈现很高的起伏。

**范围与替代解释：**部分沙塔/岩石可能另有独立模型绘制；仅凭本帧高度范围不能把每个可见高塔都归给这些patch，也不能证明建造、侵蚀、坍塌或悬挑算法。VSOut的数值是场景坐标，物理米制未核实。下一步可按高patch的投影范围做逐像素贡献核对，并用有时间戳的多帧数据查形体演化。

**Godot适配：**固定样片先沿用项目的可见高度场，提供足够高的局部形体、陡坡法线和可辨侧面受光；独立固定模型只在证据和画面要求指向不可由高度场表达的形状时加入。实时接入仍读取同generation完成态，不能修改沙量账本。否决办法是同机位冻结沙床，仅改几何高度/法线，检查主画面与近景是否达到[参考板](reference_board.md)的体积、侧面和接触目标。

## 问题二：沙色、颗粒与亮纹怎样分层

**包内事实（C3，默认值）：**`Sand`材质对象`asset:6dd7bb6bc7d926fd43c08d22c9c767b7edf531cf11a4a555fcd41830f2f9c721:20`引用Shader PathID605、二维`Sand`纹理PathID232和三维`Caustics`纹理PathID932。默认颜色为`sandColor=(0.9255,0.8863,0.7255)`、`sandColor2=(0.9294,0.8980,0.7529)`、`wetSandColor=(0.9060,0.8104,0.6333)`，均不等同本帧有效像素值。[材质typetree](../data/readable/assets/6dd7bb6bc7d926fd/20/typetree.json)、[引用索引](../data/index/dependencies.jsonl)、[视觉配置](../data/index/visual_config.jsonl)。

**运行时事实（C3，限5006）：**PS `ResourceId::3382` 的指令1采样`t3`二维纹理，指令19/31采样`t4`三维纹理；寄存器绑定对应`t3=ResourceId::617`（1024² RGBA8）、`t4=ResourceId::1105`（256×256×64 R8）。[PS反汇编](../data/readable/rdc/test1/event_5006_pixel_disassembly.txt)、[绑定反射](../evidence/p02_sand_bindings.json)、[纹理快照](../evidence/g04_texture_snapshots.json)。包内二维`Sand`纹理的解码mip0像素经上下翻转后与运行时`t3` **4,194,304字节逐字节相同**，故此项包内→RDC映射为C3；只确认解码texel，不宣称序列化payload与GPU字节相同。[逐字节复验](../evidence/p02_sand_texture_match.json)。三维`Caustics`与`t4`的尺寸/类型及绑定相符，但尚无内容同一性证据，仅作为候选，不能称已映射。

**绘制贡献（C3，限本帧与显示映射）：**事件5006后的场景HDR展示图中，水面绘制之前已有密集亮纹；其原始HDR快照为1280×720 RGBA16F。[底面后展示图](board/pass_5006_sand_after_topdown.png)、[原始快照索引](../data/index/rdc_snapshots.jsonl)。可说底面绘制贡献了至少部分亮纹，不能仅凭名称认定它是物理焦散或证明三维纹理唯一成因。HDR展示图经过RenderDoc PNG转换且方向翻转，仅供分层查看，不与最终RGBA8直接比色。

**Godot适配：**干湿两套暖沙色和高频细纹应随可见床面与高度法线稳定附着；浅水亮纹先在底面受水域遮罩与深度衰减，水面可再提供独立高光，不把同一亮纹在两层重复染亮。候选先做沙色、二维细纹、三维/程序亮纹各自开关，在固定完成态和同曝光下逐项归因。

## 问题三：为何能读出受光和阴影

**已观察事实（C3，限5006）：**PS指令122有`sample_c_lz`比较采样`t0`，绑定资源为`ResourceId::3344`（D32深度）；指令126/129对插值向量与常量方向向量做`dp3`，该片段随后参与输出。它支持“底面像素着色包含阴影比较与方向性受光”，但具体灯光模型、阴影bias和材质粗糙度公式尚未完整恢复。[PS反汇编](../data/readable/rdc/test1/event_5006_pixel_disassembly.txt)、[绑定反射](../evidence/p02_sand_bindings.json)。

**Godot适配：**优先用场景固定主方向光和真实沙面法线验证高沙体侧面与投影阴影，再调材质；不通过直接涂深侧面替代几何受光。岩石与独立装饰物仅用来判断阴影关系，不纳入当前核心资产复刻。
