# G05 编辑反馈阶段定位与笔刷枚举优化

日期：2026-10-10。状态：CPU 笔刷枚举优化已验证；RG4 编辑反馈与正式成本仍未通过。

## 时间线观察

在原正式耦合场景、1920×1080 可见窗口、D3D12、GTX 1050、VSync off、持续浪中，诊断副本为前三笔命令记录主线程阶段。原正式入口不启用阶段追踪。诊断时的共享预览脚本和命令队列原字节分别保存为 [预览脚本快照](reference_preview_g05_instrumented.gd.txt)（SHA256 `0ABF3AAA1FCBAF9336DDB063B53E657349E674354956D3C4E7D85C6CEE8658B0`）和 [队列快照](tool_command_queue_g05_instrumented.gd.txt)（SHA256 `2C36D20983DA509879E369F3176F314EA6E9148888842F3E2AD74EC400306849`）。正式共享预览脚本随后已恢复到 RG4 所列 SHA256 `E10841E9B3D6CDDE1F24CEA6ED9564C3C085408B96EEAB49C4C919289E96D43B`。

- [默认路径时间线](g05_edit_timeline/manifest.json)：首笔 243.616 ms；提交后约 11 ms 进入补丁处理，已在途沙预取等到约 212 ms 才完成，CPU 命令应用结束于约 240 ms。
- [悬停试验时间线](g05_edit_timeline_hover/manifest.json)：首笔 236.135 ms，提交前没有已成功的沙预取；提交后等在途预取约 210 ms。把指针设到编辑目标附近的 [试验](g05_edit_timeline_hover_target/manifest.json) 仍是提交前 0 次成功预取、首笔 232.983 ms。[再次复跑](g05_edit_hover_debug/manifest.json) 首笔为 48.335 ms，悬停命中床面但提交前成功预取仍为 0 次。命中计数是**提交后**回调，不能宣称点击前已经预取完成；运行间延迟波动很大。
- [关闭提交后预取](g05_edit_no_submit_prefetch/manifest.json) 的首笔为 207.922 ms：直接沙同步约 169 ms，CPU 应用约 25 ms。切换请求路径没有消除冷延迟。
- [启动前一次整纹理读回](g05_edit_prebootstrap/manifest.json) 本身耗时 216.294 ms；首笔仍有 272.369 ms，单次预热未解决问题。
- [延后一帧发起沙同步](g05_edit_defer_sync/manifest.json) 的三笔为 97.376/101.199/124.860 ms，仍有不达标项；该试验同时改变命令落点 tick，不能直接把改善归于延后一帧，未进入正式入口。

这些数据将反馈长尾定位到 GPU 沙影子可用之前，以及次要的 CPU 命令应用；修订发布到首绘制完成通常只有数毫秒。`apply_us` 是 CPU 命令应用后的时间戳，`visible_frame_us` 是探针在修订发布后等待的首个 `frame_post_draw`，不代表肉眼像素变化的精确时刻。上述三笔诊断仅用于归因，不能代替 20 笔反馈验收。

## 只读回小区域的反证

[区域探针](probe_g05_sand_region_readback.gd) 在同一 tick180 暂停完成态依次读回 32×32 区域和整张 256×256 沙纹理，区域字节与整纹理对应 texel 逐值相等。[区域先](g05_sand_region_readback.json) 为 28.230/21.748 ms；[整张先](g05_sand_region_readback_reverse.json) 为 24.506/26.666 ms（数值顺序均为区域/整张）。区域只有 4 KiB，整张 256 KiB，但这两轮没有显示稳定的区域传输优势。活跃模拟下的 100–200 ms 长尾不能仅据数据量归因。探针使用 Godot `RenderingDevice.texture_copy` 和 `texture_get_data_async`，适用范围只到该暂停完成态。

补做 [活跃模拟成对探针](probe_g05_sand_region_active.gd)：正式耦合场景在1920×1080可见窗口持续运行，每12 tick在同一渲染线程回调内连续请求32×32区域与整张沙图，12组交替请求顺序。每组分别回传4096/262144字节；[JSON](g05_sand_region_active.json) 中区域/整张回调延迟中位45.551/45.552 ms，逐组差距0–0.6 ms。源/JSON SHA256 分别为 `22A4678BC878F00A93E3EA33CAE9A0525C03729226C7852B7ED8228877B316B7` / `DC9DFCA00360A8DE667E488808F86208CA01417F39AA4B0D7EBE0F400ACC9A08`。当时另有用户Godot预览占用GPU，且成对请求可能在同一队列围栏一起完成；所以只支持“本条件下减小传输量没有缩短回调等待”，不能估计独立区域请求的正式20笔反馈或空闲GPU表现。暂不把区域读回接入权威沙影子。

## CPU 笔刷枚举优化

`SandWaterDomain._brush_cells()` 原先对每次 0.38 m 笔刷扫描整张 256² 网格。在 [原 CPU 分段](g05_edit_cpu_phase/manifest.json) 的三笔中，`domain.apply_tool()` 为 27.491/27.612/29.520 ms；快照和 dirty-max 阶段各不足 0.05 ms。现改为仅枚举笔刷圆/扫掠胶囊的包围盒，保留原来的格子中心、距离、权重公式及 y→x 遍历顺序，并向外多取一格防浮点边界遗漏。

[等价探针](g05_brush_bounds_equivalence.json) 用固定 seed `53021` 对 64² 与 256² 共 274 个圆形、边界、域外与扫掠用例逐元素对比原逐格算法，全部一致；256² 目标笔刷在同进程的原逐格/包围盒遍历分别为 48.923 ms/0.086 ms。优化后的 [CPU 分段](g05_edit_cpu_phase_bounded/manifest.json) 中 `domain.apply_tool()` 为 1.155/0.148/0.822 ms。17 项模拟契约、3 项场景集成、拓扑及 [旧沙夹具工具操作](../../../../tests/visual_phase2/run_sand_fixture_tools.ps1) 通过。沙域源码当前 SHA256 `449B69482A2DE6347A3562B6610507B2669BB8BCDC34CB6E15E363946866CADC`。

正式耦合场景另用原 G04 探针的仅改输出目录副本 [probe_g04_edit_bounded.gd](probe_g04_edit_bounded.gd) 复跑：三笔挖/堆/扫掠编辑、库存加场内沙量守恒、64个碰撞 chunk、tick180存档恢复与tick210原始/恢复配对字段及表现时钟均通过，[新 manifest](g04_probe_bounded/manifest.json) 记录原/恢复 GPU 字段最大绝对差全为0。探针 SHA256 `11DA382B7E7DF477DEAE5A219AD9608BA816D5D9940F436AF5CDCBD2C9EE73D7`，manifest SHA256 `2F2C732A9C72B6B89FD23300F882ADFEC2AA0F09838C30641989E7350911B4BE`；旧 G04 证据未覆盖。

优化后的 [20 笔反馈](g05_edit_feedback_bounded/manifest.json) 最大 129.860 ms，未过 ≤100 ms；首笔 90.717 ms，此后多笔沙同步在 100–130 ms。CPU 成本下降是已测事实，整体反馈仍受 GPU 沙读回等待影响。

## 隔离项目的渲染队列短试验

为检查 Godot `rendering/rendering_device/vsync/frame_queue_size` 是否是主要等待源，在 `D:/godot/project/sandcastle_queue1_curated` 单独创建精简项目；脚本、测试和必要的 task 资源是副本，场景目录是联接，正式 `project.godot` 与正式脚本均未修改。隔离项目采用上文两份阶段追踪脚本快照及当前包围盒沙域。最初的全 task 联接导致导入扫描大量历史产物，已停止；对其清理被自动审批策略拒绝，因此未做破坏性清理。另一个精简尝试导入异常后保留诊断目录。最终精简项目导入成功，探针在 1920×1080 可见 D3D12/GTX 1050 运行，运行时读取到实际队列值。

首次全 task 联接的导入在 `g05_cost` 中额外生成一份 `release_edits_bounded_60s_coupled_frames.csv.import` 和九份同前缀 `.translation`，创建时间为 2026-10-10 08:12:51–52；它们不是验收产物。对这十个已核实文件的逐项清理也被自动审批策略拒绝，故暂留，勿纳入数据索引或成本证据。

同一精简项目、同一 5 笔探针的 [队列 1](g05_edit_queue1_isolated_manifest.json) 和 [队列 2](g05_edit_queue2_isolated_manifest.json) 最大提交到首绘制分别为 113.072/115.343 ms，均未达 100 ms；第 2–5 笔仍触发沙同步。队列 1 清单 SHA256 `98677473867745DF80F78BA823C11E152FD7DD8D3FED27D7CF53FFA6ED30BCCF`，队列 2 为 `DC98847764C8DAEC600B298C6C82E6F1EA2AD8CE0CF13F3E1A55971EB37C2A08`。两次先后执行且机器有其他 Godot/GPU 负载；5 笔样本不能估计正式 p99，也不能证明 2.271 ms 差异由队列设置造成。当前不把此设置带入正式项目。

另在隔离项目队列 2 下，只把求解器的 `sand` 读取改为同步 `texture_get_data`，其余字段维持异步；[试验脚本快照](gpu_shallow_solver_g05_sync_trial.gd.txt) SHA256 `5F5AB7D852FAB2557A6DE7E447F1697165D82044A271E520B13C0180ECC96920`。[五笔结果](g05_edit_sync_sand_isolated_manifest.json) 最大 116.135 ms（清单 SHA256 `5EE7B703B7DB36BC6A503D2A95CB8AC7F6D66D2A3483890D7D5F705950DFD7AE`），仍未达标；首笔虽为 44.254 ms，但后四笔均为 110–116 ms。同步读回会占住渲染线程，尚无总成本证据，且此短样本未给出反馈收益，因此没有进入正式代码。

## 成本环境限制与下一查证

优化后 [60 秒编辑窗口](g05_cost/release_edits_bounded_60s_coupled_manifest.json) 为 p99 50.483 ms、16.112 tick/s，连编辑前 10 秒预热只到 tick170；随后的 [20 秒无编辑窗口](g05_cost/release_wave_current_20s_coupled_manifest.json) 和恢复正式预览脚本后的 [无编辑复测](g05_cost/release_wave_no_instrument_20s_coupled_manifest.json) 分别只有 17.348/17.441 tick/s，说明当时的慢速不由笔刷枚举或阶段追踪独立造成。这些新窗口**不作为正式成本 A/B**，旧失败结果也不回写。

[同时负载快照](g05_concurrent_gpu_load.json) 于 2026-10-10 07:51 Asia/Shanghai 显示 GPU 利用率 88%，且 Godot 编辑器及其启动的另一个沙滩预览场景正在运行。未终止这些用户进程。待当前机器可提供独占或稳定可记录的 GPU 负载时，按正式 1080p、60 秒编辑窗口复测同一场景和 profile，再决定本优化对 p99、30 Hz 的收益。后续读回优化应先记录沙同步请求/回调与 GPU 队列时间，保留权威沙量和命令队列语义。
