# G05 成本候选与归因

状态：候选收敛，RG4 仍未过。下表的 20 秒运行仅用于单因素筛选；正式门槛使用真实窗口至少 60 秒的数据。所有数字来自 `g05_cost/*_coupled_manifest.json`，环境为 GTX 1050、D3D12、1920×1080、VSync off、持续浪，除非另述。原始 CSV、有效 profile 与具体运行配置均在同名 manifest 中。

| 候选或单因素 | 窗口 | 墙钟 p99 | tick/s | 结论 |
|---|---:|---:|---:|---|
| 原固定样片完整受光沙 shader | 60 s | 55.338 ms | 19.198 | 成本失败；旧 v8 20 秒对照 19.771 ms、29.996 tick/s，新增沙面材质是主要增量。 |
| 关闭细沫 / 接触 / 颗粒法线 | 各20 s | 52.644 / 53.339 / 52.868 ms | 约20 | 单独削这些层无法解决主要成本。 |
| 旧 unlit 沙 shader | 20 s | 27.974 ms | 30.040 | 快，但没有场景太阳对沙体的受光，未采用。 |
| Lambert fragment / 自定义 `light()` | 各20 s | 44.820 / 48.231 ms | 23.468 / 19.942 | 仍超限。 |
| 顶点受光 | 60 s | 39.103 ms | 28.573 | 真实场景光照可保留；单独不够。 |
| 顶点受光 + 单级阴影 + 64×128 静态细沫网格 | 60 s | 33.261 ms | 29.999 | 候选场景恰贴门槛，后续正式场景复测 34.097 ms，余量不足。 |
| 进一步减至 32×128 细沫 | 60 s | 33.672 ms | 29.667 | 收益不稳定，细沫更稀疏，未采用。 |

`no_sun_shadow` 的初期 20 秒试验基于原 fragment lit shader，p99 42.894 ms，不能直接推断最终顶点受光组合；关闭投影的决策由后者的 60 秒复测和同状态 A/B 支持。手写 4-tap 阴影虽降到 27.659 ms，但沙体出现明显自阴影锯齿，拒绝。混合 unlit 底床/局部 lit overlay 在岸线产生锯齿，拒绝。降低 `render_subdivision`、半分辨率反射、关闭底纹等试验触发严格有效 profile 校验，不能当作通过的候选。

正式入口 `scripts/visual/test1_beach_fixed_entry.gd` 在调用共享预览配置后关闭阴影，因为共享父脚本会重置场景里的 `shadow_enabled`。首次只改 `.tscn` 的复测仍为 34.583 ms；定位到该覆盖后，同样场景的正常入口为 31.459 ms。场景同时保存 `shadow_enabled=false`，使预先可定的配置可查。

主视角 300 秒窗口 p99 为 31.112 ms，但 tick/s 为 29.949，保留未过。tick 8370 的完成时长 631.053 ms，位于约269.7秒；近景与掠射300秒各达30.002 tick/s。源于引擎、测量机或其他外部状态尚未知，不能把异常自行剔除或回写旧失败。编辑负载 60 秒另见 [RG4](../验收/RG4_实时沙滩与联合验收.md)。

30 分钟交替编辑的计时探针提交 566 笔、发生 530 次 `sand_only_syncs`，只有 36 次 `sand_prefetch_hits`。编辑后五个 tick 内最大完成时长的中位数约39.6 ms、p95约652 ms，163/566 笔附近超过100 ms。由于测试每90 tick一次，提交相位固定在 `tick % 30 == 28`，周期审计与编辑可能相互争用；需做错开审计相位的对照。当前可直接确定的是多数独立编辑触发沙影子同步，这与编辑负载吞吐下降一致；不能仅据相关性断言所有长停顿都是该同步造成。

无逐 tick 缓冲的 60 秒单因素复验：每90 tick提交，p99 35.888 ms、tick/s 28.863；改为每91 tick，其余不变，p99 31.771 ms、tick/s 29.958。周期相位是实质成本因素，但后者仍未过严格30Hz门槛。91 tick 相位扫描持续300秒、98笔编辑时 p99 34.477 ms、tick/s 29.882，长窗口也未过。

悬停预取隔离试验在 `reference_preview.gd` 增加默认关闭的只读开关，仅试验场景开启。最初误接在另一条 demo 继承链，20笔的0次预取命中属于无效试验，代码已从错误脚本撤回。有效接线且两边均显示笔刷环、指针位置相同时，60秒对照20笔为20次沙同步、0次预取命中，p99 33.054 ms、29.940 tick/s；预取试验19笔为0次沙同步、19次命中，p99 31.377 ms、29.680 tick/s。独立 [反馈试验](g05_edit_feedback_hover_trial/manifest.json) 20/20次命中，但冷首笔仍210.1 ms，余下19笔约53–81 ms。后续[阶段追踪](G05_编辑反馈阶段定位.md)确认点击前成功预取为0，所谓命中发生在点击后的等待中；因此不能把该结果解释成提前备好的沙影子。正式场景保持 `prefetch_sand_on_hover=false`，试验代码和场景保留供查证。

`apply_us` 由共享预览脚本 `_apply_due_tool_commands()` 在 CPU 命令应用后记录，`visible_frame_us` 是探针等待该修订号后的第一个 `frame_post_draw`；它不证明肉眼实际像素变化时刻。三轮长尾都在应用前，应用后的绘制尾段相对短。预取运行首笔已命中且没有沙同步，提交→应用仍为207.215 ms，所以沙影子读回不能单独解释冷首笔。下一次有意义的测量应在同一笔命令记录提交、`_dispatch_paused_patch` 入口、沙同步请求/回调、`_apply_due_tool_commands` 入口/出口及 GPU patch 提交时间和修订号，以区分主线程等待、读回和 CPU apply。

无编辑对照的 `input_diagnostic` 显示 `command_id=0`、应用日志0条、`prefetch_sand_on_hover=false`、`sand_only_syncs=0`、`sand_prefetch_hits=0`；此前一轮无编辑运行出现315次预取命中，配置异常，未作为干净对照。编辑运行20笔有19次沙同步、1次预取命中。独立20笔反馈在GPU负载约23%时最大79.635 ms，通过短反馈门；另一轮负载约42%的最大128.211 ms未过。启动预读回试验最大88.947 ms，但后续无预读回对照已通过，不能归因于预读回，因此正式脚本未采纳。

离线逐 tick 拆分：空闲编辑运行 `render_submit_us→ledger_render_us` 的 p50/p99 为24.688/36.508 ms，`cfl_render_us→render_finish_us` 为4.598/17.071 ms；无编辑分别为25.988/37.533 ms 与3.688/23.094 ms。两者的长尾均主要处于渲染线程提交之后的异步等待段，CPU tick 提交本身 p99 低于0.6 ms。`--max-fps 60` 使后一等待段 p50 增至12.557 ms，限帧不是本机可用的修复。该时间划分只定位等待区间，尚不能进一步区分 GPU 工作、队列或引擎调度。

[逐帧编辑邻域分析](g05_cost/release_edits_idle_60s_edit_locality.json)由[可复验脚本](analyze_g05_edit_locality.py)从两份原始 CSV/manifest 生成，按正式探针的 p99 取位规则统计。编辑运行 3979 帧中，提交 tick 或后一 tick 的119帧有19帧超过33.3 ms，局部 p99 68.808 ms；其余3860帧仅28帧越界，p99 30.564 ms。20笔的局部尖峰是真实可定位的成本来源；另一次无编辑运行仍有62/3950帧越界、p99 37.172 ms，说明同时存在非编辑长尾。两次运行的外部负载不能逐帧配对，邻域统计只支持同运行关联，不证明每个尖峰的内部成因。下一步应对沙影子读回请求、回调以及同笔编辑附近的主/渲染线程帧时间同步打点。

补充[20秒主线程帧诊断](g05_cost/release_edits_mainframe_diag_20s_coupled_manifest.json)，只对正式成本探针开放原本已经实现的 `--main-frame-timing` profile 参数，和 `--tick-timing` 同时使用；第一次因参数白名单遗漏报 `invalid arguments`，未产生测量，随后修正白名单。正式耦合场景、profile、1080p/D3D12/VSync off、持续浪、10秒预热未变；此短窗口不用于 RG4 验收。第1–6笔提交 tick 为352/442/532/622/712/802。[主线程帧入口时间戳](g05_cost/release_edits_mainframe_diag_20s_coupled_main_frames.csv)显示，六次提交之后同一 tick 完成的下一次 `_process` 帧入口间隔分别为62.849/50.703/80.243/70.254/100.363/99.156 ms，入口 `tick_pending` 均从1变为0。提交发生在此前一帧入口之后，距离下一入口仅0.048–0.248 ms，故尖峰并非 `_submit_brush()` 本身的长同步调用；长间隔落在待完成 tick 和下一帧入口之间。其余主线程帧也有非编辑长尾。该定位仍不足以把间隔细分为沙读回、GPU队列等待或引擎调度，下一步需要同笔请求/回调/主线程阶段共用时间戳。

## 沙读回 CPU 校验工作线程候选

[单笔追踪场景](test1_shadow_trace_scene.tscn)及[探针](probe_g05_shadow_trace_cost.gd)仅覆盖第2–6笔需要沙影子同步的编辑；[原始时间线](g05_cost/release_edits_shadow_trace_20s_coupled_shadow_trace.csv)显示 `render_request_exit→readback_callback` 为19.735–29.102 ms，回调后主线程 `validate_enter→resume_enter` 为38.298–40.409 ms，而 `_submit_brush()` 本身为0.053–0.082 ms。与之前仅凭反馈阶段推断相比，这次把主线程校验明确量出。诊断脚本记录同一 `Time.get_ticks_usec()` 时钟的主/渲染线程事件，20秒窗口只用于归因。

独立[工作线程场景](test1_worker_sand_scene.tscn)让不可变沙读回字节在 `WorkerThreadPool` 解码/校验，再在主线程登记权威沙影子、库存与命令。对应[原始时间线](g05_cost/release_edits_worker_sand_20s_coupled_shadow_trace.csv)和[双运行汇总](g05_cost/release_edits_worker_sand_20s_comparison.json)显示工作线程校验中位12.870 ms，读回请求到编辑恢复中位从67.501降至37.363 ms；短窗口帧 p99 39.341→34.225 ms，完成 tick/s 29.937→29.971。两次不同时间运行，不能把整窗差值全归于线程迁移。[20笔反馈](g05_edit_worker_sand_feedback/manifest.json)的热编辑19笔为19.360–58.517 ms，但冷首笔200.763 ms，未过100 ms；冷首笔是提交后预取命中，不走该工作线程沙同步路径。

去除追踪开销的[场景候选](test1_worker_sand_clean_scene.tscn)在正式1080p、D3D12、VSync off、10秒预热、持续浪下，[60秒20笔编辑](g05_cost/release_edits_worker_sand_clean_60s_coupled_manifest.json)为 p99 **38.941 ms**、29.982 Hz，未过 RG4；紧接的[原场景20笔对照](g05_cost/release_edits_worker_control_60s_coupled_manifest.json)为41.168 ms、29.935 Hz，亦未过。逐帧邻域：候选编辑附近140帧仅2帧超过33.3 ms、p99 31.101 ms；原场景对照120帧有22帧越界、p99 66.710 ms；远离编辑的候选仍有77/3843帧越界、p99 38.941 ms。这支持候选削减局部编辑尖峰，但完整成本门仍由非编辑长尾拖住，跨运行环境也未严格相同。

[G04功能复验](g04_probe_worker_sand_clean/manifest.json)在候选场景下通过三笔编辑、沙量加库存守恒、64个碰撞chunk及tick180→210配对恢复；`sand_hashes` 和恢复后 rock/sand/water/momentum/foam/local_front hash 与[原正式场景](g04_probe_bounded/manifest.json)逐项相同。60秒成本运行后，候选补上 `WorkerThreadPool` task ID 的完成回收和退出等待；[回收版源码](test1_worker_sand_clean_entry.gd) SHA256 `1034E444A027D38CD31128659FA8C1CD0E66155EF43D5AA49D6C771649104E9F`。此前成本运行时的源码可由[试验快照](test1_worker_sand_clean_pre_cleanup.gd.txt)复原。

回收版随后在[60秒完整编辑负载](g05_cost/release_edits_worker_sand_cleanup_60s_coupled_manifest.json)测得 p99 **36.937 ms**、29.959 Hz，仍未过成本门；[同运行邻域分析](g05_cost/release_edits_worker_sand_cleanup_60s_edit_locality.json)中编辑附近142帧仅1帧超过33.3 ms，远离编辑的3768帧有93帧超限。候选已接入正式耦合场景：[正式入口](../../../../scripts/visual/test1_beach_edit_worker_entry.gd)与回收版仅注释不同，入口 SHA256 `C9B4A4D15B9FE1DF97F653DF9330A08CCF54312FA275F9D505873F850F9C0582`，场景 SHA256 `8633AE81FD3B95678D296CAC09C3B22268A0AF65EA137A845DA642C7E4B0BCD5`。共享预览源码仍为 `E10841E9B3D6CDDE1F24CEA6ED9564C3C085408B96EEAB49C4C919289E96D43B`。

接入后[正式场景 G04 复验](g04_probe_worker_integrated/manifest.json)通过三笔编辑、沙量库存闭合、64个碰撞 chunk 与 tick180→210 恢复；恢复后的各权威字段和白沫/局部浪 hash 与旧正式场景逐项相等。[正式入口20笔反馈](g05_edit_worker_integrated_feedback/manifest.json)全部完成，最大提交至首绘制帧为 **60.818 ms**，本次满足100 ms门槛；历史冷首笔失败仍保留。用户已要求暂停性能优化，因此不再用新测量冲抵既有成本失败。
