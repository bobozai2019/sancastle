## 2. G01：先确定整体画面怎样组成

1. 确认test1最终画面与用户参考属于同一目标；记录capture hash、输出资源、机位/投影能恢复部分与不可恢复部分。
2. 根据全部事件目录做渲染图：沙/底面→水面→独立亮沫→后处理/最终输出，并把depth/scene color/纹理/CS/实例buffer连接起来。
3. 主机位需保留沙滩占画面比例、浪推进方向、浅水可见范围、主要沙体和太阳阴影关系。辅机位选择近景/掠射，用于揭露片层、穿岸和厚度问题。
4. 建目标板：干沙、高沙体、浅水、深水、浪前、岸脚、遮挡ROI与原始pass图；每张标输出尺寸、color space、曝光/映射、事件和局部定位。
5. 世界尺度能由数据解码则记录，不能解码则采用场景相对尺寸；不能把竞品0.5m高度/29950实例直接变成Godot固定预算。

结论要求：哪些层贡献了最终观感，哪些属于几何、光照、材质、合成或输出映射；最终亮白部分不能全归因于某一层。

## 3. G02：沙子分析哪些

| 问题 | 包内证据 | RDC/运行期证据 | 最终结论必须回答 |
|---|---|---|---|
| 沙体是何种表示 | Mesh/视觉配置/相关字段/shader | VS输入/VSOut/采样/截面 | 高度场、独立模型或其他表示能确认到哪；哪些形状能表达 |
| 高塔/陡坡怎样形成 | 初态/材料参数、状态纹理及相关ComputeShader | 冻结几何、模拟前后、必要时带时序观测 | 初始形体、保形和受损分开，不由单帧推断塌落算法，不研究建造业务流程 |
| 沙色/颗粒/法线 | Lit/Sand、纹理、材质实际字段 | PS采样/常量、受光/阴影资源 | 哪些纹理/世界尺度/粗糙度影响沙质感 |
| 干湿与侧面明暗 | 湿度/材质字段/灯光设置 | 有效常量、阴影/深度、最终贡献 | 干湿、光照与沙岩分类分别起何作用 |
| 水下沙底/亮纹 | 底面材质与Caustics引用 | 底面pass前后、纹理/CS来源 | 水底效果落在哪一层，避免Godot重复染色 |

预期取得的是可实现的沙形/受光/材质依据。任意悬挑、细城垛、实时崩塌如无证据不能宣称已恢复；不把更高分辨率/体素作为默认结论。

## 4. G03：水、浪、光学和亮纹分析哪些

| 问题 | 必取数据 | 怎样判定 |
|---|---|---|
| 水面高度与浪前截面 | 水面VS字节码、输入/VSOut、高度或状态纹理、有效参数 | 复算抬升/横移/曲率；区分主水面高度和独立白沫视觉厚度 |
| 水面法线与小波 | 1024²方向纹理、PS/VS采样、尺度/时间常量 | 解码真实采样/组合；纹理“看起来像法线”只能先记线索 |
| 浅水透底和深水颜色 | 水面PS、scene color/depth、材质颜色/消光字段 | 区分吸收/散射/alpha/合成，记录单位和深度来源 |
| 反射与折射 | 相关输入纹理、法线空间、UV/深度指令、渲染顺序 | 找到实际取样链，确认前景遮挡/回退；不凭倒影外观判断算法 |
| 水底亮纹生成与动画 | Caustics/causticsMap、底面PS、上游CS或纹理 | 纹理采样、程序生成、投射来源据实区别；时间证据不足则未知 |
| 高光/曝光影响 | 太阳/环境/阴影/后处理常量 | 分离照明与色调映射，防止把输出亮度当材质颜色 |

对能取得公式的链，报告输入→采样/计算→参数→输出，给原始常量与片段定位。对未知链，报告可观察要求与候选Godot适配方案，说明怎样用分项消融区分。

## 5. G04：白沫、岸线与动态

1. 对6196确认它在实际capture里仍是强亮绘制，保存前/后HDR像素与图、混合/深度状态、全部或明确范围实例数据。
2. 解码四边形的世界位置、大小、朝向、颜色/alpha/UV/年龄等可证实字段；buffer语义须有shader指令和stride支持，不能按字节猜“寿命”。
3. 追踪CS3867/3872及真正实例buffer生产者，分别记录场景输入、中间纹理、写入/追加/间接参数、消费端；区分“驱动白沫的输入”与“实例的实际生成公式”。
4. 判断亮沫高度与水面/岸脚的对齐、depth test、尺寸分布、密度和分裂外观；水平小片事实只支持该帧姿态，不自动证明完整粒子生命周期。
5. 单帧不能证明推进速度、衰减、平流和侵蚀因果。若关键时序必须确认，录制竞品同机位、有时间戳的入浪→退浪片段，再取少量关键多帧捕捉；若无法取得，原作动态结论保持C0/C1，Godot动态目标独立验证。
6. 岸脚分析以实际可见沙面、水面、湿域与相交位置为基准；同时看主浪前与障碍脚，避免永久白环/干沙误白。
