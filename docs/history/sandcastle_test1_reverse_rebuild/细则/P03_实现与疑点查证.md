# P03 实现与疑点查证

日期：2026-10-09。负责人：主执行者。状态：[未开始]。进度：0/5。依赖：RG2。

目标：按已分析的效果作用链做完整沙滩样片，随后整合现有实时模拟和交互。每个改动能说明依据及验证方式；未知点沿索引查证，失败候选不进入默认profile。

范围约束：实现效果技术与本项目接口适配；业务、堆挖交互和存档沿用本项目已有系统。查证不分析或复刻竞品任务、经济、物品/工具业务、UI、存档业务和平台接入，不恢复C#业务方法或业务调用链。

## 3. G01：先做正确的整体场景

1. 用RG2相近构图初始化沙滩、浅滩沟槽、宽沙体和少量高沙体，画面包括完整深浅水与入浪区域。尺度根据已确认数据或相对关系确定。
2. 场景固化地形/水面显示节点、相机、太阳、环境、资源绑定、固定信号；用必要脚本初始化数据及运行GPU系统，不在_ready生成静态层级。
3. 先固定沙床和表现时钟，检查沙体轮廓、床面/法线/沙岩分类、真实受光和阴影。此时不混入侵蚀/塌落造成形体变化。
4. 复用既有材质能力，只有实施映射指定的缺口才改；建立改前截图和source/profilehash。
5. 保存主/近景/掠射相机定义、初始bed、水深和light配置，后续所有分项使用同一基线。

## 4. G02：沙、浅水和亮纹

1. 沙先实现暖色、粗糙度、细颗粒与坡面受光；颗粒绑世界/沙面位置，转镜头不漂移。已有wetness/compaction只做材质映射，干湿/压实效果单独对照。
2. 浅水把沙底可读性、深度颜色、法线小波、高光、反射/折射逐层加入；每次只改变一层，同态保留权威状态hash。
3. 亮纹按分析选定的纹理/程序/投射适配接到底面，不重复在沙底和水面各加一遍。查尺度/相位/衰减，干地负例不亮。
4. 每个公式/参数注明结论ID或Godot适配ID；参数名、单位、范围与实际消费者写入profile/schema。
5. 近景和掠射检查浅水是否被遮死、前景是否被折射拖入水、反射是否形成硬大块，记录相关Q-ID再查证。

## 5. G03：浪、白沫与接触，完成固定样片

1. 先纯色主水面观察浪前轮廓/深度/湿域，核对分析中的几何与状态输入。目标是可见连续起伏；不预设必须完整翻卷。
2. 白沫按证据选择独立细片/实例或其他适配表示，统一水面高度和可见沙床。明确seed、生成源、覆盖/尺寸、迁移/衰减、深度测试及资源预算。
3. 主浪前白沫与岸脚接触分别隔离：先关一个看另一个，检查贡献；禁止用大范围混白遮住几何/接触问题。
4. 检查无波、干沙、陡岸、岛脚、前景遮挡和三机位；观察单包生成→推进→消退及连续多包。
5. 录制至少60秒、至少3次入退浪主视角，再补近景/掠射片段；机位不同只比特征，不能按同坐标像素判竞品等价。
6. RG3通过再整合模拟。效果仍缺时登记根因/候选及Q-ID，不能把成功截图的日志PASS当视觉通过。

## 6. G04：接已有实时模拟和编辑

1. 同一profile进入coupled场景，复用GPU域、波命令、tool queue、碰撞代理、湿度、侵蚀和已有支持/恢复能力。
2. 让可编辑沙体由权威沙字段形成；显示采样和碰撞误差遵守旧契约，动态增减量沿旧账本。装饰/诊断几何若用于早期分析，不替代正式可编辑沙。
3. 录制现有操作链：堆沙→挖沟→浪覆盖→退浪→已有水沙演化；相同初态/seed与不操作负例对照。
4. 卡顿只在当前真实编辑负载取时间戳，定位回读/同步/碰撞/dispatch；在相应模块修复，避免静态帧性能替代交互。
5. 暂停、冻结、保存恢复、转镜头继续使用同一表现时钟；实例/白沫持久字段需要明确保存/可重建策略和版本默认。
6. 改到模拟/碰撞/保存链的部分重跑对应旧回归，纯视觉开关前后权威字段同态。直接入口、捕图、录像、性能探针均读effective_profile。

## 7. 不清楚时怎样查证：实际执行范例

完整流程见[查证契约](../契约/分析结论与查证契约.md)，下面是执行者可直接采用的顺序。

### 例A：浪前变成大片白墙

1. 固定当前tick与镜头，保留源码/profilehash，登记Q-WAVE-WHITE。
2. 解释候选：水面着白范围过大；独立白沫尺寸太大；深度/高度错位。
3. 索引查水面VS/PS和6196的shader/实例buffer/常量，取得raw与可读数据，查看各层实际贡献。
4. Godot分别关主面白色、关独立白沫、纯色水面；每次只变一个因素，权威水沙不变。
5. 若归因到实例尺度，查原作投影尺寸分布与相同视角可观察要求再选Godot尺寸；若归因到几何，查VSOut截面/显示采样，不能继续调白色增益。
6. 更新结论/限制，修复后再测无波/岸脚和多相位。

### 例B：水底亮纹是细密闭环、与参考不同

1. 登记Q-CAUSTICS-SHAPE，冻结水/沙/光照，分别保存开与关亮纹。
2. 从Caustics候选对象查材质/PPtr和实际底面PS采样输入，取得原纹理raw、格式、UV尺度及时间常量；如运行时生成则追CS。
3. 对比同类投影ROI中的线宽、柔和度、分叉/频谱和明暗；只匹配频率不足以证明形状正确。
4. 候选每次只改生成形状、投影或增益之一；原公式未知时标Godot适配，不声称还原。

### 例C：高沙体一运行就被推平

1. 冻结模拟看初始几何；区分初始造型不足和运行时松弛。
2. 索引查初始沙形/状态数据、Sand相关材料参数、材质及ComputeShader，不查竞品建造业务方法，不由沙体截图猜力学参数。
3. Godot保存沙量/压实/支持状态前后及剖面，核对现有材料/结构更新。
4. 若只是视觉样片表示问题，修初始数据/显示；若需改物理保形，单立影响决策并重验相关守恒/碰撞/恢复，不顺手改整个沙模型。

### 例D：索引没有对应数据或反编译失败

1. 返回P01记录的failed/raw_only条目，核对来源版本/hash和缺失依赖。
2. 可取原字节则先保留，不能用空数组/空方法替代。
3. 包内拿不到的运行时状态改从RDC producer/consumer链获取；时序拿不到则带时间戳运行观察。
4. 仍无法确定时，保留unknown并验证Godot替代；需要该未知项才能继续的任务单独标依赖，推进可独立部分。
