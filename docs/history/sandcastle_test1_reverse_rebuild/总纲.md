## 1. 目标与执行入口

做出接近 `sandcastlegame/test1.rdc` 的沙滩：有体积与受光的沙体、可读沙底的浅水、向岸推进的浪、细碎白沫和自然水沙接触；随后接入项目已有水沙模拟与堆沙/挖沙交互。用户指定顺序为 **先拆包并建立原始数据索引 → 分析效果来源与结论可信度 → 实现并持续查证疑点**。

**代码范围：只分析效果技术代码和数据，不分析或复刻竞品业务代码。**重点为沙/水/浪/白沫/亮纹的Shader、ComputeShader、纹理、网格、buffer、材质和运行时有效参数。C#/IL2CPP仅作必要视觉资源类型/字段/序列化配置的辅助解码入口，不做全量方法反编译、业务调用链或业务行为恢复。渲染顺序与dispatch优先从RDC直接取证；Godot业务和交互沿用本项目现有系统。

本计划是这条新工作线的入口。旧 `sandcastle_water_render_alignment`、`sandcastle_sand_foundation`、`sandcastle_visual_reconstruction_phase2` 和 `sandcastle_water_sand_coupling` 的实现、证据及已冻结数值契约继续复用；不回写旧验收或把旧进度累计到本包。新的独立样片可在本包分析门通过后实施，不等待旧 WR-G3 全部通过；正式回接共享入口时再明确接口与回归范围。

截至2026-10-10已完成拆包、分析、固定样片和实时小体积编辑整合；用户现要求全部暂停并清理中间产物，RG4未通过。计划定义保持原验收门槛，实时进度、失败和未知项见 [执行状态](执行状态.md)。

| [Godot 实现与验收](契约/Godot实现与验收契约.md) | RG2 冻结实施边界 | 场景固化、GPU状态、时钟、profile、视觉与回归 |

本项目是本地文件和 Godot GPU 接口，没有 HTTP/数据库/网页路由或 OpenAPI 需求。相关文件与命令接口采用字段级契约。

| 模式 | 输入 | 输出及用途 |
|---|---|---|
| package_readonly | 竞品原文件、哈希、选定工具 | 索引和导出，不修改原包 |
| rdc_replay | 指定 SHA256 的 test1.rdc | 事件、资源、原始字节与绘制贡献 |
| frozen_sample | 新样片、固定完成态/seed/时钟/镜头 | 每次只改一个变量的视觉对照 |
| realtime_fixed | 固定沙床、连续浪、同一profile | 快速确认视觉路线和时序 |
| realtime_coupled | 现有GPU水沙、堆挖交互、同一profile | 最终集成与动作观察 |
| legacy_regression | 原夹具和原配置 | 原正确性、碰撞、保存恢复回归 |
| release_measurement | 可见1920×1080、D3D12、GTX1050、VSync off | 当前完整配置成本；记录实际环境 |
