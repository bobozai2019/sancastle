# 分析结论与查证契约

日期：2026-10-09。角色：contract。状态：draft，RG2冻结。

分析与查证只覆盖沙、水、浪、白沫、亮纹的效果技术及数据。竞品业务代码、任务/经济/物品/工具/UI流程、存档业务和平台接入均排除；技术疑点优先从资源、Shader/ComputeShader和RDC取证，不扩大为C#方法或业务调用链恢复。

## 1. 结论结构与可信度

`analysis/conclusions.jsonl`中每条结论必填：`conclusion_id, topic, statement, claim_kind, confidence, evidence_ids, source_locations, procedure_ref, counterevidence, limitations, applicability, godot_action, unresolved_question_ids`。

`claim_kind`为`observed_fact/algorithm_inference/godot_adaptation`。可信度使用下表，不生成缺乏统计含义的“95%可信”。

| 级别 | 判据 | 可怎么使用 |
|---|---|---|
| C3 直接证实 | 原始字段/运行时数据/指令或可重复绘制贡献直接支持该陈述，定位和复验完整 | 作为有明确范围的事实；单帧事实仍只适用于该帧 |
| C2 交叉支持 | 至少两类实质独立证据一致，如包内字段+运行时常量、指令链+单变量重放；替代解释已排查 | 支持实施选择；算法结论仍写推断 |
| C1 线索/假设 | 仅名称、字符串、图片外观、参数相关性或未核实伪代码 | 用于检索或设计实验，不直接冻结原作算法 |
| C0 未知/冲突 | 缺证据、解析失败或多证据冲突 | 登记Q-ID，安排查证或明确替代路线 |

可信度针对具体陈述，不针对整个模块。“某Shader名字存在”可直接证实其字节线索，但“它实现了真实焦散”仍是C1/C0。资产默认值和运行时实际值不能互换。相同原始数据的PNG与图表不算两份独立证据。

## 2. 什么能算分析结论

每个主题的报告按固定次序写：问题 → 已确认事实 → 推断与替代解释 → 可信度及适用范围 → 未知项 → Godot实施选择 → 验证/否决办法。

算法还原须标出字段、指令/反汇编范围、输入输出、单位/坐标空间及常量值；不能只写“像浅水方程/粒子系统/焦散”。无法恢复完整公式时，允许结论为“公式未知；已确认分层/输入/输出，因此选验证过的适配”，不算恢复原算法。

## 3. 未知问题表

`analysis/questions.jsonl`字段：`question_id, symptom, affected_goal, blocking, hypotheses, needed_observation, source_lookup, experiment, budget_minutes, started_at, active_minutes, result, result_evidence_ids, confidence_after, next_action, status`。

`status`为`open/investigating/resolved/accepted_unknown/deferred`。`blocking`是是否阻断当前实施，不等于整个任务停工；原作公式未知而替代方案通过时可accepted_unknown，仍保留限制。

## 4. 实现中的查证链

1. 用固定seed/tick/完成态/相机/profile复现现象，保存当前代码hash和截图/日志。
2. 把疑点写成可区分的问题：例如“白片来自水面alpha还是独立白沫？”列出2–3个解释和能区分它们的观测。
3. 查资源索引，取得shader/材质/纹理/配置的raw与可读数据；从PPtr依赖追踪，核对默认值。
4. 查test1对应事件的有效绑定、原始常量、VSOut、深度/颜色和compute写入来源；核对运行时值。
5. 查相关CS/VS/PS指令、必要视觉配置或已有可信结论，识别单位、空间、stride、条件分支和混合顺序；不查竞品业务方法体或业务调用链。
6. 如静态帧不能区分时序，只读运行竞品、记录带时间戳的视频/多帧捕捉；不能用test35帧号差冒充秒数。确需改变设置做实验时记录改动值并恢复。
7. Godot做单变量开关/纯色/禁用某层/固定输入对照，同时保存权威状态hash；改变多个参数不能归因。
8. 回填结论和反证；标记直接复刻或Godot适配。验证通过才纳入profile，失败保留基线并写下一查证入口。

## 5. 典型问题的取证位置

| 疑点 | 首先取什么 | 怎样区分 |
|---|---|---|
| 浪是不是翻卷体积几何 | 水面VS字节码/VSOut/顶点输入，绘制前后和截面 | 高度/横向位移/深度次序直接观测；图片亮边不证明翻卷 |
| 大片白色来自哪里 | 水面PS与6196前后HDR、混合/深度状态 | 隔离水面与白沫贡献，不能仅按最终白像素面积猜 |
| 亮纹是纹理还是实时计算 | Caustics相关资产、底面PS采样、上游CS、实际纹理 | 找到采样/写入链；有名字不证明生成方法 |
| 岸脚白沫为什么在干沙上 | 湿域/深度输入、shader阈值、原始buffer、可见床面 | 干沙和无波负例，核对水/沙共同高度及坐标 |
| 沙侧面灰、塔太矮或被推平 | 沙材质/灯光、显示高度、沙/岩分类、模拟前后状态 | 纯色/仅光照/仅材质/冻结模拟分别对照 |
| 白沫没有衰减或跟着镜头跑 | 实例buffer/CS更新、时间常量、跨时刻记录 | 固定镜头时间序列+冻结/恢复+转镜头 |
| 倒影/透底不对 | 输入场景色/深度、法线空间、有效常量、渲染顺序 | 透射/反射/折射分别消融，前景遮挡负例 |
| 编辑或浪运行卡顿 | Godot当前负载逐pass/同步等待/回读/碰撞更新 | 单项时序归因；竞品单帧不能给出真实性能 |

查证预算到时：保留原始数据、指出无法区分之处，选择有验收依据的Godot替代或移交独立问题；不得在同一未知点无限换噪声/增益/网格试验。
