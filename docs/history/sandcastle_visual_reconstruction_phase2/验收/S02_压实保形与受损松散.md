# SAND-G0 / S02 压实保形与受损松散：通过

日期：2026-10-06。选定 S01 的有界屈服规则并接入 `sand_v1` 正式场景，水阶段 `water_v1` 参数不变。场景为 256²、0.125 m/格、2× 显示网格；两座初始各 7.9921875 m³ 的等体积塔分置于平床面，左压实、右松散。床面绝对高度抬到 0.20 m，使此步的材料/支撑试验不被潮位淹没；塔体相对尺寸与 S01 相同。

## 形态与质量

主 GPU 材料链 [A/B 原始结果](S01_sand_shape_gpu_ab.json)：压实塔 60 秒后最高点保留 100%、高轮廓 IoU 1.000，超过 ≥90%/≥0.85 门；松沙 10 秒 IoU 0.747、边缘均高从 1.765 m 降至 0.781 m。30/120 Hz、干/适湿/饱和试验见 S01 报告。独立真实场景 tick 300 的 [数值](S02_sand_fixture_t300.json) 和 [截图](S02_sand_fixture_t300.png) 与 A/B 一致：压实 IoU 1.000、松沙 0.747。

支持失效请求 `request_sand_support_loss({generation,request_id})` 仅在 `sand_v1` 完成态且暂停时接受；第 600 tick 将左塔 289 格压实度降至 0.1，沙高不由请求直接改写，后续保守边交换使左塔塌坡。旧 generation 和重复 ID 均被拒绝。30 秒后 tick 1500 左塔 IoU 0.744、边缘均高 0.777 m，见 [事件/审计](S02_sand_support_preview.json) 和 [失效后截图](S02_sand_support_t1500.png)。两塔初始总沙 15.984375 m³，tick 1500 为 15.984384 m³，偏差约 0.000057%；无负沙。塌坡后中心碰撞射线与 GPU 床高误差 2.86×10⁻⁷ m。

第 1500 tick 保存，独立新场景重启至第 1800 tick，沙、压实度、水与双向动量 GPU 字节相同；支持事件 ID、tick、revision、受影响格数随检查点保存并换 generation。存档字段 `support_event_schema_version=1` 且对旧存档兼容；`fixture_id` 和有界屈服参数也随状态保存。原 T08 存档版本门与 W04 水体检查点回归通过。执行 `pwsh -NoProfile -File tests/visual_phase2/run_sand_support_preview.ps1` 输出 PASS。

在 `sand_v1` 场景暂停态实际执行挖、堆、拍实三命令并保存，命令前缀 3 条、工具余量 0.04 m³、碰撞回读无错误，见 [工具结果](S02_sand_fixture_tools.json)。执行 `pwsh -NoProfile -File tests/visual_phase2/run_sand_fixture_tools.ps1` 输出 PASS。原工具碰撞测试误差 10⁻⁶ m、编辑到射线 35.315 ms；完整碰撞、跨 tick 撤销/重做与原 GPU 材料三用例均通过。

本步支持失效是明确请求触发的材料状态变化。由水流冲刷自动判定局部支持不足、让损伤随过程发生，属于 S05 耦合演示；此处不把显式请求当作已实现的自动冲刷检测。
