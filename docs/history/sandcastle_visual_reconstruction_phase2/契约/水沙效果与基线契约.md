# 水沙效果与基线契约

状态：阶段冻结。T09 水体（W01–W06）→T10 沙子（S01–S06）已完成。W01 水夹具、W03 显示床面/岸线边界、W04 波包命令、W05 白沫历史及检查点恢复、W06 水体整档，以及 S01–S06 沙夹具、材料模型、耦合事件与最终配置均已冻结。实际结果只写 `验收/`，不写进契约。

水阶段使用固定 bed，关闭侵蚀、沙坡松弛和支持破坏；水底光学分工可以调整，干沙保形和材质属于后续沙任务。水阶段完成后冻结接口，沙阶段复用并回归；不以沙模型未完成阻塞水体验收。

## 1. 继承的硬边界

1. `bed = rock + sand`，m；water 为水深 m；momentum 为深度平均通量；wetness/compaction 为 [0,1]。沿用原单位和 ping-pong/耦合 pass 顺序。
2. GPU 完成态是渲染权威；同一状态 revision/generation 配套读取。旧 generation 请求不得影响新场景。
3. 显示材质、白沫、细波、纹理过滤不能写 sand/water 或改变质量账户。
4. 256²、32 m、30 Hz 物理基线保留。渲染网格细分不等于物理网格升级。
5. 守恒、非负、命令排序、重放、障碍水量重映射与存档版本门沿用原契约。

## 2. 夹具/显示配置 API（计划新增）

`configure_fixture(config) -> {ok: bool, code: StringName, effective_config: Dictionary}`。

| 字段 | 类型/默认 | 约束/含义 |
|---|---|---|
| `fixture_id` | StringName / `water_v1`、`sand_v1` 或 `sand_coupled_v1` | 水、保形沙与耦合沙分别版本化 |
| `seed` | int / W01、S01 各自冻结 | 同机重复生成一致 |
| `grid_size` | int / 256 | 本阶段正式验收固定 256 |
| `cell_size_m` | float / 0.125 | 正值，正式范围 32 m |
| `enable_erosion` | bool / 水档 false；沙耦合档 true | 必须记录实际运行值 |
| `enable_material` | bool / 水档 false；沙档 true | 水档冻结沙演化；与当前耦合链关系明确 |
| `enable_structures` | bool / 水档 false；`sand_v1` 与 `sand_coupled_v1` false；原预置耦合长稳 true | 沙夹具以材料支撑趾部而非 T06 结构件验证支持损失 |
| `camera_id` | enum / `oblique` | `oblique` / `close` / `grazing`；位置、投影、目标冻结 |
| `profile_id` | StringName / `water_v1`、`sand_v1` | 水档先冻结；沙档复用水参数并追加沙配置 |
| `capture_tick` | int / 每用例冻结 | 完成态捕图；等待所有 in-flight 提交完成 |
| `visual_time_s` | float / 固定值 | 可冻结/显式驱动；不依赖未记录的全局 TIME |
| `render_subdivision` | int / 1 | 候选 1/2；不得偷偷改变模拟网格 |

错误码：`invalid_fixture`、`invalid_profile`、`invalid_config`、`inactive_generation`、`state_not_ready`。失败不覆盖活跃配置。水镜头/基线在 W01 冻结，沙形态/材质输入在 S01 冻结，不预填未经运行的数值。

S01 冻结 `sand_v1` 数值夹具：seed 53021、256²/0.125 m，17×17 格、1.8 m 高、2.125 m 宽等体积双塔；缺口降 0.25 m、中央沟槽降 0.30 m，每塔初始沙 7.9921875 m³。压实/适湿 0.95/0.35，松散/干 0.10/0.05。S02 场景的平基岩绝对高度 0.20 m，用于避免本阶段潮水输入，塔体相对形态与 S01 一致。三镜头、2× 显示网格配置见 `sand_visual_fixture.gd`/`sand_visual_fixture.tscn`。

## 3. 显示状态包

| 字段 | 类型 | 来源/规则 |
|---|---|---|
| `generation` / `revision` | int | 同一 GPU 完成态 |
| `rock` / `sand` / `water` | Texture2DRD | 权威纹理，m |
| `wetness` / `compaction` | Texture2DRD | 原材料字段 [0,1] |
| `momentum_x` / `momentum_z` | Texture2DRD | 原浅水字段 |
| `sediment` | Texture2DRD | 原悬沙字段；光学混浊映射有界 |
| `visual_time_s` | float | 冻结/播放时间；只驱动显示 |
| `foam`（可选新增） | 单/双通道 Texture2DRD | 仅视觉；覆盖 [0,1]、寿命/衰减单位由 W05 冻结 |

水重建以 `eta = bed + water` 为输入，局部使用受限制的连续重建得到显示水面，再与同规则显示 bed 比较深度。不要无约束双线性插值水深把水铺上干岸；悬沙也不能形成干岸着色。

候选方案：有限连续采样 + 近景更密显示网格；或屏幕空间深度重建。W03 用同夹具对照后选择，保留陡坡处的边界处理。岸线偏移拟定 ≤0.5 个物理格，沙显示与拾取高度误差拟定 ≤0.02 m；W01/S01 分别建立测量方式后冻结，若不可达需 ADR 说明替代边界。

W03 已选定：水档使用 2× 显示网格，物理仍 256²；bed 在格心精确采样、格间以单调三次权重插值并夹取边界，CPU 镜像入口 `SandcastleBedDisplaySampler.sample_bed/sample_world`。湿单元 eta 加权后与同规则 bed 比较，显示水深受湿权重及邻域水深上限约束。径向和硬中点裁切试验不进入正式 profile。已用 2 px 俯视湿域遮罩与三镜头 8 px 视线探针验证 W03 边界门；后续动态波浪与沙形改变须复测同门。证据见 `验收/W03_岸线与遮挡.md`。

W06 动态复测后，`water_v1` 的水面显示高度偏移从 0.006 m 收至 0.003 m，以消除波浪经过时掠射视角的干地误盖。静态及 tick 300/360/480 的俯视偏移和三镜头误盖/漏盖按同一 W03 探针复测通过；物理床面、水深和岸线重建规则不变。原 W03 截图由捕图入口显式保留 0.006 m 用于历史对照，W06 新图使用 0.003 m。

S03 沙档沿用同一格心坐标和边界夹取，但陡侧面采用与高度场碰撞一致的三角划分（低 x/高 z 至高 x/低 z 对角线）及两片平面插值，CPU 入口 `SandcastleSandDisplaySampler.sample_bed/sample_world`。水档继续使用 W03 的单调平滑采样。沙档若直接复用水档的平滑双线性方法，陡角半格显示/碰撞偏差达 0.418 m；三角方法 722 条射线最大偏差 0.000691 m，均满足 0.02 m 门。见 S03 报告。

S04 沙材质消费同完成态的 `sand/wetness/compaction` 纹理；3.3 cm 世界空间颗粒与法线只影响显示，远景用屏幕导数渐隐。湿度连续控制色彩、粗糙度和高光，压实度控制轻微色调。四项开关为显示开关，不生成命令、不修改权威纹理。四阶段截图的湿度覆盖仅是 `sand_v1` 测试入口，正常夹具仍以 0.35/0.05 初始化；它不属于存档或公共 profile。W02 透底和动态岸线复测见 S04 报告。

水底吸收只累计一次，避免地形染蓝再叠水色导致两次吸收。透射使用实际水深/视线路径的有界估计；反射、折射、焦散式亮纹均有开关，折射不得取干岸颜色制造错位。

## 4. 沙体保形/屈服扩展

拟定方向：压实度和湿度控制有界黏聚/屈服高度或阈值，完整支持时允许模具沙形成陡侧面；支持丢失导致松散/失稳，再进入现有守恒松弛。不要仅把全域休止角调到接近 90°。

S01–S02 必须冻结：阈值名称、单位、范围；干/适湿/饱和湿曲线；松散与压实的区分；支持状态如何进入/退出；相邻共享边使用一致材料值；对子步和格尺度的适用范围。优先由已有 compaction/wetness 推导，只有原型证明必要时才新增权威字段。水任务不实现本模型。

拟定夹具目标：模具塔高度/基座宽比 ≥0.8，含陡侧面与有缺口的塔顶；具体尺寸与体积在 S01 冻结。支持完整、无外部冲刷运行 60 秒：顶部高度保留 ≥90%、轮廓覆盖 IoU ≥0.85；松散等体积对照应明显塌坡。移除支持后 30 秒内出现可测局部塌落，沙账本沿用 ≤1% 门、无负值/NaN。以上为本阶段设计门，非从原作帧反推的物理参数。

S01–S02 已选有界屈服高度 `cohesion_yield_height_m`，m，公开输入夹取 [0,2]；原场景默认 0 完全保留 T05 休止角。每条共享边由较高床面的捐赠格压实度决定增益：`clamp((compaction−0.6)/0.35,0,1)`，再乘湿度系数 `0.8+0.2*smoothstep(0.05,0.35,wetness)−0.6*smoothstep(0.65,1,wetness)`。阈值加在原湿度/平均压实度休止角高差上，双格同一状态确定同一捐赠格，因此边交换对称、质量守恒。干/适湿/饱和压实 10 秒对照和 30/120 Hz 子步试验见 S01；60 秒保形与松沙塌坡见 S02。

S02 `sand_v1` 的显式支持失效请求为 `request_sand_support_loss({generation:int,request_id:int})`，只在完成态且暂停时接受；旧 generation/重复 ID 拒绝。成功后仅将左塔 289 格压实度置为 0.1，不直接改沙高；后续屈服/守恒松弛决定塌落。支持事件的 ID、tick、revision 与受影响格数进入检查点可选 `support_event_schema_version=1` 记录，旧存档无此记录仍能加载；新存档还记 `fixture_id` 和屈服高度。

S05 新增 `sand_coupled_v1`：原尺寸双塔与海侧 51 格、每格 0.18 m 厚的松散支撑趾部，固定基岩 −0.12 m，海侧初始水位 0.10 m，海侧第 69–71 列为支撑传感区。完成态 GPU 沙纹理检测趾部相对初始 0.1434375 m³ 损失 ≥0.015 m³ 后，以相同 generation 和后续完成态 revision 自动提交一次 `request_sand_support_loss`，只降左塔海侧 102 格压实度，不直接删沙。事件记录 `cause=erosion_toe_loss`、sensor revision、应用 revision、趾部前后量；新夹具检查点使用 `support_event_schema_version=2` 并验证这些字段。原 v1 与旧检查点继续按旧规则接受。波包沿 W04 `test_packet` 上界，水体光学、岸线和白沫沿 W02–W06 profile；耦合档用等形态的轻量受光沙 shader 避免大范围实时阴影渲染成本，CFL 仍为原 0.35。

## 5. 波浪 API（计划新增）

`request_wave(request) -> {ok: bool, code: StringName, request_id: int, effective_tick: int}`。

| 字段 | 类型 | 约束 |
|---|---|---|
| `domain_id` | StringName | 当前域 |
| `generation` | int | 必须匹配，旧代拒绝 |
| `request_id` | int | 单调唯一；重复请求不得重复注水 |
| `start_tick` | int | 未开始的固定 tick；边界事务排序稳定 |
| `profile_id` | enum | 冻结的 `small_packet` / `test_packet` |
| `amplitude_m` | float | 非负、profile 上限内；有界波包叠加潮位 |
| `duration_s` | float | 正值、profile 范围内 |
| `seed` | int | 重放一致，不使用墙钟随机 |

W04 冻结：`small_packet` 幅值上限 0.06 m、时长 0.5–3 s；`test_packet` 幅值上限 0.20 m、时长 0.5–6 s。`start_tick` 必须晚于当前已完成 tick（有 tick 进行时还须晚于该 tick），同 ID 重试返回 `duplicate_request` 且不再注水；更小的已用 ID 返回 `invalid_request`。两个 profile 的波包高程以有限 sin² 包络叠加，总高最多 0.25 m，越限计数。仅从已有开放海边施加背景潮位加波高，同时输入同包络的法向动量 `wave_height_m * sqrt(g * background_depth_m)`；其余边界不变。输入水/输出水入源汇账本，CFL 子步数可查。错误：`inactive_generation`、`invalid_profile`、`invalid_request`、`duplicate_request`、`past_tick`、`not_ready`。

不向每格直接添加无账本水量；不把显示正弦高度当作岸线实际推进。W04 检查点附带 `wave_requests` 与 `wave_highwater_id`，严格校验后载入，旧 v1 存档缺字段默认为空；载入映射到新 generation。历史撤销/重做候选继承活动场景完整波命令历史，工具命令仍按原检查点选择。未来波命令保存重启续跑已在 W04 验证，W06 再做长时间恢复，S06 做耦合恢复回归。

## 6. 白沫规则

产生可使用水面梯度/压缩、湿干前沿、局部相对流速与沙体迎水变化的组合，须证明选择与画面相关。按流速平流并随时间衰减；可用有界纹理破碎边缘，不能只是速度+浅水阈值瞬时混白。

无波静水连续 10 秒：不持续自产白圈；波包结束后泡沫按冻结寿命消退；迎水和背水侧差异可见；离开湿域不留下发光残片。foam 持久性只属显示需求，不能被用于守恒或结构损伤判定。

W05 冻结：GPU 白沫历史为 256² RG32F，R 是 [0,1] 覆盖，G 是上一 tick 水深。每个完整水 tick 后依据当前流速回溯平流，按 1.8 s 指数寿命衰减；只有局部水深上升、动量压缩及浅水/坡面接触满足阈值才产生新白沫。水深 <0.0015 m 立即清零。白沫仅供水面 shader 读取，不改变水/沙/结构状态。检查点可选 `foam_history`，W05 新存档完整写入并校验；旧 v1 无字段时零初始化。波命令与白沫历史恢复分别在 W04/W05 探针验证，W06 再做长程整体验收。

## 7. 视觉与证据门

沙子五项：体积轮廓、支持下保形、陡侧面光照、细颗粒尺度、连续干湿。水五项：浅水透底、青绿深浅、连续岸线、推进浪前、白沫时序/亮纹。

每项 0/1/2 分：0 缺失/明显错误；1 有效果但有显眼伪影或未达冻结目标；2 三个镜头/对应时序均满足且有证据。W06 只验水 ≥8/10且透底/岸线/浪前均 2 分；S06 验沙 ≥8/10且保形 2 分，并复验水仍满足已通过的门。主执行者记录评分依据，人工最终复核可调整；不能只报总分。

深浅水固定探针以 0.02/0.08/0.25 m 为候选，在 W01 冻结；用固定床面脊/沟证明浅水能识别底形，无需新沙模型。不得以整图 SSIM 比较不同原作关卡。

每份 evidence manifest：`fixture_id, seed, grid_size, cell_size_m, viewport_px, camera, tick, generation, revision, visual_time_s, profile_id, effect_flags, wave_requests, hardware, frame_stats, audit, artifacts`。字段缺失视为未完成证据。
