# 参考执行、时间与最小移植

状态：文档v1.5。C03保留已登记经验规则及独立原输出反证的适用边界；C04轨迹字段与C05隔离边界保持v1.0语义，观测窗口和具体探针仍按后续任务冻结。关联需求R03–R12；关联任务T02–T07。

## C03：参考执行与误差

参考优先采用能证明输入／输出配对的原重放。无法配对或缺依赖时，选择必要的原DXBC执行器或定向重放插桩。使用原程序不自动证明重建的资源环境正确；使用相同公式的CPU代码仅作辅助诊断，不能充当原作参考。

原DXBC路线必须保留原字节和hash，验证目标后端兼容性，再建立root signature、descriptor、CBV布局、SRV／UAV视图、stride、offset、counter、纹理／采样器和dispatch规模。每次repeat先恢复全部输入及隐藏计数／依赖状态，等待完成再读回。所有兼容性修正显式记录；改写shader后必须改称适配参考，不再称原DXBC执行。

原位模式保留原资源别名与线程组织；ping-pong模式单列为Godot适配。新增同步、改变线程规模或读写隔离可能改变结果，不能混称原作行为。插桩要记录新增屏障、copy、等待及相应扰动；被观察版本与原版的差异保留在结论中。

参考集每项包括：reference_id、source_manifest、输入和输出ArtifactRef、依赖完备表、配对证据、执行模式、程序hash、repeat分组、原始字段布局、量化／截断规则、适用条件及未知项。

| 比较层 | 必须报告 |
|---|---|
| 原始字段／打包 | 原始uint4、位保留与覆盖、整数解码往返、分量／掩码错误数、最早差异坐标 |
| 连续字段 | A、可见h、床面、速度和法线分别比较；MAE、P99、最大误差及坐标、参考范围、异常值数 |
| 离散分支 | 干湿、钳制、边界、B触发与保留位的分支差异数及邻域输入 |
| 守恒／源汇 | sum(A)与sum(h)分开；列出量化、边界、源汇和钳制贡献，不把不可见A全部算成丢水 |
| 多步 | 每阶段／每步误差和首次越界位置；禁止仅比较最终平均图像 |
| 稳定性 | 同输入重复输出的字段分布、GPU／驱动／配置范围；输入hash不一致单独归类 |

误差预算文件至少包含field、metric、reference_noise、quantization_bound、floating_point_budget、branch_rule、limit、derivation、evidence_refs、frozen_at、sha256。T02／T03使用参考重复性和受控数据确定限值，在首次Godot候选比较前冻结。没有可靠量化依据时保留unknown并明确不能判断的字段。候选失败后修改预算须有独立新依据，保留旧失败及影响说明。

至少选择能区分解释的输入：原始真实快照、静水／均匀速度、干湿交界、床面台阶、域边界、钳制邻域、B阈值两侧。合成输入只能称受控实验，不称来自原作运行；是否物理可达另行说明。正常样本通过但阈值／保留位失败不得整体通过。

### 当前已冻结的单核判据

当前数值依据为[error_budget.json](../../../docs/competitor/evidence/water_solver_reconstruction/t03_error_budget_20261025_v1/error_budget.json)，身份与范围见[G3](../验收/G3_20261025.md)。按程序、完整输入、常量及有序依赖hash区分72组参考；每格编码范围与MAE/P99/max联合约束，B/source/sea/wet采用每格实测类别集合。

额外quantization_bound与floating_point_budget均为0：比较对象已是编码后的输出，没有独立依据再放宽编码余量；不表示量化或浮点物理误差为零。reference_noise只记录实际原程序重复与复制对照的样本差异，不是所有GPU调度的统计上界。新合法原执行也可能失败，必须保存失败并取得独立新依据，不能因Godot候选需要直接放宽。

数值仅覆盖所列身份、当前设备及单核实验。新参数轨迹／短序列须先取得原核参考，并在该范围的首次Godot比较前按同一方法版本化冻结；双缓冲适配单列。这个条件不豁免T05时间闭合或T06逐核／短序列要求，也不将整体任务缩小为现有样本。旧方法与数值版本保留。

### 经验范围的当前适用边界

原v1及补充[t06经验v2](../../../docs/competitor/evidence/water_solver_reconstruction/t06_error_budget_20261025_v2/error_budget.json)均是原程序已观察输出的有限规则，不是所有未见执行的上界。v2以相同72身份追加固定原程序32次，不含Godot输出；extra FP／quantization仍0，源数据回归2538及7负例通过，但未加入构造的24份独立原输出仍全部超界，证据见[T06诊断](../验收/T06_kernel_diagnostics_20261025.md)。

因此当前仅能用这些范围作可追溯差异定位，不能凭其拒绝独断Godot错误，也不能凭构造数据回归断言跨后端原位验证闭合。停止扩样直到通过，不将holdout反复加进界限。旧数值、失败与G3的原限定结论保持原样。

下一正式判据须先补实际消费的读取数据及算术／顺序分离证据。只读快照／读取流改写按adapted reference处理，保留原算术token也不能冒称未修改原DXBC；需要小样本、正反例和配对／因果范围核验。只读快照路线现有完整72身份／216次零额外允差逐位对照；对应参考、精确规则与GLSL表达式模型独立标识，见六核诊断及t06_snapshot_rules_full_20261025_v1。它仍不是未修改原位程序的数值门。名义寄存器副本在允许重排时不保证就是物理指令实际消费的操作数；精确驱动优化未知不得冒称已恢复。六核均已有原生capture／原生与Godot固定流重放，以及Godot自身原位记录／原生固定流反向消费，见t06_readstream_six_audit_20261026_v1；这些只说明已登记输入的语义读取值足以解释所测输出，不等同未插桩原程序或全部合法调度。完整72身份矩阵未全部执行，前47个完整身份的独立审计须单列为completed-prefix，不能接受全矩阵；第48个部分阶段与其余未执行身份不计完成。读流记录必须包含每调用有序原读取索引／字节偏移／有效lane／parent指令编号及post-swizzle有效bits，未写lane补零不冒称完整源元素。正常输出与完整记录流分别按零额外允差比较，实际前态／上传依赖／完成边界配对；只看正常输出不能接受元数据损坏。六核与两端读取模式的小样本已覆盖，仍须补齐必要完整夹具并核对分支覆盖，单列插桩扰动，再判该范围核验证。原位、显式ping-pong、完整字段、短序列及生命周期要求不变；未取得必要证据时G5不得通过。

## C04：运行时间与观测

多RDC先按capture hash分别定位程序／资源，再比较常量和状态。文件名、frame号差和相近画面不能证明同一时间序列，未知间隔不得换算秒。

| 轨迹字段 | 语义 |
|---|---|
| trace_id / sample_id / sequence_no | 本次轨迹、样本、单调序号；关联manifest |
| process_instance / thread_id | 仅记录所启动并核验的原作副本 |
| qpc_value / qpc_frequency / clock_epoch | CPU单调时间及换算基准；重启／重置分段 |
| cpu_call_begin / cpu_call_end | API调用时间，禁止解释为GPU完成 |
| gpu_timestamp / gpu_frequency / calibration | 有实际测量才填；与QPC映射不足时保持独立时轴 |
| frame_id / simulation_tick / stage / iteration | 实际可观察标识；不可得时null，禁止从输出编号编造tick |
| shader_hash / kernel_id / binding_identity | 匹配实际水核，避免名字相同但程序不同 |
| integration_dt / source_dt / play_time | 分别保存原值、单位证据及来源，不强行合并 |
| custom_wave / level / other_parameters | 每次实际消费或最近有效设置；必须记录作用域与覆盖规则 |
| parameter_set_id / dispatch_id / capture_id | 连接参数设置、调用与GPU常量抽查；无法配对显式unknown |
| dropped_samples / reset_reason / observed_mode | 丢样、重置、轻量记录或抓帧等配置 |

记录ComputeShader、必要的CommandBuffer／全局参数路径与GPU有效常量之间的覆盖；只有SetFloat日志不代表实际消费。现有仅对Paint记录参数的观察器不能直接证明水核输入。只扩展必要引擎／图形API，不追踪业务方法。

先做无探针、轻量探针、带抓帧三类可比短窗口。固定可控初态／配置；不能固定的差异明确列出。冻结扰动指标和接受条件后采正式轨迹：调用间隔分布、参数推进、丢样、停顿／重置，必要时GPU时间。抓帧造成的停顿不能算原作步长。

窗口至少覆盖实际可复现的静置、自然浪推进及可控输入变化；无法主动触发某种状态时先记录缺口，不虚构接口。时间闭合只限已观察条件，单帧无法证明完整生命周期。

原作工作副本与用户运行数据隔离分别核验；复制exe不等于隔离存档／配置写入。先确认可用的隔离机制与可能外部写入位置，再启动；不覆盖现有用户资料。观察完成关闭自有进程，留存源前后hash及实际写入清单。

## C05：Godot隔离与交付

T06仅创建独立计算探针及明确归属的资源，不接线正式main、test1_geometry、权威水沙、动量、源汇／沙量账本、碰撞或恢复。既有源码只读参考。新探针路径在编码前登记；需要固定节点时固化为.tscn，不能在_ready重建静态UI。

探针输入为reference_id、完整原始状态、依赖资源、参数、阶段／轮次序列、执行模式与冻结预算。输出为各核原始buffer及解码字段、状态generation、真正GPU完成边界、逐阶段差异和资源释放记录。禁止用渲染线程录制结束信号充当GPU完成。

保持原生512×256布局；可视化缩放不能参与数值判断。保留水核相关B、法线和辅助位，不能沿用旧RGBA32F四分量输入后宣称完整还原。场景显示读取同generation完成态；固定床输入不受可视化反馈修改。

单步以完整参考输入为起点；短序列使用已记录的阶段与参数轨迹，将积分dt、源汇dt、表现时钟分开。暂停／恢复／重置及资源释放不得重复推进或消费旧完成态。重复性不足时分别给出原位实测范围和双缓冲适配结果。

最终实施规格包括：六类核、字段打包、读写／屏障／阶段顺序、边界和阈值、参数来源、初态、时间语义、误差预算、可复现入口、未解决问题。完整独立交互场景是后续范围。

ready要求约定范围闭合；bounded要求核心参考与核验证通过，残余只涉及明确限定条件外或非唯一调度边界；关键输入／时间配对仍不足则为insufficient。不得通过将核心失败改名为适配而通过G6。最终结论与反证更新docs/competitor对应主题及统一入口；执行流水保留在本任务验收目录。
