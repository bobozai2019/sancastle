# W07 前缘位置与门控归因（2026-10-07）

## 字段契约与读回

单网格顶点的活动门使用当前行 ±12 行、步长 4 的七点最大上升强度，位置却只取当前行 `rise_front_state.r`。GPU 字段生成器按本行水深相对上一 tick 水深的正增量加权前缘 x；即使强度很低，x 也可能随微弱增量漂移。`--write-front-field` 在耦合参考床面 tick 390 有波导出 [256×1 RG32F 字段](W07_非对称浪前原型_20261007/unified_frontdata_wave390_coupled_front_rg32f.bin)。[分析脚本](W07_非对称浪前原型_20261007/analyze_front_support.py)与[结果](W07_非对称浪前原型_20261007/front_support.json)复算七点门：199 行本行强度 ≥0.0025，247 行窗口峰值 ≥0.0045，其中 **52 行窗口达标而本行 <0.0025**。这些行还有水深门，不能把 52 直接当作实际展开的卷唇行数；但字段确实允许门控与位置依据不同。52 行中无一行的 x 恰为无信号时的零回退值，因此这次问题主要是弱信号位置漂移，而不是零值回退本身。

## 判定

七点门与本行位置不一致是真实的数据契约缺口，但三种直接修补都未通过 V03/V06。尤其一张覆盖全域的可变形网格在活动与非活动行间重新参数化 32m 水面，局部掩膜变化会拉长连接三角形。下一表示需要能区分岛两侧前缘分支、对无活动行给稳定位置，并让活动/回退的水面拓扑保持连续；不能用窗口内 x 平均或固定 x=4m 的夹具常数替代。此次没有 V05 生命周期、V06 >4px 定量门、V08 活动成本；G03 与 WR-G0 不通过。所有新开关默认关闭。
