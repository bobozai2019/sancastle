严格 `water_render_staging_v1` 固定 tick300、耦合 tick300/600，D3D12/GTX 1050、可见 1920×1080、VSync off、同一 80 波包配置。默认关闭的 `--write-shore-source-map` 在实际可见水片上按同 UV 最近的 256² GPU 水深格着色：绿为该格水深 >0.001m，红为最近格干；片元原有重建水深门和遮挡仍有效。三次运行各四镜头、原图、白色覆盖图和水深 R32F 均退出 0。[独立复算](W13_G01_湿域来源着色_20261008/analyze_shore_source.py)核对 profile、请求、视口、原图/白遮罩/权威水深与前次 W13 G01 捕获逐字节相同，并重算纯色像素；[全部指标](W13_G01_湿域来源着色_20261008/shore_source_metrics.json)和[图像](W13_G01_湿域来源着色_20261008)可复核。

最大比例为耦合 tick600 俯斜约 **0.038%**，远少于可见水片的 2%。耦合 tick300 近景岛脚 ROI `[780,350,1280,550]` 仅 **137 / 52,829** 像素最近干格，tick600 为 **232 / 44,639**。[tick300 近景来源图](W13_G01_湿域来源着色_20261008/coupled300_source_coupled_close_shore_source.png)可见红色只沿岛脚/右岸形成细缘；大面积水片对应权威湿格。这是最近格的屏幕代理，不是正式的 ≤0.5 格世界偏移证明，也不能覆盖被床面遮挡的水片。

权威水深直接生成的[耦合 tick600 物理湿格图](W13_G01_湿域来源着色_20261008/coupled600_source_coupled_physical_wet_grid.png)显示岛、右岸及水舌的分支拓扑。逐 z 行只取最右湿格作**粗略**轮廓，耦合 tick300 相邻行最大跳变 5 格，tick600 为 50 格（z147→148），后者跨分支/岛脚，不能当单条连续岸线误差。大范围红色干格误盖已被这组三态图排除为主要来源，但可见尖齿仍可能由权威湿域形状、沙床可见轮廓、薄水透明度和局部白沫共同造成。

下一步应把 test35/testnew 对应的岸线形体与当前参考床面/物理湿域并排复核，明确需要回到 W07/W08 的输入形体调整，还是只需 W13 的沙面遮挡、接触白沫和薄水光学修复。不得通过单独羽化或让水面覆盖越过干格来掩盖物理湿域差异。V06、WR-G2 保持未通过，不计性能轮次。

## 参考形体复核（2026-10-08）

对照 [test35 重放图](../rdc_evidence/test35-frame20641_color_after_5593.png)、[testnew 重放图](../rdc_evidence/testnew_color_after_7023.png) 与 [耦合 tick300 俯斜原图](W13_G01_湿域来源着色_20261008/coupled300_source_coupled_oblique.png)：test35 可辨连续的宽沙舌、邻接暗沟及多尺度浅底；testnew 有多沙体交界。当前 staging 主要是单一大岛、局部小陡岸、右侧沙岸和横贯画面的浪前。镜头与世界布局不同，不能做逐像素对齐或把形状差异全部归咎于水 shader；但现有 `reference_bed.gd` 的两条窄沟脊和单岛构型不足以直接检验参考的多尺度沙舌/沟脊与多沙体接触。

因此把**参考床面/场景形体**列为 W07/W08 上游待返工输入；W13 继续检查同一床面下的交线、遮挡、薄水和接触白沫。当前最近湿格来源验证只能排除“大范围可见水片覆盖干格”这一种解释，不能据此放行 V01/V06。床面调整须让固定与耦合使用同一初始输入并重新捕获物理湿域及可见交线；此项参考复核不计性能轮次。
