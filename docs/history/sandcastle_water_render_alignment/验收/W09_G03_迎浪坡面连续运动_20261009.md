## 1080p 同输入录像

固定/耦合共用的 staging profile 中选择耦合场景、连续 80 包、俯斜镜头。关闭着色开关的 [baseline AVI](W09_G03_迎浪坡面电影_20261009/baseline60full_coupled.avi) 与仅启用 `prototype_front_face_rim_tone` 的 [候选 AVI](W09_G03_迎浪坡面电影_20261009/rimtone60full_coupled.avi) 均为 D3D12/GTX 1050、AVI 文件头与首帧解码 **1920×1080、481 帧、约 60 FPS、8.01 秒**。两者请求/有效 profile SHA、80 条波包请求、逐帧完成 tick 与表现时钟完全相同；每个 30 Hz 完成态在 60 FPS 录像中恰重复两帧（240 对），没有中间帧插值。[复算脚本](W09_G03_迎浪坡面电影_20261009/analyze_rimtone_movie.py)与[逐 tick 指标](W09_G03_迎浪坡面电影_20261009/rimtone60full_metrics.json)保存解码和差异。

最初仅用命令行分辨率录制得到 1280×720 AVI，已按文件头判为无效样本；1080p 两次正式录制在启动前临时覆盖项目 viewport，录制后 `override.cfg` 已移除，`project.godot` 未改。运行 manifest 的 1920×1080 不能替代 AVI 文件头检查。

在 480×270 降采样的 A/B 中，>8/255 差异像素在 tick0/30/60/90 均为 0，tick120/150/180/210/240 为 263/1,841/2,224/2,320/2,074。[tick180 候选抽帧](W09_G03_迎浪坡面电影_20261009/rimtone60full_frame360.png)及[tick240 候选抽帧](W09_G03_迎浪坡面电影_20261009/rimtone60full_frame480.png)显示亮脊沿前缘进入画面；抽帧并非完整运动主观验收。该变化仅是 JPEG 图像代理，录像入口未独立读回每 tick 物理场。

## 启动瞬态与泡沫门控负例

逐 tick 对照还发现原候选在 tick1、37 各有短暂差异（2,449、389 个降采样显著像素），[tick1 原候选](W09_G03_迎浪坡面电影_20261009/rimtone60full_frame2.png)在模拟域边缘和岛周出现过早亮边。相同 staging 输入的 GPU 字段读回：tick1 前缘活动峰值 0.5624，46,400 格超过着色活动下界 0.0032；tick37 峰值 0.00485、813 格超过下界。两个时刻泡沫字段总量均为 0。该字段记录了初始水面调节/早期边界活动，不能单独证明出现了可见破浪。

新增仅诊断用的 `prototype_front_face_foam_gate`，使着色活动乘以本地泡沫覆盖。其 [1080p AVI](W09_G03_迎浪坡面电影_20261009/rimfoam60full_coupled.avi) 与同一 baseline 的 [逐 tick 复算](W09_G03_迎浪坡面电影_20261009/rimfoam60full_metrics.json)显示 tick1/37 差异消失，但亮脊首次出现推迟到 tick185（原候选约 tick109）；tick240 降采样显著像素从 2,074 降至 970。[tick240 静态泡沫门控图](W09_G02_局部主网格_20261008/rdcactiverimfoam240_coupled_oblique.png)仍有白带，但该门控会丢失约 76 tick、2.53 秒的早期浪形，**不选为单独解法**。三份 1080p 录像均保持相同 80 波包与完成态时钟，且全部只是可视候选，不计正式实时性能。

## 波源启动门控

新增默认关闭的 `prototype_front_face_source_gate`，由预览场景在每次完整 tick 发布后检查**本代已批准、正振幅且 `start_tick≤completed_ticks`** 的波请求，并设置水材质的 `prototype_front_face_source_started`；从 checkpoint 恢复时也重新计算。它只挡住第一包波之前的初态调节，不用固定秒数猜测浪到达时间。[波源门控 1080p AVI](W09_G03_迎浪坡面电影_20261009/rimsource60full_coupled.avi)与 baseline 的[逐 tick 复算](W09_G03_迎浪坡面电影_20261009/rimsource60full_metrics.json)核对了 80 波包、相同 profile 和 480 条相同的完成态时间线，门控回读在 tick<8 为 false、tick≥8 为 true。

与原亮脊录像逐 JPEG 帧 SHA 对照，**仅帧 2、3（tick1）不同；从帧 16（tick8）起 465 帧逐字节相同**。波源门控去掉预波 tick1 的假亮边，同时保留原候选约 tick109 开始的主浪脊和 tick37 的边缘变化。后者已在波包 tick8 注入之后，不能仅凭泡沫为零判作错误；仍需与视角/波源传播核对。泡沫门控因丢失早期真实浪形不选型。

复用原 [staging checkpoint 探针](W09_G03_迎浪坡面电影_20261009/rimsourcecheckpoint_manifest.json)，在固定/耦合两模式开启候选及波源门控：tick240 保存、恢复到新 generation，随后同步推进到 tick270/600。三个时点两模式的水、两动量、泡沫历史、二维前缘历史五份 GPU 字段逐字节一致，正常/恢复画面 SHA 一致，`prototype_front_face_source_started` 均回读 true。探针退出 0 且显式 PASS，验证活跃保存点的恢复接线。

新增[波源前 checkpoint 对照](W09_G03_迎浪坡面电影_20261009/rimsourceprewavecheckpoint_manifest.json)：固定/耦合都在 tick4 保存并恢复至新 generation；tick4 门控原始/恢复均为 false，tick8、37、120 均为 true。四个时点两模式的五份 GPU 字段逐字节一致，画面 SHA 一致。tick4 泡沫格数为 0、局部前缘正值格数为 2,304，因此此次确实覆盖波源启动前的初态。探针退出 0 且显式 PASS；临时 1080p viewport 覆盖已移除。此项不涵盖交互请求、主观连续性或实时成本。

再以[交互请求与 checkpoint 对照](W09_G03_迎浪坡面电影_20261009/rimsourceinteractivecheckpoint_manifest.json)覆盖无预排波入口：固定/耦合在 tick20 通过 `request_wave()` 提交 tick25 的正振幅波包，旧 generation 请求先被拒绝；tick22 保存并恢复至新 generation。tick22/24 的原始/恢复门控均为 false，tick25/60/120 均为 true；五份 GPU 字段逐字节一致，各时点画面 SHA 一致，探针显式 PASS。该证据验证直接 API 请求与恢复，不等同于编辑器/游戏 UI 操作或任意输入序列。临时 1080p viewport 覆盖已移除。

下一步继续解决侧视浪体厚度、转镜头和 30 Hz 完成态间的表现阶跃，并复核交互 UI 与实时成本。候选与波源门控仍默认关闭，不能放行 V03/V07。

最终诊断源码下，严格 staging `stagingrimfoamdiag240` 与此前 `stagingrimtone240` 的固定/耦合两份水深 F32 及六机位 PNG 均逐字节同态；可选泡沫门控未改变默认路径。

波源门控接线后再采 `stagingsourcegate240`：与 `stagingrimfoamdiag240` 的两份水深 F32 和六机位 PNG 均 SHA256 相同；默认 staging 仍未启用任何亮脊门控。

后续[较高主面抬升与波源门控](W09_G02_较高主面抬升与波源门控_20261009.md)发现早期门控只挡着色、不挡显示几何；现已在显式门控下同时抑制波源前的 `prototype_crest()` 抬升。无波四机位高低抬升候选零显著差异，有波 tick240 保持既有画面；固定/耦合预波及直接 API 请求的 checkpoint 恢复复验 PASS，默认 staging 六图/两水深同 SHA。
