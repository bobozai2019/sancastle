# W07 边界/CFL 同步读回隔离试验

日期：2026-10-07。结论：**淘汰同步读回候选。** 将每 tick 的 tide ledger（1 KiB）与 CFL tiles（4 KiB）两次异步读回改为渲染线程内 `texture_get_data` 后，渲染线程从进入请求到提交返回的中位数从 0.037 ms 增至 25.990 ms；活动阶段帧 p99 从 37.226 ms 增至 51.165 ms，tick/s 从 27.124 降至 25.860。两组本已超过 V08 成本门，同步方案更差。Godot 的 [RenderingDevice 文档](https://docs.godotengine.org/en/stable/classes/class_renderingdevice.html)明确说明 `texture_get_data` 会等待 GPU 完成后返回数据。

## 实施边界与负载

新增仅在 `tests/visual_water_alignment/prototypes/` 中使用的 `reference_sync_readback_solver.gd`，继承原 `gpu_shallow_solver.gd`，只覆盖这两个字段的 `request_data`，保留求解器 pass、CFL 子步、物理参数与其它读回。`reference_preview.gd` 通过默认关闭的 `prototype_sync_boundary_readback` 选择该原型；成本和捕图探针可传入 `--sync-boundary-readback`，manifest 记录真实选择。生产求解器没有改动。原型代码保留为可复现失败对照，不进入正式 profile。

同一耦合参考床面、oblique 镜头、phase2 光学/白沫 + η 坡度法线 + 0.16 m 显示浪脊 + 不规则白沫调制，屏幕光学关闭。持续波包；真实可见全屏 1920×1080、VSync off、D3D12/GTX 1050。Godot 日志标识 `v4.7.beta.custom_build.dff2b9bb6`。两组各预热 2 秒、采样约 3 秒，分别独立启动；仅改变同步读回开关。两组均 exit 0、探针预期 `PASS`、日志无 shader/script ERROR；overload、NaN、无效/负水沙格均为 0。

| 阶段指标 | 原异步读回 | 原型同步读回 |
|---|---:|---:|
| 采样秒数 / 帧数 / tick 时间线数 | 3.023 / 164 / 82 | 3.016 / 79 / 78 |
| tick/s | 27.124 | 25.860 |
| 整帧 p99 | 37.226 ms | 51.165 ms |
| 渲染线程进入→读回请求提交返回 p50 / p95 | 0.037 / 0.217 ms | 25.990 / 36.250 ms |
| tick 边界段 p50 / p99 | 36.218 / 42.047 ms | 35.177 / 49.099 ms |
| tick 总时长 p50 / p99 | 36.933 / 43.644 ms | 35.860 / 49.650 ms |
| 整帧已测 GPU p99 | 6.662 ms | 6.721 ms |

CSV 时间统计仅用 `stage=oblique` 行，按时间戳差算毫秒；p50/p95/p99 使用排序后下标 `floor((N-1)×p)`。同步路径的回调在 `render_submit_us` 前内联发生，所以旧时间线的“提交→异步回调”差值会为负，不适用于该路径；表中只列仍有共同语义的区间。同步读回的 tick 中位时长略短，但尾部和整帧成本明显变差，不能据此选它。这里的 GPU p99 不是读回阻塞时间。

本次是路线淘汰用短诊断，不代替 30 秒预热 + 60 秒逐镜头正式 V08 成本验收，也未逐 tick 比较完整水/沙/账本/恢复状态。因此只证明这条候选在相同短负载下成本更差，不证明长期数值等价。异步路径中渲染回调到主线程处理的等待仍待细分；不能在异步回调中递归提交下一批 GPU 命令，已有 D3D12 碰撞代理记录会得到陈旧或零数据。
