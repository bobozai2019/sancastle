# W07 D3D12 与 Vulkan 同负载对照

日期：2026-10-07。结论：**只切换渲染后端不能通过 V08/WR-G0。** 同一耦合参考场景、同一显示候选，Vulkan 的 60 秒阶段 tick/s 比 D3D12 高（29.232 对 26.877），但整帧 p99 更差（41.059 对 38.039 ms），两组均未同时达到 p99≤33.3 ms 与模拟≥30 tick/s。Vulkan 的读回回调中位数较低而尾部更长；这不是已验证的性能修复。

为防探针把驱动误记成固定 `d3d12`，W07 成本探针现将 [Godot 当前驱动 API](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-get-current-rendering-driver-name)结果写入 manifest；这个 API 报告实际启用的驱动，包括命令行覆盖或回退后的值。仅测试探针改动，生产入口和求解器未改。

## 负载与统计

同一 `water_render_coupled_v2` 参考床面、oblique 镜头、combined 显示（phase2 光学/白沫、η 坡度法线、0.16 m 显示浪脊、不规则白沫调制），持续合法 0.18 m/6 s 波包每 180 tick 一次。两组独立启动，各预热 30 秒、采样 60 秒。真实可见全屏 1920×1080，VSync off，NVIDIA GeForce GTX 1050，Godot `v4.7.beta.custom_build.dff2b9bb6`。两组 exit 0、预期探针 `PASS`、日志无 shader/script ERROR；overload/NaN/负或无效水沙格为 0。`PASS` 只表示数据收集成功，manifest 的 `meets_cost_bound=false` 才是本门结果。

| 60 秒 oblique 活动阶段 | D3D12 | Vulkan |
|---|---:|---:|
| 实际阶段时间 / 帧数 | 60.015 s / 3225 | 60.036 s / 3509 |
| 有效 tick / 其中 3 个 CFL 子步 | 1613 / 1609 | 1755 / 1751 |
| 模拟 tick/s | **26.877** | **29.232** |
| 整帧 p99 | **38.039 ms** | **41.059 ms** |
| 已测渲染 GPU p99 | 7.094 ms | 6.895 ms |
| 提交→最后读回渲染回调 p50 / p95 / p99 | 25.665 / 30.765 / 32.202 ms | 23.134 / 37.716 / 44.234 ms |
| 最后读回渲染回调→主线程齐备 p50 / p95 / p99 | 10.290 / 15.100 / 16.674 ms | 8.867 / 14.472 / 19.726 ms |
| tick 总时长 p50 / p95 / p99 | 36.710 / 44.341 / 47.202 ms | 33.402 / 49.595 / 56.108 ms |

时间线仅取 `stage=oblique` tick，p 值使用排序后下标 `floor((N-1)×p)`；整帧/GPU指标取原探针 manifest。两组 `source_active_fraction=1.0` 只表示请求波包处于活动时窗，不证明高泡沫屏幕墙钟覆盖达到 25%。由于预热按墙钟计，两组采样起点分别为 tick 816/873，波包相位并非逐 tick 对齐；这是相同请求模式的成本对照，不是同状态输出比较。渲染 GPU p99 不包含异步读回等待、队列空档或主线程交接，不能解释为总 tick 成本。30+60 秒在一个 oblique 镜头满足本次后端归因长度，但不足以替代三镜头加高泡沫正式门，也未比较跨后端水沙/账本逐 tick 等价。因此保留 D3D12 现有基线，不改正式驱动或声称 Vulkan 已验收。

启动前各有 2+10 秒同负载诊断（同目录 `d3d12_wave_*`、`vulkan_wave_*`），方向一致：D3D12 27.277 tick/s、37.063 ms 帧 p99；Vulkan 29.244 tick/s、42.576 ms 帧 p99。正式判断依据上表长样本。
