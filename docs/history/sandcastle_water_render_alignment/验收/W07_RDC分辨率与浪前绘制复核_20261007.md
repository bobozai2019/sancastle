`WR-G0_参考与标准.md` 的 ROI 来自 `task/sandcastle_visual_reconstruction_phase2/rdc_reference/*_replayed_0.png`。直接读取三张 PNG 均为 **1920×1080**；`W07_roi_metrics.json` 的路径、尺寸与之相符。`rdc_evidence/*_color_after_*.png` 则是逐绘制导出的 **1280×720** 场景 HDR，绑定中间纹理为 **256×128**。两组图长宽比相同，坐标换算因子为 2/3；它们不是同一个分辨率的图像。目标板的 1920 ROI 和 `74px/1920` 宽度因此保留，不能直接在 1280 绘制图上按原坐标取样。至于最终图从场景 HDR 到 1920 输出的具体处理链，此次未解码。

## 绘制归因

三份 RDC 的强亮浪前均在水面之后由单独绘制补入：`test35` event 5495（6 指数 × 22035 实例）、`test1` event 6196（6 × 29950）、`testnew` event 6943（6 × 29104）。它们使用 SrcAlpha/InvSrcAlpha 混合，读 256×128 RGBA16F 中间纹理、2048² 深度和结构化缓冲，保留场景深度。水面本身另有 indexed/instanced 绘制和深度写入。[RDC 绘制及资源清单](../rdc_evidence/README.md)保存事件和输入出处。

对三个事件的 **全部实例**读取 RenderDoc VSOut，按 `SV_POSITION float4 + TEXCOORD0 float3 + TEXCOORD1 float3` 的 40 字节步长解码；每实例四个唯一顶点、6 个索引。三帧所有顶点组的世界 Y 恒定，四角沿世界 X/Z 轴排列，均为**水平四边形**，不是竖立的相机朝向面片。`SV_POSITION.xy / w` 换算到 1280×720 场景图后的分布如下（全体中位数）：

| 捕帧 | 成功解码实例 | 世界四边形边长中位 | 场景图投影宽×高的中位 |
|---|---:|---:|---:|
| test1 | 29950/29950 | 0.0356 m | 2.28×1.64 px |
| test35 | 22035/22035 | 0.0342 m | 4.17×3.01 px |
| testnew | 29104/29104 | 0.0605 m | 3.52×2.46 px |

完整分位数、四角样本与读取脚本见 [test1](../rdc_evidence/test1_foam_mesh_summary.json)、[test35](../rdc_evidence/test35_foam_mesh_summary.json)、[testnew](../rdc_evidence/testnew_foam_mesh_summary.json)、[只读脚本](../rdc_evidence/probe_foam_mesh_api.py)。这些是捕帧在其自身世界坐标与相机下的尺寸；不能直接套用到 Godot 的米制场景。具体粒子含义、生成公式和生命周期仍未证实。

复现调用：在 PowerShell 中对 `test1`、`test35`、`testnew` 依次设置 `$env:WR_CASE`，然后运行 `D:/other_software/RenderDoc/qrenderdoc.exe --python D:/godot/project/sandcastle/task/sandcastle_water_render_alignment/rdc_evidence/probe_foam_mesh_api.py`。脚本只读打开 `rdc/` 的原始捕帧，把每例 JSON 原子写入本证据目录；qrenderdoc 调用返回后，以 JSON 的 `mesh_summary.decoded_instances` 等于绘制实例数为完成判据。

将绘制前后 1280×720 PNG 对齐，在目标板的 1920 ROI 按 2/3 映射后，用 `max(RGB_after−RGB_before)>16` 仅作**空间定位诊断**：

| 捕帧 | 映射后的 1280 ROI | 变化像素 / ROI | 观察 |
|---|---|---:|---|
| test1 | `[687,300,867,600]` | 4506 / 54000（8.3%） | 主浪前局部强亮；绘制前已有暗色水面边界 |
| test35 | `[927,167,1100,600]` | 8886 / 74909（11.9%） | 右岸亮带在该绘制后显著出现 |
| testnew | `[133,287,433,487]` | 2161 / 60000（3.6%） | 岛脚接触亮边被局部加强 |

这些 PNG 是 HDR 的显示映射输出，阈值面积不等于原始 shader alpha、实际粒子覆盖率或最终 1920 图的亮芯宽度。逐像素 HDR 前后值与像素历史证据仍以 RDC 清单为准。尤其 V03 的 `74px/1920` 是最终图完整浪前亮芯，不应误当作 event 6196 单独贡献的宽度。

## 下一原型约束

WR56 的开放单网格翻卷让下表面被深度遮住，关闭深度又错误盖住前景；单材质按截面着白要么把浪背涂成大块，要么只余细边。参考绘制提示下一路线应将 **有真实高度与正确深度的水体** 和 **受深度检验的细小水平亮沫片层** 分开验证。后者必须由项目权威前缘、湿域、泡沫历史和相位驱动，先在固定/耦合床面检查岛脚、陡岸与无波负例；随后核对水体自身是否具备 V03 曲率和厚度，再作 V05 生命周期与 V08 正式成本。旧独立泡沫网格曾因与主水面高度不合而被遮挡，新候选必须共用实际表面高度并按近景像素量级校准面片；不能把 RDC 的世界边长或 29950 实例数直接复制为 Godot 预算。

本复核只确定参考坐标来源和绘制职责，尚无新效果原型或性能测量。V03/V05/V06/V08、W07 G03、WR-G0 仍不通过。
