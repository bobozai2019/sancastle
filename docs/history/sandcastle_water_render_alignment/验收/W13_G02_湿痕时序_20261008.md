# W13 G02：同源入退水与湿痕诊断（2026-10-08）

状态：**权威湿度时间线及同帧材质消费验证 PASS；湿痕视觉与 G02 [进行中]，W13 0/3，性能 0/10**。当前候选不选入共享 profile。

严格 `water_render_staging_v1` 耦合场景，D3D12/GTX 1050、可见 1920×1080、VSync off、80 个连续波包。捕图器新增 `--write-wetness-field`，从 GPU 当前 `wetness` R16F 槽只读回写，精确校验 `256²×2` 字节；另存水深 R32F、三镜头与现有水面遮罩。同初态和同波包请求的 tick300/600/900/1020/1200/1500 六份 [manifest、字段和画面](W13_G02_湿痕时序_20261008) 均退出 0。[独立复算](W13_G02_湿痕时序_20261008/analyze_wet_trace.py)核查 profile 哈希、视口、GPU 后端、字段长度/有限值、初态哈希和 80 波包请求完全相同；[指标 JSON](W13_G02_湿痕时序_20261008/wet_trace_metrics.json)保存逐时刻结果。

水深 >0.001m 的湿格 tick300→600 从 **46,754** 增至 **60,739**，新入水 14,122 格；tick900→1020 有 **2,032** 格退水，tick1020→1200 又有 **2,153** 格退水。持续露出的 1,507 格（tick900 湿、1020 与1200 干）湿度中位数为 **0.405→0.243→0.050**。这说明现有 GPU 湿度随进退水变化且按约 10 秒排水回到 0.05 残余值；不能仅以两个终点画面推断每一格的首次退水时刻。

共享 staging 的耦合床面实际使用 `reference_coupled_bed.gdshader`，其中已有 `use_wet_finish`。同 tick1020 暂时关闭该参数的三镜头对照，原图和之前采样的原图逐字节相同，水深/湿度字段逐字节相同；俯斜/近景/掠射 >2/255 的变化分别为 **849,884 / 654,433 / 283,720** 像素。因此湿度确实作用于沙面整体色泽、粗糙度和高光。最初误对通用 `gpu_terrain.gdshader` 做的消融为零像素，因它不是此 staging 的床面 shader，已撤销开关，该组文件不用于结论。

当前 staging 床面没有专门的退水湿边。默认关闭的 `prototype_wet_trace_gain` 只读候选在同 tick1020 使用现有湿度与水深，让退水沙面更暗；基线原图和字段仍与前次逐字节相同，候选俯斜/近景/掠射 >12/255 的变化为 **47,010 / 9,983 / 14,091** 像素。[俯斜候选](W13_G02_湿痕时序_20261008/wet1020_trace_coupled_oblique_wet_trace_candidate.png)形成过宽、过深的岸侧带，且原本的尖齿、接触白沫和低角交线问题仍在；**不选入共享 profile**。

后续需要更短间隔同一条退水时间线、屏幕 ROI 与可见床面交线联合判定湿痕宽度/淡出，并调整遮蔽水下区域和衰减曲线。此证据不放行 V06、WR-G2 或 W13 G02，也不计性能迭代轮次。
