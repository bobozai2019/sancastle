## 试验内容与边界

隔离 shader 通过 `hint_screen_texture` 读取已绘制的不透明沙床，通过 `hint_depth_texture` 与 `INV_PROJECTION_MATRIX` 重建视图深度。水面真实坡度法线与冻结的程序细波共同偏移屏幕取样；指数透射把采样底色与深水散射色混合；采样点落到水面前方时，深度保护退回原始屏幕坐标。亮色“反射”只是一种天空颜色代理，**未实现也未证明场景反射**。Godot 文档明确屏幕/深度纹理的用法，并指出透明物体不进入这两个纹理：[屏幕读取说明](https://docs.godotengine.org/en/4.5/tutorials/shaders/screen-reading_shaders.html)、[空间 shader 限制](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)。原作的具体折射/反射算法仍为 unknown。

只修改 `tests/visual_water_alignment/prototypes/` 下 shader 与捕图入口。[shader 快照](screen_optics_prototype_20261007/reference_water_screen_snapshot.gdshader) SHA256 `41319B4956C52BE04EA8FD1706D8AFBDA2992C217E9BB0A6D3CF10ECB5EFFCF8`；[捕图快照](screen_optics_prototype_20261007/capture_reference_screen_snapshot.gd) SHA256 `64B49CC2053D47A72D1119A2973410AD7254085694A1C532157D41D4E6A769BE`。捕图器加入 `--require-1080p` 与精确 tick 停止：目标前暂停自动推进，必要时手动执行最后一步，且 `completed_ticks` 不精确相等就报错。

## 结果与处置

正常 `+0.02` 折射相对零偏移，在三镜头分别有 28,130 / 15,658 / 1,762 像素的 RGB 任一通道差值 >2；全图 RGB 平均绝对差分别约 0.124 / 0.099 / 0.020（8-bit 值）。人眼看到的整体改变仍很弱。用未验证水深的暂定俯斜 ROI 做 8-bit 中位亮度诊断，深 `[300,550,600,800]` 为 179.59，较浅 `[890,690,1030,880]` 为 202.36，深/浅约 0.887；ROI 深度尚未回读核实，**不能据此正式判定 V02**，但它提示当前分层可能不足。

正常 `+0.02` 下开关深度保护图像相同；本场景与偏移方向不足以激活保护。仅供遮挡压力诊断的 `-0.2` 偏移下，保护与关闭在三镜头分别有 96,586 / 52,983 / 4,413 像素差值 >2，近景可见无保护时浅滩亮纹被错误移走，说明保护分支实际生效。`-0.2` 明显超出拟用视觉参数，不能作为视觉通过图。

第一次试编译把 `INV_PROJECTION_MATRIX` 直接写在辅助函数内，Godot 输出 `SHADER ERROR`，但捕图脚本仍打印 `PASS` 且进程码为 0。该次 `wr_w07_screen_zero_20261007` 产物无效；改为显式传入矩阵并用日志检查后才生成上表证据。另一次捕图曾到 tick 121，亦未用于最终 A/B。正式入口须把 shader/script 错误检查纳入包装器，不能只看脚本 PASS。

当前路径仅证明 Godot 可以在不透明床面上做屏幕透射和受深度保护的取样。浅底层次、真实场景反射、透明障碍、连续浪前、耦合沙床、视觉相似度及 1080p 活动性能都未证实；V01/V02/V06 仍为 partial/unknown，WR-G0 保持未通过。
