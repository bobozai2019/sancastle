# W09 G02 统一网格二维前缘限域（2026-10-08）

结论：**默认关闭的原型有局部改善，但 V03/V06/WR-G0 未通过**。统一网格原先用 256×1 行前缘的峰值与相邻行峰值决定整行卷浪活动，二维场的空隙仍可能拉出远处水片。本次增加 `--unified-2d-support`：保留原卷浪网格与物理求解，在同一行前缘 X 位置采二维活动前缘；峰值与中心位置不一致时衰减卷浪掩码。这个开关只用于 `unified-curl` 隔离原型，staging 不启用。

同一曲流入海口耦合床、D3D12/GTX 1050、1920×1080、**二倍显示细分**、连续 80 波包 tick240，`localizedrebase240` 与 `unified2d240` 除二维限域外配置一致。两次受检捕图退出 0/PASS；波包请求与初态相同，泡沫 PNG SHA 相同，水深最大差 7.45×10⁻⁸m、行前缘 RG32F 最大差 2.29×10⁻⁵。四机位 >12/255 差异像素依次为俯斜 42,912、近景 89,547、掠射 75,052、侧视 74,168。[当前基线俯斜](W09_G02_局部主网格_20261008/localizedrebase240_coupled_oblique.png)、[二维限域俯斜](W09_G02_局部主网格_20261008/unified2d240_coupled_oblique.png)、[当前基线侧视](W09_G02_局部主网格_20261008/localizedrebase240_coupled_wavefront_side.png)与[二维限域侧视](W09_G02_局部主网格_20261008/unified2d240_coupled_wavefront_side.png)显示远侧和沙舌旁多余片面减少，左侧仍有大三角面，峰谷、曲率与岸边裁切不满足 V03/V06。

无额外波包 tick300 的 `localizedrebase300nowave`/`unified2d300nowave` 四图逐像素相同，泡沫同哈希，水深与行前缘只存在 ≤7.45×10⁻⁸m / 1.49×10⁻⁸ 的运行间差异。[复算脚本](W09_G02_局部主网格_20261008/analyze_seam_join.py)和[结果](W09_G02_局部主网格_20261008/seam_join_analysis.json)包含以上配对；`staging2dflagoff240` 固定/耦合双场景严格 profile 捕图包装器 PASS，六张默认 staging 机位图与接入前 `stagingbrokenoff240` 的 SHA 完全一致。

在找二维限域前，另测了两种局部化主网格的接边混合公式：移动卷浪区端点或移动两侧水面端点，使中间活动强度下的 X 位置对齐。以当前源码重采的基线比较，有波侧视分别只改 2,027/384 个 >12/255 像素，无波第一种四机位零显著差异；大三角面在基线及两个版本都存在，**两项公式试验均撤回**。曾以历史 `localizedestuary240` 图比较得出“接边改动暴露大片水片”的初步判断，后来发现历史行前缘算法与当前不同；当前同源码基线纠正了这个归因，不能把旧图大差异归于接边公式。

本次只作功能和视觉诊断，未测正式活动成本，W09 性能仍 **0/10**。下一步须在单一行重排产生的跨段大三角片上处理网格拓扑，并将二维连通分量对应到真正局部的主水面替换区；仅在行掩码上乘二维峰值不足以放行。
