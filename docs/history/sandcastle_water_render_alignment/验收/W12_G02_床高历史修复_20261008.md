# W12 G02：床高历史修复与复验（2026-10-08）

状态：**隔离来源负例与旧 staging 存档运行兼容 PASS；W12 G02 [进行中]，W12 0/3，性能 0/10**。真实连续流水的足量稳态侵蚀和最终 V05 画面仍未验收。

## 修复

采集时[旧 shader 的 GPU 反例](W12_G02_床降伪浪源GPU复现_20261008.md)表明，单看 `depth_now-depth_previous` 会把床降 0.02m、水深同步增加 0.02m 的恒定自由水面误判为上升浪源。[生产 shader](../../../../shaders/simulation/visual_foam_step.glsl)现在用 `eta_now=(bed_now+depth_now)` 与 `eta_previous=(bed_previous+depth_previous)` 计算上升率。RG32F 泡沫历史的 G 通道继续保存前一水深，供浪前字段读取；[泡沫字段](../../../../scripts/visual/gpu_foam_field.gd)增加两张 256² R32F 前一床高 ping-pong 纹理。固定、耦合[参考入口](../../../../tests/visual_water_alignment/prototypes/reference_preview.gd)及[演示入口](../../../../scripts/demo/gpu_water_preview.gd)均从当前岩床和沙床初始化床高历史。检查点已有当前床面 shadow，恢复后以该床面初始化下一步所需历史，格式不变。

## 同配置证据

[合成 GPU 探针](../../../../tests/visual_water_alignment/prototypes/probe_foam_bed_drop.gd)直接运行新生产 shader SHA256 `19d7bec7f157791f75e0b4a63bd04c7ae8dc06eb82e016f1ea96ae8174e6edb0`，D3D12/GTX 1050、256²、初始床 0.10m/水深 0.10m、1m/s 流速，其他参数与旧反例相同。[原始数据和分析器](W12_G02_床高历史修复_20261008)复算通过：稳态及仅床降组泡沫均全零；真实 `eta` 上升 0.02m 仍为每格 0.2307099，与旧 shader 的阳性原始输出**逐字节相同**。

严格 staging profile、1920×1080、tick300 的固定/耦合无波与 80 连续波包[四组捕图](W12_G02_床高历史修复_20261008)均退出 0 并生成三镜头、RG32F 与水/岩/沙 F32。独立[复算](W12_G02_床高历史修复_20261008/analyze_staging_pair.py)显示无波两组 `foam>0.05` 格数均为 0，活动波分别为固定 2884、耦合 2500。对应旧版为 0/0/2884/2521；四组水、岩、沙字段与旧版逐字节相同。耦合活动波少 21 格，符合排除床面变化伪来源的方向，但不能仅据此定位每格来源。

[检查点探针](../../../../tests/visual_water_alignment/prototypes/probe_staging_checkpoint.gd)在固定/耦合单包活跃泡沫 tick240 保存，恢复后于 tick240/270/600 比较五个 GPU 字段及完整图像，全部一致；缺 profile、缺局部前缘的负例仍拒绝。结果见[manifest](W12_G02_床高历史修复_20261008/bed_history_checkpoint_manifest.json)。[修复前存档探针](../../../../tests/visual_water_alignment/prototypes/probe_prior_foam_checkpoint.gd)另加载 W08 时保存的固定/耦合 tick240 活跃白沫存档，在新 shader 下恢复并推进至 tick270；固定泡沫覆盖 1051→2018 格，耦合 828→1740 格，原始存档 SHA 与结果见[manifest](W12_G02_床高历史修复_20261008/prior_foam_checkpoint_manifest.json)。这证明旧 staging 存档可运行并继续产生泡沫，不代表新旧 shader 后续画面逐字节相同。这些是功能/恢复复验，未按性能门计轮；新增床高纹理的正式成本仍待 W12 性能轮测量。V05 的参考形状、静水 10 秒和真实足量稳态侵蚀仍需独立验收。
