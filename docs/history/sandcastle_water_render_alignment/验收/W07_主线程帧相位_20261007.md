# W07 异步读回回调与主线程帧相位

日期：2026-10-07。结论：持续波包的耦合参考场景中，**渲染线程读回回调到主线程接收的约 10.6 ms 中位/均值等待，几乎延续到下一次 `_process` 入口前**。271 个可配对 stage tick 的 deferred 回调都在下一次 `_process` 前处理，中间没有 `_process` 入口。这说明本次观察到的是主线程帧交接的等待形态，尚不能断言渲染线程队列、引擎帧节流或某项主线程任务是根因。

只在 W07 隔离 `reference_preview.gd` 增加默认关闭的 `profile_main_frame_timing`：每次 `_process` 入口记单调时间、进程帧号、完成 tick 与 pending 位。成本探针的 `--main-frame-timing` 仅在同时指定 `--tick-timing` 时启用，并另存 main frames CSV；求解、读回及显示路线未改。分析脚本用共同的 `Time.get_ticks_usec()` 时间轴，把每个 tick 的两次渲染读回回调、主线程最后一次 ready 与下一次 `_process` 入口配对。

## 负载与结果

耦合参考床面、oblique、持续合法波包、combined 显示；真实可见全屏 1920×1080、VSync off、D3D12/GTX 1050。预热 2 秒、采样 10 秒。运行 exit 0、探针预期 `PASS`、日志无 shader/script ERROR，overload/NaN/无效或负水沙格均为 0。阶段 543 帧、272 tick 时间线、27.186 tick/s、整帧 p99 37.877 ms；仍未过 V08 成本门。

| 同一阶段的时间关系 | p50 | p95 | p99 |
|---|---:|---:|---:|
| 最后渲染读回回调→主线程两回调处理完 | 10.726 ms | 15.453 ms | 16.753 ms |
| 最后渲染读回回调→下一次 `_process` 入口 | 11.917 ms | 17.246 ms | 18.387 ms |
| 主线程两回调处理完→下一次 `_process` 入口 | 0.781 ms | 2.271 ms | 2.940 ms |

第三行显示的是“入口前多久”；分析 JSON 同时保留有符号差值。271/271 个可配对 tick 的主线程 ready 均先于下一个 `_process`，其间 `_process` 入口数为 0。阶段最后 1 个 tick 没有后续记录的 `_process` 入口，按边界条件剔除。百分位以排序后 `floor((N-1)×p)` 位置计算，不外推到其它镜头或正式长采样。

这与此前 [60 秒跨线程分解](W07_读回等待分解_20261007.md)的持续波包回调→主线程均值约 10.2 ms 相近。当前数据提示该段主要随帧时机出现；若要优化，应先测具体帧节奏与主线程/渲染线程负载，而不在异步读回回调中直接递归提交 GPU 命令。这个短诊断不证明调度改动、状态等价或 WR-G0 通过。
