# W07 二维湿段拓扑三相位复核（2026-10-07）

结论：**当前单波包的主可见前缘是沿岸断续的单活动湿段，不是同一行两条同时活跃浪前。** tick 330/390/450 的真实湿水域各有约 40–47 行分成两段，但按单 tick 水深上升峰 >0.0045m 的条件，每一活动行都只有一段越门。上一轮短段网格的青帆和裂缝不能归咎于大量同排双前缘；主要仍是截面/主水面交叠、沿岸开缝和透视着色问题。此结论只覆盖该确定性单波包与所列阈值，不证明所有多波/绕流负载都单分支。V03/V05/V06/V08、W07 G03、WR-G0 不通过。

## 原始输入与算法

耦合参考床面、合法 0.18m/seed31 波包、GTX1050/D3D12、1920×1080 全屏。在 tick 330 和 450 用 `capture_reference.gd --wave --write-local-front-field --write-water-field --write-previous-foam --crest-height=0.25 --no-main-foam` 新捕原始字段；tick 390 复用[上轮同态字段](W07_二维局部前缘原型_20261007/local_field_wave390_coupled_manifest.json)。三组初始 rock/sand/water 哈希完全相同，为 `1625571958/2318428149/4161789743`。[本次原始证据目录](W07_二维湿段拓扑诊断_20261007)含两个新 manifest、RGBA 截图、water F32、previous foam RG32F 与 local front RG32F。所有 raw 文件长度均经脚本校验；新 manifest 视口均 `[1920,1080]`、tick 与文件名一致。

[可复算脚本](W07_二维湿段拓扑诊断_20261007/analyze_wet_front_topology.py)在各行把当前水深 >0.01m 的连续格归为湿段；分数与 GPU 字段 X pass 相同：`max(depth_now-depth_prev,0) × smoothstep(0.01,0.04,depth_now)`。每段最大分数 >0.0045m 视为活动；相邻行湿段 X 范围重叠或只差 1 格时连边，并计算连续片段。逐项 JSON（含输入 SHA256 和 0.005/0.01/0.02m 三个湿阈值）见[topology_summary.json](W07_二维湿段拓扑诊断_20261007/topology_summary.json)。脚本 SHA256 为 `738326cf28a64007bda508d017865bde3ec74367e7493ed87f9e1259a259ae8b`。

## 对后续形态的约束

当前负载可从每行一个活动前缘起步，但必须在沿岸强度缺口处有连续端点，且近岸湿水余量不足时正确收尾；不能简单逐行断开让每个短段露出锯齿边，也不能用整行封闭管跨过静默区。多波、双波交汇和绕障仍需另设读回验证，不能从本次三帧推断单分支恒成立。形体应优先解决与原水面共边的弯曲截面、可见正反面和白沫分布，再重复多相位/活动成本门。
