# W13 G02：岸脚接触白沫来源的屏幕诊断

状态：[诊断完成，候选未选型，G02 未通过]。W13 性能 0/10；本次为已有 staging 路径上的字段/三机位诊断，不计性能轮。

## 实施与同态

在 staging 使用的 `reference_water_local_front.gdshader` 新增**默认关闭**的 `prototype_contact_foam_source_debug`，捕图命令增加 `--write-contact-foam-source`。该捕图路径在精确 tick 后将泡沫历史的前一张 GPU 纹理绑定到 `foam_previous_state`，并自动保存其 RG32F 读回。只有诊断图启用：依据当前位置及四邻格水深区分现存干湿交界，依据当前水深和上一 tick 水深区分上涨；绿=近干且上涨 >0.0015m，黄=近干但未达上涨门槛，蓝=内部上涨，灰=其他水片。域边缘未被当成干格。诊断图不改变正常着色、模拟或 staging profile；三机位正常 PNG 与 [既有同 tick 严格证据](W13_G01_湿域来源着色_20261008.md)逐字节相同，权威水深 F32 也相同。Godot D3D12/GTX 1050、可见 1920×1080、连续 80 波包、耦合 tick300/600 捕图均 PASS。

复算见 [脚本](W13_G02_接触来源诊断_20261008/analyze_contact_source.py)和[结果](W13_G02_接触来源诊断_20261008/contact_source_metrics.json)，包含同态断言；PASS。代表图：[tick300 俯斜接触来源](W13_G02_接触来源诊断_20261008/contact300bound_coupled_oblique_contact_foam_source.png)、[tick600 俯斜接触来源](W13_G02_接触来源诊断_20261008/contact600bound_coupled_oblique_contact_foam_source.png)。

前两次诊断曾把大面积水域标蓝或完全没有活动绿像素。根因是普通 staging 路径只在上升浪唇原型启用时发布/绑定 `previous_foam_texture`；这次接触图虽保存了上一张 GPU 纹理，却未把它绑定给水材质。现在诊断捕图路径明确绑定，并使用格心 `textureLod`；复算核对当前/上一 tick F32，蓝色活动带与少量绿色接触像素都可见。旧的 `contact300`、`contact300prev`、`contact300sample`、`contact600`、`contact600low` 图仅保留为失败对照，**不得作为来源结论**。

## 结论

当前字段确能在可见水片上区分少量动态岸脚接触（绿）与大量静态近干水线（黄），俯斜机位约九成以上的绿像素落在水片遮罩 4px 边内。它给接触白沫提供独立的定位来源；尚未验证可见白沫的宽度、破碎形态、与浪前白沫层级或退水消失时序。下一步应以该来源做默认关闭的可见接触层候选，并同机位检验时间连续性、近景遮挡和 V06；不能直接把黄色静态水线着白。W13 G02/V06/WR-G2 保持未通过。
