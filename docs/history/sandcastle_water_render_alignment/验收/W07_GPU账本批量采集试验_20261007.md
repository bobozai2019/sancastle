# W07 GPU 潮汐账本批量采集试验

日期：2026-10-07。结论：**批量保留每 tick 原始潮汐增量在本机可行，且与逐 tick CPU 账本精确一致；尚未减少任何逐 tick 回读，也未通过 V08。** 这是后续解除源汇账本回读依赖的技术组件验证，不是新调度路线的性能证明。

W07 隔离原型新增 `reference_tide_ledger_ring.glsl/.gd`：在原潮汐边界 pass 后，把 x=0 的 256 个 R32F `tide_delta` 原值按 tick 顺序写入 GPU storage buffer。实验停止在指定 tick 后只对 ring 做一次异步缓冲区读回，按原求解器的先后顺序在 CPU 中累加正/负值。这样不在 GPU 上以 float32 累加，避免额外舍入。现有求解器**仍然每 tick 读回潮汐增量与 CFL**，并继续驱动正式账本；ring 只做旁路核对。原生产 shader、求解器和 profile 均未改。

## 状态与账本核对

D3D12/GTX 1050、耦合参考床面、可见全屏 1920×1080、VSync off。每组从 tick 8 发同一个合法 0.18 m/6 s 波包，精确停在 tick 90 或 270；无 ring/有 ring 分别运行。探针检查每个字段的非空长度、SHA256、完成态 revision、源汇账本和沙闭合值；四组运行 exit 0、预期 PASS，日志无 shader/script ERROR。

| 停止 tick | ring 一次读回 | 正式账本水源 / 汇 m³ | ring 合计误差 | 11 字段与无 ring 对照 |
|---:|---:|---:|---:|---|
| 90 | 92,160 字节 | 12.0391714940779 / 0.513112458167598 | **0 / 0** | SHA256 全同；revision 323 |
| 270 | 276,480 字节 | 32.5548915257677 / 1.59409667388536 | **0 / 0** | SHA256 全同；revision 1043 |

最终版 tick 270 另将 ring 每 256 个增量分别求和，与现有渲染线程逐 tick 源/汇回调逐项对照：**270 个 tick 的最大单 tick 源/汇误差均为 0**。这排除了仅凭终值相等而遗漏个别 tick 错配的问题。tick 90/270 的状态比较和逐 tick 核对见[分析 JSON](W07_GPU账本批量采集_20261007/ledger_ring_summary.json)。它只覆盖这组确定性波包；尚未验证工具事件、跨实例恢复、长时滚动缓冲区或多个异步批次在途。

## 短成本诊断与限制

保持原逐 tick 回读，额外启用容量 1000 tick 的 GPU ring；耦合 oblique、持续合法波包、2 秒预热 + 10 秒活动的短 A/B 为：无 ring/有 ring **27.026/27.154 tick/s**、整帧 p99 **37.283/37.575 ms**、GPU 渲染 p99 **6.782/6.781 ms**。短样本只说明新增 copy pass 未显现巨大开销；不能据此证明稳定性能增益。两组仍低于 30 tick/s 且超过 33.3 ms，V08 保持失败。

下一步要把这个原始增量 ring 改成有界双缓冲批次，确保异步读回、账本入账、检查点和退出时没有漏 tick；同时 CFL 决策仍需摆脱逐 tick CPU 回读且保持稳定性。完成这两个依赖后，才有可能测量真正减少回读的完整状态与三镜头活动成本。当前原型默认关闭，仅在 W07 诊断入口启用。
