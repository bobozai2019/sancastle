# W07 活动成本：逐 GPU pass 时间戳

日期：2026-10-07。结论：**持续波包把耦合模拟从约 2 子步/tick 提高到约 3 子步/tick，增加了约 0.42 ms/tick 的已标记 GPU compute 执行；此前约 34–36 ms 的 tick 前段等待不能直接归因于这些 compute kernel。** 此次诊断仍未让 V08 或 WR-G0 通过；下一步应拆出渲染线程排队、读回完成与主线程回调间隔。

## 方法

新增只读[参考型逐 pass 探针](../../../../tests/visual_water_alignment/prototypes/probe_reference_pass_timestamps.gd)，复用求解器、水沙耦合和碰撞代理已有 `RenderingDevice.capture_timestamp` 埋点。耦合参考床面 `oblique`，现有 phase2 光学/白沫、η 坡度法线、0.16 m 显示浪脊和不规则泡沫调制同时开启；本次不启用上一轮仍在候选阶段的折叠亮纹。实际可见全屏 1920×1080、VSync off、D3D12/GTX 1050。每组独立运行，30 秒预热、60 秒采样。持续波包按既有成本探针每 180 tick 发一个合法 6 秒、0.18 m `test_packet`；无额外波包组保留场景原潮位和水沙模拟，仅作归因。

在本机引擎构建中，旧逐 pass 探针已验证 `get_captured_timestamp_gpu_time()` 的差值以纳秒计；表中换算为毫秒。CPU 时间戳和 GPU 时间戳均只围绕已标记 dispatch，不包含未标记的纹理复制/读回、渲染队列空档、主线程等待或完整画面渲染。采样边界有一两个不完整 tick，因此以总耗时除实际完成 tick 作规模诊断，不能称每个 tick 都有完整逐 pass 配对。

| 负载 | 采样墙钟 | 完成 tick / tick/s | edge/drain/update/sediment/material 各自次数 | 已标记 GPU pass 总和 / tick | CFL GPU p50 | tide GPU p50 |
|---|---:|---:|---:|---:|---:|---:|
| 无额外波包 | 60.020 s | 1703 / 28.374 | 各 3408，约 2.001/tick | 0.840 ms | 0.0302 ms | 0.0307 ms |
| 持续波包 | 60.020 s | 1588 / 26.458 | 各 4760，约 2.997/tick | 1.258 ms | 0.0276 ms | 0.0297 ms |

逐 pass 总和增加 **0.418 ms/tick**；完成 tick 的平均墙钟间隔由约 **35.24 ms** 增至 **37.80 ms**。两者不是同一测量区间，不能将差值直接相减成某个线程的耗时。下面列出主要 GPU pass 的累计执行时间除以完成 tick：

| pass | 无额外波包 ms/tick | 持续波包 ms/tick | 有波单次 p50 ms |
|---|---:|---:|---:|
| edge | 0.132 | 0.197 | 0.0645 |
| drain | 0.092 | 0.139 | 0.0440 |
| update | 0.194 | 0.292 | 0.0963 |
| sediment | 0.156 | 0.271 | 0.0891 |
| material | 0.184 | 0.277 | 0.0901 |
| tide + CFL | 0.065 | 0.060 | 约 0.03 各 |

有波的 28,666 对、无额外波包的 21,871 对时间戳 GPU 差值均为正；`cfl` 各为完成 tick 数，`audit`/`sand_audit` 约每 30 tick 一次。无额外波包 collision 埋点约 0.77/tick、有波约 1.00/tick，其 GPU 总量分别约 0.015/0.020 ms/tick，不能解释数毫秒差额。两组日志均 exit 0、预期 PASS、无 shader/script ERROR；这里 PASS 仅表示采集成功。

该结果与[已有 tick 等待链](W07_Tick等待链_20261007.md)相符：两个异步读回齐备前的等待占主要墙钟；但 GPU kernel 时间小不等于整条 GPU/驱动/读回链小，也未证明是哪一个队列或回调延迟。启用时间戳会改变负载，本轮无波 28.374 tick/s、持续波包 26.458 tick/s，低于先前未启用时间戳的相似组合约 28.933/26.979 tick/s；它适合定位，不能替代正式性能结论。下一步应分别记录 render-thread 入队/dispatch、GPU 回读回调和 main-thread 接收时间；项目的碰撞代理已有 D3D12 异步回读回调内递归提交导致后续数据陈旧的实测注释，因此不能简单在回调内直接发下一批 GPU 计算。真实高泡沫墙钟覆盖仍未获正式验证。
