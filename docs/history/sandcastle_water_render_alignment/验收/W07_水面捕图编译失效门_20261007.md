# W07 水面捕图的编译失效门（2026-10-07）

结论：**局部前缘水面与平面反射床面的 shader 编译失败现在会使 W07 捕图器退出 1，不再写出误导性的 PASS 截图和 manifest。** 该门只保证这两份 shader 在目标场景里实际绘制出预期诊断颜色；不能证明反射位置、颜色、遮挡或 V02/V08 达标。

## 实现

[捕图器](../../../../tests/visual_water_alignment/prototypes/capture_reference.gd)在 exact tick 的 oblique 镜头短暂开启局部水面 `prototype_depth_bands`，等两帧后以 16px 网格抽样主视图。该分支应分别画出浅水红与深水蓝，各至少 20 个样本；随后恢复原参数并再等两帧才保存正式截图。若启用 `--planar-reflection-probe`，还抽样同一时刻的 960×540 镜像视图，要求至少 20 个沙色像素，确认水上床面复制层确实参与绘制。计数写入 manifest `shader_probe`。门只对 `--local-front-profile` 及其可选反射视图运行；未试图推断其它 shader 入口的编译状态。

正常固定床面 tick120：红 562、蓝 1402、反射沙 777；正常耦合床面 tick390：红 304、蓝 1692、反射沙 767。两组均退出 0、PASS、无 shader/script ERROR，分别见[固定 manifest](W07_shader_guard_20261007/fixed120_planar_guard_water_manifest.json)与[耦合 manifest](W07_shader_guard_20261007/coupled390_planar_guard_coupled_manifest.json)。恢复注错源码后的固定场景再次退出 0；其 oblique/close/grazing 三张主视图及三张反射视图 PNG 与注错前逐字节相同。

## 故障注入负例

先在隔离的 `reference_water_local_front.gdshader` 第 2 行临时注入 `FORCED_BAD_SHADER_TOKEN`，运行固定 tick120：Godot 输出 `SHADER ERROR`，捕图器诊断 `red_samples=0, blue_samples=0`，退出码 **1**，没有 `forced_bad_water` 截图或 manifest。恢复水面 shader 后，在捕图器生成的反射床面 shader `fragment()` 内临时注入同一无效标识符，运行固定 tick120：主水面仍有红 562、蓝 1402，但 `reflected_sand_samples=0`，退出码 **1**，没有 `forced_bad_reflection` 截图或 manifest。注错均已撤回，当前源码中不含该标识符；恢复后又执行了正常捕图。负例日志中的 Godot `PASS` 不再出现，只有诊断 FAIL。

该检查修复了此前“Godot 报 shader 编译错误但捕图器仍 PASS”的证据缺口。它仍可能漏掉运行时取样坐标错误或材质参数语义错误，故 V02 要继续做图像／目标对位；V08 要用独立活动成本数据。源码 SHA256：`reference_water_local_front.gdshader` `844B13260D004344E2312C80A3A22A3B4164A8D4CCB3EBB68ADC307F242EE14B`，`capture_reference.gd` `92F50058E830B085EEDB4B2C2AF0403715D576648AA2B0994DBF3552432F5933`。
