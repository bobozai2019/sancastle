# W07 tick 读回与线程交接等待分解

日期：2026-10-07。结论：**耦合参考场景的 tick 时间约 97% 落在“提交后等待异步读回回调”与“渲染回调到主线程接收”两段；持续波包相对无额外波包的 tick 增量主要出现在后一段。** 这是线程时间线归因，尚未证明某个驱动、GPU 队列或主线程任务是根因，V08/WR-G0 继续 FAIL。

在 W07 隔离预览中增加 `Time.get_ticks_usec()` 跨主/渲染线程标记：主线程 `_start_tick`，渲染线程进入和完成边界/CFL 读回请求，渲染线程收到 tide ledger/CFL 异步回调，主线程处理两回调并再次提交，渲染线程完成水沙/白沫计算命令提交，最后主线程收到完成通知。只计时，不改求解、子步、读回方式或物理参数。详细各字段见 [CSV](W07_读回等待分解_20261007/wave_combined_wait_coupled_tick_timing.csv) 表头；时间为相同单调时钟下相邻标记差，不是 GPU kernel 耗时。

## 负载与结果

同一耦合参考床面、`oblique`，phase2 光学/白沫 + η 坡度法线 + 0.16 m 显示浪脊 + 不规则白沫调制。真实可见全屏 1920×1080、VSync off、D3D12/GTX 1050。两组各独立预热 30 秒、采样 60 秒。持续波包为每 180 tick 一个合法 6 秒、0.18 m 请求；无额外波包保留原潮位和水沙模拟，仅作归因。两组运行均 exit 0、预期 PASS、无 shader/script ERROR。阶段 tick CSV 与 manifest 数目一致，所有新增标记非零、按流程单调；分析脚本拒绝缺失/逆序数据。

| 采样 | 有效 tick / 子步 | tick/s | 帧 p99 | tick 总时长均值 | tick 总时长 p99 |
|---|---:|---:|---:|---:|---:|
| 无额外波包 | 1719；全为 2 步 | 28.646 | 33.146 ms | 34.512 ms | 45.429 ms |
| 持续波包 | 1591；1587 为 3 步、4 为 2 步 | 26.506 | 39.201 ms | 37.321 ms | 46.881 ms |

| 时间段 | 无额外波包 均值 / p50 / p99 ms | 持续波包 均值 / p50 / p99 ms |
|---|---:|---:|
| 主线程发起 → 渲染线程进入 | 0.078 / 0.045 / 0.307 | 0.198 / 0.126 / 0.671 |
| 渲染线程进入 → 两个读回请求提交 | 0.078 / 0.045 / 0.356 | 0.073 / 0.039 / 0.349 |
| 提交 → 两个读回的渲染回调均到达 | **27.886 / 28.284 / 34.200** | **26.188 / 25.954 / 32.157** |
| 最后渲染回调 → 主线程处理最后回调 | **5.745 / 5.342 / 15.343** | **10.198 / 10.216 / 17.842** |
| 主线程两回调齐备 → 渲染线程开始完成提交 | 0.014 / 0.009 / 0.064 | 0.008 / 0.004 / 0.038 |
| 渲染线程完成水沙/白沫命令提交 | 0.696 / 0.585 / 1.865 | 0.645 / 0.547 / 1.732 |
| 完成提交 → 主线程完成通知 | 0.012 / 0.007 / 0.055 | 0.010 / 0.005 / 0.049 |

两段长等待的均值合计为无额外波包 **33.631/34.512 ms**、持续波包 **36.386/37.321 ms**，均约占 tick 总时长 **97%**。有波运行中，读回提交到渲染回调反而短约 1.70 ms，渲染回调到主线程处理长约 4.45 ms；这是两次独立运行的观察差值，不作逐 tick 因果断言。ledger 与 CFL 的渲染回调相隔中位约 0.013–0.015 ms，CFL 总是稍后；主线程两处理相隔中位约 0.21–0.27 ms。因而额外的主线程交接延迟不是 ledger 与 CFL 两次 GPU 回调之间的间隔。

上一轮[逐 GPU pass 时间戳](W07_逐Pass归因_20261007.md)测得已标记 compute 总量从约 0.840 增至 1.258 ms/tick；它不覆盖 GPU 队列空档、纹理复制与异步回读，不能从本表的 26–28 ms 中直接相减。当前采样还带有时间戳开销，不能替代未打点的正式成本。`source_active_frames` 只表示波源请求活动，不是屏幕高沫真实墙钟占比。

**下一步：**测 render callback 到主线程 `call_deferred` 执行的等待与相邻帧工作关系；比较安全的调度策略时不得在异步读回回调内直接递归提交 GPU 工作，仓库碰撞代理已记录该做法在 D3D12 产生陈旧/零数据。任何调度变更需核对水/沙/账本/恢复字段逐 tick 一致，并重跑三镜头活动成本。
