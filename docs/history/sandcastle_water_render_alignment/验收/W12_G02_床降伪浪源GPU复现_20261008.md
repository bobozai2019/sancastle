# W12 G02：床降伪浪源的生产 GPU shader 复现（2026-10-08）

状态：**修复前缺陷复现 PASS；W12 G02 [进行中]，W12 0/3**。本报告保留采集时的负例；后续修复及复验见[床高历史修复](W12_G02_床高历史修复_20261008.md)。采集时未更改 shader 或共享 profile。

前一轮[真实无波样本](W12_G02_无波床降与推进波对照_20261008.md)在 tick299→300 的最大床降仅 0.000107m，未达到单 tick 上升门约 0.000833m，故未触发。为覆盖足量床降，新增只读隔离 [GPU 探针](../../../../tests/visual_water_alignment/prototypes/probe_foam_bed_drop.gd)，直接加载生产 `visual_foam_step.glsl` 的 SPIR-V，以 256² R32F/RG32F 纹理执行一次真实 D3D12 compute。三种输入都为均匀 1m/s 水平流、无压缩、初始泡沫 0、前一水深 0.10m：

| 情形 | 当前床面 | 当前水深 | 自由水面 `bed+depth` | 预期来源 |
|---|---:|---:|---:|---|
| 稳态 | 0.10m | 0.10m | 0.20m，不变 | 无 |
| 仅床降 | 0.08m | 0.12m | 0.20m，不变 | **无** |
| 真实水面抬升 | 0.10m | 0.12m | 0.22m，上升 0.02m | 有 |

三组均使用相同生产 shader、`dt=1/30s`、0.125m 格、1.8s 生命周期、25.0 来源增益。探针保存[manifest 和原始输出](W12_G02_水深误触发_20261008)；[分析器](W12_G02_水深误触发_20261008/analyze_synthetic_bed_drop.py)复算[指标](W12_G02_水深误触发_20261008/synthetic_bed_drop_metrics.json)，PASS。稳态输出全零；仅床降与真实水面抬升的 RG32F 输出 **逐字节相同**，每格泡沫值 0.2307099、65,536/65,536 格超过 0.05。当前 shader 只读前一水深和当前岩沙床，后者仅以坡度参与接触系数；均匀床降保持坡度不变，故两组输入对其生成判据不可区分。这是受控 GPU 反例，不意味着现有 80 波包真实场景每格都出现该值。

修复需要在泡沫生成时同时知道前一 tick 床高，使 `eta_now=bed_now+depth_now` 与 `eta_previous=bed_previous+depth_previous` 比较；现有 RG32F 历史的 G 通道仍供浪前/局部前缘读取前一水深，不能简单改义。可选择独立的前一床高纹理并纳入 checkpoint/readback/恢复契约，或版本化扩展历史格式；两条路线都需覆盖旧存档迁移和成本。验证门是本隔离三组中床降为零、真实抬升仍有泡沫，并在固定/耦合活动波包、足量流水侵蚀、活跃保存恢复下复验。只添加泡沫强度阈值不能从信息上区分这两个输入。
