084235与084554是两个独立写进程，同一当前源码/资源hash（manifest差异0）、相同默认参数和输入，均没有执行cold restore。检查点及继续的全部状态bin、metadata和shader身份bin逐位相同。这两次排除了“该组原写分支一定不可重复”，但不能证明所有运行稳定。

083941实验写与084235默认写：tick17状态和metadata相同，tick24 sand/bed_0不同。该跨实验差异不能单凭shader公式相同宣称严格等价或把差异唯一归因于恢复。仍需直接记录实际GPU push bytes和首个分歧pass。

重要结论：失败窗口31份SPIR-V确实相同（C3）；因此这些失败不能由SPIR-V版本不同解释。float64参数一致的证据来自通过窗口，不能外推到失败。hash采集时机与配对结果相关，尚不构成原因已确认；CPU/GPU提交次序、常量实际编码/消费及其他未记录输入仍unknown。

同步实验使用[官方compute_list_add_barrier API](https://docs.godotengine.org/en/4.4/classes/class_renderingdevice.html#class-renderingdevice-method-compute-list-add-barrier)。该API说明不能证明本机4.7.2 D3D12发生了具体barrier缺陷；没有使用已弃用且无操作的barrier()冒充修复。
