# ADR v1.14：UI 队列、碰撞所有权与重置

日期：2026-10-11。仅适用于 edit_validation 候选，不放行正式入口。

UI 使用原 ToolCommandQueue 和 v1.13 调度器接收连续输入；GPU 忙时仍可接收，容量、名义库存预留和逐笔策略快照遵守原契约。命中块的已应用碰撞 revision 必须达到该块最新结算需求，否则明确拒绝该输入。拖动起点只在接收成功后推进。

结算后登记脏块及相邻块所需 revision；完成态发布后请求碰撞。碰撞 pack 不得绑定 receipt_pending 或 publication_pending 状态。每批标记实际绑定的完成态 revision，不能将一批最大请求 revision 当作所有块的来源证明。观察日志默认关闭。

退出关闭碰撞代际及待处理请求，等待实际 receipt 和碰撞 staging 回调归还所有权，再释放 RID。已完成 CPU 结算的终态在关闭中仍返回 applied；未结算命令可取消，不能重复结算。

重置立即禁收、取消等待命令并释放预留；等待已接收的活动事务、碰撞回调及输入驱动完成，然后建立新 generation 的求解器、队列和碰撞。新 generation 的输入 ID 从 1 开始，旧回执无效。重置与严格保存恢复不同，不宣称检查点或撤销已实现。

测试注入坐标从 Camera.unproject_position 的逻辑视口坐标经 get_final_transform 转为窗口坐标，再交给 Input.parse_input_event。960×540 窗口下逻辑视口为 1280×720、变换尺度 0.75；旧注入测试只证明其记录的实际命中位置，不能证明原计划的世界坐标覆盖。运行时鼠标入口使用收到的逻辑坐标，不额外变换。

复验与限制见 [整合验收](../验收/T05_UI碰撞与重置整合.md)。100 ms 门限未变；C 冷首笔失败仍保留。暂停、撤销、检查点和完整成本未放行。
