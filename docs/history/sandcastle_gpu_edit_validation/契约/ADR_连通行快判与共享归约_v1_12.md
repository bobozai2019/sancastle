# ADR v1.12：连通行快判与共享归约

日期2026-10-11。默认关闭实验候选；保留CLI fast_full_wet及shader名称以避免路径歧义，当前准确范围为下述连通行拓扑，名称不作为算法证据。

在v1.11全湿特例基础上，允许每行有一个连续非湿区间。GPU检查所有输入仍合法；每行第一/最后格湿，且至少一整行完全湿。每个湿格都能沿本行湿前缀或后缀到达左/右边界；左右边界全湿且贯通上下，完整湿行连接两侧，因此所有湿格属于同一四邻域组件。这是充分条件，不宣称必要条件；不满足时仍原BFS，不因外观像单池而合并。

归约仍逐行Kahan，只访问wet(h>.001 && obstacle<.5)成员，容量/供水/接纳/残差/量预算公式不改；非湿格复制原值，不删除水或动量。组件大小、touched和量预算采用实际wet_count。共享dry_loss单独保存，不能复用obstacle字段破坏后续wet判定。私有word27路径标记沿v1.11，主回执不变。

050403原路径56项数值PASS，050526快判56项PASS；两域×原10状态及新增row_hole/row_obstacle/ring_pool/multiple_holes，1288份有效bin严格等价（只排除预先未初始化private receipt和声明的私有word27）。单孔/单障碍孔使用快判；隔离环池和每行两个孔均回退。新统计fast_path_used来自GPU私有回执，不是CPU推断。

050343带timestamp互动4笔反馈95.454/73.984/69.004/50.191ms，全部100ms门PASS；与044453原算法52份raw等价。050800不带timestamp首笔129.730ms FAIL，后三笔84.620/79.726/47.879ms；不能用先前PASS覆盖冷首笔差异，当前Gate未放行。剩余C的water_velocity_reduce单invocation仍约20–27ms；是否优化C零速度归约需另做单因素对照，当前未实施。
