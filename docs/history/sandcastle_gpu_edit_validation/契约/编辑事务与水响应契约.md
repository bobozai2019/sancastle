## 1. 已读约束与复核

本轮在工作区清理前读到水沙 frozen v1：256²、32m、0.125m/格、固定1/30秒模拟步；世界XZ/Y高度；sand是参考密度沙量厚度，water是有效面积水深，momentum_x/z是hu/hv（m²/s），bed=rock+sand、eta=bed+water。每个pass输入/输出分离，显示读取同generation/revision的完整完成态；不直接照搬竞品原地UAV读写。

性能完成标准按用户2026-10-11修订为实际完成吞吐≥15次/秒、p99≤63ms、暂停编辑碰撞反馈≤100ms；约15–16次/秒、49–63ms、89–98ms为已接受效果基线。固定模拟步/CFL、数值和恢复约束不变；旧30次/秒、33.3ms等转为后续优化目标，详见[ADR v1.58](ADR_用户接受当前性能基线_v1_58.md)。

旧NUM-08专门验证编辑瞬间water逐格不变。本包保留`legacy_depth`对应旧测试；新增`conservative_displacement`必须另立ADR和验证版本，不能覆盖旧用例或修改旧PASS/FAIL。冻结原文已迁入docs/knowledge/water_sand，T00已与Domain、Queue及shallow_tool_patch源码复核；旧NUM-08结果保持。

本地接口不涉及HTTP/OpenAPI。现有 `ToolCommandQueue`、`SandWaterDomain` 是行为参考，GPU迁移不静默改变已有公共字段、排序或错误码。

## 2. 命令与结果

| 命令字段 | 类型/单位 | 规则 |
|---|---|---|
| domain_id | StringName | 活跃域 |
| generation | int64 | GPU提交必填；拒绝旧代 |
| sim_tick / command_id | int64 | 原`(sim_tick,command_id)`排序；ID单调且恰好执行一次 |
| kind | enum | MVP remove_sand/place_sand；其他沿旧路径，回退前必须同步当前revision |
| shape | enum | circle/swept_segment |
| transform | position_m/end_position_m，米 | 同现有单元中心距离与扫掠线段规则 |
| radius_m / strength | float | 半径(0,4]m，strength[0,1]，有限值 |
| amount_m3 | float m³ | 正数；实际请求=amount_m3×strength；扫掠整条只计一次 |
| seed | int64 | 固定重放 |

现有挖沙最多4轮对可挖格按权重重分配，实际挖出量进入桶；库存不足的place拒绝整笔，不自动改为少量放置。GPU等价阶段保留这些语义，不以“同样守恒”为由换分配算法。强度0按当前行为核对，权威状态和账本必须不变。

对外CommandResult继续使用command_id、status(applied/rejected)、applied_tick、sand_delta_m3、dirty_chunks、dirty_cells（GPU可调试用）、error_code。**sand_delta_m3沿当前桶账户符号：挖为正、放为负**，不能改成床面增量符号。

候选内部GPU回执拟增字段，不直接扩展公共API：

| 字段 | 类型 | 约束 |
|---|---|---|
| ticket_id / command_id | int64 | 精确对应事务，去重 |
| generation / input_revision / output_revision | int64 | 回执绑定实际执行版本；不把迟到回执套到当前revision |
| applied_tick / result_code | int64 / enum | 实际执行tick/有限状态码映射 |
| actual_sand_m3 | float | 用提交后实际GPU增减量核对，不能只回传名义请求量 |
| dirty_chunk_mask / dirty_rect | 固定布局 | 全部受影响碰撞/显示区域；边界截断明确 |
| invalid_flags / clamp_count | uint | 非有限、负值、超预算及保护事件可审计 |

stride=128 bytes、int64身份用两uint、容量64待排队/1在途、16byte对齐、reserved=0，完整offset及错误映射见ADR v1；不采用竞品32/36字节。错误沿现有 invalid_command、insufficient_sand、out_of_domain、stale_tick、inactive_generation、backend_unavailable；内部失效/审计异常另有失败记录，不伪装applied。

## 3. 事务与发布

1. CPU校验/排队，并预留放沙库存；挖出的未结算量不可立即花费。可用库存=已结算库存−未完成预留，失败/取消/退出释放预留。
2. GPU按固定顺序计算权重、4轮可挖量或放置量，写独立候选态/归约结果。禁止同格无序浮点atomic决定分布；重复命令不二次执行。
3. 校验状态和量后条件提交；失效事务不污染权威输出。读回小型结果结算一次，拒绝旧generation，避免迟到绝对patch覆盖新沙场。
4. ADR v1冻结“GPU完成态、命令回执、CPU账本”发布边界：同域一笔在途，旧完成态独立显示，回执结算后才发布；不允许回执前画面发布。若仍受回执等待主导，另记录设计选择，不以未版本化账本换延迟。
5. 热路径不以前置整图沙读回计算笔刷；CPU沙影子若用于其他消费者必须标注revision。混合旧工具路径、保存和完整审计允许在明确边界同步，不可无条件每笔触发。
6. 保存/恢复等待受控的一致事务边界；记录pending/reservation，或先结算完再快照，策略需冻结。撤销与对应重做要求已由用户取消（ADR v1.44）；普通保存恢复仍遵守完整完成态与严格继续配对。

## 4. 水策略

| 策略 | 范围 | 权威变化 |
|---|---|---|
| legacy_depth | 沙GPU迁移基准 | 编辑瞬间water/momentum保持旧规则 |
| conservative_displacement | 大块床高上升 | 排出的水移入连通可接纳格；挖沙先保留现有后续通量填充 |
| bounded_impulse_only | 单变量诊断候选 | 水量不变，仅有界动量输入；不是正式排水方案 |
| displacement_with_impulse | 前两候选分别通过后 | 同时位移和经验证速度输入 |

保守位移读取同一完成态。闭域编辑前后Σwater×A_eff相等；开放边界变化只按真实边界源汇记账。悬沙按携水比例搬运，接收动量与供体流速关系明确；干格momentum归零，不跨障碍/不连通水池传量。

局部接纳不足时明确保留剩余量/扩大合法连通接纳范围或拒绝事务，不删水，也不凭空把余量计为外流。ADR v1冻结旧湿组件N²容量遍历、接纳eta上限+0.02m、容量不足留水及失败原态不变。MVP只主动处理床高上升，挖沙不得凭空补水。

速度参数先定义m/s，再转为hu/hv；不能把竞品的5直接写入当前momentum纹理。输入能量/外部冲量及限速计数明确，满足CFL/子步上限，不以降Hz规避超载。砂模板方向与有符号增益属于候选，效果以曲线验证。

## 5. 数值/恢复门

已读旧阈值：闭水5分钟相对误差≤0.5%；工具1m³搬运≤0.5%；水沙耦合沙量5分钟≤1%。这些是兼容上限，不足以代替逐笔局部核对。

ADR v1与edit_protocol.gd已冻结eps_cell、eps_edit_sand、eps_edit_water、eps_reduction：依据float32量化、受影响格面积、实际范围和固定归约误差预先计算并记数值；逐笔核对场增减+桶/源汇闭合，不用巨大域总量的百分比掩盖小笔误差。容差未冻结不得通过G0。

CPU/GPU对照允许事先冻结的数值误差；同候选同机同seed/输入应可重现。既有严格保存恢复测试继续逐位配对，不以CPU/GPU迁移容差替代其门槛。未解释的负沙/负水/NaN、旧回调生效、重复结算为0。

## 6. 观测字段
