# ADR：扫掠速度方向的稳定计算 v1.7

日期2026-10-11。EV-008：R32F投影差的方向精度不足，数学模板、沙权重与预算不变。

033001 D矩阵40项中两个swept/+0.5样本失败，64²/256²各4格超2e-7m²/s逐格门，最大2.45958870766921e-7m²/s。水/悬沙恒等、外部impulse、能量、clip和CFL检查通过。原FAIL及q_f32/oracle_f64/input/receipt原始数据保留，独立numpy取证定位见swept_precision_forensics.json。

原先使用`p-(a+segment*t)`，近中心线时两个接近数相减，残差归一化放大R32F投影误差。内部点的径向方向数学上等于带符号的线法向，因此改为`normalize(vec2(segment.y,-segment.x))*sign(cross(p-a,segment))`；t<=0/t>=1仍取端点方向，退化线段沿圆规则。距离0方向0，不造指定中心方向。沙prepare及weight仍使用原实现，不同时改变沙分配、量化、模板幅度或Q更新代数。

只改变速度方向的数值计算。033451原40项全部通过，swept/+0.5最大逐格差5.8864955392729e-9m²/s；0速度/零强度逐位门、clip_count和原水沙/动量/能量预算未放宽。极近线的任意坐标、中心控制、CFL64边界和真实输入仍须后续覆盖，不能从这组样本泛称所有浮点输入完全等价。
