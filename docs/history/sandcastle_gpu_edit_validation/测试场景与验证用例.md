# 测试场景与验证用例

日期：2026-10-11。角色：validation_plan。本文件保留验证矩阵；三层场景已于T02建立，CPU/GPU笔刷及水候选待T03/T04。实际结果仅见验收报告。

## 1. 三层场景

| 场景拟定路径 | 固定内容 | 用途 |
|---|---|---|
| tests/edit_validation/edit_numeric_lab.tscn | 64²封闭水盆，正交相机，0.125m/格，固定床/沙/水 | 逐格数值和0–5秒响应曲线 |
| tests/edit_validation/edit_brush_lab.tscn | 256²/32m正式网格，沙/水显示、固定相机、碰撞代理 | CPU/GPU笔刷、回执、拾取/碰撞、单变量成本 |
| tests/edit_validation/edit_beach_lab.tscn | 继承现有完整沙滩场景，profile和视觉负载一致 | 全场持续浪/侵蚀/堆挖/保存恢复及正式成本 |

重用 `tests/investigation/underwater_deposit_probe.gd` 的最小格局与已有solver；参考当前CPU工具域，不复制一套生产求解器。场景相机、光照、mesh、资源绑定保存到tscn/tres，脚本只注入状态、命令和记录。GPU数值用主RD可见小窗口；正式性能必须可见1080p，不用隐藏/无头窗口结果。

## 2. 方案矩阵与归因顺序

| 组 | 沙执行位置 | 水编辑 | 比较目的 |
|---|---|---|---|
| A 当前基线 | 现有CPU影子→笔刷→GPUpatch | legacy | 正式现状 |
| B GPU沙候选 | 原工具规则迁GPU | legacy | 只改变笔刷执行路径 |
| C 位移候选 | 与B相同 | 保守位移，无附加速度 | C对B，只看排水策略 |
| D 速度候选 | 与B相同 | 不位移，仅有界速度 | D对B，只看速度输入 |
| E 组合候选 | 与B相同 | 保守位移+通过验证的速度 | E对C，只加速度；E对D只加位移 |

water单变量必须从**完全相同的沙编辑完成态**起跑，避免CPU/GPU沙高细微差异干扰。全域→局部dispatch、预取后台校验等另开单因素对照，不塞入首个B。每个run重建同初态，不把连续重放的累积状态当基准。

## 3. 沙笔刷用例

| ID | 输入 | 必观测/判定 |
|---|---|---|
| S00 | 无命令、零强度、重复重置 | 状态/账本不漂移；观测探针不会制造编辑 |
| S01 | 单次挖/堆，半径0.25/0.75/4m、固定strength/amount | 按实际量结算，格权重和结果对照CPU |
| S02 | 圆与扫掠线段，包括退化线段 | 扫掠一次总量，不因距离/采样数重复计费 |
| S03 | 域边、角落、跨碰撞chunk、无沙/薄沙 | 截断/拒绝按原语义；不穿rock、不负沙、不漏脏chunk |
| S04 | 库存不足与临界库存、4轮可挖不足 | 放沙拒绝整笔；挖沙部分实际量与旧规则一致 |
| S05 | 同tick重叠命令、快速挖→堆、重复ID、过期tick/代 | 排序固定、不透支、不二次执行、旧命令不影响新域 |
| S06 | 参数NaN/Inf、越界、空footprint | 合法错误、无污染状态；若发现基线缺陷单独登记 |
| S07 | GPU dig/place后旧smooth/compact混合使用 | 旧路径使用正确revision；不以陈旧绝对patch覆盖GPU新沙 |

每笔比较权威sand/compaction、实际搬运量、库存、源汇、脏范围、结果状态；逐笔局部误差和整段闭合均需过门。不要求未影响区域浮点重写，避免新算子造成域外漂移。

## 4. 入水响应用例

基础复现：64²、0.125m/格、封闭、初始12cm静水；圆盘半径0.75m，平顶高度20/80cm单变量对照，再测圆顶。将这些高度转换为具体沙量/候选初态，记录转换，不把“80cm”当未入账命令。

| ID | 变化 | 必观测/判定 |
|---|---|---|
| W00 | 无编辑静水；干地堆挖 | 静水平衡；干地不制造水/动量 |
| W01 | 平顶20cm与80cm入12cm水 | 固定相同footprint；排水量和局部残水曲线，不因大高差又退化为只抬水 |
| W02 | 80cm平顶与等输入尺度圆顶 | 沙形单变量，区分形状与算法 |
| W03 | 干湿边、深水、小量编辑 | 不误清整片水；深水与原小笔编辑无异常 |
| W04 | 封闭盆地、障碍隔断/两个不连通水池、接纳容量不足 | 不跨障碍传量、不丢余水、不伪造出域量 |
| W05 | 悬沙水、有初始流、挖沙及连续堆挖 | 携水悬沙搬运、动量处理、挖沙不凭空补水 |
| W06 | 速度=0及预先冻结的多档合法速度、正负模板区域 | 位移/速度贡献可分；CFL/限速/干格、反向流与振荡记录 |
| W07 | 大量重设水深的错误候选（隔离负例） | 审计能抓未解释水量损失；不能通过新增虚假sink让坏例PASS |

样本时间：编辑前、提交完成、0.1/0.25/0.5/1/2/5秒**模拟时间**，另录墙钟及完成tick；低吞吐不能冒充慢物理。固定物理子步可做隔离对照，正式30Hz+CFL模式须另验，不能把固定1/600秒诊断吞吐当正式速度。

输出：中心及footprint内最大/平均水深、区域剩余水量、向邻域迁移量、eta峰值、速度/动量上限、悬沙/水沙闭合、负值/NaN/限速/超载、入水后持续曲线和同机位录像。T01在运行候选前冻结局部排水目标；无原作时间曲线不声称秒级复刻。

W01的核心判定可以直接定义：沙帽已高于编辑前自由水面，且连通接纳区容量足够时，完成编辑事务后沙帽上的残水应达到冻结的干湿阈值，排出的量须在接纳区或真实合法出口找得到。20/80cm两者均已出水，能够排出的初始水量相同是合理结果，不能把“80cm排水量必须更大”当成功标准。容量不足另走W04的保留/拒绝策略。

## 5. 交互与恢复用例

- 冷启动第一笔、稳定后的单笔、持续拖动、连点、空操作；实际鼠标拾取路径与自动轨迹各测，不能只绕过输入层直接调用命令。
- 挖堆处可见沙面与碰撞代理采样同位置，记录最大高度差及更新延迟，碰撞反馈≤100ms；不靠放宽容差掩盖陈旧拾取。
- 连续命令未回执时再放沙、库存耗尽、回执重复/乱序、重建generation、退出；库存预留释放和事务恰好一次。
- 冻结/暂停时编辑与恢复运行；时钟和语义保持。撤销及对应重做、跨tick撤销分支重演、磁盘redo已取消，见[ADR v1.44](契约/ADR_取消撤销重做范围_v1_44.md)。
- 保存时有pending命令/预留，恢复后继续同输入；沙、水、momentum、悬沙、压实/湿度、账本、时钟及已有视觉history按既有门配对。

## 6. 性能窗口

| 阶段 | 窗口 | 用途/判定 |
|---|---|---|
| 定位 | 新20秒同钟追踪；覆盖预取命中/未命中及冷首笔 | 有重日志，不作成本PASS |
| 候选筛选 | 同态短窗口、无编辑/单笔/拖动 | 先排除无收益或错误候选 |
| 初步完整负载 | 预热10秒+60秒持续浪/20笔编辑 | 与已存历史窗口对照；新A/B需同环境，不能只比旧数字 |
| 最终成本 | 稳定候选，预热30秒+300秒；独立/联合入口各至少三组交错A/B | 固定脚本含无编辑、挖、堆、持续拖动，记录活动段及全窗 |
| 最终稳定性 | 冻结配置后受影响三机位各300秒、耦合30分钟 | 只对稳定候选集中执行，不每小改重跑 |

A/B按A-B、B-A交错，输入/初态/profile相同；记录硬件、真实尺寸、VSync、GPU外部负载与实际参数。异常外部负载需标记窗口，不悄悄删掉失败帧。性能版流式写日志，不存大图或全量CSV到内存；数值捕状态版另跑。

统计p50/p95/p99/p99.9/最大帧时间、编辑附近/远离编辑帧、命令→首可见、碰撞延迟、按完成时间戳的tick/s、GPU笔刷/归约耗时、CPU提交/解码/发布耗时、读回次数/字节、资源趋势。按2026-10-11用户修订，[ADR v1.58](契约/ADR_用户接受当前性能基线_v1_58.md)的本轮性能门为：实际模拟完成速率≥15次/秒、p99≤63ms、暂停单次编辑碰撞反馈≤100ms；已接受短测效果约15–16次/秒、49–63ms、89–98ms。原30次/秒、33.3ms、首可见100ms为后续优化目标，>50ms编辑相关帧只记录、归因，不作为独立硬门。固定1/30秒模拟步及CFL不变。原验证窗口、稳定性与对照交付保留；历史FAIL原样保存，新标准结果另记。
