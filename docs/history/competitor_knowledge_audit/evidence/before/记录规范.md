# 竞品知识统一记录规范

生效：2026-10-11。角色：documentation_policy。依据：用户要求“所有竞品相关的知识在确定无误后，统一记录到docs下”。项目强制入口见[AGENTS.md](../../AGENTS.md)。

## 归档位置与时机

竞品已确认的实现、资源、有效参数和可复用取证结论，以 `docs/competitor/` 为统一知识入口。新结论确认后，在当次任务交付前写入对应主题文件并更新README索引，不得只留在聊天、task草稿或其他记忆库。

调查过程、失败记录保留在既有docs/search和docs/history；本目录写可独立理解的事实及来源指针，不搬动历史源或复制多份互相竞争的正文。原包/RDC保持只读；大型raw、运行快照与脚本可沿用既有英文数据目录，docs中必须有身份、可用性、证据定位和复验索引。

## 什么算确认

1. 直接字段、有效绑定、可复验指令或原始数据/受控贡献支持的具体陈述，可按项目判据记C3。
2. C2交叉支持必须有至少两类实质独立证据、排除主要替代解释，明确仍是交叉支持/语义解释；不能写成完整原作算法已直接恢复。
3. C1线索/假设、C0缺证/冲突只入“待验证/未知”区域，不混入已确认事实。包内默认值不自动升级为运行时参数；编译字节码不是原始源码。
4. 历史确认与当前证据可用性分开记录。原始数据缺失时保留历史评级和来源，不宣称本次C3复验完整；必要时先恢复原始数据再作新确认。
5. 单帧只支持该帧几何、资源、字段与调用；不证明动态寿命、秒级速度、侵蚀因果或性能。不同捕帧ResourceId不通用。

## 最小条目模板

```markdown
## <稳定条目ID>：<一个具体结论>

- 更新日期：
- 对象与范围：原包版本/容器hash；捕帧hash；对应事件/对象身份。
- 分类/可信度：观察事实 / 算法推断 / Godot适配；C0–C3。
- 确认状态：本次直接复验 / 历史已确认；本机证据完整 / 仅索引 / 缺失待恢复。
- 结论：可独立理解的具体行为。
- 证据定位：对象字段/原字节范围，或event、stage、slot、ResourceId、mip/slice/selector；来源报告与产物hash。
- 复验方法：工具/版本、命令、输入、预期观测；新输出目录。
- 反证与适用边界：
- 未知项：单位、公式、时序或未映射字段。
- 修订关系：补充/替代哪个陈述，旧记录在哪里。
```

当前主题文件可按稳定领域合并条目，不为每一条事实新建文件。源文件SHA256、产物hash和可用性记录在evidence_inventory.json或后续版本化索引；主题正文中的ID应能在证据表定位。

## 更新与去重

先搜索本目录、docs/search和docs/history：

- 同结论、同范围、同证据：补定位或索引，不重复建立知识条目。
- 新捕帧/新参数/新边界：追加明确范围和日期，保留旧报告；不能用新正例抹掉旧负例。
- 推断被证实：补直接证据及新的范围/评级，关闭对应未知项并保留原历史假设。
- 证据冲突或范围不清：登记冲突，暂停“确定无误”的宣传，安排区分实验；不静默选择更强结论。
- 原作事实、Godot适配、AI目标示意分别标注，不互为证据。

## 交付检查

- [ ] 结论有稳定ID、对象/capture完整身份和明确适用范围。
- [ ] 当前证据确实可用，或明确缺失/仅历史确认。
- [ ] 已核对包内默认/帧内有效、场景单位/米制、静态事实/动态因果。
- [ ] 原始数据与索引配对，失败与部分解析可追溯。
- [ ] README入口、主题文件与未知项同步；内部链接可打开。
- [ ] 没有覆盖旧失败、旧Gate或原包；没有引入竞品业务分析。
