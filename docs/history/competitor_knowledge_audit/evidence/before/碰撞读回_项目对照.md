# GPU读回、沙面碰撞与当前项目对照

原作已观察到GPU辅助采样、CPU缓存、分块网格更新和物理射线。当前项目通过统一Height通道生成分块高度图，通过Probe通道供漂浮道具采样；两种数据都来自完整完成态。相似的数据流不证明采样规则、调度频率或成本相同。

## COLLISION-COMPARE-01：原作确认范围与证据

- CPU拾取使用相机射线和Physics.Raycast；命中PlaneChunk后补充Readback数据，部分未命中路径回退到平面。四样本sandAmount均值写入网格顶点y，JobHandle.Complete后重新绑定MeshCollider。限定方法和字节定位见[命中代码补证](笔刷命中检测_代码补证.md)。这些是所选版本的C3指令事实，不是墙钟调度记录。
- [运行时碰撞网格](运行时碰撞网格取证.md)记录sharedMesh、缓存与物理射线样本。test1的256×128、1MiB辅助输出与独立运行的256×256、2MiB CPU缓存是不同观测，不拼为同一帧。
- 碎石与道具所需字段见[输运专题](碎石输运与道具浮力.md)和[来源索引](transport_evidence_inventory.json)。原作浮力/水阻公式、读回频率、每次编辑的等待策略及实际延迟仍未知。数据可用性见[证据与未知项](证据与未知项.md#数据可用性)。

## COLLISION-COMPARE-02：当前统一通道

| 环节 | 当前实现 |
|---|---|
| 入口 | `scenes/main.tscn`和`test1_geometry`使用统一DomainRuntime；Height负责碰撞发布，Probe负责消费者点采样 |
| 床面输入 | 完成态rock+sand；256²域分8×8块，每块33×33高度样本 |
| 高度包 | 每批最多16块；纯高度payload上限69696B，ABI v3完整包69828B，包含身份、块信息与revision |
| CPU加工 | 两个Height槽接收异步读回；WorkerThreadPool解码和验证，主线程在物理步应用HeightMapShape3D |
| 发布预算 | 每物理帧累计最多8块或1500μs；块的generation/state_seq/revision决定结果能否应用 |
| 编辑终态 | 录制接受与GPU最终结果分开；普通输入可使用上一份完整碰撞面，不将逐笔碰撞完成或两物理帧等待作为公共编辑门禁 |
| 恢复 | 切换generation后过滤旧回调，重建全部64块；候选状态和消费者恢复遵守统一生命周期 |
| 道具采样 | Probe ABI v3每次最多32点，请求1152B、输出3200B；床面、水深、流速与碰撞误差信息供CPU受力使用 |

源码：[Height通道](../../scripts/simulation/unified_edit/height.gd)、[高度包](../../scripts/simulation/unified_edit/height_codec.gd)、[Probe包](../../scripts/simulation/unified_edit/probe_codec.gd)、[主入口](../../scripts/beach/unified_playable_entry.gd)。完整协议与所有权见[技术规格](../当前技术规格.md)和[模块接口](../knowledge/water_sand/模块与命令接口契约.md)。

## COLLISION-COMPARE-03：拾取与物理反馈边界

主入口用摄像机射线执行100m、mask=1的`intersect_ray`，输入位置再进入统一命令管线。碰撞高度发布有预算，视觉完成态与物理形状并非每一时刻同时更新；不能把使用共同床高字段解释为所有位置、所有时刻精确重合。

main现有瓶子、木板和木棍使用2/4/3点Probe与Jolt刚体接触，详见[漂浮道具](../漂浮道具.md)。物理形状承托和CPU受力不会自动把接触冲量写回权威水沙；GPU碎石也是独立表现消费者。用户射线形成编辑命令与刚体双向流固耦合是不同接口。

## COLLISION-COMPARE-04：对照与复验边界

原作四样本平均网格和项目高度图的分辨率、插值与单位不同，不能仅按顶点数或读回字节数比较精度和性能。复验应固定输入、完成态身份、相机和采样点，分别测GPU打包、读回等待、worker加工、物理步应用与实际命中偏差。原作没有同条件时间戳，因此不据当前源码推断其更快或零等待。
