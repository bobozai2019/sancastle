## WATER-SOLVER-ARCH-01：状态、计算与执行关系

- 整理日期：2026-10-27。
- 来源：`sandcastlegame/test1.rdc`，225224034 B，SHA256 `761aa980c2426f75a1fa7364bf6d2655ff4dd20ea76566e630ee5b53ea0ec5b2`；运行观察的程序身份另按时钟证据索引核对，不能把运行观察的资源号套到此捕帧。
- 分类／可信度：打包字段、原程序、绑定与 API 顺序为观察事实 C3；可读方程中的机制解释按各专题标注 C2；未观察的连续行为保持 C0／C1。
- 来源身份、原程序和复验入口见[水求解来源索引](water_solver_sources_20261027.json)。本机所选原始数据与正式导出可读；旧临时实验中的缺失数据不因本归档而恢复。索引说明本次实际核对范围，不宣称重新执行 GPU 实验。

### 状态与编码

test1 水场为 512×256，每格 16 B 的 `uint4`，共 2 MiB；沙场为 1024×512、8 MiB。水场保存边速度、内部水量、床高、宏观法线与响应／源项字段，不是只保存高度的一张纹理。

| 位段 | 含义 | 解码／用途 |
|---|---|---|
| word0 bits0–7／8–15 | 宏观法线 X／Z | `2×code/255−1` |
| word0 bits16–31＋word1 bits0–7 | X 边速度 | 24 位，`8×code/(2²⁴−1)−4` |
| word1 bits8–31 | Z 边速度 | 同上 |
| word2 bits0–23 | 内部水量原始解码值 `A_raw` | `10.1×code/(2²⁴−1)` |
| word2 bits24–31＋word3 bits0–15 | 水所见床高 `b` | 24 位，`10.1×code/(2²⁴−1)` |
| word3 bits16–23 | 上升／陡面响应 B | 水量核在所查分支写 0 或 255，下游按归一化值消费 |
| word3 bits24–27 | 格内源项 | 源汇核按阈值及比例消费 |
| word3 bits28–31 | 海侧回设权重 | `alpha=code/15` |

可见水深为 `h=max(A_raw−0.05,0)`，自由表面为 `eta=b+h`。部分数值审计把 `A_raw−0.05` 记作解码 A；引用 `sum(A)` 时必须先核对报告定义，不能把两种约定混用，更不能直接将该和称为物理水体积。床高、速度等字段即使不是某核的主要更新量，也可能因重新打包而变化。

详细解码及极值反例见[状态布局](水处理全流程与项目对比.md#pipe-state-01-两个分辨率与一份打包水记录)、[重编码事实](水求解参考与同步.md#water-pack-01e1495也会重新舍入已有速度码)和[非主字段变化](水求解参考与同步.md#water-pack-02非主更新字段在极值输入下也会变化)。

### 六类核

| 核／test1 首次事件 | 已确认的计算结构 | 不能省略的条件 |
|---|---|---|
| 床面更新／1484 | 将沙场高度四点插值到水格，解码两种高度后取较大值，再打包床高 | 原沙场 SRV、障碍高度来源、完整字段重编码 |
| 速度积分／1490 | 由自由表面高差加速边速度，再施加阻尼、边缘衰减、邻速混合、湿干阻挡和限速 | 床形、边界、dt、重力与格距；简化梯度式不是完整核 |
| 水量积分／1495 | 按边速度正负选择供水侧深度，用上风通量差更新水量并生成 B | 本格修正项、限幅、量化和原位读取；不能只保留理想守恒主式 |
| 速度平流／1500 | 回溯采样并插值速度 | 回溯位置、分量布局及边界；它与水量搬运是不同阶段 |
| 源汇／1537 | 蒸发、障碍微扰、海侧目标水位回设、customWave 与格内源项 | playTime 与源汇 dt 分开，保留障碍纹理和空气依赖 |
| 宏观法线／1543 | 从自由表面邻域差分计算并编码法线 | 读取的是水面基准，法线字段与几何绘制采样不是同一个步骤 |

可读公式、有效参数与原指令定位见[传播计算](水处理全流程与项目对比.md#5-宏观水流与浪的传播)、[源汇计算](水处理全流程与项目对比.md#6-海侧造浪回落与水量源汇)及[宏观法线](水处理全流程与项目对比.md#7-宏观法线与真正绘制的水面)。这些章节包含项目对照段，原作公式必须按其来源和评级单独引用。

### 阶段与同步

匹配 test1 的这一段顺序为：床面更新 → 三轮“速度、水量、平流” → 源汇 → 法线。每次 16×8×1 组、32×32×1 线程，水核在同一命令列表中使用同一结构化水 UAV，核间有 UAV 屏障。其他已观察条件存在不同轮数，不能把“三轮、12 次 dispatch”写成全游戏固定周期。

核内邻格读取与本格写回共用水缓冲区；核间屏障不保证所有线程先读旧态再统一写回。有限设备上的同输入重复原程序执行已有不同输出，不能据缓冲区布局推断唯一线程推进顺序。同步定位见[API 同步事实](水求解参考与同步.md#water-sync-01水链在同一命令列表上以uav屏障相连)，轮数边界见[多捕帧证据](水求解参考与同步.md#water-capture-01不同捕帧的轮数与同帧周期不能固定为三轮一次)。

## WATER-SOLVER-TIME-01：时间与调用规律的已知范围

已观察运行中，传播积分 dt 为 `0.00732421875`，源汇 dt 为约 `0.025`。源汇调用处公开引擎 getter 处于固定步上下文；所观察前缀的累计积分轮数符合 `floor(N×source_dt/integration_dt)`。读数与计数为 C3，保留余量的累计器解释为 C2，唯一原调度方法尚未恢复。

公开引擎 timeScale 显式持值为 0.5 时，所测缩放时钟和墙钟调用节奏变化，单次源汇 dt 仍约 0.025；不能把它改写为 0.0125，也不能把名义 40 个模拟步／模拟秒直接叫作墙钟 40 Hz。playTime 有实测轨迹和 GPU 常量对应，但其生成公式、初始偏移和完整造浪输入规律仍未知。

这些连续观察使用 512×512 运行域，自然无主动编辑及公开引擎 1／0.5／1 干预分别有独立范围；它们不扩大 test1 的 512×256 单核数值判据，也不证明原作 UI、暂停、重置或无探针频率。详见[时钟证据](水求解参考与同步.md#water-runtime-clock-01配置步长与累计积分轮数分别有实测依据)和[受控输入证据](水求解参考与同步.md#water-runtime-control-01公开时间输入改变墙钟节奏单次源汇步长保持不变)。

## WATER-SOLVER-VALIDITY-01：实现可解释范围与未知

原 DXBC、完整依赖和受控输入能直接用于核级参考。六核只读快照以及两端原位加载记录已有算术对应：原生记录可交给原生和 Godot 固定流程序消费；Godot 自身原位记录也可交给原生固定流程序消费。对应结论限实际索引的输入、程序和设备，见[读流协议与反证](水求解参考与同步.md#water-readstream-01六核原位读取记录与双向算术配对)。

只读快照、固定流消费和 Godot 表达式模型都是显式适配；插桩的额外存储和寄存器分配可能改变调度。保留原算术 token 不等于保留未插桩执行结果；记录值能解释某次输出，不等于恢复原始 HLSL、最终机器指令或全部合法线程顺序。原经验范围无法包住独立原输出的反证保持有效，不能继续扩样直到候选通过。

| 问题 | 当前结论／可信度 | 补证需要区分什么 |
|---|---|---|
| 原位线程可见顺序 | 原位结构及所测非唯一输出 C3；唯一调度 C0 | 未插桩行为与记录扰动、设备和编译差异 |
| 真实秒级波速、波幅衰减与长期残差 | 未闭合，C0／C1 | 时轴、长度单位、边界输入、耗散与水量变化 |
| 完整水量守恒 | 通量结构和局部修正 C3；完整账本与长期漂移未知 | 边界、源汇、限幅、量化及内部残差分别统计 |
| playTime／customWave 全部生成规律 | 已观察轨迹 C3，完整公式 C0 | 输入来源与调用时钟，而不是从单帧外观拟合周期 |
| 暂停、恢复、重置和完整初始化 | 未验证完整，C0 | 计数与状态是否保留、重置边界和资源初态 |
| 实时成本和跨硬件一致性 | 无通用承诺 | 真实可见负载、计时口径、GPU 时间戳及目标设备 |

因此，六核的输入、局部计算、写回、同步和限定时间行为已有可实施依据；原作长期运行和全部状态转换仍需独立证据。水面材质、焦散和泡沫绘制属于相邻专题，不能仅凭求解核说明全部沙滩观感，入口见[竞品技术知识](README.md)。

## 证据读取与复验

先查[来源索引](water_solver_sources_20261027.json)，核对源文件及程序 hash，再按各 manifest 的 selector、输入、CB、SRV、模式和工具版本读取原始字节；指令号和 ResourceId 不跨 capture 复用。历史失败、部分结果及缺失项保留原记录。

本归档只使用现有数据。新的 GPU 复验必须先证明临时文件、用户数据、日志和可配置缓存全部位于项目根内，且无外部目录联接；旧启动器未完成这一边界核验，不能直接当作当前可执行入口。实验进度及未完成覆盖保留在[任务执行状态](../../task/competitor_water_solver_evidence/执行状态.md)，不混入本技术方案。
