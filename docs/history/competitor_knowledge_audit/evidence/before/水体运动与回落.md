## MOTION-VELOCITY-01：自由水面高差可以使流向反转

- 分类/可信度：指令及参数 C3；作为完整运动算法的语义解释 C2。
- 包内 VelocityIntegration DXBC SHA256 `9e5c7da8738200d374076a6cc3b48be52fdbad70e8c8dc2bd27eb75431d30523`，与 E1490/1505/1520 相同。
- 有效参数：`deltaTime=0.00732421875`、`gravityForce=16`、`maxVelocity=2`、`damping=0`、`kappa=1000`。包内编译变量的字节偏移与本帧消费寄存器逐项对应，不解释未使用 cbuffer 字节。
- 每格的 vx 是该格与 +X 邻格之间输运时使用的速度；vz 同理用于 +Z 边。以 X 为例，主要加速度为 `−gravityForce×(eta_R−eta_C)/dx`，并以 deltaTime 积分已有速度。岸上 eta 高于海侧邻格时，这一项可以产生正 X（向海侧）的加速度。
- 此后还有边缘衰减、邻格速度混合、湿干阻挡与向量限速，不能只用上述梯度冒称完整核。边缘项由四边 smoothstep 窗口构成，乘 `1−deltaTime×edge`；邻速与更新后中心速度按 `(sum_neighbors+kappa×v)/(4+kappa)` 混合。主体 damping 为零仍不表示没有数值耗散。
- 湿干保护的深度阈值由 `waterCellSize.x×0.0001` 给出，本帧约 5.859e-6 场景单位。它与项目的 0.001 m 干格动量归零门槛不同，单位尚未统一。
- 证据：E1490 指令 87–139 的 eta、梯度、积分、阻尼、混合和限幅；精确十六进制指令（文件缺失；旧定位`../../test_output/test1_water_motion/analysis_v1/e1490/instructions_hex.txt`）、常量解码（文件缺失；旧定位`../../test_output/test1_water_motion/analysis_v1/e1490/constants.json`）、包 manifest 的同名变量与 offset。
- 反证/未知：零 damping 不证明水永远不停；原作后续输入、时间倍率、沙床演化及其他源项仍会改变运动。

## MOTION-MASS-01：水量搬运的守恒结构与完整更新边界

- 更新日期：2026-10-24。范围：同一 `test1.rdc`（225224034 字节，SHA256 `761aa980c2426f75a1fa7364bf6d2655ff4dd20ea76566e630ee5b53ea0ec5b2`）所选 E1495 HeightIntegration 与 E1537 UpdateAmount；只读复核既有原始导出，不新增原作连续运行结论。
- 确认状态：本机所选 CS、反汇编及有效 cbuffer 原字节可用，hash 与 [manifest](evidence/water_schedule_20261024_v2/manifest.json)一致。下述指令与字段为 C3；实际总量漂移及其大小未知。

**已观察的公式结构：** E1495 指令 58–89 按速度方向取供水侧深度，92–94 以各边通量差更新 amount。忽略后述修正、限幅、量化，并假定相邻格读取同一时刻数据时，公共边的转移量可以成对抵消，具有守恒搬运结构。因此，“上风搬运”或“没有使用 MUSCL”本身都不能作为不守恒的证据。

完整核还有以下边界：

1. 指令 53–57 计算本格深水修正 `C_i=max((hL+hR+hT+hB)/4−2dx/(dt×g),0)`，62／76／80／88 将同一个本格 `C_i` 从四个供水深度中减去。有效 `dx=0.05859375、dt=0.00732421875、g=16`，修正阈值为 1.0 个捕帧深度单位。它修正的是各边通量使用的深度，并非直接从最终 amount 扣除同一个水量。
2. 指令 95–96 对 amount 限制在有效 `[0,10]`，98–103 再按 24 位尺度量化；这些局部操作没有在该核内将截断／舍入差成对回分给相邻格。
3. 该核从同一 UAV 读取邻格并写回本格，不能默认等同于所有格同时读取固定旧状态的双缓冲离散系统。

**算法推断与待验证（C1，非原作漂移实测）：** 公共边两侧分别使用本格 `C_i` 和邻格 `C_j` 时，按所查公式得到的通量是 `v(h_donor−C_i)` 与 `v(h_donor−C_j)`；修正不同时不保证成对抵消。修正未触发或恰好相等时，这一差异消失；限幅也可能完全不触发。因此不能仅凭存在这些分支就断言本帧损失了多少水、持续漏水，或把全部不闭合归于某一项。

**源汇与误差分别判断：** E1537 指令 54–60 的蒸发、86–105 的海侧目标水位／customWave 回设、106–112 的格内源项会明确改变水量。开放域总水量随输入输出变化是预期行为；守恒应检验“总水量变化＝边界与源汇净交换＋数值残差”，不能要求造浪时总水量恒定。尚未取得原作完整源汇账本，不宣称其完全没有账本。

**结论边界：** 可以确认有通量搬运结构和影响严格守恒的局部操作；尚未确认完整原作链严格水量守恒，也没有量得长期漂移。波幅衰减还涉及能量／动量及数值耗散，即使水量守恒也可能出现，不能把波变平直接解释为水消失。

复验：按 manifest 的原始字节 hash 核对 [E1495 反汇编](evidence/water_schedule_20261024_v2/e1495.asm)和 [E1537 反汇编](evidence/water_schedule_20261024_v2/e1537.asm)；以 float32 解码 E1495 cb0[154].x、cb0[157].zw、cb0[114].y／cb0[115].y。实际守恒误差仍需固定边界／源项，取得带时间戳的连续完整水场并分别统计源汇、量化／限幅及内部搬运残差。本文旧的岸上水量代理及跨独立重放差分不能替代该验证。本节澄清 `MOTION-TRANSPORT-01` 与 `MOTION-PERF-STRUCTURE-02` 的守恒含义，不将未知动态结果升级。

## MOTION-COMPARE-WAVE-01：水波传播与当前求解器的比较

范围为test1 E1490、E1495、E1500、E1537的编译指令与有效常量，身份见[字段索引](wave_propagation_sources_20261020.json)和[完整水更新导出](evidence/water_schedule_20261024_v2/manifest.json)。原作单位和跨帧行为不能由该帧推定。

**本次直接复核的指令/字段事实（C3）：**

1. E1490 指令 87–114 使用 `floor+max(amount−0.05,0)` 的相邻差，乘空间倒数、重力与 dt 后加到已有边速度。`cb0[154].xy=0.05859375`，`cb0[157].zw=(0.00732421875,16)`；指令 115–121 对应主体阻尼、边缘衰减与邻速混合，`cb0[159].y=0、w=1000`。指令 122–139 包含湿干阻挡和限速，`cb0[158].x=2`。变量名称沿用历史包内映射，有效数值本次直接来自原字节。
2. E1495 指令 53–57 有深水修正，58–89 按边速度符号选择供水侧深度并计算通量，92–96 以通量差积分 amount 并限幅。所查质量通量不含当前项目 `−0.5×wavespeed×(hR−hL)` 这种 Rusanov 项。此结论只描述该核的指令差别，不等于原作完整离散系统无耗散。
3. E1500 的反向速度采样及双线性插值保留，`cb0[158].z=0.20000000298`。E1537 中本帧 `customWave=1.6163164377、level=1、waveAmplitude=0.0497018844`，源项 dt 为 0.025；海侧持续输入不能当作自由波寿命证据。
4. 分辨率字段 `cb0[155].xy` 按 uint 解码为 512×256；捕帧坐标域 30×15。与当前 32×32 m、256²、0.125 m/格相比，仅在坐标单位对齐的适配假设下，原网格线性间距约细 2.13 倍。原作米制尚未校准，不称“真实分辨率高 2.13 倍”。

**算法推断及边界：** 在均匀湿床、小振幅、零背景流且各限幅未触发的线性化下，`F=u_edge×h_upwind`的主要水量项为`H×u_edge`，不自动产生Rusanov的重力波速水深平滑项。但“原作弱波衰减更少”仍属C1；平流插值、量化、邻速混合、原位更新、边界和床形都会影响实际结果。当前项目已有二阶路径，不以一阶衰减量测代表默认实现。

**仍未知：** 原作同尺度自由波衰减曲线、波速与墙钟映射、重力/长度单位、连续编辑冲量与原作波观感的因果；没有证据确认其使用额外 Boussinesq、FFT 或物理涟漪层。新取数不关闭 `Q-WATER-RETURN-TIME-01/ORDER-01/INTEGRATE-01`，旧阶段误差和失败保留。

12 次 dispatch 均为 16×8×1 个工作组、每组 32×32×1 线程，覆盖 512×256 格。传播核心按速度更新→水量更新→速度平流连续执行三轮。四个既有运动核的原始 hash 与 `MOTION-COMPARE-WAVE-01` 一致；积分核的有效 `cb0[157].z=0.00732421875`，水量源项使用另一个 dt=0.025。此处的“三轮”仅指该捕帧区间，不能推断所有帧固定三步，也不能把积分 dt 与墙钟等同。

**项目对照（项目范围的观察事实，不作为原作性能证据）：**

当前正式求解器是 `h/hu/hv` 守恒状态、MUSCL 重构、SSP-RK2、湿干及供水限制、CFL 拒绝重试，水沙耦合随接受子步推进。CPU 每 tick 录制 64 个候选槽：MUSCL 自身 901 次 dispatch API 调用，另有耦合 640 次；前一数字不含边界、完成标记和显示尾部。无效槽的间接全域 dispatch 组数可为零，因此不能把 API 次数当作实际全域计算次数。原作所选区间和项目 tick 的时间与功能范围不同，禁止据 12 与 901 的比例宣传速度倍数。

优化前，场景2通过正式入口、5 秒预热与 20 秒只读异步采样取得 37 份完成决策：每 tick 平均接受 13.62 步、拒绝 7.57 步，共使用 21.19 个候选槽，剩余 42.81 个槽无实际步进。当时 `rk_decide` 的 mode 2/3 在判断槽是否有效之前扫描 1024 个速度块并做归约；连同一次 mode 7 校验，每 tick 共 129 次归约。上述样本对应平均 85.62 次无效槽归约，约占该类归约调用的 66.37%，**不是 GPU 总耗时或 FPS 提升比例**。基线证据及固定源码副本见[项目分析](../../task/competitor_water_optimization/20261024/分析.md)与[计数原始结果](../../task/competitor_water_optimization/20261024/attempts.json)。当前实现已按下面的 Godot 适配消除这项无效扫描。

**已实施的 Godot 优化与验证边界（不作为原作实现）：**

1. mode 2/3 在整个工作组一致确认 `tr[6]==0 || control[1]!=0` 时，于速度扫描和 barrier 前退出；保留 mode 7 初态校验、64 槽容量、审计、错误传播和有效步计算。
2. `rk_edge` 在线程内一次取得本格中心状态、重构条件和两个方向的坡度，生成四面状态；正向面由共享边通量和床源项复用。公式和输入阶段不变，所测状态与优化前逐字节一致。已保存实际 SPIR-V 编译产物；它不是最终 D3D12 原生指令，不能用字节码大小代替执行成本。
3. 标准水沙耦合的固定命令并入 MUSCL 的 GDScript 描述缓存，并缓存直接／间接调度标记；自定义与计时包装回调继续逐步调用。尚未引入原生录制器，dispatch 数量与同步边界保留。

实施源码、单项对照、异常路径和恢复验证、场景2成本与局限见[优化结果](../../task/water_execution_optimization/结果.md)。项目数值一致性结论限所测输入；原作毫秒成本和长期自由波规律的未知状态不变。

**反证、适用边界与未知：** 原作上风水量搬运／速度平流与项目的守恒二阶求解不等价；同 UAV 邻格读写、24 位打包以及原作三轮更新不能直接替换现有实现。原作网格有 131072 格，项目有 65536 格，不能将所选结构较短解释为原作网格更少；原作米制、自由波衰减、时序及毫秒成本仍未知。最初的只读采样仅统计工作量，优化效果以随后独立对照为依据；更早场景2性能测试与采样之间显示资源曾发生变化，不跨配置拼接性能结论。
