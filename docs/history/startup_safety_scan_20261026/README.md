## 独立的原生崩溃

首次图形扫描v1退出码3221225477，日志包含CrashHandlerException及nvwgf2umx.dll、d3d12core.dll堆栈；没有任何SCAN_BEGIN标记。已观察到的是扫描脚本开始打印资源标记前的原生崩溃，不能确定是驱动、Godot、缓存或其他初始化因素。随后无窗口构造及拆分的四轮正式启动通过，不能据此宣称原生问题修复。原因归为C0未知，保留原始日志，不算成某个具体场景脚本错误。

## 扫描器验证和边界

用前一次水花修复保存的真实before/after资源校验规则时，发现早期检测器把tres头部当属性块，漏读独立的resource段；已修复。最终反例校验中两个原故障资源都被R001识别，修复后两个资源均不匹配。早期“零静态风险”输出已被后续9候选结果取代，保留原始报告，不覆盖。

无窗口v2使用旧Python包装器，其report没有总pass字段；本次结论来自实际124条loaded/instances_valid结果、进程退出0及日志无错误，不冒称旧报告具有新版的来源漂移校验。图形live_v3包含四轮明确ready/advanced/error检查。扫描器最终版本新增原生崩溃、超时、来源漂移和静态待审风险判定；该包装器的新增记录逻辑不冒称已在早期运行执行。Godot测试脚本未因报告逻辑更新而改变。

本次没有证明所有历史场景入树运行、任意玩家交互、长稳、全部RID生命周期或所有黄色警告均无问题。批量构造不执行_ready，重复启动只提供受测路径的覆盖。不能用引擎退出0替代检查ERROR日志，也不能通过关闭警告让结果变绿。

原始结果见本目录v1/v2/live_v3子目录、规则反例和生成器回归JSON、summary.json；checked_sources_after_scan.zip保存检查后的源文件，不冒称旧包装器曾冻结运行前后全部来源。全部输出与可配置用户/缓存目录均在项目内。

## 最终当前版本复核

收尾文档来源检查发现两份正式表现场景及对应manifest与既有索引不一致，变更来源未确定，未回滚文件或强刷索引。随后重新进行125资源/50场景构造及四轮正式入口短运行，两个最终报告的runtime_pass均为true，受检来源前后无漂移。最终live报告同时保存实际消费的configuration.sources；资产JSON也加入最终版本的来源检查。此结论属于当前受测版本，不将文档索引漂移归给某个未经证实的主体。

静态报告仍保留9个R001待人工核对匹配，因此总pass为保守的false、review_required=true；这与runtime_pass=true不矛盾，不能改写成9个已发生故障。复核证据见vegetation_review.json。

检查时test_output缺少.gdignore，已补隔离标志；扫描器以后也自动创建输出隔离标志，避免测试场景副本进入编辑器索引。不能据此倒推先前的来源变化或原生崩溃一定由索引引起。
