# 场景切换与功能复用

两个正式入口共用[统一技术方案](当前项目技术方案.md)，场景身份由[unified_scene_routes.gd](../scripts/beach/unified_scene_routes.gd)准确路径定义。

| key | 正式场景 | 初态与边界差异 |
|---|---|---|
| main | [main.tscn](../scenes/main.tscn) | 项目沙滩初态、自动波包及手动波浪 |
| test1_geometry | [test1_geometry.tscn](../scenes/playable/test1_geometry.tscn) | 30×15可见范围、捕帧基础沙床与三条水槽及支流，低水位起步与20模拟秒上岸/回落 |

场景不是旧main运行类的继承变体。它们直接挂统一入口，分别实例化已固化表现；manifest和seed来自 `assets/unified_edit/presentation/<key>.json/.variant`。两场默认erosion/brush_water/foam/gravel/local_front开启、render_subdivision=2、自由相机开启；main默认水策略2，test1_geometry默认策略3；main初始512颗碎石、普通内聚高度0，geometry初始0颗、内聚高度2m。

两场默认水传播为`muscl_mc_ssprk2_v1`，入口`water_solver_id`空值使用该默认。启动前可显式选一阶，场景服务将当前有效算法带到目标构造；既有缓存检查点按目标算法通过来源校验恢复，不原地修改活动generation的算法。

## 共享UI与新场景接入

所有统一沙滩继承 [beach_ui.tscn](../scenes/components/beach_ui.tscn)。该基础场景只保存固定HUD，不携带沙床、相机或模拟状态。两份presentation场景继承它并添加世界节点，正式入口再绑定统一运行脚本与道具服务。修改公共场景的布局、按钮、图标绑定和固定信号即可同步全部派生沙滩；不在派生场景启用可编辑子节点来维护界面副本。

这是同一份UI定义在不同场景中的实例。切换时旧HUD随旧沙滩释放，新HUD绑定目标沙滩，不是跨场景常驻的HUD单例。共享工具选择及场景进度仍由BeachScenes服务保存；参数窗口仍由Parameters Autoload持有。HUD面板拖动位置属于各实例，不跨场景保存。没有FloatingProps服务和PlacementPreview的场景自动停用道具面板。

新正式沙滩应从公共UI基础场景创建继承场景，添加统一运行所需的世界、相机与UnifiedEditRuntime，提供自身presentation清单和seed，再在正式入口挂`unified_playable_entry.gd`。场景key及路径登记到`unified_scene_routes.gd`的KEYS、FORMAL和LABELS；有候选入口时同时登记CANDIDATE。场景选择列表按KEYS顺序读取LABELS，UI文件无需为新增场景修改。水沙规格、初始化清单和场景服务身份检查仍须分别满足，继承UI不替代后端接入。

公共UI沿用`Interface/ShapeBrushPanel`、`Interface/EditPanel`、`Interface/FloatingPropsPanel`以及根节点下`UIVisibility`、`UIDrag`路径。统一入口实现工具、道具、波浪、暂停与视角回调；派生入口不得重复连接这些固定信号。`tests/shared_ui/structure.py`检查正式/候选场景未重复定义UI，`tests/shared_ui/runtime_probe.gd`验证实际控件与场景切换。公共UI基础场景是继承资源，不单独作为可运行沙滩。

## geometry几何适配

可见X=-15..15、Z=-7.5..7.5，256²权威域中使用240×120格；完整ground数据双线性采样，高堆沙细节不声称逐点等价。原作坐标按(x,y,z)→(-x,y,z)映射，再由 `assets/test1_geometry/channels.json` 定义三条弯曲入海水槽与一条连通支流。槽底Y=0.62–0.82m，半宽0.32–0.62m，岸坡过渡宽0.55–0.72m；离线采用Catmull–Rom中心线、平滑岸坡和多槽最低床面合成。槽外保留捕帧床高，槽内只降低初始沙厚。水槽为项目造型适配，不是原作沟槽算法恢复。基底Y=0，初始水深max(0.95−床高,0)、动量0。项目将原场景数值作为米，是Godot适配，原作现实米制/可挖底界未知。

初态构建使用 `python -X utf8 tools/test1_geometry/build_channel_state.py`，随后执行Godot离线脚本 `tools/test1_geometry/bake_channel_seed.gd` 更新统一表现seed。基础高度、槽线配置与初态均保存在正式assets目录。新初态使用自己的水沙库存；运行中不补造槽线或另行注入沙源汇，旧来源签名检查点仍遵守严格恢复限制。

海侧默认低位0.95m、抬升0.45m、周期20模拟秒：0–1秒低位、1–4秒抬升、4–5秒高位、5–9秒回落、9–20秒低位；实际岸边响应有传播延迟。默认配置见[water_cycle.json](../assets/test1_geometry/water_cycle.json)。水参数窗口可覆盖基础水位（−2..2m）、抬升（0..0.6m）和周期（0.1..3600s），保存后重启生效。上岸/回落分段固定使用周期的5%、20%、25%、45%节点；角频率和相位不参与该模式。覆盖只改变启动边界，不重烘焙初始水深或平移自动退水阈值；实际配置参与冻结和检查点校验。Z外侧干燥障碍、X侧隐藏延续段连接现有边界；编辑限制在可见矩形内。

本场景启用海侧自动退水。可见湿区平均表面高于1.04m时启动，降到0.98m时停止；这是按当前沙床将岸线保持在地图中部附近的阈值，挖填或水槽中的局部积水可能改变岸线。每0.5模拟秒以16×8固定点估计湿区平均水面，忽略水深≤0.03m和障碍格。默认相机画面最右侧对应负X海边；触发后该侧边界及邻近带按最高0.12m/s持续降低，内侧平滑减弱，下限0.90m。退水期间压低海侧潮汐边界，避免高位潮汐持续补水。停止后恢复原潮汐输入；暂停也暂停检测和退水。

## 共享能力与切换

两场均预存同一VegetationLayer和九种植物的代理网格与多视角图集。main在近30×30m范围生成候选，test1_geometry限定到约30×15m可见区；实际数量由各自初态床水、坡度、障碍和分布参数决定。植被只读公共水沙完成态，暂停时仍可随挖填更新根部；切换或恢复按目标完整床水重新生成，不从会话检查点读取单丛姿态。详见[植被机制](植被.md)。

所有场景共用输入、工具声明、流水线、水沙模拟、材料、完成态表现、碰撞、预览、相机、暂停和原生检查点。水材质静态参数相同不代表画面相同：水深、动量、沙形、边界与机位均影响观感。生命周期与所有权见[当前技术规格](当前技术规格.md#发布碰撞与生命周期)。

服务按“结束笔画→保存完整状态→shutdown并确认旧域→加载目标→恢复目标进度”处理，阻止重复切换。保存失败保留当前场景；旧资源未确认释放则停止目标加载；目标初始化/恢复失败，用刚保存检查点沿原正式路径重建。工具/UI设置与每场域状态由服务和入口各自保存，不能跨域直接套检查点。

正式与测试候选按准确PackedScene路径分formal/candidate族，缓存使用family:scene_key。同族场景本次运行独立续进度，新进程从默认初态开始；不存在“关闭统一模式回退旧后端”的选项。

## 新增场景

先离线生成静态表现、初态及来源manifest，定义域、合法配置和边界；创建只挂统一入口/固定Runtime的wrapper，注册统一路由与场景内静态菜单。验证全部工具、可见域拾取、水/沙预算、暂停、保存恢复、切换失败、旧代读者与关闭。不能通过旧入口继承链再构造第二个求解器。

历史固定床面实验使用512×256网格，旧入口 `scenes/test1_water_motion_trial.tscn` 当前缺失，不能按旧说明直接运行；保留的驱动、公式核和适配数据不等于完整场景。它不属于两个正式入口，也不是当前可编辑系统的物理后端。竞品计算结构见[水求解实现方案](competitor/水求解实现方案.md)，原判定与geometry早期交付记录保留在[历史文档](history/README.md)。

## 漂浮道具的场景范围

两个正式入口均实例化固定FloatingProps组件及三槽道具面板，各自登记水瓶、木板、木棍各一件。切换前保持并终结公共读者，再释放水沙域；进入目标场景重置三件，不从会话检查点还原姿态。成功恢复换代会重建采样身份与零积分预算，失败恢复保留原代三件。详见[漂浮道具](漂浮道具.md)。

## 独立参数窗口

窗口归Parameters Autoload持有，跨场景保留布局。旧场景退出前解绑，目标场景绑定其实际配置；普通工具状态沿用会话共享，外观与待重启值按场景保留。需重建项保存后不参与本进程后续初始化，用户自行重启后加载。已有检查点仍按当前冻结配置严格恢复；详见[参数窗口](参数窗口.md)。

## 两场景湿沙

场景1与场景2默认启用[表面湿痕](沙面湿痕.md)，退水后保留湿色。两场景的新检查点为SANDUE07，保存并精确恢复历史；未登记的旧v6来源不自动迁移。
