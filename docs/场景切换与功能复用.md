# 场景切换与功能复用

2026-10-13。主入口仍是 `scenes/main.tscn`。右上角工具面板新增场景下拉框，选好后点击“切换”。菜单和信号保存于 `scenes/components/scene_switch_panel.tscn`，三个可编辑场景都继承 main 的完整节点、UI及功能链。

## 可切换入口

| 菜单 | 场景 | 运行区别 |
|---|---|---|
| 主沙滩 | `scenes/main.tscn` | 原初始化、自动波浪和当前权威水沙算法 |
| test1 沙床 · 可编辑 | `scenes/playable/test1_capture.tscn` | 捕帧沙床/水深/动量的项目域适配，保持较高海侧水位，可手动触发波浪 |
| 上滩回流 · 可编辑适配 | `scenes/playable/test1_backwash.tscn` | 同一份捕帧初态，加16模拟秒周期海侧水位，使用main的权威求解器 |

三个场景都有自由挖沙/填沙、每次体积设置、拖动笔刷、真实物理拾取、碰撞更新、自由/固定相机、手动波浪、暂停、调试、性能面板、原生保存与恢复。2026-10-13按用户要求取消背包沙量依赖，挖填范围0.01–1.00m³、默认0.10；实际增减记外部源汇并沿用GPU事务链，见[external_v1契约](knowledge/water_sand/ADR_自由挖填沙_external_v1.md)。

原 `scenes/test1_water_motion_trial.tscn` 是固定沙床、512×256逆向运动核的独立取证实验，保持原样。本次菜单中的“上滩回流”是**共用main交互和权威水沙的可编辑版**，不是把原实验核冒充已满足项目守恒/编辑/恢复契约的正式后端。两者公式、域、时钟和用途分别见[运动独立实验](水体运动_独立测试.md)与[竞品运动适配补充](competitor/水体运动与回落.md#可编辑场景切换补充2026-10-13)。

## 切换时的状态

- 挖填量、选定工具、手动波幅、HUD与性能采样开关在场景之间沿用。
- 每个场景的沙形、水场、沙源汇、tick、波浪队列及相机/暂停状态独立保留；切回时恢复自己的进度。
- 切换先停止新输入，等待已受理编辑和在途tick结算，调用已有完整GPU检查点保存，再等待 `shutdown()` 释放旧域，最后初始化目标并恢复其记录。generation递增，拒绝把其他场景的检查点套到当前域。
- 保存失败时保留原场景。目标初始化/恢复失败时，用刚保存的检查点重建原场景。切换期间阻挡重复请求、世界笔刷和相机输入。
- 会话文件以create-only方式保存到 `user://scene_sessions/<会话>/`。此次运行内的往返自动恢复；重新启动后从默认主沙滩开始，不自动读取以前会话。旧文件保留用于恢复调查，没有放宽检查点源码签名校验。

## 复用方式

主场景使用 `scripts/beach/beach_playable_entry.gd`，它继承原 `beach_recovery_entry.gd`。新入口通过 `_initialize_domain()` 提供初态，之后共用编辑、模拟、材质、碰撞和检查点代码。默认main调用原fixture初始化，未替换其水沙公式或数值策略。

`test1_playable_layout.gd` 将原512×256捕帧初态双线性采样到项目256×256/32m域；旋转180°，让海侧对齐既有x=0入口，床高减0.95作为项目海平面基准；水深取 `max(amount−0.05,0)`，先求各源格速度×水深再插值并转换方向。固定rock=-1m、可编辑sand为余下床高；域外padding延续捕帧边缘。初始湿度和压实度是项目适配值。新场景采用自适应CFL，避免把主场景原床形的固定子步假定套在捕帧高地与深水上。

这些坐标/单位、可编辑沙岩分解、湿度压实度、padding和16秒水位曲线均是Godot适配，未确认原作米制或时序。输入身份被纳入检查点源码签名，原RDC与导出水场不写回。

以后新增场景：在 `scenes/playable/` 新建继承main的 `.tscn`，提供合法初态/域ID，加入服务 `SCENES` 和菜单静态选项，并验证编辑/水量/碰撞/恢复。单独加载没有这一套后端的视觉实验不会自动获得完整交互。

## 水材质一致性与观感差异（2026-10-13）

本次直接启动三个可编辑场景，冻结于初始完成态，在同一1280×720、D3D12 Forward+、GTX1050窗口核对运行时有效输入。水、沙、细沫、岸脚的Shader hash、全部固定uniform及静态贴图身份一致；GPU状态/反射贴图的类型与尺寸一致，但内容随各自场景变化。`prototype_planar_view_projection`由当前相机计算，属于视角输入，不能当作固定材质参数要求三场景数值相同。太阳变换亦一致。材质统一不等于已经对齐最终观感。

| 初始湿格统计（h>0.001，项目适配单位） | 主沙滩 | test1沙床 / 回流 |
|---|---:|---:|
| 平均水深 | 0.2292 | 1.0386 |
| 90%分位水深 | 0.4155 | 1.9539 |
| 最大水深 | 0.5687 | 2.5610 |
| 平均流速 | 0 | 1.1502 |
| 相邻湿格水面梯度平均幅值 | 约0 | 0.1188 |
| 默认相机位置 | (-6,6,10) | (-10,10,-18) |

这些统计来自实际GPU水、岩、沙和动量读回，不是shader默认值。test1尺度映射沿用当前适配，不证明竞品米制；平均水深约为main的4.53倍。同一套RGB吸收公式会随光程加深而变暗；细法线由速度/相位驱动，宏观法线由水面高度场决定；不同机位还改变反射、窄高光和相机到底面的光程。因此test1海区偏暗、波纹和反光不同有明确输入原因，不能归因为偷换水材质。

单变量对照保存了每场景默认画面、同一main机位；test1另保存仅关闭细法线、仅关闭吸收的诊断画面。仅换机位改变反光位置，深水仍暗；仅关闭吸收后深海沙底显露，暗色明显消退。诊断不改权威场、不推进tick，5个原字段前后逐位相同。test1沙床和回流场初始5字段与隐藏UI后的默认PNG均逐位一致；开始模拟后的16秒海侧曲线不同，不能用不同进度断言材质不同。

有效参数、原字段、画面和30项检查见[本次结果](../test_output/water_material_consistency_20261013_v2/result.json)，源快照与hash见[证据索引](../test_output/water_material_consistency_delivery_20261013/manifest.json)。复验入口为`tests/integration/water_material_consistency_probe.gd`。v1将相机反射矩阵误归为固定参数而报告2项不一致，原失败保留；v2按运行时视角输入区分后通过。本次未修改正式材质、权威水沙或相机配置，也未将深水光学尺度校准、捕帧边缘padding或观感对齐改判完成。
