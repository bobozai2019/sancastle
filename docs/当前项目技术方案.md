# Sandcastle 当前项目技术方案

适用当前统一正式入口。本文描述正式两个场景当前实现；固定数值、容量及兼容性见[当前技术规格](当前技术规格.md)，操作见[主场景操作](主场景操作.md)。

## 技术栈与入口

项目使用 Godot 4.7.2、GDScript、RenderingDevice compute shader 和 Godot材质shader。项目默认启动 [main.tscn](../scenes/main.tscn)，Windows驱动为D3D12，默认视口1280×720。Forward+、实际窗口、设备与VSync属于验证条件，不能从headless启动推导GPU或视觉通过。

main、test1_geometry均直接绑定 [unified_playable_entry.gd](../scripts/beach/unified_playable_entry.gd)，根脚本继承Node3D。场景内固定 [UnifiedEditRuntime](../scenes/unified_edit_runtime.tscn) 与SurfaceA/SurfaceB消费者槽，静态UI、相机、材质、网格和连接保存为资源。启动读取表现manifest和初态，不再沿旧recovery/gravel/async入口继承链构造后端。

Windows导出通过 [runtime_source_export](../addons/runtime_source_export/source_export.gd) 在正常资源导出之外保留运行时读取的原始文件：`project.godot`，以及assets、scripts、shaders、scenes和亮纹原型资源目录下的场景、资源、脚本、shader/include、JSON、初态`.variant`与二进制数据。`editor/export/convert_text_resources_to_binary=false`使场景和文本资源按原样加载，避免旧转换缓存遗漏自定义Resource新增的导出字段；脚本仍按导出预设编译，纹理仍由正常导入链加载。FileAccess使用原始字节校验表现manifest、冻结配置身份并编译compute。仅设置include_filter不能保证导入资源或编译脚本的原始路径可读。缺失或hash不符会中止沙水初始化，水面与编辑工具随之不可用。`python tools/validate_export.py --output <新输出目录>`用匹配版本的编辑器运行实际PCK；工作目录隔离到项目外，避免本地源码补齐包内缺失文件。

## 操作与参数界面

场景内保留工具选择、世界操作、触发波浪、暂停与切场景。Parameters Autoload 持有六个静态原生参数窗口和进程帧采样，场景操作读取入口共享参数，窗口经统一服务修改。工具项下一笔生效，材质／环境项实时生效，冻结模拟及道具项保存到启动配置后由用户手动重启；窗口不发起自动重建。启动配置、参数范围、实际消费者与窗口生命周期见[独立参数窗口](参数窗口.md)。

## 统一编辑事务

产品默认catalog声明十一物理profile：挖/填/悬沙的圆盘及扫掠版、城堡、沙墙、铲子、平滑和压实。碎石是独立标签的显示输入，也使用同一队列和生命周期。profile只选择现有操作、形状、材料/水策略和合法参数；新增玩法流程见[扩展指南](unified-edit-extension-guide.md)。

公共Executor先读取当前权威态生成候选，归约实际变化和预算，再生成材料与水候选，统一检查身份、有限值、非负值、字段权限、守恒及授权。沙/材料在公共mode7提交，水响应在同一决定下经mode4提交；结果由实际GPU变化决定。原语不能直接写权威场、独立提交、发布或等待CPU。拒绝不留下半条沟、半笔材料或水响应，也不依靠整场备份再CPU回滚。

普通挖沙在每轮分配中使用相同的供沙集合计算权重和实际扣沙：仅覆盖权重大于0且剩余单格沙体积大于1e-6m³的格子参与。低于或等于阈值的薄层保留，不参与该轮扣沙；沙量不足时按实际可挖量完成。提交前同时核对实际减量、分配累计量、原始请求量和授权上限，误差使用既有ULP预算，不能用分配阈值放宽回执授权。

城堡按固定世界标高补至模板表面，高于模板的原沙保留；沙墙与铲子以公共笔画baseline和累计coverage约束目标高度。产品铲子使用CAPPED_SHOULDERS：中央挖量只受沙量、目标深度和命令授权约束，每侧独立接收不超过实际挖量的一半，达到笔画基准以上0.5m后停止加沙，放不下的部分按实际量记入sand_sink_m3。本笔挖过的格子可以再次接沙，回填后可再铲至已记录的沟底；没有实际挖量时不新增供沙覆盖标记。普通自由挖填及悬沙使用已知录制请求的名义源汇，目标高度和铲子未接收余量使用实际量结算，不能把两种账本精度混称精确守恒。

主场景默认策略2（动量 B），通过公共 [water_response.gd](../scripts/simulation/unified_edit/water_response.gd) / [water_response.glsl](../scripts/simulation/unified_edit/water_response.glsl) 执行。按本次实际接受的床面差施加动量，填沙外推、挖沙内拉；编辑阶段保持水深和悬沙，后续搬运由常规浅水tick完成。默认力度0.25，独立工具参数窗口可调[-1,1]；选择策略3使用原位移/局部速度公式。公共策略2语义对所有调用者一致，test1_geometry入口仍默认策略3。公式、作用条件及参数见[编辑水响应规格](当前技术规格.md#编辑水响应与主场景开关)。

策略3的湿区排水使用[拓扑阶段](../scripts/simulation/unified_edit/water_packed_topology.glsl)建立原有连通分量和行序索引，再由[分阶段计算](../scripts/simulation/unified_edit/water_packed_parallel.glsl)完成容量、位移、残差与审计。逐格阶段分配到1024个64线程工作组；补偿归约保持各账目原来的逐格顺序，多账目并行计算，分量互相独立。11个计算阶段在初始化时特化，阶段间仅有GPU依赖，不新增CPU读回。拓扑超限、非法输入和审计失败继续交给原通用核复核，权威写入仍只有原公共条件提交。

接纳、GPU完成和物理收敛是独立边界。每批按队首工作类型及tick合并连续可录制编辑，最多64条；所有编辑、水tick和显示工作沿同一RD有序流录制；后继不等待CPU回执或碰撞。新样本遇背压明确拒收，END保留重试；已接纳命令继续排空。fatal/unknown属于所有权故障，不伪装成普通REJECTED，不重放未知命令。

工作槽在真实回读完成、CPU消费回执及Transport确认回收后复用。Pipeline记录其创建线程作为槽位所有者；渲染回收与槽位所有者同线程时立即确认，现有pump可在消费回执后继续使用空槽，不增加调度循环。跨线程回收仍通过deferred通知所有者，不能从渲染线程直接修改CPU槽位，也不保证同帧复用。

## 水、悬沙与材料模拟

水在二维高度场上使用浅水数值核，状态为水深与水平动量。GPU CFL选择子步，保留共享边通量、出流缩放、状态更新及边界注入；实际推进时间由完成态累计actual_dt决定。水沙耦合包含悬沙输运、侵蚀/沉积、沙坡与材料更新，使用当前配置的数值核及容量侵蚀规则。

一阶水步和耦合阶段在初始化时缓存固定的pipeline、uniform绑定及push常量，按双槽索引直接录制，避免每个子步重复查询字典和构造参数数组。缓存只由数值模块创建，不能由工具profile配置执行顺序；它借用当前所有者的RID并随所有者释放。64轮间接派发、GPU CFL决定的有效轮数、各阶段顺序和计算列表边界保持，CPU不读取CFL结果来决定当轮工作。

数值路径由 `water_numerics.gd` 校验并在启动前冻结。默认 `muscl_mc_ssprk2_v1`；入口 `water_solver_id` 可显式选择 `rusanov_first_order_v1` 一阶路径。二阶录制器由Water持有，默认使用MC限幅，可在独立水窗口设置0–1保波程度，保存重启后混合Superbee坡度，再配合SSPRK2和GPU试步接受/拒绝，不创建第二条提交队列。MUSCL依据两方向传播速度和以0.2计算CFL，第二阶段超限则缩小试步；它的64个尝试槽与一阶路径的一次CFL决策不同。独立窗口中的保波调整标为需重建／重启，不调用热重建。原有程序API仍可沿检查点/候选替换路径保留原始沙水和实际时间，浮物按恢复语义重置；该受限API不等于任意参数热改能力。活动generation不原地切换求解器，算法身份参与配置和恢复校验。详细结构见[技术全景](Sandcastle项目技术全景.docx)。

MUSCL在私有U1/U2中保存试算，重构水深、水位与速度，使用共享边静水重构和成对床面压力修正。SSPRK2两阶段各自按当阶段的水通量、供体浓度和出流限制输运悬沙；不能用最终净水通量代替两个阶段的搬沙。拒绝的试步不提交权威场、不推进耦合或时钟。接受后写入公共双槽，侵蚀/沉积交换、支撑、坡面和材料链只按接受dt执行一次，再归一到槽0。边界与表现尾链仍由Water统一录制，公开完成态不包含RK中间态。

录制器将标准耦合阶段并入实例内的类型化命令缓存，参数、边界选择或耦合回调变化时重建；自定义／计时包装回调保留逐步调用。GPU 对无效候选步提前跳过速度归约，空间算子在单线程内复用本格重构结果，供正向共享边和床源项共同使用。64 次试算容量、每阶段执行顺序、计算列表同步边界及权威状态格式保持一致；这些优化不改变求解器的物理参数和离散公式。

海侧潮汐/波包属于统一水步中的边界输入。主场景与geometry使用不同初态/边界；geometry采用20模拟秒低位→抬升→回落周期，是Godot适配。geometry同时以0.5模拟秒间隔抽样湿区水面，超过1.04m后在默认视角最右侧海边持续退水，降至0.98m停止。退水沿负X边缘的窄带渐变扣水并同比缩放动量，实际水汇计入原账本，沙床与悬沙不直接移除；检测和排水复用同一个边界阶段，不新增CPU回读或独立调度。暂停不推进模拟或表现时钟，但可录制编辑和碎石投放。细节参数随场景manifest、boundary配置和材料资源冻结，不从历史测试脚本默认值推断。

## 几何与表现

权威床面由rock+sand构成，水面使用床面及水深。表现通过同generation、完整state_seq及实际完成时钟绑定沙、水、悬沙、白沫、亮纹与接触，不能混读正在写的双槽。显示细分与着色重建不提高256²权威模拟或物理高度分辨率。

- 沙体：固定网格读取完成床面，结合湿度、压实度、法线及受光；geometry额外显示沙体侧面。薄沙与裸岩混色对沙厚度使用线性采样，使颜色连续过渡；床面高度仍用精确texel读取与原三角重建，着色采样不改变模拟、碰撞或沙量。
- 水：当前静态表现资源使用RGB吸收透底、流向细法线、角度反射权重、窄太阳高光和带完整mip的三维纹理亮纹。该亮纹是纹理采样动画，不能称实时光线焦散。
水面泡沫由 `foam_state.r` 的历史强度控制存在范围，再由静态绑定的 `assets/water_foam/foam_detail.png` 打开孔洞与破边。该自建周期细胞纹样采用线性数据采样，512×512 RGBA8，包含9级附加mip，导入后完整图像为1,398,100字节。两个正式场景使用 `foam_detail_mode=1`，岸脚覆盖增益为0.55；独立点状细沫仍隐藏。

细节流动从同代完成态动量取 `q/max(h,0.02)`，先将速度限长至2 m/s，再乘流动增益。完成态时钟驱动相差半周期的两个局部位移，默认周期4 s，三角权重交叉混合，避免纹样无限漂移。两个 `textureGrad` 采样使用未位移世界纹理坐标的导数选择mip。默认密度1/m、破碎程度1、流动增益1；零流速保持图案，暂停保持时钟。历史减弱时阈值由0.22升至0.96并逐渐开孔，历史为零或床面干燥时无泡沫；最终覆盖统一用于颜色、透明度、泡沫直射和水面高光抑制。该路径只读取发布场，不改变泡沫生成消散、权威水沙、动量或检查点格式。

- 浪与白沫：边界驱动水场，水面内白沫和岸脚表现读取完成态及其历史。两个正式入口的独立细沫节点`PrototypeFrontFoamDense`均隐藏，不提交该层绘制；泡沫历史场仍供水面和岸脚使用。不能从单帧外观确认原作时序。
- 水侧壁：固定[WaterSides组件](../scenes/components/water_boundary_sides.tscn)共享水面材质输入与时钟，上沿对应水边界，下沿贴可见沙床；随挖填、涨退水和换代更新。
- 碎石：GPU表现颗粒随水输运、搁浅并贴床；不增加权威沙量，不阻水，也没有逐颗刚体碰撞。
- 植被：两个正式入口预存海草、海带、岸边矮草和沙丘丛草，按初始水深、床面和分布场筛选；GPU只读水沙驱动根部下移和临界阻尼摆动。草叶为不透明批量网格，写入场景深度参与水下遮挡，填沙可遮埋；暂停冻结，恢复按完整床水重新分布。配置、发布与持久化边界见[水草与岸草](植被.md)。

实际运行表现为 `scenes/unified_edit/presentation/` 与 `assets/unified_edit/presentation/`，通过[presentation.gd](../scripts/simulation/unified_edit/presentation.gd)绑定manifest、材质和初态。原candidate目录、公共shader与纹理仍可能是直接运行依赖，名称含candidate不构成删除依据。原RDC事实、Godot适配和未知项见[竞品入口](competitor/README.md)。

## 碰撞、恢复与关闭

高度worker完成后，物理消费者按块分帧应用：每个Height所有者在一个渲染帧内最多尝试8块，并在累计原生形状调用达到1.5ms后停止继续应用；单次调用不可中断，因此这不是整帧耗时的硬上限。同一渲染帧内的多次物理通知共用预算，两个高度槽轮流获得后续帧的消费机会。部分应用保留快照游标和真实读者租约，全部消费后才确认GPU脏块；关闭可丢弃剩余CPU形状工作，旧版本不能覆盖较新块。候选仍须完整备齐64块后换代，漂浮道具仍依照实际已应用版本和既有接触误差条件等待。

沙床物理代理分64块。高度回读与worker生成不阻塞工作槽；物理线程应用已完成任务，拾取可使用上一份完整碰撞面。未变化块允许保留较早版本，停止输入后消费者收敛。

保存先结束笔画并取得完整完成态，保留原始双槽、材料/历史、控制状态、账本、配置与身份。恢复不重放工具：先验证SANDUE06/SANDUE07或允许的旧数据，在同一种Pipeline候选中准备完整64块同代碰撞，物理提交阶段统一替换材质、碰撞与当前域。highwater沿用，command_id不能从1重用。

退休代保持在途回执与读者租约；只有获得真实终结/解绑证明后释放。当前和退休的高度、检查点、预览等读者都按维护节奏重试。未知证明不授权force-free或伪造成功。场景切换使用相同生命周期；各场景本次运行进度独立缓存，目标失败按原正式入口恢复。

## 确定性与性能限制

检查点恢复原始字段与恢复后继续演算的逐位确定性是不同保证。已有固定检查点对照中，同机同后端使用精确旧水面与水侧shader原件，继续填沙、挖沙后仍出现约1e-7量级的水沙及动量字段差异，具体根因未知；这不证明新表现对演算无影响，也不能据此放宽逐点比较。恢复继续遵守既有原始字节、配置、账本和时钟校验；体积账本容差不适用于逐格字段，当前不承诺恢复后任意演算序列逐位一致。

新泡沫路径沿用既有水面绘制与历史场，增加两次细节纹理采样，没有新增水面表现节点、历史RT或compute阶段；这些结构信息不能换算为固定帧率或零额外成本。现有D3D12、GTX1050完整负载对照的旧路径自身时序仍不稳定，部分整帧尾部和模拟吞吐超出原成本边界，尚不能确认新路径完整负载性能达标。视口GPU区间不包含全部异步compute；需分别观察整帧分位数、实际完成模拟时间/墙钟时间及覆盖明确的GPU区间，暂停画面的GPU改善不能替代实时负载结论。

## 工程维护与验证

数值/ABI或writer变更先更新相关契约，再做编译、短运行、负例和受影响功能回归；表现变更先固定初态/seed/tick/机位/profile做单变量对照。配置稳定后才集中做代表性成本和长稳，文档修改无需重跑GPU长稳。

架构检查从正式根、服务和catalog建立保守引用闭包，检查敏感方法、writer、资源身份和九类违规样例。它有明确调试器/旧codec数据验证边界，不是任意GDScript程序的完整调用图证明；不能自动重生成seal来批准代码改动。

维护命令与ABI见[技术规格](当前技术规格.md)。交互式执行指南由本地生成器读取当前源码生成。

## main漂浮道具消费者

main固定组件包含水瓶、木板、木棍和通用FloatingPropsService。它通过公共只读Probe读取完成态，按实际水时钟余额准入原生Jolt世界步；不拥有GPU执行器，不回写水沙。使用现有HeightMap和类型化Profile，暂停/保存局部保持，成功恢复或重进重置；test1_geometry不投放。结构、受力、版本和扩展见[漂浮道具](漂浮道具.md)。

静态FloatingPropsPanel包含三道具槽和落点光圈。选择槽位后左键投放或移动，拾取模式把既有实例收入槽位；世界中有效物体为0–3件。UI与沙刷通过互斥模式分发输入，Terrain/Prop射线分层，右键取消不捕获相机。服务在局部物理边界等待旧探针真实终结、换owner并重新采样目标位置，其他物体保留运动状态；生产水沙队列继续推进。全拾取时停止空采样，恢复/重进仍按预存三件布局初始化。

## 两场景表面湿痕

`main` 与 `test1_geometry` 默认使用单张256² R32F外观历史，湿痕更新合并到成功沙水发布。关闭湿痕的配置保留既有物理湿度着色。启用配置保存SANDUE07/version7扩展，未启用配置保持SANDUE06/version6，native3权威数据不变。公式、表面编辑、时间、恢复格式及旧档限制见[沙面湿痕](沙面湿痕.md)。
