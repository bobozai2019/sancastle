# 竞品与当前主场景：GPU读回、CPU碰撞计算和发布对照

更新：2026-10-12。范围：当前`scenes/main.tscn`实际源码接线，与既有竞品取证对照；本次未启动游戏、重放RDC或测量耗时。原作结论复用已归档证据，不新增竞品方法分析；不改变模拟或碰撞契约。

**两者的大框架相同：GPU更新水沙状态，GPU生成可读采样，CPU接收数据并发布地形碰撞输入，物理引擎在CPU侧处理查询/刚体。**当前项目的不同点主要在采样范围、CPU加工方式、形状类型、版本控制和编辑事务等待。原作道具浮力/接触细节、读回调度与实际成本仍未知。

- 当前源码为本次直接读取事实；源码大小/hash/选择器见[本次对照索引](collision_comparison_sources_20261012.json)。此评级不代表新增运行验证或性能PASS。
- `main.tscn`把GpuCollisionProxy脚本覆盖为`scripts/simulation/edit_validation/collision_proxy.gd`，它继承通用GPU碰撞代理；入口为`beach_recovery_entry → beach_interaction_entry → beach_gpu_entry`。比较以这条实际接线为准，不能用旧技术方案正文里的CPU笔刷流程代替当前GPU编辑事务。

## COLLISION-COMPARE-02：各环节的具体差别

| 环节 | 竞品已确认范围 | 当前主场景源码 |
|---|---|---|
| GPU输入 | 压缩groundCells/waterCells，经Readback.Update采样解码 | 碰撞专用compute直接读rock/sand纹理 |
| 读回内容 | ReadbackCell stride32：水速、沙切线、水量、沙量、床高及crestSpawn | 每碰撞采样点只输出一个R32F床高=`rock+sand` |
| 读回范围 | test1有256×128、1MiB采样输出；独立run02 CPU缓存为256×256、2MiB。它们是不同观测，不混为同一帧 | 域256×256，分8×8块；每块覆盖32×32单元、33×33高度样本，最多16块一批 |
| 字节规模 | 以上是全采样缓冲，兼供其他CPU消费者；更新频率未知 | 单块4356字节，16块69696字节，约68.1KiB；初始化/完整重建可分批覆盖64块。此处只计算碰撞高度payload，不含回执/审计/检查点等其他读回 |
| CPU几何计算 | IJobParallelFor每顶点读取四个readbackIndices，取sandAmount平均写y；随后JobHandle.Complete | GPU已打包最终床高；主线程解码float数组、校验有限值、分块拷贝和设置map_data；这条碰撞代理没有独立CPU顶点Job |
| 碰撞表示 | 分块MeshCollider，更新顶点后sharedMesh先null再meshC；样本有共享输入mesh对象 | Godot/Jolt，StaticBody3D上的分块HeightMapShape3D；默认每次分配新高度图shape，CollisionShape节点复用 |
| 哪些块更新 | 已确认Ground.UpdateColliders方法遍历planeChunks全数组；不能推广为每帧/每笔都遍历 | 编辑按GPU回执dirty_mask选块，默认加3×3邻块；常规侵蚀按累计变化上界达到0.001m选块，并补共享边界邻块 |
| 读回形式 | 异步Request/回调Copy存在；同步ComputeBuffer.GetData另有入口，实际使用频率未知 | 碰撞通道使用texture_get_data_async，渲染线程回调call_deferred到主线程应用 |
| 版本保护 | 已取对象/缓存发布窗口；未确认原作全局generation/revision机制 | 显式generation、请求revision、实际绑定revision、每块applied_revision；过滤旧generation和更旧发布 |
| 编辑后等待 | 实际等待策略/频率尚未恢复；不能说不等碰撞 | 成功GPU编辑：等128字节回执和CPU结算→授权视觉发布→等受影响块碰撞revision→等两次physics_frame信号→释放gpu_busy |
| 输入命中 | CPU Physics.Raycast；命中PlaneChunk后用Readback补充法线/单元信息，某些未命中有平面回退 | CPU intersect_ray；主入口只接收代理body且对应块revision满足collision_needed的命中，未就绪则拒绝该输入 |

当前默认`release_config.gd`没有`--beach-bounded-collision`，所以更精确的bounded dirty_rect选块属于可用实现，不能说当前默认已启用。`beach_gpu_entry._ready`显式`reuse_chunk_shapes=false`，不能据通用代理支持复用就宣称当前主场景复用HeightMapShape资源。侵蚀读回摘要已经在途时，tick不等待该摘要完成；它与用户编辑事务等待碰撞是不同路径。

来源定位：

- [GPU碰撞打包](../../shaders/simulation/shallow_collision_pack.glsl)：按chunkId生成33×33采样，边界clamp，`rock+sand`写packed_heights。
- [通用碰撞代理](../../scripts/collision/gpu_collision_proxy.gd)：`_dispatch_pending_render`、`_on_data_render`、`_apply_data`、`_replace_chunk_shape`；下一批不在异步回调内部递归提交，使用延后调度。
- [主入口碰撞代理](../../scripts/simulation/edit_validation/collision_proxy.gd)：编辑receipt/publication pending时延后打包，绑定时记录solver实际state_revision。
- [GPU编辑主入口](../../scripts/beach/beach_gpu_entry.gd)：`execute_admitted_gpu_command`、`_gpu_chunks`、`_render_gpu_publish`。
- [交互主入口](../../scripts/beach/beach_interaction_entry.gd)：`pick`、`_pick_current`，以及输入调度与事务衔接。
- [常规侵蚀发布](../../tests/visual_water_alignment/prototypes/reference_preview.gd)：`_record_dirty_max`、`_erosion_collision_chunks`、`_render_request_erosion_chunks`；0.001m是累计上界触发条件，不是本次实测几何误差。

反证与边界：竞品碰撞样本与当前项目域、单位、网格分辨率和滤波不同。原作四样本平均与本项目单点床高读取不是同一重建，不能只凭顶点数或读回字节数评价更精细、更准确或更快。当前generation/revision保护说明源码有该规则，不代表原作不存在类似保护。

## COLLISION-COMPARE-03：此处的“写回”有两种方向

1. **GPU→CPU读回→发布物理形状**：两边都有直接支持。当前GPU写的是碰撞staging高度纹理，CPU设置的是Jolt使用的HeightMapShape；竞品CPU设置的是MeshCollider输入mesh。这条链在当前代理中是单向的地形发布。
2. **CPU碰撞冲量→GPU水沙状态**：不是上述读回/发布链自动完成的事情。当前碰撞代理只把chunkId上传GPU、读床高并发布形状，没有将刚体接触冲量写到水动量或沙状态的逻辑。原作是否有其他物体排水/阻水/接触反馈路径，本次已有证据不足，保持未知。

当前鼠标命中位置可作为后续GPU笔刷命令输入，这属于用户编辑命令，不等于物理接触冲量双向耦合。原作Gravel.Update直接GPU搬运是独立链，也不能当作GPU对木棍/船执行刚体接触求解的证据。

## COLLISION-COMPARE-04：对道具和性能的含义

- 当前已经具备“动态沙地碰撞输入”，但主场景尚未接入竞品那类木棍/瓶子/船多点浮力，以及Gravel的GPU碎粒输运。建立道具运动时可复用现有地形碰撞；还需要采样水/床面/流速的物体探针和CPU受力组件。
- 竞品ReadbackCell保留多类字段，当前碰撞包只有床高，因此不能直接拿当前碰撞读回包计算水流推力。项目其他GPU字段存在，不代表物体采样与受力已经接线。
- 当前碰撞高度传输范围更集中，且免去这条链上的四样本CPU顶点平均；CPU仍执行解码/校验/拷贝/形状发布，物理引擎内部更新成本没有消失。
- 当前GPU编辑事务的串行等待是可确认区别：回执、发布、碰撞版本和两个物理帧信号均在事务释放之前。`await`让出主线程，不等于一直阻塞CPU线程；但`gpu_busy`期间正常tick/后续编辑不会按普通路径继续推进。这会影响事务延迟，具体占比须实测。
- 没有竞品同负载、同尺寸、带时间戳的成本证据，不能据此宣称它更快，或把其碰撞发布调度当作零延迟。此次不重判任何旧成本/长稳Gate。

复验：重新读取索引列出的当前源码并核对hash，沿main场景/脚本继承与默认release配置追踪上述函数。竞品复验使用原取证报告对应source hash、raw selector与校验工具。时延比较须分别测GPU打包、读回等待、CPU形状发布和事务等待两物理帧；不可将GPU pass耗时、回调延迟和端到端等待直接相加为同一性能指标。
