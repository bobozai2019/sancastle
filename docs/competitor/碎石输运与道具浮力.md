# 竞品碎石与道具

原包把GPU碎粒与刚体道具分开：Gravel按局部沙水状态更新位置；木棍、瓶子和船等持有Rigidbody、Collider及Buoyancy。名为Pebble的独立刚体资源不能仅凭外观归入Gravel。

## GPU碎粒

所记录test1 E1566与包内Gravel.Update精确匹配。局部规则为双线性读取沙水；水量超过0.05时开启水流位移，另叠加沙运动和坡度／切线贡献；Y贴采样床面。床高在本步旧位置取样，不能擅自改成移动后重采样并仍称原算法。

退水可以关闭水流贡献；平缓且静止的沙床上其他贡献也可为零。重新覆盖且存在流速时，同一粒子可以继续移动。它不证明跨浪周期的实测寿命、真实滚动、颗粒互相堆叠或完整刚体接触。

完整初始化、删除、seed变化与实际绘制资源映射仍未闭合。相关编译程序可由[全帧程序索引](evidence/shader_execution_20261025/selected_v1/manifest.json)定位；当前资料不包含全部粒子运行轨迹。

## 刚体道具配置

[包内配置清单](floating_props_sources_20261018.json)记录29个带Buoyancy的不同根资源、合计49个采样点；该计数包含不同资源变体，不等于菜单种类数。清单包含质量、阻尼、重心及Box／Sphere／Capsule／MeshCollider配置。

这些字段证明配置结构，不证明每种对象都稳定漂浮。完整浮力、水阻、排水体积、埋沙固定／释放公式及连续受力轨迹未知；字段名不能替代方法证据，包内质量也未校准成真实千克。

沙地支撑与道具受力是不同链路：动态沙地使用CPU读回与分块MeshCollider输入，见[碰撞与读回](运行时碰撞网格取证.md)。没有证据据此承诺零延迟、逐帧发布或双向流固耦合。
