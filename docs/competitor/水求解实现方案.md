# 竞品水求解实现方案

对象为Sandcastle所选沙滩水场。test1捕帧225224034 B，SHA256 `761aa980c2426f75a1fa7364bf6d2655ff4dd20ea76566e630ee5b53ea0ec5b2`。字段、原指令、有效绑定和常量为C3；可读机制解释为C2，未观察的动态行为保持未知。[来源索引](water_solver_sources_20261027.json)。

## 状态与编码

水场512×256，每格16 B的uint4，共2 MiB；沙场1024×512、8 MiB。以下word编号从0开始，`Q=2^24-1`。

| 位段 | 字段 | 解码 |
|---|---|---|
| word0 bits0–7／8–15 | 宏观法线X／Z | `2*code/255-1` |
| word0 bits16–31＋word1 bits0–7 | X边速度 | `8*code/Q-4` |
| word1 bits8–31 | Z边速度 | 同上 |
| word2 bits0–23 | 内部水量A_raw | `10.1*code/Q` |
| word2 bits24–31＋word3 bits0–15 | 水所见床高b | `10.1*code/Q` |
| word3 bits16–23 | 上升／陡面响应B | 所选水量核写0或255 |
| word3 bits24–27 | 格内源项编码 | 源汇核按阈值及比例消费 |
| word3 bits28–31 | 海侧回设权重 | `alpha=code/15` |

```text
h = max(A_raw - 0.05, 0)
eta = b + h
```

0.05是内部偏置，未校准为现实5 cm。部分审计将`A_raw-0.05`称为A，引用总量时必须区分定义；编码和或解码和也不自动等于物理体积。实际float32尺度以原指令十六进制常量为准。

## 阶段与资源

匹配test1的这段顺序为：床面 → 三轮“速度、水量、平流” → 源汇 → 法线。事件分别为1484，1490／1495／1500及后两轮，1537，1543。每次16×8×1组、32×32×1线程。其他已观察条件存在不同轮数，不能固定为全游戏三轮。

原核在同一水UAV上读邻格并写本格，阶段之间有UAV屏障。核间同步不保证所有线程先读旧态；原位线程顺序不能视为确定的双缓冲离散系统。[阶段、绑定及同步](水求解参考与同步.md)。

## 六类计算核

### 床面

E1484将水格中心映射到沙场，四点插值两种解码高度后取较大值，重编码水所见床高。原沙场SRV与完整字段重打包均须保留。非主更新字段也可能因float32重新量化而变化。

### 速度积分

边速度由自由表面高差驱动。以X方向为例，省略保护项的主式为：

```text
v_star = vx - dt*g*(eta_right-eta_center)/dx
v_mix = (sum_neighbor_velocities + kappa*v_star)/(4+kappa)
```

完整核还包括主体阻尼、四边窗口衰减、湿干阻挡和向量限速。test1有效`dt=0.00732421875、g=16、dx=0.05859375、maxVelocity=2、damping=0、kappa=1000`；湿干保护深度阈值为`dx*0.0001`。零damping不意味着无数值耗散。

### 水量积分与B

按边速度正负选供水侧可见深度，再作通量差：

```text
C_i = max((hL+hR+hB+hT)/4 - 2*dx/(dt*g), 0)
F_edge_as_seen_by_i = v_edge*(h_donor-C_i)
A_next = A_raw - dt*divergence(F)
```

`C_i`从本格四边的供水深度中扣除，不是从最终A再直接减一次。本帧修正阈值为1，A限制在0..10后量化。水量上升率大于0.1且输入法线水平长度大于0.5时，将B置255，否则为0。

公共边两侧可能使用不同修正项，另有限幅、量化及原位读取，因此理想通量的成对抵消不能证明完整链严格守恒。必须分开边界、源汇和数值残差，也不能把波变平直接解释为水消失。

### 速度平流

E1500按当前速度回溯，手工双线性读取四个源格并重新编码速度，本帧有效advectionFactor约0.2。它与水量搬运是不同阶段；完整重打包不承诺任意非主字段按位不变。

### 源汇

E1537包含空气场衰减的蒸发、障碍近表面微扰、海侧目标回设和格内源项。本帧源汇dt约0.025，与传播积分dt不同。

```text
evap = exp2(-0.721348*air_term)*sunColor.r*evaporationFactor*0.001
A -= source_dt*evap
A_target = max(level + max(sin(playTime)*waveAmplitude,-0.5) - b, 0.05)
A = lerp(A,A_target,alpha)
若customWave>0，再向level+customWave-b按alpha混合
```

这只是完整核的可读分解，后续仍有限幅和量化。test1有效`level=1、customWave≈1.6163164、waveAmplitude≈0.0497019、evaporationFactor≈0.1`；满权重且有水的customWave目标可见水面约2.566316场景单位。不能从该单帧推出造浪周期或按键释放后的变化。

### 宏观法线

E1543从自由表面邻域差分生成并编码法线。宏观法线、材质细法线和实际水网格采样是不同层次，不能相互替代。[原始精确程序](evidence/water_solver_reconstruction/t06_exact_programs_20261025_v1/manifest.json)。

## 时间

已观察运行中的源汇dt约0.025、积分dt为0.00732421875；累计积分轮数符合`floor(N*source_dt/integration_dt)`。计数和读数为C3，保留余量累计器解释为C2，唯一原调度方法未知。

公开引擎timeScale显式持值0.5时，缩放时钟与墙钟调用节奏改变，但每次源汇dt仍约0.025。名义40个模拟步／模拟秒不等于墙钟40 Hz。playTime有参数与GPU常量对应，但完整生成公式、初始偏移及customWave全部输入规律未知。

连续运行证据是512×512域的限定自然／公开引擎变速条件，不扩大test1的512×256数值范围，也不证明原作UI、暂停、重置或无探针频率。[时钟映射](evidence/water_solver_reconstruction/t05_clock_mapping_20261025_v1/clock_mapping.json)。

## 适用边界

六核输入、局部计算、写回与同步具有可实施依据；原程序的同输入非唯一输出、浮点重排和插桩扰动必须保留，见[参考边界](水求解参考与同步.md)。真实长度单位、长期波速／衰减、完整守恒和生命周期仍未知。原始HLSL、驱动最终机器指令及所有合法线程顺序没有恢复。
