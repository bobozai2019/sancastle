# Sandcastle 项目清理审计（2026-10-17）

## 审计结论

`scenes/main.tscn` 不能单独作为可运行工程保留：它声明了多个场景、脚本、Shader、Theme 和网格依赖，并继承水沙场景；项目还需要 `project.godot`。主场景的场景切换功能另有动态场景目标。把其他文件全部删除会使工程无法打开或运行。

本次按“主场景最小工程”范围核对，未移出文件：现存非入口文件中包含运行依赖、存档兼容身份输入、历史报告引用的源码或验收证据。无引用线索的文件也需要按用途复核后才能列为可移出项。

从 `scenes/main.tscn` 直接读取到以下路径（间接依赖还会继续展开）：

## 项目内容规模与处理建议

- `docs/`：955 个文件，其中历史材料、验收证据、知识契约、竞品取证等应按项目约定保留或迁移；不能用代码依赖性判断有无价值。
- `task/`：171 个文件；当前任务状态须按各任务的总纲/执行状态判断，部分内容是原始证据。
- 全项目共 62 个 `.tscn`：`scenes/` 下 32 个，其中 30 个在 main 的递归 PackedScene 资源链上；另 2 个是单独实验/测试入口。`tests/` 下还有 30 个独立验证场景。
- `scripts/`：642 个 GDScript；`assets/`：220 个文件；`shaders/`：162 个文件。应通过场景、脚本、配置和动态加载共同引用关系筛选。
- `test_output/`：94,476 个文件、约 31.1 GB；有运行结果、捕图、日志和历史验收证据，整目录删除会丢失复验材料。
- `rdc/`：约 2.0 GB；`sandcastlegame/`：约 3.6 GB 原始竞品数据。项目说明要求先核对 hash 与索引，不能按“当前入口未引用”删除。
- 当前 Git 状态包含大量已修改文件及未跟踪代码、场景和任务；清理时需逐项保留用户工作。

## 存档兼容与动态资源边界

- `scripts/beach/beach_scene_service.gd` 在运行时加载 `scenes/playable/test1_capture.tscn` 与 `scenes/playable/test1_backwash.tscn`；这两个场景是主入口功能的一部分。
- `scripts/beach/beach_recovery_entry.gd` 递归计算目录内容的源码签名，包含 `scenes/`、`scripts/simulation/`、`scripts/visual/`、`scripts/collision/`、`scripts/water/reference/`、`scripts/beach/`、`tests/visual_water_alignment/prototypes/`、`assets/test1_beach/`、`assets/water_material_natural_candidate/` 和 `shaders/simulation/`。
- 主场景链还索引 `assets/gravel/`、`assets/brushes/`、`shaders/brushes/`；异步流水线按配置生成的资源来自 `scripts/simulation/edit_validation/frame_pipeline/` 和对应的模拟 Shader。
- 因此，删除哈希目录内的“未直接加载”文件会改变存档身份，潜在影响已有恢复。保留这些文件符合本次选择的兼容范围。
- `test_output/`、`rdc/`、`sandcastlegame/` 是忽略目录，不属于 main 运行依赖；其中已有结果、原始捕帧和竞品原包证据。按项目说明核对之前不清理。

## `scenes/` 场景用途分类

静态追踪 main 的 `PackedScene` 引用和继承链后，`scenes/` 下 32 个场景分为：

- **main 递归依赖链：30 个。** 包括主场景、组件、场景切换的两个 test1 目标、继承的水沙材质/视觉链，以及预览/碰撞等被继承资源引用的场景。它们不是都显示在当前画面里，但主场景资源加载链会引用它们。
- **不属于 main 链：2 个。** `scenes/approx_gpu_edit.tscn` 是近似 GPU 编辑独立实验入口，由 5 个实验测试/工具引用；`scenes/shape_brushes/brush_playable_candidate.tscn` 是形状刷子候选入口，由 `tests/shape_brushes/ui_lab.tscn` 引用。
- **`tests/` 下的 30 个场景**是独立验证 Lab，不由 main 运行时加载；它们仍服务于相应测试。不能仅因 main 不引用就认定无用。

以上 2 个非 main 场景虽不是启动依赖，但 `beach_recovery_entry.gd` 会对整个 `scenes/` 目录做源码身份索引；删除/移动会改变存档签名。要清理它们，需要先接受旧存档身份变化，或另行调整签名范围并处理兼容性。
