# 投放悬沙 v1

2026-10-16，按用户要求增加随水输运的投沙。此处是本项目 Godot 适配，不是竞品算法结论。

## 权威语义与命令扩展

新增 UI 工具 `suspended_sand`（投流沙），与 `place_sand`（填沙床）分开。投流沙复用 GPU 加沙事务与 external_v1 源汇账户；命令仍是 `place_sand`，增加可选字段 `sand_destination="suspended_v1"`。无此字段或为 `bed` 时，保留原填床语义；未知目标以及挖沙搭配悬沙目标均拒绝。

128 字节命令传输使用偏移 112 的 u32 目标扩展 v1：0=沙床，1=悬沙，其余值拒绝。回执格式和 native v2/edit v4 检查点结构不变；配置签名增加 `suspended_sand_destination_version=1`，记录扩展和沙云源码身份。旧配置存档仍按已有严格身份校验，不伪装迁移。

投放半径 0.75 m，每次 0.01–1.00 m³，与填床共享投放量控件。当前完成态水深须大于 0.001 m 且无实体障碍；按笔刷权重只在合格格内分配完整请求体积。足迹完全无水时按原错误码 3 拒绝，无字段或源汇变化。该扩展只在启用侵蚀/悬沙耦合和 external_v1 的 GPU 交互入口开放。

事务读取当前 `sediment`，通过原量化/体积验证后写入两个悬沙槽。沙床、水深、动量、局部材料和压实度不因投放直接改变，不运行沙床抬升所需的水位移/速度事务；实际回执量只增加 `sand_source_m3`。失败沿原回滚和发布授权链处理，后续模拟继续使用同 generation 的完成态。

之后由现有 `sediment_step.glsl` 按水通量搬运并按容量/速率沉降，原侵蚀、沉降和水流系数不变。暂停允许投放，输运/沉降等到继续；流水中可继续携带，干格最终沉积到床面。没有另建颗粒物理或独立沙量账户。

## 显示

`suspended_sand_cloud.gdshader` 复用当前水面顶点重建代码与参数，来源为项目 `rdc_water.gdshader` 的 fragment 之前部分（源 SHA256 `16a93e3d6942429073cbcbcba73b59bbe42e80c61bf776e9f15170ca69fd8b89`），替换为只读悬沙量的棕金沙云片元。原 shader、bundle 和原参数档案保持原样。沙云随权威纹理变化，不用独立移动噪声假装输运；与水面共用网格、完成态床面/水面、波峰、接触输入及表现时钟，额外高度偏移 0.001 m 避免重叠闪烁。调试模式隐藏沙云，正常画面透明度为 `(1-exp(-sediment*24))*0.85` 并在极浅水处淡出。这是二维深度积分悬沙的可视化，不表示三维粒子轨迹。

## 验证及边界

实际可见 D3D12 / GTX 1050，`tests/integration/suspended_sand_probe.gd` 覆盖 main、test1_capture、test1_backwash：真实 UI 选工具和水下碰撞拾取、0.1 m³ 只增悬沙、两个槽一致、床/水/动量逐位不变、实际源汇闭合、沙云绑定、native 保存恢复和工具选择、输运出笔刷足迹、沉降及总沙量闭合、全干足迹无修改拒绝。

`test_output/suspended_sand_20261016_v2/result.json` 是最终结果。20 tick 输运/沉降观察在保存恢复之后仅将探针的 `erosion_rate_per_s` 设为 0，以排除背景新侵蚀对这批投放沙量的混淆；保留实际水流、输运、容量与沉降。游戏默认参数不变。v1 在默认侵蚀下观察到两个场景悬沙总量净增加，不能据此断言投放沙没有沉降；该失败报告保留。

原 UI/沙床编辑回归见 `test_output/suspended_sand_smoke_20261016/result.json`。本次没有重做长稳、严格多 tick 恢复继续或完整负载性能验收，不扩展旧报告的通过范围。
