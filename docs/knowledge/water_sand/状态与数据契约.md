# 状态与数据契约

> 从 `docs/history/sandcastle_water_sand_coupling/契约/` 迁入。文中 `验收/` 路径指向该历史任务包的验收记录；`frozen v1` 只约束接口，不代表当前 test1 验收通过。当前状态见[项目现状](../../README.md)。

状态：frozen v1（Gate 1A，2026-09-28）；后续改动须新 ADR、版本号与 CPU/GPU 回归。冻结的是数据/单位/方向契约，非 GPU 实现通过。

## 网格与单位

| 项 | 初始值 | 单位/约束 |
|---|---:|---|
| 域尺寸 | 32 × 32 | m |
| 网格 | 256 × 256 | cell，约 0.125 m/cell |
| 固定步长 | 30 | Hz，Gate 0 可调整 |
| 坐标 | XZ 平面，Y 高度 | 世界米；转换函数唯一 |

网格索引固定为 `i = z_index × grid_size + x_index`；`x_index` 向世界 +X，`z_index` 向世界 +Z，单元中心 `(x+0.5, z+0.5)` 映射到世界 `((x+0.5-N/2)Δx, (z+0.5-N/2)Δx)`。纹理第 0 行对应 `z_index=0`，不得由画面 UV 翻转改变物理索引。海侧仅 `x_index=0` 是给定水位/零动量水库边界，另三侧首版封闭；每次边界水量变化进入水源汇账本。

## 权威状态

| 字段 | 类型/格式起点 | 单位与语义 | 约束 | 持久化 |
|---|---|---|---|---|
| `rock` | R32F | 不可侵蚀基底高 | 静态 | seed 或全量 |
| `sand` | ping-pong R32F | 参考密度等效厚度 | ≥0 | 是 |
| `water` | ping-pong R32F | 有效水域水深 | ≥0 | 是 |
| `momentum_x` / `momentum_z` | ping-pong R32F ×2 | 浅水方程水平二维动量（单位宽流量，m²/s）；CPU 参考代码中的 `momentum_y` 对应世界 Z | 干格归零；限速事件计数 | 是 |
| `flux` | ping-pong RGBA32F | 四向非负出流体积流率 m³/s | R/G/B/A = −X/+X/−Z/+Z；共享边只算一次，正流只写上游一侧的对应出流通道，下游通过邻格通道读取入流 | 是 |
| `sediment` | ping-pong R32F | 悬浮沙等效厚度 | ≥0 | 是 |
| `wetness` | ping-pong R16F | 湿度 [0,1] | 有界 | 是 |
| `compaction` | ping-pong R16F | 压实度 [0,1] | 有界 | 是 |
| `obstacle` | R8_UNORM 首版二值 | `0` 畅通、`1` 阻水；中间值暂禁 | 障碍变化须做水量/悬沙重映射，不得吞水 | 是 |

派生值：T01–T04 固定 `bed = rock + sand`、`surface = bed + water`，压实度暂不直接改变几何高度；T05 若启用密度曲线，必须先以 ADR 定义体积重映射，再改为 `sand_height=sand×ρ_ref/ρ_bulk(compaction)`。`water` 是占用后的有效面积水深；首版二值障碍 `A_eff∈{0,Δx²}`。`sediment` 与 `sand` 同为参考密度等效厚度，非浓度；上游搬运浓度从 `sediment / max(water, ε)` 派生。

`momentum_x`/`momentum_z` 对应浅水保守量 `(h u, h v)`，单位 m²/s。CPU 参考历史命名 `momentum_y` 映射世界 Z，不改变 GPU 纹理命名。水面与地形材质只能采样已完成的同一 `sim_tick` 版本；每个计算 pass 禁止同一纹理同时作为输入与输出。

256² 的格式可用性已在目标 GTX 1050/D3D12 主 RD 上以 `tests/run_format_probe.ps1` 验证：R32F、RG32F、RGBA32F、R16F、R8_UNORM 均可用 `STORAGE_BIT | SAMPLING_BIT | CAN_COPY_FROM_BIT` 创建 256² 纹理，原始记录见 `验收/G1A_gpu_format_support.csv`。这只证明格式/usage 支持，不证明后续多 pass 正确或性能。

## tick 与通量约定

1. `sim_tick` 指下一个待完成的固定步。该 tick 的工具命令先按 `(sim_tick, command_id)` 应用，再更新潮位边界并记源汇。
2. 对每条共享边只评估一次带静水平衡修正的浅水数值通量；按上游可用量统一缩放，写四向非负出流，再更新相邻两格水深与二维动量。边界之外不重复求通量。
3. 使用同一完成态水通量搬运悬沙，随后侵蚀/沉积、湿度/坡面等 pass；完成校验后 `sim_tick += 1`，材质/碰撞版本才可发布。
4. `flux` 单通道单位 m³/s，`flux_right[i]` 与 `flux_left[i+1]` 不得同时为正。单格水量变化按 `Δt/A_eff × (四邻入流−四向出流)`；首版障碍完全阻水格为零。虚拟管道 CPU 比较器不是生产通量定义依据。

## 守恒账户

- 水量：`Σ water × A_eff`，加上潮汐、雨、蒸发、障碍重映射和边界进出源汇。
- 沙量：`Σ(sand + sediment) × A`，加上工具桶、外部调试源和边界流出。
- 账本累计字段至少包含 `water_source_m3`、`water_sink_m3`、`sand_source_m3`、`sand_sink_m3`、`tool_inventory_m3`；数值探针需记录初值、当前存量、源汇和闭合误差。潮汐外部水库引入的变化不是封闭域守恒损失。
- 封闭水回归阈值：5 分钟相对误差 ≤0.5%。
- 沙搬运阈值：T01 工具回归 ≤0.5%；T04/T05 五分钟或滑坡前后 ≤1%。
- clamp 只作最后防护；任何被 clamp 的量必须计数，不能用它掩盖账本错误。

## 数值错误语义

`negative_water`、`negative_sand`、`nan_state`、`mass_budget_mismatch`、`stale_generation` 必须进入审计记录；P0 错误在阶段 Gate 前为零或有明确、量化且批准的容差。
