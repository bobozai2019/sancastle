# 状态与数据约束

适用当前统一入口；完整资源、ABI和恢复格式见[技术规格](../../当前技术规格.md)。

## 网格与单位

| 项 | 初始值 | 单位/约束 |
|---|---:|---|
| 域尺寸 | 32 × 32 | m |
| 网格 | 256 × 256 | cell，约 0.125 m/cell |
| 请求频率 | 30 | Hz；实际时钟累计接受的actual_dt |
| 坐标 | XZ 平面，Y 高度 | 世界米；转换函数唯一 |

网格索引固定为 `i = z_index × grid_size + x_index`；`x_index` 向世界 +X，`z_index` 向世界 +Z，单元中心 `(x+0.5, z+0.5)` 映射到世界 `((x+0.5-N/2)Δx, (z+0.5-N/2)Δx)`。纹理第 0 行对应 `z_index=0`，不得由画面 UV 翻转改变物理索引。海侧仅 `x_index=0` 是给定水位/零动量水库边界，其余边界按场景冻结配置处理；每次边界水量变化进入水源汇账本。

## 权威状态

| 字段 | 类型/格式起点 | 单位与语义 | 约束 | 持久化 |
|---|---|---|---|---|
| `rock` | R32F | 不可侵蚀基底高 | 静态 | 原生完整字段 |
| `sand` | ping-pong R32F | 参考密度等效厚度 | ≥0 | 是 |
| `water` | ping-pong R32F | 有效水域水深 | ≥0 | 是 |
| `momentum`（R=qx，G=qz） | ping-pong RG32F；CPU/磁盘逻辑字段仍为`momentum_x` / `momentum_z` | 浅水方程水平二维动量（单位宽流量，m²/s）；CPU 参考代码中的 `momentum_y` 对应世界 Z | 干格归零；限速事件计数 | 是 |
| `flux` | ping-pong RGBA32F | 四向非负出流体积流率 m³/s | R/G/B/A = −X/+X/−Z/+Z；共享边只算一次，正流只写上游一侧的对应出流通道，下游通过邻格通道读取入流 | 是 |
| `sediment` | ping-pong R32F | 悬浮沙等效厚度 | ≥0 | 是 |
| `wetness` | ping-pong R16F | 湿度 [0,1] | 有界 | 是 |
| `compaction` | ping-pong R16F | 压实度 [0,1] | 有界 | 是 |
| `obstacle` | R8_UNORM二值 | `0` 畅通、`1` 阻水；中间值暂禁 | 障碍变化须做水量/悬沙重映射，不得吞水 | 是 |

派生床面为`bed=rock+sand`，水面为`surface=bed+water`；压实度不直接改变几何高度。sediment与sand都为参考密度等效厚度，不是浓度。动量为`hu/hv`，速度从动量与有效水深派生；CPU参考代码中的momentum_y对应世界Z。

材质和消费者读取同generation、完整state_seq及实际完成时钟；仅sim_tick相同不足以证明是同一份完成态。邻格数值阶段须使用明确稳定的输入／输出，不能将每格独立的发布或历史更新误作邻格原位求解的许可。

GPU权威动量使用两张256² RG32F ping-pong纹理，R/G分别保存qx/qz（hu/hv），每分量仍为Float32；Views另持有一张RG32F完成态动量，供材质、查询、白沫、碎石、植被及溅水读取。三张动量纹理合计原始载荷1,572,864 B，数量减少不代表像素载荷或物理显存减半，也不保证帧率提升。

CPU与磁盘保留momentum_x、momentum_z逻辑字段及现有native3、SANDUE06/07版本。初始化和恢复分别将current/spare两个分量按uint32位型交错打包；捕获每份RG一次，长度及全部异步回执完整后再无损拆分。公开查询仍返回原逻辑分量。每tick不做拆分，不增加pack/unpack dispatch；发布、完成态身份、源汇和动量账本不变。严格配置与来源校验仍生效，字段格式未变不代表所有旧档自动兼容。

## 水步与通量

Pipeline按已接纳工作顺序录制编辑、水tick与显示。默认MUSCL使用两阶段悬沙搬运和SSPRK2组合，仅接受步提交权威场、执行交换／材料阶段并累计actual_dt。可显式选择的一阶路径使用共享边通量、出流缩放与状态更新。

flux的R/G/B/A为−X/+X/−Z/+Z非负出流体积速率m³/s；一阶输运由供体出流及相邻入流计算。MUSCL可能在两阶段发生流向反转，不能用最终净flux替代两个Euler阶段的悬沙输运。

## 守恒账户

- 水量：`Σ water × A_eff`，按实际启用的边界和控制源汇闭合；若扩展雨、蒸发或障碍重映射，同样必须显式记账，不能默认这些扩展已接入正式入口。
- 沙量：`Σ(sand + sediment) × A`，按当前工具账户与边界源汇核对。
- 账本累计字段至少包含 `water_source_m3`、`water_sink_m3`、`sand_source_m3`、`sand_sink_m3`；数值探针需记录初值、当前存量、源汇和闭合误差。潮汐外部水库引入的变化不是封闭域守恒损失。
- 封闭水回归阈值：5 分钟相对误差 ≤0.5%。
- 沙搬运阈值：标准工具回归≤0.5%；水沙耦合五分钟或滑坡前后≤1%，仅适用于对应标准回归，不能当作普通名义源汇的精确保证。
- clamp 只作最后防护；任何被 clamp 的量必须计数，不能用它掩盖账本错误。

## 保存与错误边界

保存使用原始current／spare、控制区、材料／支持状态、受支持历史、账本、配置及身份高水位。默认启用湿痕时为SANDUE07/version7，关闭时为SANDUE06/version6，native3权威布局相同；保存先排空，恢复不重放pending命令。

有限值、非负、授权、字段权限、状态身份与守恒由公共审计检查。失败不得发布部分候选；fatal／unknown保留所有权和诊断。宏观回归阈值不替代逐笔ULP预算或原始字段恢复校验。
