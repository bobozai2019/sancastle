# Sandcastle 当前技术规格

适用正式main与test1_geometry统一入口。本文描述当前生效实现。架构解释见[技术方案](当前项目技术方案.md)。字段偏移以[layout.gd](../scripts/simulation/unified_edit/layout.gd)为唯一源码；契约详见[统一流程契约目录](../task/sandcastle_unified_edit_pipeline/契约/)。

## 域、坐标与单位

| 项目 | 规格 |
|---|---|
| 权威网格 | 256×256，65536格，cell_size=0.125m，域32×32m |
| 坐标 | XZ为水平面，Y为高度；索引z×256+x；格心=((x+0.5−128)×0.125,(z+0.5−128)×0.125) |
| 面积/体积 | 单格面积0.015625m²；等效厚度×面积得到m³ |
| 床面/表面 | bed=rock+sand；water存水深；水面及表现共用可见床面基准 |
| 速度 | qx/qz存水平动量hu/hv，单位m²/s；速度为动量/有效水深，干格按数值核处理 |
| geometry显示 | X=-15..15、Z=-7.5..7.5；权威域内240×120可见格，不把显示细分当模拟加密 |
| 碰撞 | 8×8共64块，每块33×33高度采样，包含共享边界 |
| 时钟 | sim_tick、revision、state_seq各自独立；表现使用GPU完成态累计actual_dt，暂停冻结 |

入口按1/30秒请求水步；一阶求解器GPU CFL Courant=0.35，子步1–64，safe_dt=Courant×cell_size/最大传播速度，actual_dt=min(requested_dt,64×safe_dt)。超限缩短实际推进时间，不能用tick/30代替完成时钟。非有限/非法CFL或身份耗尽会设置故障标志。

默认求解器配置为 `environment.water_numerics={schema:1,solver_id:"muscl_mc_ssprk2_v1"}`，可显式选择 `rusanov_first_order_v1` 回退一阶。schema=1保留严格二字段；非零保波程度使用严格三字段 `{schema:2,solver_id:"muscl_mc_ssprk2_v1",wave_retention:r}`，r为有限数且在[0,1]内，仅二阶支持。数值对象参与配置冻结。MUSCL使用MC重构与SSPRK2，CFL取0.2并按两个方向速度上界之和确定trial dt，第二阶段不满足限制时拒绝并缩小步长；最多64次尝试，只累计接受的实际时间。不得将上面的一阶actual_dt公式用于MUSCL。

MUSCL 的 CPU 录制器缓存类型化命令描述，包括 pipeline、uniform set、间接调度缓冲与偏移、push constant 字节、直接／间接调度标记及组数；缓存键包括请求 dt、cell size、边界启用状态、保波程度、耦合 Callable 和 prescribed_tide_boundary，键改变时重新构建。标准 Coupled.record 的固定阶段通过 muscl_recording_passes(1)并入同一描述表，借用原资源与常量，省去每候选步的脚本回调；自定义或计时包装回调仍逐步执行。缓存仅属于当前 Water 资源实例，释放时清空，不进入检查点，也不复用引擎 compute-list ID。每个 tick 仍依原顺序录制全部 64 次候选尝试及原计算列表边界；边界参数在实际录制时读取，耦合和尾部消费者保留原执行位置。

GPU 决策核的 mode 2/3 在 trial 无效或 control 已失败时，由整个工作组在速度扫描及 barrier 前统一退出；mode 7 初态校验、审计、错误传播和容量上限保留。空间算子在每个线程内复用本格 primitive、可重构条件与两个方向的坡度，得到四个面状态；正向面同时供共享边通量与床源项使用。邻格状态在该计算阶段内不变，复用不改变 MUSCL 面值、供水限制或 RK 公式，也不新增跨工作组共享状态。

面板“保波程度”r默认0、范围0–1、步长0.1。坡度为 `(1-r)×MC+r×Superbee`；Superbee对同号左右差分a、b取 `sign(a)×max(min(2|a|,|b|),min(|a|,2|b|))`，异号时为零。r=0直接走原MC计算。调节不减小Rusanov信号速度，不改CFL、湿干阈值、速度帽或非负保护，也不额外施加水量或动量源。更锐利的重构可能改变波形，不保证所有条件下的振幅或持续时间单调增加，不能换算为指数衰减时间。

调参先结束笔画、取得完整检查点，再只改变数值对象并构造新generation。域、完整源码、solver与所有非数值参数必须相同；候选提交才替换有效配置，候选失败保留旧域和旧值。原字段、账本与完成时间保持，浮物按现行恢复语义重置。保存记录有效数值配置，UI恢复取存档中的保波程度；场景切换保留各域值，新场景沿用当前设置。

默认r=0的二阶路径仍受0.125m网格与限幅器耗散影响，不能保留任意短波。固定床两秒小振幅波中，1m、2m、4m波长的振幅保留约35.6%、93.3%、99.6%；0.5m仅约0.0316%。固定铲沙输入下，平床远场可辨窗口相对一阶只延长0.7s，main条件延长1.6s；这些数值依赖初态、冲量和固定测点，不构成任意地形的一秒延长保证。显示细分不改变此边界。

## 物理字段与资源

| 字段 | GPU格式 / 槽 | 语义 |
|---|---|---|
| rock | R32F，单槽 | 不可挖基底高度m，可为负 |
| sand | R32F，双槽 | 非负等效沙厚m，也用于当前几何 |
| water | R32F，双槽 | 非负水深m |
| sediment | R32F，双槽 | 非负悬沙等效厚度m |
| momentum_x、momentum_z | 各R32F双槽 | 水平动量m²/s |
| wetness、compaction | 各R16F双槽 | [0,1]；原始half字节恢复，不经CPU解码重编码抹掉细值 |
| obstacle | R8_UNORM，单槽 | 二值阻水掩码 |
| flux | RGBA32F，双槽 | 四向非负出流m³/s |
| mold_support | RG32F，双槽 | 成型材料标记/参考数据，按材料codec解释 |
| edge_x/z、drain、cfl_tiles | RGBA32F或R32F工作纹理 | 共享边通量、缩放和CFL归约；非公开工具字段 |
| MUSCL U1/U2、两阶段edge/drain、correction、bed_source、exchange_sediment | 私有阶段纹理 | RK试算、压力/床面源项和交换暂存；不进入native检查点 |

MUSCL重构h、eta、u、v；MC斜率为同号差分的带符号min(2\|Δ左\|,2\|Δ右\|,0.5\|Δ左+Δ右\|)，异号为零。共享边静水重构与床面压力修正配对。两个Euler阶段分别限制供体出流并输运悬沙，最终按SSPRK2组合；合成的净水通量不作为唯一悬沙供体依据。试算失败只改私有数据，接受后才提交、执行一次侵蚀/沉积交换与材料链、归一公共槽0并累计dt。GPU检查有限值、非负和阶段CFL，安全统计分别累计舍入修正与速度限制，不能将修正当成额外物理源汇。

格式与初始化由[state.gd](../scripts/simulation/unified_edit/state.gd)定义。只读发布、白沫和碎石另有资源，不能把上表当完整显存预算。纯视觉改动不得改变权威水沙、动量或源汇。材料配置来自 `assets/brushes/molded_material_candidate.json`：compaction_target=0.95，R16F实际存储值0.9501953125；成型内聚高度0.9m，饱和标记深度0.125m。场景普通内聚高度独立：main为0，geometry为2m。

## 声明、能力与权限

Intent绑定domain、generation、command_id、tick、profile_id/version/hash及起点；可包含终点、参数、受限features、authorization、笔画身份/基准/sample和seed。未知键、错误类型、NaN/Inf、非零float32下溢、非法组合或超范围拒绝，不静默修正。

| operation | 形状与目标 | 行为 |
|---|---|---|
| VOLUME_DELTA | DISK/SWEPT_CAPSULE；床沙或只增悬沙 | 普通挖填、投流沙 |
| TARGET_HEIGHT | HEIGHT_STAMP固定世界高度；或SWEPT_CAPSULE笔画基准 | 城堡/沙墙补到目标，保留更高原沙 |
| TRANSFER | SWEPT_CAPSULE，床沙 | 固定基准，中央挖沙、两肩限量接收，材料保留 |
| REDISTRIBUTE | DISK，床沙 | 守恒平滑 |
| FIELD_ADJUST | DISK，材料 | 压实，不改变沙量 |

默认产品[default_catalog.tres](../assets/unified_edit/default_catalog.tres)含11物理profile。精确模型script绑定、冻结副本和来源hash必须验证；profile不得携带Callable、执行器、shader路径或第二个调度器。

普通体积减沙最多执行4轮候选分配。每轮的有效供沙条件为 `weight > 0 && remaining_sand × cell_area > legacy_epsilon_m3`，权重归约与逐格扣减共用该条件；`cell_area=0.015625m²`、`legacy_epsilon_m3=1e-6m³`。阈值内残沙不再扣减，不能计入分配分母之外的额外挖量。GPU提交前校验实际体积相对原请求量和`available_m3`的超量均不大于既有`eps_sand_m3`，同时保留实际变化与分配累计量的核对；分配用epsilon不替代ULP授权预算，CPU回执校验保持独立。

产品`shovel_v1`声明版本2，transfer_policy=CAPPED_SHOULDERS。中央候选挖量由固定baseline、累计沟底和现存沙量确定，再受`transfer_budget_m3`授权限制；两侧容量不参与缩减中央挖量。令实际挖量为R，左右容量为Cₗ、Cᵣ，则各侧接收目标分别为`min(R/2,Cₗ)`、`min(R/2,Cᵣ)`，逐格上限为该笔baseline+0.5m。左右独立按权重与容量分配，不要求实收量相等；多余沙移出沙场。历史供沙格可以作为后续段的接收格，回填后仍可挖至累计沟底；未实际减沙的格子保持原coverage。零授权、岩床下限、障碍、域边界及原子提交校验继续生效。BALANCED_SHOULDERS保留原有的等量、守恒搬运语义，供显式选择该策略的扩展声明使用。

## 编辑水响应与主场景开关

水策略允许0–3，具体数值路径由公共water_response定义；策略2（动量 B）和3（原位移＋速度）允许非零speed_m_s，策略0/1的speed_m_s必须为0。悬沙、平滑和压实的声明水策略为0。write mask从operation/destination/有效policy推导，调用方无权缩小自报掩码绕过审计。authorization只能降低amount/add/transfer预算，0是有效限制；不能增权或绕过有限值、非负、守恒、原子性与消费者检查。

main默认策略2，独立工具窗口可选择原策略3。main表现manifest设置water_policy=2，test1_geometry默认策略3。公共后端策略2采用实际接受的 `Δbed = bed_after - bed_before`，`Δq = h × direction × speed_m_s × (Δbed / 0.2m)`。direction为从本次命令线段最近点指向单元中心的单位向量，退化线段按点处理，零距离为零向量；正力度下填高向外、挖低向内。覆盖已作用于床面候选，不重复乘权重，不乘模拟dt。水深≤0.001m、障碍≥0.5、覆盖外、无床面变化或力度0不施加冲量，候选总速度沿用4m/s上限。

编辑瞬间水深和悬沙双槽保持，沙床变化仍改变几何水面标高；后续水量搬运由常规水tick完成，暂停不推进tick。并行候选准备、有限值/非负/守恒审计、回执与公共条件提交保持。铲子需拖出有效线段，沟槽与两侧接收均采用实际床面差。此公式为Godot适配，不宣称竞品原公式。

工具窗口推拉力度范围[-1,1]、步长0.05、默认0.25。切换模式或力度先结束当前笔画、失效预览，仅影响后续命令，已接纳命令继续使用冻结policy/speed和有效hash。保存恢复selection同步开关和力度。检查点恢复要求来源校验或已登记的受限迁移通过。

关闭连通排水的策略2现使用独立[water_velocity_prepare.glsl](../scripts/simulation/unified_edit/water_velocity_prepare.glsl)：256组×256线程逐格复制候选、清理暂存并汇总首个非法格，再以1组×256线程生成128字节回执。新增私有检查缓冲2048字节，两阶段特化pipeline由Response持有并释放；按工作组统一读取拒绝/致命状态后决定是否执行，阶段之间没有CPU读回等待。后续策略2接动量B，速度归约、守恒审计和共同提交保持原流程。它不构建连通域，因此没有每行8湿段/32分量边界；开启后的策略3仍使用下述原排水路径。

开启连通排水的并行实现保留256²域、4邻接湿区、每行最多8湿段/最多32分量的快速路径边界，以及原通用回退。分量索引、供受分配、逐格补偿求和、残差行序与ULP修正上限、容量和守恒预算不变。新增私有暂存为 `65536×48 + 16+32×96 = 3,148,816` 字节，约3.003MiB；不进入权威字段或检查点。1024组逐格阶段、最多32组分量阶段和1组全局汇总顺序录制，11份特化pipeline由Response持有并释放；不改变三工作槽、回执时机和碰撞策略。

配置必须unrestricted_sand_tools=true。enable_structures、rise_front_history、contact_history当前仅支持false；erosion、brush_water、local_front、foam、gravel按合法能力校验。diagnostics不计入stable configuration_hash；实际来源文件、声明、模板、环境与材料身份参与冻结。修改运行中资源不能改变已排队快照。


### 水面泡沫细节契约

水面泡沫由 `foam_state.r` 的历史强度控制存在范围，再由静态绑定的 `assets/water_foam/foam_detail.png` 打开孔洞与破边。该自建周期细胞纹样采用线性数据采样，512×512 RGBA8，包含9级附加mip，导入后完整图像为1,398,100字节。两个正式场景使用 `foam_detail_mode=1`，岸脚覆盖增益为0.55；独立点状细沫仍隐藏。

细节流动从同代完成态动量取 `q/max(h,0.02)`，先将速度限长至2 m/s，再乘流动增益。完成态时钟驱动相差半周期的两个局部位移，默认周期4 s，三角权重交叉混合，避免纹样无限漂移。两个 `textureGrad` 采样使用未位移世界纹理坐标的导数选择mip。默认密度1/m、破碎程度1、流动增益1；零流速保持图案，暂停保持时钟。历史减弱时阈值由0.22升至0.96并逐渐开孔，历史为零或床面干燥时无泡沫；最终覆盖统一用于颜色、透明度、泡沫直射和水面高光抑制。该路径只读取发布场，不改变泡沫生成消散、权威水沙、动量或检查点格式。

`foam_detail_mode`只接受整数0或1；0保留原表现路径且允许无细节纹理。模式1初始化时要求实际Texture2D、非空图像、至少一级附加mip、完整图像不超过2 MiB；密度范围0.5–12/m、破碎程度0–1、周期0.5–8 s、流动增益0–2、速度上限0–4 m/s，所有数值必须有限。失败分别通过 `presentation_foam_detail_mode_invalid`、`presentation_foam_detail_parameter_invalid`、`presentation_foam_detail_texture_missing`、`presentation_foam_detail_texture_invalid` 返回正式初始化错误。`foam_flow_debug=false`，诊断灰度输出不作为正式效果。

两个正式表现场景将`PrototypeFrontFoamDense.visible`设为false，独立点状细沫不参与绘制。`effects.foam_enabled`仍控制共享泡沫历史计算，水面内混白、前缘与岸脚继续消费该场；隐藏细沫节点不会关闭这些模拟及表现输入。

## 参数配置与窗口

Parameters Autoload 的固定布局为 `scenes/parameters/parameter_windows.tscn`，参数目录为 `assets/parameters/catalog.json`。窗口只通过参数服务修改工具、材质、环境与启动配置，不写权威字段。工具设置结束旧笔画后供下一笔使用；波包持续时间允许0.5–6秒、幅度0–0.2m，已接纳波包不变。

启动配置保存于 `user://parameters/startup.json`，version=1，最大256KiB，按两个场景key分组。进程启动读取一次，保存重启项不会改变当前进程后续场景的启动快照。`environment.coupling_parameters`按目录类型和范围校验已有侵蚀／材料常量；`foam_parameters`控制已有白沫消散时间和生成增益；`prop_parameters`记录启动前应用的道具profile覆盖。物理配置参与原有冻结身份与检查点校验，不允许任意参数差异恢复。

普通工具选择检查允许已验证的radius_m、strength；平滑与压实也使用此二字段，旧普通工具空参数仍可验证。native物理字段、容差及槽位不变。完整参数、适用范围和生效规则见[独立参数窗口](参数窗口.md)。

## 事务、回执与账本

- freeze成功只说明数据有效；submit仍检查域/代次、后端、关闭和背压。队列满返回queue_full，结果容量满返回results_backpressure，不分配假GPU成功。
- BEGIN/sample/END走同队列；目标高度/搬运持有baseline与累计coverage。圆盘使用当前点，只有capsule连接两端。形状笔画段≤2m；普通sweep使用独立有界声明。
- APPLIED=1必须有权威变化，revision增加1；NO_CHANGE=2可仅改变coverage，revision不变；REJECTED=3须无沙/水/材料/coverage变更。控制不能APPLIED，允许合法NO_CHANGE或无副作用REJECTED。
- 结果必须匹配命令、代次、租约、domain/effective hash、profile版本及实际tick；state_seq指批末完整发布。旧代、重复或错误回执不能再次结算。
- 普通体积编辑使用APPROXIMATE_EXTERNAL：已知GPU录制的原请求×strength记名义源汇，包含业务拒绝，不能当精确物理沙量。
- 目标高度使用EXACT_EXTERNAL，按实际增减记源汇。CAPPED_SHOULDERS使用TRANSFER_WITH_SINK：source=0，transferred=left_received+right_received，sink=removed-transferred，added=transferred；GPU按既有ULP预算检查实际床沙净变化+sink、各侧分配目标和挖量授权，CPU独立核对回执，成功后仅累计sink。BALANCED_SHOULDERS使用CONSERVATIVE_TRANSFER，source/sink=0并校验两肩等量；平滑、材料和控制账本不变。实际累计源汇随检查点保存恢复，profile版本、策略和来源hash参与配置身份，不将旧配置检查点静默当作新语义加载。
- GPU公共审计核对实际变化、ULP预算和授权，不能由decoder检查或导出成功替代。容差沿既有契约，不用扩大touched并集放宽沙量误差。
- fatal/unknown保留原始诊断和租约，不产生普通业务ACK，不授权重放、结算或强制释放。

## 发布、碰撞与生命周期

表现/预览/碰撞读取同generation完整版本；GPU录制顺序不等于CPU通知顺序或碰撞就绪。worker仅在is_task_completed之后回收，不在编辑主流程阻塞等待物理。

三工作槽的CPU状态由Pipeline创建线程持有。`transport.retire(identity)`必须确认相同generation/slot/lease且回读已完成；返回后，同所有者线程直接执行`_retired`，其他线程使用deferred通知。`slots.retired`仍只接受已消费且最后读者完成的租约；失败和旧租约不得释放当前槽。该确认不调用新pump、不扩大批次或槽位容量；同线程路径可由现有pump在本轮复用空槽，跨线程路径仍可能等后续帧。

一阶水tick固定录制64轮间接子步；每轮为3个浅水阶段，加上启用侵蚀时的9个水沙/材料阶段。固定资源绑定和参数按双槽索引预缓存，边界相关常量选择仍使用当前有效状态。GPU CFL、实际推进时间、阶段顺序及原有计算列表同步边界不变；缓存不引入额外GPU资源或CPU同步读回。

高度槽完成worker后进入`applying`，保存已验证结果和下一块游标。每个Height所有者按`Engine.get_process_frames()`共享8次形状替换/1500μs调用累计预算；达到任一条件后保留余量到后续渲染帧。计时覆盖原生形状替换调用，单次调用不可抢占，允许该次调用跨过时间预算；并非整个physics阶段或多个所有者合计的硬上限。两个槽轮换优先消费，已应用版本及接触变化上界逐块更新，全部消费后才走原GPU ACK。worker仍只在真实完成后回收，非有限值/代理拒绝按原规则重列dirty，关闭丢弃未应用CPU部分后再确认；不提前清除borrowed，也不降低恢复候选64块完整就绪要求。

恢复候选必须备齐64块同代高度和材质绑定，在physics阶段原子交换。当前未变化块允许较早seq；候选整体要求完整同代准备，不能混用规则。旧代关闭接纳/录制后仍持有最后读者，直到真实GPU结束、解绑和worker证明完整。未知证明按维护节奏重试，不将超时当完成。

正式与候选通过准确PackedScene路径分族，缓存key为family:scene_key；场景服务保存→shutdown→加载，目标失败按原正式路径回滚。当前会话进度不等于跨进程自动续档。当前支持保存恢复，不对外提供任意逐命令撤销保证。

## 检查点与兼容性

geometry的海侧退水由[boundary.glsl](../scripts/simulation/unified_edit/boundary.glsl)在既有水tick边界阶段执行，一阶与二阶共用。每0.5模拟秒检测可见矩形内128个固定采样点的湿区表面均值，水深须大于0.03m且无障碍；启动/停止阈值为1.04/0.98m。负X海侧x=0的规定水位逐步降低，x=1…23、z=68…187带内按`0.12×实际已完成时间差×(1−smoothstep(0,24,x))`降低水深，水面不低于0.90m，已低于此值的水不补齐。对应格的XZ动量乘以新旧水深比，避免降低水深时增加速度；沙床与悬沙不由排水边界移除。边界实际水变化累计到原source/sink账本。仅排水带受到直接扣水，其他区域通过常规水流传播响应。

此检测复用既有1组64线程边界dispatch；没有新增CPU回读、整域扫描或独立调度。活动期最多更新23×120个带内格；未到检测时刻不重新采样，未活动时不遍历排水带。它估计可见湿区水位，不是精确面积积分，也不能保证隔离水池被排空。参数在water_cycle.json的overflow版本1中冻结；修改后需要重新启动，参数与shader身份参加检查点来源验证。

原生128B水控制区的104…127B在启用overflow v1的geometry配置中保存扩展：104=u32活动标志，108=f32下次检测时钟，112=f32最近均值，116=u32检测次数，120=f32活动期边界累计移除水量，124=f32上次边界时钟。96B保留原实际海侧水位。全零扩展表示尚未检测；未启用的配置仍要求扩展全零。扩展与原生水态原样保存恢复，检查标志、有限值、时钟和次数范围；48…71B仍要求为零。活动期移除统计包含该阶段海侧边界及排水带的sink，是总水sink的子集。

[检查点 codec](../scripts/simulation/unified_edit/checkpoint_codec.gd)：未启用湿痕为SANDUE06/edit version6，启用湿痕为SANDUE07/edit version7；均保留native3、container1；8B magic+u32容器版本+u32长度+32B SHA256组成48B头，payload最大32MiB。Variant对象反序列化关闭；文件create-only，临时文件写入/flush后rename。

保存包含原始current/spare字段、材料/白沫/受支持历史、控制完成态、账本、实际时钟、波包、选择、有效配置/来源及highwater。恢复验证当前磁盘配置身份和数据后建立候选；highwater不重置，generation换代。

已登记来源的edit5/native3、edit4/native2可通过[legacy_sources.gd](../scripts/simulation/unified_edit/legacy_sources.gd)数据校验迁移，来源catalog为 `assets/unified_edit/legacy_source_catalog.variant`。数值算法及已登记历史模型的精确投影由[numerics_checkpoint_sources.gd](../scripts/simulation/unified_edit/numerics_checkpoint_sources.gd)与 `assets/unified_edit/numerics_source_catalog.variant` 控制：同发布要求完整source map一致且仅数值选择参数不同；历史来源要求离线pin的完整原配置、逐来源/逐目标映射、完整目标source map及明确的参数差异白名单。缺失历史water_numerics按一阶解释，不能随当前默认值改变。

投影保留原始权威字节、既有账本数量和实际时钟，在新generation重建目标求解器私有工作资源；只允许已审阅的旧模型身份、hash、特征列表及账本标签映射，不宣称旧算法与当前算法等价。当前常规配置和账本校验仍严格，原生control仅按恢复协议换代。旧codec/Recovery的受限静态验证函数不构成旧后端fallback；未知来源、跨域、损坏、普通物理参数改变或未登记目标明确拒绝。新增兼容格式须补迁移策略和证据，不能改magic/版本号伪装兼容。

检查点恢复原始字段与恢复后继续演算的逐位确定性是不同保证。已有固定检查点对照中，同机同后端使用精确旧水面与水侧shader原件，继续填沙、挖沙后仍出现约1e-7量级的水沙及动量字段差异，具体根因未知；这不证明新表现对演算无影响，也不能据此放宽逐点比较。恢复继续遵守既有原始字节、配置、账本和时钟校验；体积账本容差不适用于逐格字段，当前不承诺恢复后任意演算序列逐位一致。

## 性能统计口径与限制

新泡沫路径沿用既有水面绘制与历史场，增加两次细节纹理采样，没有新增水面表现节点、历史RT或compute阶段；这些结构信息不能换算为固定帧率或零额外成本。现有D3D12、GTX1050完整负载对照的旧路径自身时序仍不稳定，部分整帧尾部和模拟吞吐超出原成本边界，尚不能确认新路径完整负载性能达标。视口GPU区间不包含全部异步compute；需分别观察整帧分位数、实际完成模拟时间/墙钟时间及覆盖明确的GPU区间，暂停画面的GPU改善不能替代实时负载结论。

窗口帧间隔、GPU执行区间、CPU完成通知和物理消费者收敛是不同指标。CPU通知按帧领取，不能视为GPU耗时；部分dispatch标签不能代表整个编辑事务。性能面板的窗口统计口径见[性能面板](性能面板.md)。

策略2不构建编辑时的湿区连通域；策略3的每行8湿段、32分量快速路径边界及通用回退会影响复杂湿区的执行成本。水tick的CFL子步、侵蚀、白沫、碎石、漂浮道具和碰撞消费者也参与实际运行负载。性能不设脱离设备、后端、窗口尺寸和场景负载的统一帧率保证。

## 沙面厚度着色

两个正式入口共用 `async_rdc_bed.gdshader`。片元以 `filter_linear`、`repeat_disable` 读取完成态沙厚度，低于0.02m采用裸岩色，0.02–0.16m通过原smoothstep权重混合薄沙与裸岩。插值只影响着色，阈值及沙粒密度30/m保持；高度读取仍使用 `texelFetch` 与既有三角重建，水沙权威数据、碰撞分辨率和账本不受影响。

## 植被表现消费者

九类各2048候选，共18432槽；root与motion均为128×144 RGBA32F，每类读取实例ID加2048倍kind偏移。root保存XYZ与原网格缩放，缩放0表示未存活；motion保存XZ倾斜和XZ速度。私有与发布副本合计1179648B，类型与范围配置缓冲464B。原包多视角RGB+深度图集和代理网格用于裁剪、三视角混合及深度重建。Visuals只读既有rock/sand、水深、动量和障碍，沿同一水tick尾链及编辑后投影更新，work_seal后按原完成态发布与换代。

床高与沙面共用三角形重建，根部只降低；摆动以实际接受dt作临界阻尼解析更新，暂停编辑dt=0。目标倾斜长度不超过0.65，水速度分母下限0.005m，水深权重在0.002–0.05m间平滑变化。水沙权威字段、账本、原生检查点结构不因植被改变；恢复按完整床水重新筛选和初始化。类型区间、尺寸、分布及渲染限制见[植被](植被.md)。

## 漂浮道具消费者契约

正式main预存三件、最多9个有效采样点；UI自由摆放与拾取的登记容量为3件，每类1件，世界中有效物体0–3件，全部拾取时不提交零点探针。公共Probe ABI3请求1152B/输出3200B、最多32点，Height快照ABI3仍69828B/16块/两槽。累计床变上界是私有消费元数据，不属于native3权威字段。Profile v2与严格身份校验、真实Jolt时钟、5mm总床面差预算、暂停/恢复语义见[漂浮道具](漂浮道具.md)及[机器ABI](../task/sandcastle_floating_props/契约/probe_ABI_v3.json)。

原生旧来源只允许离线登记的精确配置投影：完整来源/目标source map和声明值均须匹配，派生模型hash须满足允许的等价投影约束；未知来源、改变的声明和未审阅目标仍拒绝。

UI交互API为manipulate_body(body_id:int, point:Vector2, yaw_rad:float, pickup:bool)，返回operation_id/error/domain_id/generation。调用在已注册三件中选择，有限值/域边界/邻体间距/代次/关闭及生命周期冲突均校验；无动态实例工厂。放置位置需留足shape包围半径+0.2m域内裕量，与其他在场实例的XZ距离至少为双方足迹半径之和+0.05m。拾取后碰撞layer/mask=0，投放恢复2/3，沙刷掩码1、道具拾取掩码2。consumer_v3/schema3仅接受离线白名单中的完整来源配置，additional_sources上限4；不改变native3字段，不保存UI/道具状态。[C07契约](../task/sandcastle_floating_props/契约/C07_UI交互.md)记录新观察起点与关闭语义。
